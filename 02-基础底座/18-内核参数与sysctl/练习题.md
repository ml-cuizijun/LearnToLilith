## Q1

**★★★★★｜生产调过哪些 sysctl？web / db / k8s 有何不同？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 §3 原理 · §8 必会 · 常考

### 场景

「你们机器内核参数怎么调的？」有人背一长串，把 Redis 清单糊到所有 Worker 上。

### 完整解答

**一句话**：按 web/db/k8s 角色裁剪旋钮，先证明瓶颈再调一个，一份清单打全球是错的。

按瓶颈三类讲，每类带证据，再按角色裁剪：

```
  连接队列满  → somaxconn + tcp_max_syn_backlog + syncookies     Web/网关
  出站端口尽  → tw_reuse + ip_local_port_range + 连接池         Web
  fd 不够     → file-max + LimitNOFILE                         Web
  延迟毛刺    → swappiness=1；Redis fork → overcommit=1        DB
  间歇丢包    → conntrack 80%；pid_max                         K8s node
```

量级：somaxconn **32768**（默认 128）、backlog **8192**、port_range `1024 65535`、file-max 百万、ulimit **65535**、swappiness **1**。

**先证明再调。** 持久化 `/etc/sysctl.d/`，`sysctl --system`。一份清单打全球是错的。

### 再追问

somaxconn 和应用 listen 什么关系？——取 **min**。应用 `listen(65535)`、内核 128，实际 128。

## Q2

**★★★★★｜somaxconn 默认 128 会怎样？容器里怎么调？**

**覆盖**：核心 · 必会 · 常用

**对应**：知识点 §3 原理 · §7 生产排障

### 场景

活动开闸，登录超时。网关 listen 很大，宿主机没动过。`ss -lnt` Recv-Q 顶在 128。

### 完整解答

**一句话**：全连接队列实际长度是 min(listen, somaxconn)，默认 128 会把登录 SYN 顶满。

```
  SYN → 半连接(tcp_max_syn_backlog 默认 1024) → 全连接 min(listen, somaxconn)
                                              → 默认 128 满了 → SYN 重传 / 登录超时
```

发现：`ss -lnt` Recv-Q 持续大于 0；`netstat -s | grep overflow`。

处理：somaxconn、backlog、应用 listen 一起拉到 32768+；syncookies 保持 **1**。SYN flood 靠 syncookies，不要只靠 backlog 天文数字。

容器：较新内核 somaxconn namespaced，Pod `securityContext.sysctls` 值 `"32768"`。旧内核改宿主机。读容器内 `/proc/sys` 验证。

### 再追问

半连接队列呢？——`tcp_max_syn_backlog`，生产 **8192+**。

## Q3

**★★★★★｜TIME_WAIT 太多怎么治？能开 recycle 吗？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 §3 原理 · §8 必会 · 常考

### 场景

Nginx 反代游戏 API，后端 TIME_WAIT 几十万，偶发 `Cannot assign requested address`。

### 完整解答

**一句话**：治本是连接池/keepalive；买时间是 tw_reuse + 扩 port_range；`tcp_tw_recycle` 已删除不能用。

1. 治本：应用层连接池 / Nginx **upstream keepalive**（[23](../23-Nginx/)）。
2. `tcp_tw_reuse=1`：只复用**出站** TIME_WAIT，需要 timestamps。
3. 扩 `ip_local_port_range` 到 **`1024 65535`**（默认 32768-60999）。

不要降 `tcp_fin_timeout` 当常规。**`tcp_tw_recycle` 4.12+ 已删除**；老内核在 NAT 下会丢连接。答案里写「已废弃，不用」。

### 再追问

tw_reuse 会影响入站玩家连接吗？——不会。只对这台当客户端的那一侧生效。

## Q4

**★★★★★｜ulimit 和 fs.file-max 差在哪？改了为什么还不生效？**

**覆盖**：核心 · 必会 · 常用

**对应**：知识点 §3 原理 · §1 基本概念

### 场景

Nginx 报 `Too many open files`。有人已经把 `fs.file-max` 调到 100 万。

### 完整解答

**一句话**：fd 有三道门 file-max → nr_open → ulimit/LimitNOFILE，以 `/proc/pid/limits` 为准。

```
  fs.file-max     整机（生产 1000000+）
       └─ fs.nr_open    单进程 hard（默认 1048576，通常不调）
            └─ ulimit -n / LimitNOFILE   实际生效的 soft（1024 → 65535+）
```

以 **`cat /proc/<pid>/limits`** 为准。

- 交互登录：`limits.conf`（PAM）
- **systemd 服务不读 PAM** → `LimitNOFILE=65535`，还要重启进程
- 容器不读 limits.conf → shim / K8s securityContext / `setrlimit`

### 再追问

nr_open 要不要调？——一般不用。soft 65535、全局百万已覆盖绝大多数网关。

## Q5

**★★★★☆｜容器里 sysctl 不生效怎么办？YAML 写了 somaxconn 仍是 128**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 §3 原理 · §5 核心配置

### 场景

YAML 写了 `net.core.somaxconn=32768`，容器里 `cat /proc/sys/...` 仍是 128。

### 完整解答

**一句话**：先问参数是否 namespaced——多数 vm/kernel.* 和 file-max 只能改宿主机。

先问：**这个参数 namespaced 吗？**

| 参数 | 怎么改 |
|------|--------|
| 多数 net.ipv4.* | Pod securityContext.sysctls |
| somaxconn | 新内核是；旧内核否 → **改宿主机** |
| fs.file-max / 多数 vm / kernel.* | 否，宿主机 |

旧内核：privileged initContainer 改的是**整节点**，要当节点配置。验证永远读容器内 `/proc/sys`。

### 再追问

能在容器里改 file-max 吗？——不能。节点 sysctl.d 或受控 DaemonSet。

## Q6

**★★★★☆｜conntrack 表满什么症状？K8s node 还要调什么？**

**覆盖**：必会 · 常用

**对应**：知识点 §3 原理 · §7 生产排障

### 场景

K8s 节点上登录「一会行一会不行」。CPU 不高。`dmesg`：`table full, dropping packet`。

### 完整解答

**一句话**：count/max >80% 告警；表满间歇丢新连接，治本少短连接或切 IPVS。

表满时 **新连接被丢**，已跟踪的还在。kube-proxy iptables 模式几乎每条连接占一项。默认 max 常见 **65536**。

```bash
cat /proc/sys/net/netfilter/nf_conntrack_count
cat /proc/sys/net/netfilter/nf_conntrack_max
# count/max > 80% 告警
```

买时间：调大到百万级（生产常见 **1048576**，按内存）。治本：少短连接、切 IPVS、NodeLocal DNS Cache（[15](../15-iptables与conntrack/)、04-08）。

K8s node 同时盯：`kernel.pid_max` **4194304**（默认 32768）、`inotify.max_user_watches` **524288+**、宿主机 file-max。不要把 Redis overcommit=1 推到所有 Worker。

### 再追问

为什么是间歇的？——表有空位时又能建；打满又丢。count 锯齿。

## Q7

**★★★★☆｜swappiness 设 0 还是 1？dirty_ratio 不调会怎样？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 §3 原理 · §8 必会 · 常考

### 场景

Redis 延迟毛刺。`swappiness` 还是 60。有人建议 `swapoff -a`。日志机写突然全体卡住，脏页到过 20%。

### 完整解答

**一句话**：Redis 用 swappiness=1 不是 0；dirty_ratio 默认 20 会让所有写进程集体阻塞。

默认 60：还有 page cache 就开始换匿名页。调到 **1–10**。Redis 官方 **1 不是 0**。

- `0`：内存突增更容易直接 OOM Kill。
- `1`：几乎不换，极端仍给内核退路。

常见：swap **开着**、swappiness 很低。容器里多数不能独立设，改宿主机。

`overcommit_memory=1`：fork 瞬间 RSS 看起来翻倍，避免 bgsave 失败。代价超分，Web 机别抄。

`dirty_ratio` 默认 20：脏页到内存 20% 时 **所有写进程阻塞**。收到 **10**、`dirty_background_ratio` **5**。磁盘慢仍查 [05](../05-磁盘与IO/)。`min_free_kbytes` 一般不调。

### 再追问

THP 呢？——Redis 建议 `transparent_hugepage=never`，防延迟毛刺。和 max_map_count 不是一回事。

## Q8

**★★★☆☆｜ES 报 vm.max_map_count 太低？ENOSPC 一定是盘满吗？**

**覆盖**：常用 · 常考

**对应**：知识点 §3 原理 · §5 核心配置

### 场景

Elasticsearch 日志：`max_map_count [65530] is too low`。CI 报 `ENOSPC: System limit for number of file watchers`。

### 完整解答

**一句话**：ES 要 max_map_count≥262144；ENOSPC 也可能是 inotify watches 不够，不一定是盘满。

Lucene 用大量 mmap。官方 **≥262144**（默认 65530）。

```bash
sysctl -w vm.max_map_count=262144
echo "vm.max_map_count = 262144" >> /etc/sysctl.d/99-elasticsearch.conf
sysctl --system
```

inotify `fs.inotify.max_user_watches` 默认 **8192**，CI / Node 调到 **524288+**。`ENOSPC` 不一定是盘满。高密度节点再看 `pid_max`。

### 再追问

这些要写进 Web 网关镜像吗？——按角色。ES 节点才强制 map_count；网关优先队列和 fd。

## Q9

**★★★★☆｜内核 TCP keepalive 能当游戏心跳吗？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 §3 原理 · §8 必会 · 常考

### 场景

战斗长连接「死连接」几小时才消失。有人把 `tcp_keepalive_time` 调到 30 秒当心跳。

### 完整解答

**一句话**：内核 keepalive 只清僵尸 TCP，游戏存活必须应用层 15–45s 心跳，两层不能混。

默认 **7200s** 才开始探，9 次 × 75s，清死连接极慢。生产可收到 **600/30/3**，**仍然只是清僵尸 TCP**。

游戏需要知道「人是不是还在玩」：必须 **应用层 15–45s 心跳**。内核检测不了应用卡死、半开但还能 ack 的壳。

空闲超过 time 才探；有数据的连接不会无故被探死。怕 NAT 超时，才把 time 降到分钟级，和玩法心跳仍是两层。

### 再追问

tcp_fastopen=3？——双端都支持才有意义。不是心跳问题。

## Q10

**★★★☆☆｜改错了怎么回滚？升内核要注意什么？**

**覆盖**：必会 · 常用

**对应**：知识点 §4 落地 · §7 生产排障

### 场景

有人在高峰把 swappiness 调到 0，Redis 直接 OOM。下周要升内核，脚本里还有 `tcp_tw_recycle=1`。

### 完整解答

**一句话**：sysctl 改 conf + `sysctl --system` 回滚；LimitNOFILE 要重启进程；升级前查 recycle 已删、namespaced 是否变。

sysctl 回滚：改 conf + `sysctl --system`。LimitNOFILE 必须 **重启进程**。错误 0 改回 **1**，不要先 `swapoff` 掩盖。

升级：`tw_recycle` 可能已不存在；somaxconn 是否 namespaced 会变。先升一台看 Recv-Q、延迟、OOM。角色 conf 随镜像走，不要登录后手糊。

一参一改。没有图就全调一遍叫拍脑袋。

### 再追问

安全 sysctl 能不能写进 99-production.conf？——可以同机不同文件。redirects/rp_filter 在 [17](../17-Linux安全加固/)，不要和性能清单说不清。
