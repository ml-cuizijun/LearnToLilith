## 1. 基本概念

两台同等机器，各跑 HAProxy（或 Nginx）+ Keepalived。对外只宣告 **一个 VIP**。Keepalived 用 VRRP 决定谁占 VIP；HAProxy 负责把流量分到后端并做健康检查。

**值班里怎么认现象**（先听监控/玩家怎么说，再对表）：

| 现场说的 | 技术含义 | 你的第一刀 |
|----------|----------|------------|
| 「一半玩家掉线一半正常」 | 双 VIP 脑裂 | 两台 `ip addr` 看 VIP |
| 「入口全超时但进程在」 | HAProxy 假死 / VIP 没漂 | track_script + stats |
| 「切主后还是打到旧机」 | GARP 没刷 / 跨三层 | tcpdump ARP |
| 「MySQL 入口连不上」 | mode tcp 或后端 DOWN | stats 看 server 状态 |

两件事别混：

| 组件 | 干什么 |
|------|--------|
| **Keepalived** | VIP 在哪台；VRRP 通告；track_script 探本机代理 |
| **HAProxy** | 流量怎么分；四层/七层；rise/fall 摘后端 |

LVS 是内核四层、超大并发入口，模式和 DR 里 RIP 配置在 **16**。Keepalived 也可以管 LVS 的 ipvs 规则，那是 16 的搭配；这里默认 **Keepalived 只做 VIP + 探 HAProxy 进程**。

脑裂概念（分区双主）在 20。两节点 VRRP **没有 quorum**，心跳被挡就会双 VIP，这是本章现场题。etcd 靠多数派停写；Keepalived 两台停不了写。重要数据不要指望 VRRP 当一致性协议。

云上「VIP」常常是产品 SLB，不一定能自建 VRRP，那是 07。

> **记住**：Keepalived 管 VIP 在哪台，HAProxy 管流量怎么分。VRRP 通 ≠ 后面的代理还活着。必须 track_script。

**面试怎么说**：「双机入口我画 Keepalived 漂 VIP + HAProxy 分流量两层；VRRP 是协议 112 不是 UDP 端口；脑裂先停一台 keepalived 止血。」

## 3. 原理

### 3.1 四层七层：HAProxy vs Nginx

**一句话：** 库/战斗 TCP 用 HAProxy mode tcp；静态 HTTP 用 Nginx。

**打个比方**：四层像邮局只认邮编和门牌号，七层像还要拆信封看收件人姓名和备注——战斗长连接没有「一封信就结束」，硬拆信封会卡在缓冲和超时上。

**现场走一遍**（有人要把游戏战斗 TCP 挂到 Nginx HTTP 反代）：

1. 看现有 Nginx 配置：

```bash
nginx -T | grep -E 'proxy_pass|stream|listen'
```

2. 屏幕只有 `listen 443 ssl` + `proxy_pass http://backend`，没有 `stream {}` 块。

3. **说明什么**：这是七层 HTTP 反代——战斗帧同步长连接走这里会变成解析、缓冲、超时事故源（23）。

4. 正确分层：登录 HTTP → Nginx（23）；战斗 TCP → HAProxy `mode tcp` 或 LVS（16）：

```bash
grep -A5 'frontend.*tcp' /etc/haproxy/haproxy.cfg
```

5. 应看到 `mode tcp`、`balance leastconn`、`option tcp-check`，超时分钟级而非 30s。

**输出解读**：

| | HAProxy | Nginx |
|--|---------|-------|
| 定位 | 专业 LB | Web + 反代 + LB |
| 四层 TCP/UDP | 很强、原生 `mode tcp` | stream 模块有 |
| 七层 | 有，ACL 够用 | 静态、缓存、更花 |
| 健康检查 | HTTP/TCP/自定义，细 rise/fall | 开源偏被动 max_fails |
| Stats | 自带页面看会话 | 要模块 |
| 典型 | 库代理、游戏 TCP、纯 LB | 站点、API 网关 |

数据库、Redis、战斗 TCP、要精细探活 → HAProxy。静态和复杂 HTTP → Nginx（23）。超大四层、要上内核 → LVS（16）。超时链同样外短内长（23）。

**面试怎么说**：「战斗 TCP 和 MySQL 入口我用 HAProxy mode tcp；登录静态走 Nginx。不是为了统一入口把长连接塞七层。」

### 3.2 VRRP：通告、GARP、抢占

**一句话：** VRRP 是 IP 协议 112；VIP 漂靠 GARP 刷 ARP。

**打个比方**：VRRP 像两个人抢一个门牌号——Master 每隔 1 秒喊「我还在」（advert），Backup 三声没听见就挂上新门牌并广播「门牌换人了」（GARP），让邻居更新地址簿。

**现场走一遍**（主备切换演练，确认 VIP 漂得正常）：

1. 备机上看当前谁有 VIP：

```bash
ip addr show eth0 | grep 192.168.1.100
```

2. 主机关 HAProxy（有 track_script 时）：

```bash
systemctl stop haproxy
```

3. 备机 2～3 秒内应出现：

```text
inet 192.168.1.100/24 scope global secondary eth0
```

4. 同时抓 GARP：

```bash
tcpdump -i eth0 arp -nn -c 5
```

```text
ARP, Request who-has 192.168.1.100 tell 192.168.1.100, length 28
```

5. **说明什么**：新 Master 发 Gratuitous ARP 刷同网段 ARP 缓存，交换机学到新 MAC。玩家侧 HTTP 常无感；战斗 TCP 往往要重连。

**输出解读**：

| 参数 | 含义 | 常见值 |
|------|------|--------|
| `advert_int` | 通告间隔 | 1s |
| 超时判定 | 约 `advert_int × 3` | 3s 无 advert 升主 |
| `priority` | 谁更愿意当主 | 100 vs 90 |
| `virtual_router_id` | 同组标识 | 51，撞 id 会乱跳 |
| `nopreempt` | 主恢复不抢回 | 避免二次闪断 |
| `weight -30` | 脚本失败降权 | 100-30=70 < 90 才漂 |

`state MASTER/BACKUP` 只是开机意愿；**真正谁主看 priority**。VRRP 通常要 **二层互通**；跨三层 ARP/GARP 刷不到，表现为漂了仍打到旧机。云上组播常被禁：改 **单播** `unicast_src_ip` + `unicast_peer`，安全组仍要放行协议 112。

**面试怎么说**：「VRRP 是 IP 协议号 112，不是 UDP 端口 112。谁主看 priority 不是 state。VIP 切换靠 GARP 刷 ARP，一般 1～2 秒。」

### 3.3 脑裂：两节点没有 quorum

**一句话：** 双 VIP 先停一台 keepalived；两节点没有 quorum。

**打个比方**：两台对讲机被墙隔开，各以为对方死了，同时自封队长——这就是脑裂。etcd 有投票机制能停写；Keepalived 两台没有「多数派」，只能尽量让通告通。

**现场走一遍**（改完防火墙后两台都有 VIP）：

1. 两台同时查：

```bash
ip addr show | grep -A2 192.168.1.100
```

2. 两台都显示 `inet 192.168.1.100` → **脑裂确认**。

3. **止血**：只停一台 keepalived，不要两台一起改 priority：

```bash
systemctl stop keepalived   # 只在一台执行
```

4. 确认只剩一台有 VIP 后，抓 VRRP 通告：

```bash
tcpdump -i eth0 proto 112 -nn -c 20
```

5. 若抓不到双向 advert → 查防火墙是否把 **协议 112** 当「UDP 端口 112」拦了（现场最高频）。

```mermaid
flowchart LR
    A[MASTER 周期性 advert 协议 112] --> X[防火墙丢掉 / 线路分区]
    X --> Y[两边都超时看不见对方]
    Y --> Z[都占 VIP · 双主]

    classDef bad fill:#DC2626,stroke:#7F1D1D,stroke-width:2px,color:#fff
    class Z bad
```

**输出解读**：

| 现象 | 含义 | 下一步 |
|------|------|--------|
| 两台都有 VIP | 脑裂 | 先停一台 keepalived |
| `proto 112` 单向 | 通告被挡 | 改防火墙规则 |
| `virtual_router_id` 撞车 | 两组抢通告 | 规划 VRID |
| `auth_pass` 不一致 | 像看不见对方 | 对齐认证 |
| 漂了业务不通 | GARP/新主 HAProxy | 查 listen 和防火墙 |

etcd 不会双 Leader 双写（多数派）。Keepalived 两台停不了写，只能尽量让通告到达。若后端已双写，按 20 选真相、评估 RPO，不是只修 VIP。

**面试怎么说**：「双 VIP 我先停一台 keepalived 止血，再 tcpdump proto 112。两节点 VRRP 没有 quorum，和 etcd 脑裂不一样，Keepalived 停不了写。」

> **记住**：VRRP 是协议 112；VIP 漂不漂看 priority 减完 weight 还够不够。进程在不等于还在接请求。双 VIP 先停一台。

## 4. 落地

两台同规格、同网段（VRRP 二层）、安全组放行协议 112（不要写成 UDP 112 端口）。HAProxy 与 keepalived systemd enable。VIP 不要和业务 IP 抢 ARP。云上先确认能不能自建 VRRP。

HAProxy 配置要点（`/etc/haproxy/haproxy.cfg`）：

```
global
    maxconn 50000
    log /dev/log local0
    user haproxy
    group haproxy

defaults
    mode http
    timeout connect 5s
    timeout client 30s
    timeout server 30s
    option httplog
    option dontlognull

frontend web_frontend
    bind *:80
    default_backend web_backend

backend web_backend
    balance roundrobin
    option httpchk GET /health
    server web1 192.168.1.10:8080 check inter 2s rise 2 fall 3
    server web2 192.168.1.11:8080 check inter 2s rise 2 fall 3

frontend mysql_frontend
    bind *:3306
    mode tcp
    default_backend mysql_backend

backend mysql_backend
    mode tcp
    balance leastconn
    option tcp-check
    server mysql-master 192.168.1.20:3306 check
    server mysql-slave  192.168.1.21:3306 check backup
```

Keepalived（`/etc/keepalived/keepalived.conf`）：

```
vrrp_script chk_haproxy {
    script "/etc/keepalived/check_haproxy.sh"
    interval 2
    weight -30
    fall 2
    rise 1
}

vrrp_instance VI_1 {
    state MASTER
    interface eth0
    virtual_router_id 51
    priority 100
    advert_int 1
    authentication {
        auth_type PASS
        auth_pass yourpassword
    }
    virtual_ipaddress {
        192.168.1.100/24
    }
    track_script {
        chk_haproxy
    }
}
```

Backup：同 VRID/VIP/auth/track，`priority 90`。游戏 TCP：`mode tcp`、分钟级 timeout，别继承 http 的 30s。验收：单 VIP、`proto 112` 双向、停 haproxy 能漂、httpchk 能摘假活后端；Stats 鉴权。

## 5. 核心配置

| 选项 | 含义 | 改错会怎样 |
|------|------|------------|
| `mode tcp` / `http` | 四层 / 七层 | 战斗走 http 会解析失败 |
| `check` | 开启探活 | 不 check = 死后端仍打 |
| `inter 2s` | 间隔 | 太大切得慢 |
| `rise 2` / `fall 3` | 连续成功才 UP / 失败才 DOWN | 抗抖 |
| `backup` | 主全挂才用 | — |
| `httpchk GET /health` | HTTP 探 | 只 200 端口活、Java 卡死仍 UP |
| `tcp-check` | 四层探端口 | 游戏 TCP 假活 |
| `timeout client/server` | 外短内长 | 只抄 30s 会断长连接 |
| `virtual_router_id` | 同组相同 | 撞 id → VIP 乱跳 |
| `priority` + `weight` | 谁主 | weight 太小不漂 |
| `nopreempt` | 不抢回 | 要不要二次闪断 |
| `advert_int` | 通告间隔 | 太大漂得慢 |
| `unicast_peer` | 云上禁组播时 | 仍要放行协议 112 |
| `timeout tunnel` | 长连接隧道 | 游戏 TCP 只抄 30s 会断 |
| stats bind | 内网 + auth | 公网裸奔泄后端名单 |

探脚本：

```bash
#!/bin/bash
# /etc/keepalived/check_haproxy.sh
if ! killall -0 haproxy 2>/dev/null; then
    systemctl start haproxy
    sleep 2
    if ! killall -0 haproxy 2>/dev/null; then
        exit 1
    fi
fi
exit 0
```

只 `killall -0` 是进程级；假死不 accept 要探端口或 HTTP。

> **记住**：四层 mode tcp + tcp-check；七层 httpchk 要碰到业务。

## 6. 命令与操作

值班先跑：谁有 VIP、协议 112 通不通、haproxy 在不在听、stats 里 server 是否 UP。

```bash
ip addr show
tcpdump -i eth0 proto 112
killall -0 haproxy
ss -tlnp | grep -E '80|3306|8080'
haproxy -c -f /etc/haproxy/haproxy.cfg
systemctl reload haproxy
systemctl stop keepalived   # 脑裂止血：只停一台
```

| 目的 | 命令 | 看什么 |
|------|------|--------|
| VIP 在谁 | `ip addr` | 是否双主 |
| VRRP | `tcpdump proto 112` | 通告双向？ |
| 配置 | `haproxy -c` | reload 前 |
| 后端 | stats 页 / socket | rise/fall 后 UP 没有 |
| 脚本 | 手工跑 check_haproxy.sh | exit 码；权限 |
| 运行时会话 | `echo show stat \| socat stdio /run/haproxy/admin.sock` | 后端 UP/DOWN |

### 6.1 探活与读写分离

HTTP 用 `httpchk GET /health`（要碰到依赖）；TCP 用 `tcp-check`（可能假活）。MySQL 读写：写 3306 → master，读 3307 → slaves（03）。

### 6.2 VIP 与 track_script

weight -30 须让降完低于备机。没 track_script：VRRP 只保 keepalived 活。`nopreempt` 避免主恢复二次闪。

### 6.3 VPN 与正向代理

| 场景 | 选 |
|------|----|
| 运维进内网 | WireGuard（新）/ OpenVPN（老） |
| 跨云机房 | 云 IPSec VPN / 专线（07） |
| 开发进测试 | WireGuard / Tailscale |
| 出海加速 | 云全球加速（GAAP），**不是**给玩家上办公 VPN |

**正向代理**出网；**反向代理**接用户（23）。Squid/Dante；SSH `-D` 临时用（25）。`http_proxy`/`no_proxy` 内网 CIDR 必配；Docker 要 systemd drop-in。WireGuard 密钥进堡垒/密管（25、17）。

| 需求 | 工具 |
|------|------|
| Web + 静态 | Nginx 23 |
| 精细 TCP/HTTP LB | HAProxy |
| 内核超大四层 | LVS 16 |
| 主备 VIP | Keepalived |
| 办公 VPN | WireGuard |
| 内网出网代理 | Squid + no_proxy |

```mermaid
    style split fill:#FEF2F2,stroke:#DC2626,stroke-width:4px,color:#7F1D1D
    style one fill:#FEF3C7,stroke:#D97706,stroke-width:4px,color:#92400E
```

| 现象 | 先查 | 不要做什么 |
|------|------|------------|
| 两台都是 MASTER、都有 VIP | 协议 **112**；`tcpdump proto 112` | 两台同时调 priority 对打 |
| VIP 不漂 | priority/weight 算完；脚本其实成功；`nopreempt` | 只重启业务 |
| 漂了但业务不通 | 新主 HAProxy；防火墙；GARP | 当后端全死重启战斗服 |
| 漂得慢 | `advert_int` 太大 | — |
| Java 卡死仍 UP | httpchk 要碰到依赖 | 加大 timeout 掩盖 |
| 主恢复又闪一次 | nopreempt | 当成又一次故障切来切去 |
| 构建机设了代理连不上 Harbor | no_proxy 内网 CIDR | 只 export 当前 shell |

活动高峰入口：先确认 VIP 唯一、HAProxy listen、后端 health，不要把 VRRP 抖动当成要重启逻辑服。

## 8. 必会 · 常考

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 入口有 Nginx 就不必 HAProxy | 错 | 库/战斗 TCP/精细探活用 HAProxy |
| 战斗长连接和登录都塞七层 | 错 | 长连接走四层 |
| VRRP 是 UDP 端口 112 | 错 | **IP 协议号 112** |
| `state MASTER` 决定谁主 | 错 | 看 priority |
| 两节点 VRRP 有 quorum | 错 | 没有；会双 VIP |
| 脑裂和 etcd 一样停写 | 错 | Keepalived 停不了写 |
| 只探 PID 就等于代理活着 | 错 | 假死不 accept 要探端口 |
| weight -10 一定能切（主 100 备 90） | 错 | 100-10=90 不够；要低于备机 |
| httpchk 只 200 即可 | 错 | health 要碰到依赖 |
| 玩家加速走办公 VPN | 错 | GAAP / 云加速，不是 WireGuard 办公 |
| 正向代理不用 no_proxy | 错 | 内网会绕一圈失败 |
| 双 VIP 先两台一起改优先级 | 错 | 先停一台止血 |
| Keepalived 不能只做 LVS | 错 | 能，那是 16；本章是 HAProxy 双机 |
| 主恢复必须抢回 VIP | 错 | nopreempt 可避免二次闪 |
| Docker 只 export 代理就够 | 错 | systemd Environment= |

数字：协议 **112**；GARP **1～2s**；整段切 **2～3s**；`advert_int` 常见 **1s**，超时约 ×3；priority **100/90**，weight **-30**；`inter 2s rise 2 fall 3`；VRID 例 **51**。

易混：HAProxy vs Nginx vs LVS；VIP vs 后端探活；协议 112 vs UDP 112；抢占 vs nopreempt；tcp-check vs httpchk；正向 vs 反向代理；脑裂止血 vs 修数据。
