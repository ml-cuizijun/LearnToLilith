## Q1

**★★★★★｜生产服务器怎么加固？从入口讲到发现**

**覆盖**：核心 · 必会 · 常考

### 场景

安全同学问：「你们游戏逻辑服机器怎么加固的？」有人只答「改了 22 端口」。

### 完整解答

按三层讲，不要堆工具名：

```mermaid
flowchart TB
    a[入口：堡垒机唯一 + key only + 禁 root + 禁密码 + 防火墙默认 DROP]
    b[权限：独立账号 + sudo 白名单 + nologin + 640 + SELinux Enforcing]
    c[发现：auditd 离机 + AIDE + 异常登录/外连 + fail2ban]
    a --> b --> c
    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    classDef c fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class a a
    class b b
    class c c
```

新机从加固基线镜像出，CIS / Lynis 定期扫，不合格项要有人认领。

### 再追问

容器上了还要不要这些？——宿主机要。容器层靠 PSS + RBAC + NetworkPolicy（04-13 / 04-10）。不能拿「已经 K8s」当关 SELinux、开密码登录的理由。

## Q2

**★★★★★｜SSH 怎么加固？改端口算不算安全核心？**

**覆盖**：核心 · 必会 · 常考

### 场景

新环境默认 `root` + 密码。有人说「先改成 2222 顶一阵」。

### 完整解答

安全核心是 **认证方式和入口**，不是端口号。

```
  错：只改 Port 2222，仍允许 root 密码
  对：PasswordAuthentication no
      PermitRootLogin no
      PubkeyAuthentication yes
      AllowUsers deploy@堡垒机网段
      MaxAuthTries 3 · ClientAliveInterval 300
      人只从堡垒机进（ssh -J）
```

| 项 | 作用 |
|----|------|
| 禁密码 | 暴力破解失效 |
| 禁 root | 审计能对到人 |
| 限 IP | 公网撞库打不到业务机 |
| key + passphrase | 私钥拷走还有口令 |
| 改端口 | 少日志噪音；扫描器仍能发现 |
| 关 X11 / TcpForwarding | 缩小跳板面 |

改 `sshd_config` 先 `sshd -t`，再 **reload**。语法错 + restart 可能把自己锁在外面——所以才要堡垒机 / 云控制台当逃生口（25）。防火墙必须同步新端口。

### 再追问

key 被盗了怎么办？——立刻吊销该公钥、查 auditd / 堡垒机录像、轮换所有可能被拷走的 key。不要只改 passphrase 却让旧 key 留着。

## Q3

**★★★★★｜sudo 怎么管？临时要 root 怎么办？**

**覆盖**：核心 · 必会 · 常用

### 场景

活动值班说「每次重启 nginx 都要找人 sudo」，要求 `deploy ALL=(ALL) NOPASSWD: ALL`。

### 完整解答

```
  visudo
  Cmnd_Alias NGINXCTL = /bin/systemctl restart nginx, /bin/systemctl reload nginx
  deploy ALL=(root) NGINXCTL
  deploy ALL=(root) !/bin/su, !/bin/bash, !/bin/sh
```

1. 白名单到具体命令，不要 ALL。
2. 禁 `su`/`bash`，否则白名单形同虚设。
3. 每人独立账号。共享 `ops` 出事对不到人。
4. 日志进 `/var/log/secure` 或 `auth.log`，**转发离机**。
5. `Defaults timestamp_timeout=5` 缩短免密窗口。

临时 root：审批工单 → 堡垒机限时授权 → 录屏 → 到期收回。不要把「活动周」变成永久 NOPASSWD。

### 再追问

visudo 写错了会怎样？——sudo 全部失效。必须 `visudo`，并保留一个已登录的 root 会话或云控制台，直到验证 `sudo -l` 正常。

## Q4

**★★★★☆｜防火墙最小化怎么做？和安全组什么关系？**

**覆盖**：必会 · 常用 · 常考

### 场景

房间端口对 `0.0.0.0/0` 开着。有人说「反正游戏有自己的鉴权」。改完 INPUT DROP 当前 SSH 还在，以为成功了。

### 完整解答

默认 **DROP**，显式放行：

1. `ESTABLISHED,RELATED` 放在前面。
2. SSH **只放堡垒机 CIDR**，不要公网 22。
3. 业务口只放 LB / 内网上游。
4. 非路由器：`ip_forward=0`，FORWARD DROP。
5. 出站也收：NTP、制品库、DNS 显式放；陌生外连拒绝或告警。
6. 改完 **另一条会话** 验证。当前 ESTABLISHED 骗得了你。保存规则，防 reboot 丢。

云安全组是第一层，主机防火墙是第二层。链细节在 15。不要只开 syncookies 就说防火墙做好了。

### 再追问

禁 ping 要不要开？——`icmp_echo_ignore_all` 可选，排障和云探活会疼，**不是必开**。扫描项书面接受即可。

## Q5

**★★★★★｜SELinux 和 AppArmor 差在哪？被拦了能不能关？**

**覆盖**：核心 · 必会 · 常考

### 场景

Nginx 反代连不上上游。群里有人发 `setenforce 0`，「先恢复业务」。

### 完整解答

两者都是 **MAC**。SELinux 用标签 + 策略，RHEL 系；AppArmor 用路径 + profile，Debian 系。生产都应 **Enforcing / Enforce**。

```
  服务连不上
       → getenforce / sestatus
       → ausearch -m AVC / aa-status
       → 缺布尔 → setsebool -P
       → 缺策略 → audit2allow，评审后再装
       → 不要 setenforce 0 当第一刀
```

Permissive 只记不拦，排查窗口可以，当天必须回去。Disabled 连审计都没有，不要写进生产镜像。容器不替代宿主机 MAC。

### 再追问

Permissive 和 Disabled 呢？——Permissive 还能看到 AVC。Disabled 等于拆除。扫描会记一笔。

## Q6

**★★★★★｜怎么发现机器被入侵了？发现后第一步？**

**覆盖**：核心 · 必会 · 常考

### 场景

AIDE 报 `/usr/bin/ssh` hash 变了。有人要立刻 `kill` 再重装 ssh。

### 完整解答

发现靠多层：AIDE 关键路径 hash；auditd 写 passwd/sudoers/sshd；非白名单登录；未知进程 / 异常 SUID；非预期外连。

顺序：

1. **网络隔离，不关机**（保内存）。
2. 取证：磁盘快照、内存 dump、`ss`/`ps`/`last`、authorized_keys、日志。
3. 影响面：支付库、横向跳。
4. 再清理、轮换密钥、必要时重装基线镜像。

fail2ban 只能挡扫端口，挡不住失窃 key。history 空 ≠ 没人登过。

### 再追问

history 里没有可疑命令？——不是没人登过。看 auditd、离机那份 secure/auth.log、堡垒机录像。

## Q7

**★★★★☆｜auditd 和 history 差在哪？AIDE 什么时候 init？**

**覆盖**：必会 · 常用

### 场景

合规问操作审计。有人说「大家都开了 histappend」。凌晨 AIDE 告警，今晚有过补丁窗口。

### 完整解答

`history` 用户可清、可改。**auditd 是内核审计**：`-w /etc/sudoers -p wa` 对写入一定有事件。生产 = 规则 + **日志离机**。本机 audit.log 不够，root 能改（22）。

AIDE：干净安装时做基线。hash 变了先对变更单——对得上就更新基线留记录；对不上当入侵，**不要 `aide --init`**。只监控 `/etc` 不够，后门常改 `/usr/bin`、`/usr/sbin`。

### 再追问

只 `alarm` 式 fail2ban 能否代替 AIDE？——不能。fail2ban 减撞库噪音；完整性是另一层。

## Q8

**★★★★☆｜为什么不能 chmod 777？SUID 是什么？**

**覆盖**：必会 · 常用 · 常考

### 场景

游戏配置改不了，有人 `chmod -R 777 /data/game`。过两天安全扫出 `/tmp` 下一个 SUID 二进制。

### 完整解答

`777` = 谁都能读改执行。目录 `750`、配置 `640` 是底线。umask 常见 `022`。

SUID：二进制跑起来时用**文件属主**身份。`passwd` 合法；来历不明的是提权后门。

```bash
find /usr/bin /usr/sbin /tmp /data -perm -4000 -ls
```

定期扫，多出来的先隔离。sticky bit（`/tmp` 的 `1777`）只解决「不能删别人的文件」，不解决 SUID。SGID 目录是共享组，不要和 SUID 后门混谈。

### 再追问

服务账号要不要 login shell？——`useradd -r -s /sbin/nologin`。禁止业务用 root 跑。

## Q9

**★★★★☆｜改 sshd / 防火墙 / 打补丁怎么操作才不算事故？**

**覆盖**：必会 · 常用

### 场景

改端口后 reload，当前窗口还在。断开就进不去。另一次打完补丁 AIDE 全红，有人 `--init` 消告警。

### 完整解答

sshd：留堡垒机/console → `-t` → reload（不要 restart）→ **新开会话**验证 → 防火墙同步端口。

防火墙：先加 ACCEPT 再 DROP；另一条会话验证；保存规则。

补丁：变更单 → 打补丁 → AIDE 对预期 diff → 更新基线。对不上走入侵流程。

密钥轮转：离职当天吊销；泄漏先 revoke 再查录像。

### 再追问

安全 sysctl 改哪些？——redirects=0、source_route=0、syncookies=1、非路由器 ip_forward=0、rp_filter=1。连接队列在 18。

## Q10

**★★★☆☆｜合规扫 CIS 不过，要不要每条都修？**

**覆盖**：常用 · 常考

### 场景

Lynis / OpenSCAP 打出几十条。有人说「游戏服不能禁 ping、不能关转发等着当 NAT」。

### 完整解答

不用背每一条。要有：**基线镜像覆盖高危项、扫描定期跑、不合格项有人认领（修或风险接受）。**

- 高危：密码登录、root SSH、SELinux Disabled、777、无审计 → **必须修**
- 架构冲突：这台就是 NAT 要 ip_forward → 文档 + 扫描白名单
- 噪音：改 banner、禁 ping → 可接受，要有记录

扫描过了不是 IDS。还要靠 AIDE、异常登录、离机审计、堡垒机（25）。

### 再追问

新机手搓到过线行不行？——慢且会漂。从过线镜像出厂，滚动换机。
