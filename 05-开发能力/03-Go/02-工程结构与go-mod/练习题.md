## Q1

**★★★★★｜新项目第一个命令该敲什么？`module github.com/team/patrol` 这行影响什么？**

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生：go mod init 与 module path](知识点.md)

### 场景

SRE 平台要新建 K8s 巡检 CLI，仓库空目录。

### 完整解答

> 🎯 **一句话**：先 `go mod init <module-path>`；**module 行 = 全仓库 import 前缀**。

```bash
mkdir patrol && cd patrol
go mod init github.com/moonton/patrol
mkdir -p cmd/patrol internal/k8s
```

同模块内：`import "github.com/moonton/patrol/internal/k8s"`。

> 📝 **面试**：「module path 要唯一、与团队 VCS 约定一致；不必真有 GitHub 但习惯用域名反写。」

### 再追问

能写成 `module patrol` 吗？——能但不推荐，易冲突；生产用完整路径。

## Q2

**★★★★★｜`go.sum` 要不要提交 Git？合并后 CI 报 checksum mismatch 怎么办？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [三、成长：require、go get 与 go.sum](知识点.md)

### 场景

两人各 `go get` 不同 patch 版本，PR 合并后 main 构建失败。

### 完整解答

> 🎯 **一句话**：**go.sum 必须提交**；冲突时本地 `go mod tidy` 再提交，勿手删单行糊弄。

```bash
go mod tidy
git add go.mod go.sum
```

若代理缓存脏了：`go clean -modcache` 后重新 `go mod download`（团队协调执行）。

> ⚠️ **别混**：`go.sum` 不是 lock 的替代品——它和 `go.mod` 一起保证可复现。

### 再追问

`go.sum` 很大正常吗？——依赖多会大；别 gitignore。

## Q3

**★★★★★｜仓库里两个 CLI：`patrol` 和 `exporter`，目录怎么摆？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、目录布局：cmd、internal、pkg](知识点.md)

### 场景

一个 repo 既要节点巡检又要 Prometheus exporter。

### 完整解答

> 🎯 **一句话**：**`cmd/patrol/main.go` + `cmd/exporter/main.go`**，共享 `internal/`。

```text
cmd/patrol/main.go
cmd/exporter/main.go
internal/scrape/
```

```bash
go build -o bin/patrol ./cmd/patrol/
go build -o bin/exporter ./cmd/exporter/
```

### 再追问

根目录放 `main.go` 可以吗？——小 demo 可以；团队规范用 cmd。

## Q4

**★★★★★｜外部项目 `import "github.com/moonton/patrol/internal/k8s"` 编译失败——为什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、目录布局：cmd、internal、pkg](知识点.md)

### 场景

别的团队想复用你们的 k8s 封装，直接引 internal。

### 完整解答

> 🎯 **一句话**：**internal 目录对父模块树外不可 import**，编译器强制。

修法：稳定 API 抽到 `pkg/k8s` 或独立 module；或 fork 合作。

> 📝 **面试**：「internal 是语言级封装，不是约定。」

### 再追问

`internal/foo` 能被 `cmd/bar` 引吗？——能，同属本 module。

## Q5

**★★★★☆｜删了代码里的 import 后 `go.mod` 还留着旧依赖——用什么命令清理？**

**覆盖**：必会 · 常用 | **对应**：知识点 [三、成长：require、go get 与 go.sum](知识点.md)

### 场景

去掉 cobra 后 go.mod 仍 require cobra。

### 完整解答

> 🎯 **一句话**：**`go mod tidy`** 删未使用直接依赖并更新间接依赖。

```bash
go mod tidy
```

PR 检查：diff 里 go.mod/go.sum 应与代码一致。

### 再追问

`tidy` 会升级版本吗？——主要整理图；大升级用 `go get -u=patch` 等显式操作。

## Q6

**★★★★★｜`go.mod` 里有 `replace github.com/lib => ../lib`，同事 clone 后 build 失败——问题？**

**覆盖**：核心 · 常考 | **对应**：知识点 [六、replace、vendor 与 go.work](知识点.md)

### 场景

你本地联调忘了删 replace 就 push。

### 完整解答

> 🎯 **一句话**：**replace 指向你本机路径**，别人没有 `../lib`。

修法：删 replace；本地用 **go.work** 或环境隔离；联调结束别进 main。

> ⚠️ **别混**：`replace` 不是 `go.work` 的替代品——work 文件通常不提交。

### 再追问

生产紧急 patch 能 replace 到 fork 吗？——可以临时，要有回滚计划和正式版本跟进。

## Q7

**★★★★☆｜ air-gap 机房构建不能访问 proxy，怎么编？**

**覆盖**：常用 | **对应**：知识点 [六、replace、vendor 与 go.work](知识点.md)

### 场景

金融客户内网 CI 无外网。

### 完整解答

> 🎯 **一句话**：**`go mod vendor`** 把依赖拷进 `vendor/`，构建 **`-mod=vendor`**。

```bash
go mod vendor
go build -mod=vendor -o bin/patrol ./cmd/patrol/
```

定期升级依赖重新 vendor；体积变大要接受。

### 再追问

vendor 和 go.sum 关系？——仍建议保留 go.sum 校验。

## Q8

**★★★★☆｜`go build main.go` 和 `go build ./cmd/patrol/` 有何不同？**

**覆盖**：必会 · 常考 | **对应**：知识点 [五、构建与测试：go build / go test](知识点.md)

### 场景

新人只编译一个文件，报一堆 undefined。

### 完整解答

> 🎯 **一句话**：单文件 build **只编该文件**，同包其他 `.go` 不进编译；应对**包路径**构建。

```bash
go build ./cmd/patrol/    # 正确
go build -o patrol ./cmd/patrol/
```

### 再追问

`go run .` 在 cmd 子目录里可以吗？——可以，当前目录需是 main 包。

## Q9

**★★★☆☆｜本地同时改 `patrol` 和 `lib` 两个 module，不想改 go.mod replace，用什么？**

**覆盖**：常用 | **对应**：知识点 [六、replace、vendor 与 go.work](知识点.md)

### 场景

平台库与业务工具联调。

### 完整解答

> 🎯 **一句话**：**`go work init ./patrol ./lib`**，本地工作区多模块；`go.work` 一般 gitignore。

```bash
go work init
go work use ./patrol ./lib
```

### 再追问

CI 需要 go.work 吗？——不需要，各模块独立 go.mod 即可。

## Q10

**★★★★☆｜CI 日志 `verifying ... checksum mismatch`，你处理步骤？**

**覆盖**：必会 · 常用 | **对应**：知识点 [九、作战：CI 与依赖故障剧本](知识点.md)

### 场景

合并依赖升级 PR 后首个 pipeline 红。

### 完整解答

> 🎯 **一句话**：本地同 Go 版本 **`go mod tidy` → 提交 sum**；仍失败查 GOPROXY 与私有库版本。

```bash
go version
go mod tidy
go mod verify
```

勿单独手改 go.sum 一行。

### 再追问

`go mod verify` 干什么？——校验本地 cache 与 go.sum 一致。

## Q11

**★★★★☆｜`go get go.corp.com/private/pkg` 超时，公有依赖正常——可能原因？**

**覆盖**：常用 | **对应**：知识点 [九、作战：CI 与依赖故障剧本](知识点.md)

### 场景

公司私有 module 走内网 Git。

### 完整解答

> 🎯 **一句话**：设 **`GOPRIVATE=go.corp.com/*`** 绕过公共 proxy；配置 git/https 凭据或 `.netrc`。

```bash
go env -w GOPRIVATE=go.corp.com/*
git config --global url."ssh://git@corp/".insteadOf "https://go.corp.com/"
```

### 再追问

GOPROXY 和 GOPRIVATE 谁先？——私有域走直连，其余走 proxy。

## Q12

**★★★★☆｜发版前 CI 应跑哪些 go 命令？漏了哪个最危险？**

**覆盖**：必会 · 常用 | **对应**：知识点 [五、构建与测试](知识点.md)、[九、作战](知识点.md)

### 场景

只 `go build` 上了生产，竞态 bug 活动才爆。

### 完整解答

> 🎯 **一句话**：至少 **`go vet ./...` + `go test ./...` + `go build ./cmd/...`**；并发代码加 `-race`。

```bash
go vet ./...
go test -race -count=1 ./...
go build -trimpath -o bin/patrol ./cmd/patrol/
```

漏 test：逻辑错编译不过不了；漏 race：并发隐患。

### 再追问

`go vet` 能替代 staticcheck 吗？——不能，互补。

## Q13

**★★★★★｜白板：模块从 init 到 build 的一生。**

**覆盖**：核心 · 必会 | **对应**：知识点 [一、一张图：一个 Go 模块的一生](知识点.md)

### 场景

面试工程化题。

### 完整解答

分支：离线走 vendor；本地多模块 go.work。

## Q14

**★★★★★｜读目录找问题：**

```text
patrol/
  main.go          # package main
  go.mod           # module github.com/moonton/patrol
  k8s/client.go    # package k8s，无 internal
```

外部仓库想 `import ".../k8s"`。

**覆盖**：核心 · 必会 | **对应**：知识点 [四、目录布局](知识点.md)

### 场景

封装被别的服务直接依赖，团队想禁止或开放。

### 完整解答

> 🎯 **一句话**：`k8s/` 在根下**可被外部 import**；若要禁止应放 **`internal/k8s`**。

开放 API：迁 `pkg/k8s` 并保证语义版本；禁止：改 internal + 只暴露 cmd。

### 再追问

`main.go` 在根对大型项目缺点？——多二进制难扩展、混入口与库。
