## Q1

**★★★★★｜`var s []string` 能 `range` 吗？能 `append` 吗？`s == nil` 为真吗？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：零值、make 与 new](知识点.md)

### 场景

解析 API 返回前用零值 slice 当默认。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：nil slice **len=0**，可 range、可 append；**`s == nil` 为 true**。

```go
var s []string
for _, x := range s { _ = x } // 0 次
s = append(s, "a")            // OK，s 可能变非 nil
```

与 `make([]string, 0)` 比：后者非 nil，JSON 编码不同（Q8）。

### 再追问

`len(nil slice)` 是多少？——0。

## Q2

nil slice 会了——nil map 更狠。

**★★★★★｜`var m map[string]int` 后 `m["cpu"]=90` 会怎样？正确初始化两种写法？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：零值、make 与 new](知识点.md)

### 场景

指标聚合 map 未 make 就写，活动高峰直接 panic。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**panic: assignment to entry in nil map**；用 `make` 或字面量。

```go
m := make(map[string]int)
m["cpu"] = 90

m2 := map[string]int{"cpu": 90}
```

读不存在键不 panic：`v := m["missing"]` 得 0。

> 📝 **面试**：「nil map 读安全写危险；nil slice 读写 append 都安全。」

### 再追问

`delete(m, "x")` 键不存在会 panic 吗？——不会。

## Q3

make vs new。

**★★★★☆｜`new([]int)` 和 `make([]int, 0, 10)` 区别？**

**覆盖**：必会 · 常考 | **对应**：知识点 [二、出生：零值、make 与 new](知识点.md)

### 场景

有人用 `new` 想创建 slice。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：`new([]int)` 得 **`*[]int` 指向 nil slice**；`make` 得**可用 slice 头**。

```go
p := new([]int)     // *[]int, *p == nil
s := make([]int, 0, 10) // len 0 cap 10
```

slice/map/chan 用 **make**；单个零值堆分配用 **new**（少用）。

### 再追问

`new(map[string]int)` 能直接写吗？——得到 `*map`，仍要 `*p = make(...)` 才方便写。

## Q4

子切片共享底层。

**★★★★★｜`a := []int{1,2,3,4}; b := a[1:3]; b[0]=99`，`a` 是什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [三、slice 内幕：头、子切片与 append](知识点.md)

### 场景

批处理取中间段改标签，原批次数据也被改。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**共享底层**，`a` 为 `[1, 99, 3, 4]`。

```go
a := []int{1, 2, 3, 4}
b := a[1:3] // [2,3]
b[0] = 99
// a[1] == 99
```

要隔离：`b := append([]int(nil), a[1:3]...)`。

### 再追问

`b := a[:0]` 清空视觉但 cap 仍在，有何风险？——append 可能写回 a 的底层槽位（Q11）。

## Q5

这是 Q4 的 append 版。

**★★★★★｜`append` 什么时候会换底层数组？对共享子切片有何影响？**

**覆盖**：核心 · 必会 | **对应**：知识点 [三、slice 内幕](知识点.md)

### 场景

两个 slice 共享 cap，`append` 后另一个「莫名」多元素。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**len+cap 放不下时** realloc 新底层；否则在共享数组上写，**影响所有共享窗口**。

```go
a := make([]int, 3, 5)
b := a[1:3]
_ = append(b, 9) // 若 cap 够，可能写在 a 的数组上
```

不能靠 cap 赌隔离；要独立就 copy。

### 再追问

`append(s, s...)` 合法吗？——Go 1.22+ 有规则；老代码别这么写。

## Q6

头拷贝：函数内 append。

**★★★★★｜`func add(s []int) { s = append(s, 1) }` 调用后外面 len 不变——为什么？怎么改？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、传参：slice 与 map 的「头拷贝」](知识点.md)

### 场景

收集错误码 append 在函数里，main 里 slice 仍空。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**slice 头按值传**；函数内 `s=` 只改局部头；调用方要 **`s = add(s)` 返回** 或传 `*[]int`。

```go
func add(s []int) []int {
    return append(s, 1)
}
s = add(s)
```

### 再追问

map 传参函数内 `m[k]=v` 调用方能见吗？——能，map 头也是引用语义。

## Q7

并发写 map。

**★★★★★｜多个 goroutine 写同一个 map，报错是什么？三种修法？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、map 行为：遍历、删除与 nil](知识点.md)

### 场景

exporter 里全局 `map[string]float64` 缓存，`-race` 爆红。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**fatal error: concurrent map writes**（读写并发也危险）；**Mutex+map**、`sync.Map`、或 channel 聚合。

```go
var mu sync.Mutex
var m map[string]int

func set(k string, v int) {
    mu.Lock()
    defer mu.Unlock()
    if m == nil { m = make(map[string]int) }
    m[k] = v
}
```

`go test -race ./...` 必进 CI。

### 再追问

`sync.Map` 适合什么场景？——读多写少、键稳定；一般业务 map+锁更直观。

## Q8

JSON [] vs null。

**★★★★☆｜API 返回「无 Pod」时，JSON 要 `[]` 不是 `null`，slice 怎么声明？**

**覆盖**：必会 · 常用 | **对应**：知识点 [六、nil vs 空：JSON 与 API 语义](知识点.md)

### 场景

前端区分 null 与空数组；合约要求 always array。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：用 **`make([]Pod, 0)`** 或 **`[]Pod{}`**，不用 var nil slice。

```go
out := make([]Pod, 0)
if len(items) > 0 {
    out = append(out, items...)
}
return out // json: []
```

`var out []Pod` → `null`。

### 再追问

omitempty 与 nil slice？——nil 通常省略字段；空 slice 可能仍输出 `[]`（看类型和 tag）。

## Q9

copy 的前提。

**★★★★☆｜`copy(dst, src)` 要什么前提？如何拷贝 string slice？**

**覆盖**：必会 | **对应**：知识点 [三、slice 内幕](知识点.md)

### 场景

复制主机名列表给两个 goroutine 各改各的。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**dst 必须已分配且 len≥要拷长度**；`copy` 返回实际拷贝个数。

```go
dst := make([]string, len(src))
copy(dst, src)
// 或
dst := append([]string(nil), src...)
```

`copy` 只拷一层；`[][]int` 要循环深拷。

### 再追问

`copy(dst, src)` 和 `copy(src, dst)` 能颠倒吗？——方向是 `copy(dst, src)`。

## Q10

Clone 与浅拷贝。

**★★★☆☆｜Go 1.21 `maps.Clone(m)` 解决什么？嵌套 slice 值还要做什么？**

**覆盖**：常用 | **对应**：知识点 [五、map 行为](知识点.md)

### 场景

配置 map 默认值被某次请求改掉。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**浅拷贝 map**；键值若含 slice，内部仍共享。

```go
m2 := maps.Clone(m1)
```

## Q11

buf[:0] 复用陷阱。

**★★★★☆｜`buf = buf[:0]` 复用缓冲，为何还可能污染旧数据？**

**覆盖**：常用 · 常考 | **对应**：知识点 [八、作战](知识点.md)、生产模板 2

### 场景

sync.Pool 复用 `[]byte`，返回给调用方的 slice 指向 pool 内数组。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**别的别名仍持有同一底层**；`[:0]` 只缩 len 不缩 cap，旧数据还在 cap 里。

修法：返回前 `append([]byte(nil), buf...)` 拷贝；或保证无外部引用再 Put。

### 再追问

`append(buf[:0], x...)` 在独占 buf 时安全吗？——在确认无别名时常用。

## Q14

读代码找共享/并发坑。

**★★★★★｜读代码找 bug：**

```go
var seen map[string]struct{}

func mark(host string) {
    seen[host] = struct{}{}
}

func main() {
    mark("10.0.0.1")
}
```

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生](知识点.md)

### 场景

去重集合第一次调用就崩。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**seen 为 nil map**，写入 panic。

```go
seen := make(map[string]struct{})
// 或
var seen = map[string]struct{}{}
```

set 语义常用 `map[T]struct{}` 省内存。

### 再追问

`struct{}{}` 占多少内存？——零大小 struct，作值占位。
