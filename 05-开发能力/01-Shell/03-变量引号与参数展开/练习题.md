## Q1

**★★★★★｜口述：一个字符串从赋值到变成 argv[]，经历哪几步？哪两步最危险？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [一、一张图](知识点.md) · [七、展开顺序](知识点.md)

### 场景

面试白板：「Shell 变量展开顺序是什么？生产为什么强调双引号？」

### 完整解答

> 🎯 **一句话**：赋值 → 引号层 → `${}`/命令/算术展开 → **word splitting** → **pathname glob** → 引号摘除 → `argv[]`；危险在 splitting 和 glob。

主线（简化）：brace/tilde → parameter → command `$( )` → arithmetic `$(( ))` → **word splitting（IFS）** → **pathname expansion（`*` `?`）** → quote removal。

双引号让整段展开结果**跳过** splitting 和 glob，仍是一个参数。面试强调：空变量 + 未引号 `*` → `rm -rf $dir/*` 变 `rm -rf /*`。

### 再追问

- `"$@"` 为什么比 `"$*"` 安全？——`$@` 每个位置参数独立成词；`$*` 合成一个。
- `*.log` 在双引号里会怎样？——字面 `*.log`，不读目录。

## Q2

**★★★★★｜事故：清缓存脚本删了根分区，根因与修法？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [六、Pathname Glob](知识点.md) · 踩坑清单

### 场景

活动后清 CDN 缓存脚本：

```bash
CACHE_DIR=
rm -rf $CACHE_DIR/*
```

运维报告跳板机 `/etc` 下多个文件消失。有人说是 `rm` bug。

### 完整解答

> 🎯 **一句话**：`CACHE_DIR` 空 → `$CACHE_DIR/*` 变成 `/*` → glob 匹配根下所有一级目录。

修法（任选组合）：

```bash
CACHE_DIR=${CACHE_DIR:?CACHE_DIR required}
[[ -d "$CACHE_DIR" ]] || exit 1
[[ "$CACHE_DIR" == /* ]] || exit 1
shopt -s nullglob
files=("$CACHE_DIR"/*)
(( ${#files[@]} )) || exit 0
rm -rf "${files[@]}"
```

配合 `set -u` 抓**未定义**变量，但拦不住 `CACHE_DIR=""` 已定义空串——必须 `${var:?}` 或显式判空。

### 再追问

- `nullglob` 关着时 `echo $empty/*` 会怎样？——可能字面输出 `/*` 或当前目录 glob，依 bash 版本与设置；不要依赖，先判空。

## Q3

**★★★★★｜`${var:-}` `${var:=}` `${var:+}` `${var:?}` 分别什么时候用？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [四、参数展开](知识点.md)

### 场景

CI 脚本要读 `NAMESPACE`、`PORT`，可选 `DEBUG`；缺 `NAMESPACE` 必须失败，端口默认 8080。

### 完整解答

> 🎯 **一句话**：`:-` 只读默认；`:=` 默认并回写；`:+` 有值才展开替代；`:?` 未设或空则报错退出。

```bash
NS=${NAMESPACE:?set NAMESPACE}      # 必填
PORT=${PORT:-8080}                  # 默认，不污染 PORT 若已设
: "${REPLICAS:=3}"                  # 未设则赋 3
${DEBUG:+set -x}                      # 有 DEBUG 才开 trace
```

| 写法 | var 空/未设 | var 有值 |
|------|------------|---------|
| `:-d` | 用 d | 用 var |
| `:=d` | var=d，用 d | 用 var |
| `:+a` | 空 | 用 a |
| `:?m` | 报错 | 用 var |

### 再追问

- `set -u` 和 `${var:?}` 区别？——`-u` 只防未定义；空串 `""` 仍合法；`:?` 空也失败。

## Q4

**★★★★★｜`ssh $hosts uptime` 只连第一台，为什么？怎么改？**

**覆盖**：核心 · 必会 · 常用

**对应**：知识点 [五、Word Splitting](知识点.md)

### 场景

```bash
hosts="10.0.0.1 10.0.0.2 10.0.0.3"
ssh $hosts uptime
```

期望三台都查，实际只有 `10.0.0.1` 执行了 `uptime`，或 ssh 报多余参数。

### 完整解答

> 🎯 **一句话**：`$hosts` 经 splitting 变三个词，但 `ssh` 只把**第一个**当主机，后面当远程命令参数。

```bash
for h in $hosts; do    # 此处故意 splitting
  ssh "$h" uptime
done

# 更好：数组
hosts=(10.0.0.1 10.0.0.2 10.0.0.3)
for h in "${hosts[@]}"; do
  ssh "$h" uptime
done
```

`ssh "$hosts"` 会把整串当一个主机名 → `Could not resolve hostname`。

### 再追问

- 主机名含空格怎么办？——禁止用空格拼接；用数组或换行 `mapfile`。

## Q5

**★★★★☆｜下面哪些输出是什么？说明单引号/双引号差异。**

**覆盖**：必会 · 常考

**对应**：知识点 [三、引号](知识点.md)

### 场景

```bash
user=ops
echo 'user=$user'
echo "user=$user"
echo user=$user
```

### 完整解答

> 🎯 **一句话**：单引号全字面；双引号展开 `$`；无引号展开后再 splitting。

```text
user=$user
user=ops
user=ops
```

第三行若 `user="a b"` 可能变两个参数。awk 脚本 `{print $1}` 必须单引号包，否则 shell 吃掉 `$1`。

## Q6

**★★★★★｜不写 `basename`/`dirname`，从 `/var/log/nginx/access.log` 取文件名和父目录？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [四、裁剪](知识点.md)

### 完整解答

> 🎯 **一句话**：`${path##*/}` 取 basename；`${path%/*}` 取 dirname。

```bash
path="/var/log/nginx/access.log"
echo "${path##*/}"    # access.log
echo "${path%/*}"     # /var/log/nginx
```

`#` 最短前缀匹配，`##` 最长；`%` 后缀同理。镜像 `registry.io/app:v1.2.3` → tag `${image##*:}`。

## Q7

**★★★★☆｜IFS 是什么？临时改 IFS 读 CSV 一行有什么问题？**

**覆盖**：常用 · 常考

**对应**：知识点 [五、Word Splitting](知识点.md)

### 场景

```bash
line="10.0.0.1,game-srv-01,running"
IFS=',' read -r ip name st <<< "$line"
```

### 完整解答

> 🎯 **一句话**：IFS 是 splitting 分隔符，默认空格/Tab/换行；改 IFS 可解析简单 CSV，字段含逗号/引号会炸。

复杂 CSV 用 Python `csv` 模块。若坚持用 shell：`read` 后恢复 `IFS=$' \t\n'`。`<<<`  here-string 避免管道子 shell。

### 再追问

- `read` 在管道里为何子 shell？——见 [07 进程作业](../07-进程作业与subshell/)。

## Q8

**★★★★★｜函数里 `printf '%s\n' "$@"` 和 `printf '%s\n' "$*"` 差在哪？**

**覆盖**：核心 · 必会

**对应**：知识点 [五、Word Splitting](知识点.md)

### 场景

调用 `run "a b" c`。

### 完整解答

> 🎯 **一句话**：`"$@"` 保留参数个数与边界；`"$*"` 用 `$IFS` 合成**一个**参数。

```text
# "$@"
a b
c

# "$*"
a b c
```

传参给函数、脚本、`xargs` 包装时**一律 `"$@"`**。

## Q9

**★★★★☆｜用 `mapfile` 把 kubectl pod 名放进数组并循环重启，怎么写？**

**覆盖**：常用 · 必会

**对应**：知识点 [八、数组](知识点.md)

### 完整解答

> 🎯 **一句话**：`mapfile -t arr < <(cmd)` 填数组；`"${arr[@]}"` 展开。

```bash
NS=${NAMESPACE:?}
mapfile -t pods < <(kubectl get pods -n "$NS" -o jsonpath='{range .items[*]}{.metadata.name}{"\n"}{end}')
for p in "${pods[@]}"; do
  kubectl delete pod "$p" -n "$NS" --wait=false
done
echo "touched ${#pods[@]} pods"
```

空集群时 `pods` 长度为 0，循环不执行——比 `pods=$(...)` 字符串安全。

## Q10

**★★★★★｜读代码：指出所有引号/展开炸点并改写。**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 全章

### 场景

```bash
#!/bin/bash
LOG_DIR=
FILES=$(ls $LOG_DIR/*.log)
for f in $FILES; do
  gzip $f
done
awk "{print \$1}" $f
```

### 完整解答

> 🎯 **一句话**：四处炸点——空 `LOG_DIR` glob、未引号 splitting、文件名空格、`awk` 双引号吃 `$1`。

```bash
LOG_DIR=${LOG_DIR:?}
shopt -s nullglob
mapfile -t files < <(find "$LOG_DIR" -maxdepth 1 -name '*.log' -type f)
for f in "${files[@]}"; do
  gzip -- "$f"
done
# awk 单引号
awk '{print $1}' "$f"
```

### 再追问

- 为何用 `find` 不用 `ls`？——`ls` 不可解析、含特殊字符文件名不安全；`find -print0` 更稳。

## Q11

**★★★★☆｜SSH 远程执行带单引号的 grep，引号怎么嵌？**

**覆盖**：常用 · 常考

**对应**：知识点 [生产模板 2](知识点.md)

### 场景

本地执行：`ssh $host grep -E '5[0-9]{2}' /var/log/nginx/access.log | tail`

### 完整解答

> 🎯 **一句话**：本地双引号包远程命令，远程正则用 `'\''` 断句或改用 `grep -E` 传文件。

```bash
ssh "$host" "grep -E '5[0-9]{2}' /var/log/nginx/access.log | tail -5"
```

更稳：远程写脚本或用 `ssh "$host" -- bash -s <<'EOF'` heredoc。

## Q12

**★★★★☆｜`set -u` 打开后下面哪行会炸？怎么改？**

**覆盖**：必会 · 常考

**对应**：知识点 [8.2](知识点.md)

### 场景

```bash
set -u
empty=""
echo $empty
echo "${empty:-default}"
echo "${maybe:-default}"
```

### 完整解答

> 🎯 **一句话**：`echo $empty` 在 `-u` 下若写 `$unset` 会炸；已定义空串 `empty` 不炸；`maybe` 未定义用 `:-` 安全。

第三行 `echo $empty`——`empty` 已定义，**不炸**（常见考题变体：改成 `echo $unset` 则炸）。第五行 `${maybe:-default}` 不炸。生产仍应写 `"$empty"` 习惯。

## Q13

**★★★★☆｜`echo *.conf` 有输出，`echo "*.conf"` 无匹配文件时输出什么？**

**覆盖**：常考 · 必会

**对应**：知识点 [六、glob](知识点.md)

### 完整解答

> 🎯 **一句话**：无引号 `*` 由 shell 展开；无匹配时字面 `*.conf`（默认 `nullglob` 关）。有引号则永远字面 `*.conf`。

`nullglob` 开：无匹配变空参数。`failglob` 开：无匹配报错。

## Q14

**★★★★☆｜笔试：写出下列展开结果（bash）。**

**覆盖**：必会 · 常考

**对应**：知识点 [四、展开](知识点.md)

### 题目

设 `a=hello`，`b=`（空），`path=/opt/app/bin/run`：

1. `${a:-world}`
2. `${b:-world}`
3. `${#a}`
4. `${path##*/}`
5. `${path%/bin/*}`

### 完整解答

> 🎯 **一句话**：1 hello 2 world 3 5 4 run 5 /opt/app

```text
1. hello
2. world
3. 5
4. run
5. /opt/app
```

易错：`${path#*/}` 是 `opt/app/bin/run`（最短去前缀）；`##` 才去到最后一个 `/`。
