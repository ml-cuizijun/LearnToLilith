## Q1

**★★★★★｜`#!/bin/bash` 写在文件里，CI 里 `sh deploy.sh`，活动前脚本全线 `[[` 报错——为什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 · 二、出生：shebang 与调用方式

### 场景

新同学把 Git 里能跑的 `deploy.sh` 拷进 Jenkins Freestyle，构建步骤写 `sh deploy.sh`。本地 `./deploy.sh` 正常，CI 报 `syntax error near unexpected token`。

### 完整解答

> 🎯 **一句话**：`sh script` **忽略 shebang**，Ubuntu 上 `sh` 常是 dash，不认 `[[`。

shebang 只在**直接执行**脚本（`./deploy.sh` 或内核 exec）时由内核交给指定解释器。`sh deploy.sh` 的参数是：用 **sh** 读文件，shebang 行只是注释。

```bash
head -1 deploy.sh
# #!/usr/bin/env bash

ls -l /bin/sh
# /bin/sh -> dash

sh deploy.sh      # dash 解析 → [[ 报错
bash deploy.sh    # OK
chmod +x deploy.sh && ./deploy.sh   # OK，走 shebang
```

修法（三选一，团队统一）：CI 改 `bash deploy.sh`；或 `./deploy.sh` 并保证执行位；或脚本改成 POSIX（去掉 `[[`，一般不推荐复杂脚本）。

### 再追问

Docker 里只有 `sh` 没有 bash 怎么办？——镜像层装 bash 并改 shebang；或 Alpine 上评估 `ash` 兼容性，复杂脚本别硬降 POSIX。

## Q2

**★★★★★｜bash 和 sh 有什么区别？生产脚本怎么选？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 · bash vs sh

### 场景

面试官白板：「你们发版脚本用 bash 还是 sh？为什么 CI 里有人写 `#!/bin/sh` 却能跑？」

### 完整解答

> 🎯 **一句话**：**sh = POSIX 子集**；bash 有 `[[`、数组、`source` 等；`/bin/sh` 在 Debian 上常是 dash 不是 bash。

| 特性 | bash | sh/dash |
|------|------|---------|
| `[[ -f file ]]` | ✓ | ✗ |
| 数组 `arr=(a b)` | ✓ | ✗ |
| `source file` | ✓ | 用 `. file` |

生产复杂运维脚本：**`#!/usr/bin/env bash`** + CI 用 `bash` 或 `./script`。追求极简、嵌入式才考虑纯 POSIX。

「`#!/bin/sh` 能跑」可能是：脚本其实只用到 POSIX；或机器上 `sh` 链到 bash（macOS 旧行为）——**不能当通用假设**。

### 再追问

`bash script.sh` 和 `./script.sh` 在 shebang 不一致时谁优先？——`bash script.sh` 用命令行 bash，**完全忽略** shebang 指定的其它解释器。

## Q3

**★★★★☆｜`echo $(date +%F)-$STAGE` 和 `echo '$STAGE'` 结果分别是什么？展开顺序怎么说？**

**覆盖**：必会 · 常考 | **对应**：知识点 · 三、词法展开

### 场景

oncall 在脚本里拼备份路径 `backup-$(date +%F)-$CLUSTER.tar`，有人写成单引号导致变量不展开，备份名全是字面 `$CLUSTER`。

### 完整解答

> 🎯 **一句话**：先命令替换 `$(date)`，再参数展开 `$STAGE`；单引号内**全部不展开**。

```bash
STAGE=canary
CLUSTER=hall-1
echo $(date +%F)-$STAGE
# 2026-09-01-canary   # 先 date，再拼 STAGE

echo '$STAGE'
# $STAGE              # 单引号字面

echo "backup-$(date +%F)-${CLUSTER}.tar"
# backup-2026-09-01-hall-1.tar
```

面试口诀：引号 → 参数展开 → 命令替换 → 算术 → 分词 → 通配 → 重定向 → 执行。

### 再追问

反引号 `` `date` `` 和 `$(date)` 哪个优先维护？——`$()` 可嵌套、可读性好，生产用 `$()`。

## Q4

**★★★★☆｜`cmd >out.log 2>&1` 和 `cmd 2>&1 >out.log` 线上会有什么差别？**

**覆盖**：必会 · 常用 · 常考 | **对应**：知识点 · 四、分词与重定向

### 场景

发版日志「应该进文件」，Jenkins 控制台仍刷满 `kubectl` 的 ERROR；打开 `out.log` 只有 INFO。

### 完整解答

> 🎯 **一句话**：重定向**从左到右**建立；要先定 stdout 再去，stderr 才能跟过去。

```bash
# 正确：stdout → out.log，再把 stderr 指到「当前 stdout」
cmd >out.log 2>&1

# 错误：先把 stderr 指到「当时仍是终端的 stdout」，再把 stdout 指到文件
cmd 2>&1 >out.log
# stderr 仍在控制台
```

kubectl/helm 失败信息走 stderr，顺序错了就「文件里一片安静，控制台爆炸」。

### 再追问

既要控制台又要文件？——`tee` + `pipefail`（见 06 章），或 `script`/`tee` 配合，别牺牲 `$?`。

## Q5

**★★★★★｜退出码 0、127、130、137 各表示什么？`$?` 怎么用才不会被骗？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 · 六、退出码

### 场景

值班说「脚本跑了 ERROR 日志但 exit 0」；另一次 OOM 杀进程后监控显示 137。

### 完整解答

> 🎯 **一句话**：**退出码才是 CI/父进程的成败**；`$?` 必须紧挨上一条命令读。

| 码 | 含义 |
|----|------|
| 0 | 成功 |
| 127 | command not found |
| 130 | 128+2，通常 Ctrl+C |
| 137 | 128+9，SIGKILL，常见于 OOM |

```bash
kubectl apply -f bad.yaml
echo "done"
echo $?    # 0 — 这是 echo 的码，不是 kubectl 的！

# 正确
if ! kubectl apply -f bad.yaml; then
  echo "apply failed" >&2
  exit 1
fi
```

很多 CLI「打印 ERROR」仍 exit 0——门禁要看 `$?`，不是 grep 日志。

### 再追问

`wait $pid` 之后 `$?` 是谁的？——`wait` 返回子进程退出码；和直接跑前台命令一样要立刻用。

## Q6

**★★★★★｜Jenkins 步骤绿了，但集群里 Deployment 没更新——从执行模型列三个原因。**

**覆盖**：核心 · 必会 · 常用 | **对应**：知识点 · 六、CI 假绿 · 九、作战

### 场景

Pipeline：`sh 'deploy.sh | tee deploy.log'`，deploy.sh 里 `kubectl apply ... || true`。发布群说发完了，集群镜像还是上周的。

### 完整解答

> 🎯 **一句话**：**吞退出码、管道默认 $?、$? 被覆盖**——执行模型层三大假绿。

1. **`|| true`**：`kubectl` 非 0 仍继续，脚本最后 `exit 0`。
2. **无 `pipefail`**：`kubectl | tee`，kubectl 挂、tee 成功 → `$?`=0。
3. **`$?` 误读**：`kubectl; echo done; test $? -eq 0` 测的是 echo。

排查：`bash -x deploy.sh`；故意让 apply 失败看 CI 是否红；加 `set -euo pipefail`（02 章）。

```bash
set -o pipefail
kubectl apply -f app.yaml | tee deploy.log
# 现在 kubectl 失败 → 管道非 0
```

### 再追问

`tee` 必须保留又要门禁？——`pipefail` + 失败时 `exit 1`；或 `kubectl ... | tee ...; exit ${PIPESTATUS[0]}`（06 章）。

## Q7

**★★★★☆｜什么时候 `source env.sh`，什么时候 `./env.sh`？**

**覆盖**：必会 · 常用 · 常考 | **对应**：知识点 · 七、source

### 场景

战斗服发布前要 `export KUBECONFIG=...`。有人 `./set-kube.sh` 后 `kubectl get ns` 仍连错集群；另一个人 `source set-kube.sh` 可以。

### 完整解答

> 🎯 **一句话**：要**改当前 shell 环境**就 `source`；要**隔离执行**就 `./` 或 `bash`。

```bash
# set-kube.sh
export KUBECONFIG="$HOME/.kube/config-battle"

source ./set-kube.sh
kubectl config current-context   # 生效

./set-kube.sh
kubectl config current-context   # 仍是旧 context — 子进程 export 未回传
```

生产更推荐：systemd `EnvironmentFile`、CI injected variables、不依赖人工 `source` 不可信脚本（等同 RCE）。

### 再追问

能在 cron 里 `source` 吗？——cron 每 job 是新 shell，应在脚本**内部** source 或写清 `Environment=`。

## Q8

**★★★★☆｜容器入口为什么常写 `exec nginx`？脚本里 `exec kubectl` 后还能做清理吗？**

**覆盖**：必会 · 常考 | **对应**：知识点 · exec

### 场景

Dockerfile `CMD ["/entrypoint.sh"]`，entrypoint 最后 `kubectl apply` 没 `exec`，信号给 shell，Pod Terminating 卡 30s。

### 完整解答

> 🎯 **一句话**：`exec` **替换当前进程**，不返回；清理必须在 exec 之前做完。

```bash
#!/usr/bin/env bash
set -euo pipefail
render_config.sh          # 还在 shell 里
exec /usr/bin/nginx -g 'daemon off;'
echo "never runs"         # 到不了

# 错：exec kubectl 后还想 trap 清理本地 tmp
exec kubectl apply -f app.yaml
rm -f /tmp/foo            # 不会执行
```

容器 PID1：子进程变 nginx/game-server，SIGTERM 直达业务进程；shell 多一层会挡信号（需 `exec` 或 `dumb-init`）。

### 再追问

还要 sidecar 怎么办？——多容器 Pod，各容器自己的 exec 入口，别一个 shell 包所有。

## Q9

**★★★☆☆｜`cd` 为什么必须是内置？`type cd` 和 `type ls` 输出有什么不同？**

**覆盖**：必会 · 常考 | **对应**：知识点 · 五、fork 与内置

### 场景

实习生写 `subshell.sh`：`bash -c 'cd /var/log && ./collect.sh'`，父脚本里 `pwd` 还在 `/tmp`，他以为 bug。

### 完整解答

> 🎯 **一句话**：`cd` 改的是**当前 shell** 的工作目录；子进程里 `cd` 父 shell 看不见。

```bash
type cd
# cd is a shell builtin

type ls
# ls is aliased to ... 或 /usr/bin/ls

# 外部 cd 即使存在也无法改父 shell 目录
bash -c 'cd /var/log'
pwd   # 仍是原目录
```

要改变父 shell 目录：直接 `cd`（内置）或 `source` 带 `cd` 的脚本，别指望 `bash -c 'cd ...'` 外面生效。

### 再追问

`export` 是内置吗？——是；但 `./export.sh` 仍只在子进程生效，和 `cd` 同理。

## Q10

**★★★☆☆｜脚本里写 `kubectl` 和 `./kubectl` 有什么安全差异？**

**覆盖**：常用 · 常考 | **对应**：知识点 · PATH

### 场景

某台被入侵机器 `/tmp` 下放了个假 `kubectl`，运维 `cd /tmp` 后跑发布脚本（未用绝对路径），连错集群。

### 完整解答

> 🎯 **一句话**：依赖 PATH 时，**当前目录或 PATH 前缀被污染**会吃到假二进制；用 `command -v` 校验路径。

```bash
# 危险：PATH 里 . 在前（极少但可配）
export PATH=.:$PATH
kubectl get ns   # 可能跑到 ./kubectl

# 脚本里
need_cmd() { command -v "$1" >/dev/null || exit 127; }
need_cmd kubectl
KUBECTL="$(command -v kubectl)"
"$KUBECTL" get nodes
```

生产：固定工具路径或确保 PATH 不含不可信目录；特权脚本不用 `.`。

### 再追问

`which kubectl` 和 `command -v`？——脚本用 `command -v`，POSIX、不依赖 which 包。

## Q11

**★★★★☆｜`( cd /tmp; rm old.* )` 和 `{ cd /tmp; rm old.*; }` 对父 shell 目录的影响？**

**覆盖**：必会 · 常考 | **对应**：知识点 · 子 shell

### 场景

清理脚本想在子目录删文件又怕 `cd` 跑飞，用了括号；同事换成花括号后父 shell 目录变了，后面相对路径全错。

### 完整解答

> 🎯 **一句话**：`()` 开**子 shell**，`cd` 不外泄；`{}` 在当前 shell，**无隔离**。

```bash
pwd   # /home/op
( cd /tmp; pwd )    # /tmp
pwd   # /home/op  — 父 shell 不变

{ cd /tmp; pwd; }
pwd   # /tmp — 父 shell 被改了！
```

管道两侧也常是子 shell（bash 细节见 06）——管道里 `export F=1` 外面看不见。

### 再追问

什么时候故意用 `{}`？——同一 shell 里批量命令、重定向一组命令，且你**就是要**改当前目录时。

## Q12

**★★★★☆｜`FILES=*.log` 未引用，目录里没有 .log 时会怎样？和 `"$FILES"` 比？**

**覆盖**：必会 · 常用 | **对应**：知识点 · 展开与分词（衔接 03 章）

### 场景

归档脚本 `tar czf a.tgz $FILES`，空目录时把字面 `*.log` 打进包或 tar 报错，活动后复盘找不到日志。

### 完整解答

> 🎯 **一句话**：未引用时先**通配符展开**再分词；无匹配时 bash 可能保留字面 `*.log`（与 `nullglob` 有关）。

```bash
# 目录无 .log
echo $FILES      # 可能输出 *.log
tar czf a.tgz $FILES   # 危险

# 应对：引号 + 检查
shopt -s nullglob
files=( *.log )
((${#files[@]})) || { echo "no logs"; exit 1; }
tar czf a.tgz "${files[@]}"
```

执行模型要点：**展开发生在执行 tar 之前**——错在展开阶段就要按展开规则修（03 章深化）。

### 再追问

`set -u` 对空数组？——`files=()` 后 `"${files[@]}"` 要判长度，别裸用未定义下标。

## Q13

**★★★★☆｜接到「CI 脚本 syntax error」电话，60 秒你怎么查？**

**覆盖**：必会 · 常用 · 常考 | **对应**：知识点 · 九、作战

### 场景

活动前 30 分钟，发布流水线红字 `[[` 或 `syntax error`，开发催你「快改脚本」。

### 完整解答

> 🎯 **一句话**：**shebang / 调用方式 / 解释器** 三件套，别先改业务逻辑。

| 时段 | 动作 |
|------|------|
| 0–10s | 看 CI 是 `sh` 还是 `bash`/`./script` |
| 10–30s | `head -1 script.sh`；`readlink -f /bin/sh` |
| 30–45s | 同用户同命令本地复现 |
| 45–60s | 临时改 `bash script.sh` 验证；长期统一 shebang + CI |

```bash
head -1 deploy.sh
grep -E 'sh |bash ' Jenkinsfile .gitlab-ci.yml
```

别在压力下把 `[[` 全改成 `[` 而不统一解释器——下一个人 `bash` 跑又乱。

### 再追问

本地 macOS 好使 Linux CI 炸？——macOS `/bin/sh` 曾是 bash 3.2 兼容模式；Linux 是 dash，**以 CI 为准**。

## Q14

**★★★★★｜白板：从用户输入一行到父进程拿到退出码，画流程并标四个易错点。**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 · 全章

### 场景

终面：「讲清楚 shell 执行一条命令时发生了什么。」

### 完整解答

> 🎯 **一句话**：展开 → 分词 → 重定向 → fork/exec（或内置）→ wait → `$?`。

```mermaid
flowchart LR
    A[输入] --> B[展开]
    B --> C[分词]
    C --> D[重定向]
    D --> E[执行]
    E --> F["$?"]
```

四个易错点：

1. **`sh script` 忽略 shebang** → 用 bash 或 `./`
2. **未引号变量分词** → `"$var"`
3. **`2>&1 >f` 顺序** → `>f 2>&1`
4. **管道默认 $?** → 最后一个成功即 0（要 pipefail）

加一句 SRE 口径：CI 和 `set -e` 认退出码，不认日志里有没有 ERROR。

### 再追问

`&&` 和 `set -e` 关系？——`cmd1 && cmd2` 里 cmd1 失败时 cmd2 不跑，且整条可能因 `-e` 退出；`false || true` 不触发 `-e`（02 章）。
