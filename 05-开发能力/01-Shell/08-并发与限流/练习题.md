## Q1

**★★★★★｜500 台机器批量 ssh，为什么默认不能 `for h; do ssh "$h" & done` 一次全扔出去？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：一批任务并发执行的一生](知识点.md)

### 场景

大促前巡检脚本把 `PARALLEL` 注释掉「加快速度」，堡垒机告警 `MaxStartups`、本机 `bash: fork: Resource temporarily unavailable`。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：无限并发会打满 **fd/SSH 连接表/目标 rate limit**，错误成风暴且**更难定责**——必须有上限。

```bash
ulimit -n          # 1024 常见
# 500 个 ssh 同时 = 500+ fd，外加管道、日志
```

后果链：连接被拒 → 脚本重试或记失败 → 误报大面积 down → 真人上台更乱。

> 📝 **面试**：「默认串行或 `PARALLEL=10～20`；用 `xargs -P` 或 `wait -n` 池。」

### 再追问

**降并发就慢，业务催怎么办？**——分批、分 region、Ansible forks、或队列——不是把 `PARALLEL` 调到 500。

## Q2

**★★★★★｜`grep -v '^#' hosts | xargs -r -P 10 -n1 -I{} cmd {}` 每个参数什么意思？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [三、闸门一：`xargs -P` 并行](知识点.md)

### 场景

面试/值班现场会问到：**`grep -v '^#' hosts | xargs -r -P 10 -n1 -I{} cmd {}` 每个参数什么意思？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`-P 10` 最多 10 并行；`-n1` 每次一个 host；`-I{}` 替换；`-r` 空输入不跑**。

```bash
grep -v '^#' hosts.txt | xargs -r -P 10 -n1 -I{} \
  ssh -o ConnectTimeout=5 -n {} 'hostname'
```

| 选项 | 缺了会怎样 |
|------|------------|
| `-P` | 串行或默认 1 |
| `-n1` | 可能多 host 拼一条命令 |
| `-r` | 空文件仍跑 cmd 一次（GNU） |

### 再追问

**macOS 没有 `-r`？**——先 `[[ -s hosts.txt ]]` 再 xargs，或 `cat hosts | xargs -P 10` 接受空跑风险。

## Q3

**★★★★★｜`xargs -P` 退出非零，怎么知道是哪些 host 失败？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、闸门一：`xargs -P` 并行](知识点.md)

### 场景

CI 红了，日志只有 `xargs: command exited with status 1`，运维不知道要重跑哪几台。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：xargs 只给**总结果**——每个任务要自己 **`echo host >> failed_file`** 或带 host 打 stderr。

```bash
failed=$(mktemp)
grep -v '^#' hosts | xargs -r -P 10 -n1 -I{} \
  bash -c 'ssh -n "$1" nginx -t || echo "$1" >>"$2"' _ {} "$failed" || true

[[ -s "$failed" ]] && { cat "$failed"; exit 1; }
```

> ⚠️ **别混**：`xargs` 非零 ≠ 你知道 host 列表——必须子任务写失败集。

### 再追问

**能否靠 `set -o pipefail` 解决？**——不能替代 host 级记录；pipefail 只告诉你「有人失败了」。

## Q4

> 开头「从不 wait、CI 假绿」就在这题。

**★★★★★｜脚本里 `for h in "${hosts[@]}"; do work "$h" & done` 没有 wait，CI 会怎样？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [六、收尸与失败汇总](知识点.md)

### 场景

面试/值班现场会问到：**脚本里 `for h in "${hosts[@]}"; do work "$h" & done` 没有 wait，CI 会怎样？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：父 shell **先 exit 0**——子进程变孤儿继续跑或被杀，CI **假绿**，失败无人汇总。

```bash
for h in a b c; do sleep 2 & done
echo $?    # 0——循环立刻结束
# 脚本退出，后台可能还在
```

修法：`pids+=($!)` + 循环 `wait "$pid" || failed+=`。

> 📝 **面试**：「并发三件套：上限、wait、failed 列表。」

### 再追问

**加 `wait` 但不判退出码？**——仍可能假绿——要 `|| failed+=`。

## Q5

**★★★★☆｜`wait -n` 在线程池里解决什么问题？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [四、闸门二：`&` + `wait` / `wait -n` 线程池](知识点.md)

### 场景

面试/值班现场会问到：**`wait -n` 在线程池里解决什么问题？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：槽位满时 **`wait -n` 等任意一个子进程结束**再补新任务——维持恒定 `PARALLEL` 而不必先等「最早那个」。

```bash
while (( running >= PARALLEL )); do
  wait -n || true
  ((running--))
done
ssh ... &
((running++))
```

需要 bash **4.3+**；老环境用 `xargs -P`。

### 再追问

**`wait -n -p pid`？**——bash 5.1+ 直接拿到结束的 PID，方便映射 host。

## Q6

> 开头「双 cron 打穿」的互斥解法。

**★★★★★｜两个 cron 同时触发全量 rsync，怎么防？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [五、闸门三：信号量文件与 `flock`](知识点.md)

### 场景

面试/值班现场会问到：**两个 cron 同时触发全量 rsync，怎么防？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：脚本头 **`flock -n` 独占锁文件**——第二个实例拿不到锁就退出。

```bash
exec 9>/var/lock/rsync.lock
flock -n 9 || { echo "skip overlap"; exit 0; }
rsync -az ...
```

```bash
lsof /var/lock/rsync.lock    # 谁持锁
```

> 📝 **面试**：「单机互斥 flock；多机要上分布式锁，不是 NFS 上赌 flock。」

### 再追问

**持锁进程死了锁会死吗？**——内核随进程释放 fd 自动释放锁——除非僵死持 fd，要查 `lsof`。

## Q7

**★★★★☆｜`flock -n` 失败时 `exit 0` 还是 `exit 1`？**

**覆盖**：常考 ｜ **对应**：知识点 [五、闸门三：信号量文件与 `flock`](知识点.md)

### 场景

面试/值班现场会问到：**`flock -n` 失败时 `exit 0` 还是 `exit 1`？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**cron 故意跳过**用 `exit 0`（正常未跑）；**CI 不容重叠**用 `exit 1`（异常）。

| 场景 | 退出码 | 含义 |
|------|--------|------|
| cron 夜间同步重叠 | 0 | 已有实例，跳过 |
| 部署门禁「禁止双发」 | 1 | 告警人工介入 |

文档写清，别让人把 skip 当成功执行。

### 再追问

**监控怎么区分？**——日志打 `skip overlap` + 指标 `job_skipped_total`，别沉默 exit 0。

## Q8

**★★★★☆｜`Too many open files` 和 `PARALLEL` 什么关系？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [八、作战：「并发一打就挂」与「双 cron」](知识点.md)

### 场景

面试/值班现场会问到：**`Too many open files` 和 `PARALLEL` 什么关系？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：每个并发子进程占 **fd**（socket、pipe、文件）——`PARALLEL` 过大超过 **`ulimit -n`** 就炸。

```bash
ulimit -n          # 1024
# PARALLEL=500 ssh 极易超
```

修法：降 `PARALLEL`、升 `ulimit`（需权限）、或减少每任务打开文件数。

### 再追问

**只升 ulimit 不降压？**——SSH 服务端、目标机仍可能拒连——双向瓶颈。

## Q11

**★★★★☆｜`set -e` 下 `wait -n` 遇到失败子进程，循环为什么断？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [四、闸门二：`&` + `wait` / `wait -n` 线程池](知识点.md)

### 场景

面试/值班现场会问到：**`set -e` 下 `wait -n` 遇到失败子进程，循环为什么断？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：`wait -n` 返回非零 → **`-e` 触发退出**——池里要用 `wait -n || true` 并**单独记 `rc` 和 host**。

```bash
wait -n -p p || true
wait "$p"; rc=$?
(( rc != 0 )) && failed+=("${pid_host[$p]}")
```

> ⚠️ **别混**：`|| true` 只为绕过 `-e`，**不能**不记失败。

### 再追问

**能否 `set +e` 在池段？**——可以但易忘 `set -e` 恢复——局部捕获更清晰。

## Q12

### 完整解答

> 🎯 **一句话**：**10 台**串行或小 `-P` 即可；**100 台** `xargs -P` + failed 文件；**5000 台** Ansible/平台/队列，别裸 shell 硬扇。
