## Q1

**★★★★★｜`( failed=1 )` 执行后父 shell `echo $failed` 输出什么？为什么？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、变量：为什么在子进程里「丢失」](知识点.md)

### 场景

批量部署脚本把整段 `for` 包在圆括号里「怕污染环境」，结果循环外 `[[ $failed -gt 0 ]]` 永远不触发告警。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：输出 **0**（或空）——`( )` 开 **subshell**，`failed=1` 只写在子进程拷贝里，父 shell 从未被修改。

```bash
failed=0
( failed=1 )
echo "$failed"    # 0
```

对比同 shell：

```bash
failed=0
{ failed=1; }
echo "$failed"    # 1
```

> 📝 **面试**：失败列表、计数器禁止包在 `( )` 里；用 `{ }`、`while < file` 或函数 + `local`。

### 再追问

**`export failed=0` 再 `( failed=1 )` 呢？**——仍是 0。`export` 只传递**初始快照**，不是共享内存。

## Q2

> 这是 Q1 结论的「括号选型」版。

**★★★★★｜`( cmd1; cmd2 )` 和 `{ cmd1; cmd2; }` 在生产脚本里怎么选？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [二、出生：fork、subshell 与 `$!`](知识点.md)

### 场景

面试/值班现场会问到：**`( cmd1; cmd2 )` 和 `{ cmd1; cmd2; }` 在生产脚本里怎么选？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：要**改父 shell 变量**用 `{ }`；要**隔离** `cd`/环境用 `( )`。

| 需求 | 选 |
|------|-----|
| 累加 `failed[]`、`count` | `{ }` 或不用括号 |
| 临时 `cd` 打包不打乱 `$PWD` | `( cd dir && tar ... )` |
| 捕一段 stdout 进变量 | `$( ... )`（仍是 subshell） |

```bash
# ✅ 隔离 cd
( cd /tmp && make test )
pwd    # 仍在原目录

# ✅ 累加失败
{ probe a || failed+=a; probe b || failed+=b; }
```

> ⚠️ **别混**：`{` 后必须有空格，`}` 前必须有分号——`{ cmd }` 语法错。

### 再追问

**`( for h in ...; do ...; done )` 能并行吗？**——不能，仍是串行 subshell；并行靠 `&` + `wait` 或 `xargs -P`（08 章）。

## Q3

> 就是 Q1 那位同学踩的坑在管道 `while` 里的再现。

**★★★★★｜`cat hosts | while read h; do ((ok++)); done` 后 `ok` 为何仍是 0？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、变量：为什么在子进程里「丢失」](知识点.md)

### 场景

值班脚本统计存活主机数，管道写法跑完显示 `up: 0`，手动逐台 ping 明明都通。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：bash 管道让 **`while` 在 subshell** 里跑，`ok++` 改的是子拷贝。

```bash
ok=0
cat hosts.txt | while read -r h; do
  ping -c1 "$h" &>/dev/null && ((ok++))
done
echo "up: $ok"    # up: 0
```

修法：

```bash
ok=0
while read -r h; do
  ping -c1 "$h" &>/dev/null && ((ok++))
done < hosts.txt
echo "up: $ok"
```

或进程替换：`while read -r h; do ...; done < <(grep -v '^#' hosts.txt)`。

> 📝 **面试**：「管道右端 while 是经典坑；改 `while < file` 或 awk 汇总。」

### 再追问

**`sh` 脚本行为一样吗？**——很多 shell 管道右端都是 subshell；别赌实现，统一避免管道+while 改父变量。

## Q4

**★★★★☆｜连续执行三次 `sleep 1 &`，如何拿到全部 PID？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [四、前台与后台：`&`、`jobs`、`fg`、`bg`](知识点.md)

### 场景

面试/值班现场会问到：**连续执行三次 `sleep 1 &`，如何拿到全部 PID？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**每次 `&` 后立刻** `pids+=($!)`——`$!` 只保留**最后一个**后台 PID。

```bash
pids=()
for i in 1 2 3; do
  sleep 1 &
  pids+=("$!")
done
printf 'pids: %s\n' "${pids[@]}"
for pid in "${pids[@]}"; do wait "$pid"; done
```

错误写法：

```bash
sleep 1 & sleep 1 & sleep 1 &
wait $!    # 只等了最后一个
```

### 再追问

**能否 `wait` 不带参数？**——bash 会等**所有**子进程，但拿不到「哪个失败」——生产仍要逐个 `wait "$pid"` 记 host。

## Q5

**★★★★★｜`false &` 后 `wait $!`，`echo $?` 输出多少？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [四、前台与后台：`&`、`jobs`、`fg`、`bg`](知识点.md)

### 场景

面试/值班现场会问到：**`false &` 后 `wait $!`，`echo $?` 输出多少？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：输出 **1**——`wait` 把子进程退出码交给 `$?`。

```bash
false &
pid=$!
wait "$pid"
echo $?    # 1

true &
wait $!
echo $?    # 0
```

> ⚠️ **别混**：`$?` 在 `wait` **之后**读；中间插 `echo debug` 会覆盖。

### 再追问

**子进程被 signal 杀死呢？**——`wait` 返回 128+信号号（如 137 = SIGKILL）。

## Q6

**★★★★★｜`set -e` 下循环 `wait "$pid"`，一台失败脚本直接退出，怎么又汇总又 `-e`？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [四、前台与后台：`&`、`jobs`、`fg`、`bg`](知识点.md)

### 场景

200 台并发探活，第一台 `wait` 到失败码，脚本在第 3 台就停了，后面 197 台没探。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：`wait "$pid" || failed+=("$host")`——用 `||` 捕获，**不要**裸 `wait` 让 `-e` 掐断。

```bash
set -euo pipefail
failed=()
for pid in "${!pids[@]}"; do
  wait "$pid" || failed+=("${pids[$pid]}")
done
if ((${#failed[@]} > 0)); then
  printf 'failed: %s\n' "${failed[*]}" >&2
  exit 1
fi
```

> 📝 **面试**：与 02 章批处理同一口径——`-e` 下失败要显式捕获，不能 `wait || true` 吞掉不记名单。

### 再追问

**`wait -n` 呢？**——bash 4.3+ 等任意一个完成，适合限流池（08 章）；失败仍要判 `$?`。

## Q7

**★★★★★｜笔记本合上 / SSH 断开，`./sync.sh &` 起的任务还会跑吗？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、脱离：关终端、SIGHUP、`nohup`、`disown`](知识点.md)

### 场景

面试/值班现场会问到：**笔记本合上 / SSH 断开，`./sync.sh &` 起的任务还会跑吗？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**默认不会**——会话收 SIGHUP，shell 默认转发给 job 表里的进程。

```bash
# 会随终端死（除非 shell 配了 huponexit 等）
./sync.sh &

# 关终端仍跑
nohup ./sync.sh >>/var/log/sync.log 2>&1 &
```

验证：

```bash
ps -p {pid} -o pid,cmd    # 断线后是否还在
```

> 📝 **面试**：`nohup` 防 HUP，不防 reboot/OOM；生产长跑用 systemd。

### 再追问

**在 `tmux`/`screen` 里 `&` 呢？**——断 SSH 会话还在，因为 tmux 是新的 session leader——但仍不如显式 nohup/systemd 可审计。

## Q8

**★★★★☆｜`nohup cmd &` 没重定向，日志去哪了？有什么风险？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [五、脱离：关终端、SIGHUP、`nohup`、`disown`](知识点.md)

### 场景

面试/值班现场会问到：**`nohup cmd &` 没重定向，日志去哪了？有什么风险？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：默认追加当前目录 **`nohup.out`**—— cwd 不对就写错盘、撑满磁盘。

```bash
nohup ./job.sh >>/var/log/job.log 2>&1 &
# 不要依赖默认 nohup.out
```

```bash
ls -lh nohup.out    # 常见几十 GB 事故
```

> ⚠️ **别混**：`nohup` 只保证忽略 SIGHUP；**不**替你选日志路径。

### 再追问

**`nohup` 和 `cmd </dev/null`？**——`nohup` 也会把 stdin 指到 `/dev/null`，避免后台读终端卡住。

## Q9

**★★★★☆｜`disown -h` 和 `nohup` 差在哪？什么时候用？**

**覆盖**：常用 ｜ **对应**：知识点 [五、脱离：关终端、SIGHUP、`nohup`、`disown`](知识点.md)

### 场景

面试/值班现场会问到：**`disown -h` 和 `nohup` 差在哪？什么时候用？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：`nohup` 从启动就忽略 HUP；`disown` 是**已 `&` 之后**从 job 表摘掉、标记不因 HUP 死。

```bash
./long.sh &
disown -h
```

适合交互式补救；脚本里优先 `nohup ... &` 或 systemd，别依赖事后 `disown`。

### 再追问

**`disown -a`？**——摘掉当前 shell 所有 job——误伤其他后台任务，**不要**在生产脚本里乱用。

## Q10

**★★★★☆｜`out=$(deploy 2>&1)` 能拿到 `deploy` 里设置的 `failed=1` 吗？**

**覆盖**：必会 ｜ **对应**：知识点 [三、变量：为什么在子进程里「丢失」](知识点.md)

### 场景

面试/值班现场会问到：**`out=$(deploy 2>&1)` 能拿到 `deploy` 里设置的 `failed=1` 吗？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**不能**——`$( )` 是 subshell，只把 **stdout**（这里含 stderr 因 `2>&1`）当字符串；变量状态不回传。

```bash
deploy() { failed=1; echo ok; }
failed=0
out=$(deploy)
echo "failed=$failed out=$out"    # failed=0 out=ok
```

判成败用 **`if deploy; then`** 或函数 `return 1`，别指望 `$()` 传变量。

### 再追问

**为什么日志要 `>&2`？**——避免混进 `$()` 捕的结果（05 章双通道）。

## Q11

**★★★★☆｜cron 里跑的脚本能用 `jobs` 管理后台吗？**

**覆盖**：常用 ｜ **对应**：知识点 [四、前台与后台：`&`、`jobs`、`fg`、`bg`](知识点.md)

### 场景

面试/值班现场会问到：**cron 里跑的脚本能用 `jobs` 管理后台吗？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**不能指望**——cron 是非交互 shell，没有你能 `fg` 的 job 表；用 **PID 数组 + `wait`** 或写 PID 文件。

```bash
# cron 脚本
pids=()
task1 &
pids+=("$!")
task2 &
pids+=("$!")
for pid in "${pids[@]}"; do wait "$pid"; done
```

`jobs` 仅适合 SSH 里临时手工操作。

### 再追问

**如何防止 cron 重叠跑？**——`flock`（08 章）或 PID 文件 + `kill -0`。

## Q12

**★★★★☆｜为什么打包脚本常用 `( cd "$dir" && tar czf ... )`？**

**覆盖**：必会 ｜ **对应**：知识点 [二、出生：fork、subshell 与 `$!`](知识点.md)

### 场景

面试/值班现场会问到：**为什么打包脚本常用 `( cd "$dir" && tar czf ... )`？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：subshell 里 **`cd` 不污染父 shell `$PWD`**——打完包父目录仍正确，后续 `scp` 路径不会歪。

```bash
ROOT=$(pwd)
(
  cd "$ROOT/build"
  tar czf "$ROOT/artifact.tgz" dist/
)
# 仍在 $ROOT
scp artifact.tgz bastion:
```

这是 `( )` 的**正确**用法——要隔离，不是要回写变量。

### 再追问

**能否 `pushd`/`popd` 代替？**——可以，但函数里嵌套深时 `( cd ... )` 更不易漏 `popd`。

## Q13

**★★★★☆｜`ps` 看到 `<defunct>` 僵尸，和 subshell 有什么关系？**

**覆盖**：常用 ｜ **对应**：知识点 [四、前台与后台：`&`、`jobs`、`fg`、`bg`](知识点.md)

### 场景

面试/值班现场会问到：**`ps` 看到 `<defunct>` 僵尸，和 subshell 有什么关系？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：子进程已死但父 shell **没 `wait`**，内核保留 zombie 行——父退出时一并收尸。

```bash
sleep 1 &
# 若不 wait，短暂可见 zombie，父 shell 退出后消失
```

大量长期 zombie：父进程 bug（只 `fork` 不 `wait`）——修父进程，别只 kill zombie（杀不了）。

### 再追问

**`wait` 等不到的 PID？**——`wait: pid 123 is not a child of this shell`——那是别的会话起的，别乱 `wait`。

## Q14

**★★★★★｜口述「子进程可控」八条清单——每条对应什么坑？**

**覆盖**：核心 · 常考 ｜ **对应**：知识点 [六、收束：子进程凭什么「可控」](知识点.md)

### 场景

面试/值班现场会问到：**口述「子进程可控」八条清单——每条对应什么坑？**。先自己在白板上过一遍再对答案。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**( ) 隔离 vs { } 累加 · 管道 while · pids 数组 · nohup 日志 · wait 汇总 · 交互 jobs · disown 补救 · 并发见 08**。

| 条 | 坑 |
|----|-----|
| 圆括号改不了父变量 | `failed` 永远 0 |
| 用 `{ }`/`< file` 累加 | 管道 while |
| 每次 `&` 存 PID | `$!` 只最后一个 |
| nohup + 重定向 | 关终端/sync 死 |
| `wait \|\| failed+=` | `set -e` 只跑一台 |
| 脚本不用 jobs | cron 无 job 表 |
| disown 是补救 | 启动时就要 nohup |
| 限流 | 打满 SSH（08） |
