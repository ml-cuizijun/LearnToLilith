## Q1

**★★★★★｜生产脚本为什么 `DRY_RUN` 默认 true 而不是 false？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [四、默认值：`DRY_RUN` 与危险操作默认 false](知识点.md)

### 场景

oncall 复制文档里的命令进终端，漏了 `--dry-run`，CDN 全量刷新把源站打挂。

### 完整解答

> 🎯 **一句话**：**默认安全**——手滑、CI 误触、新人照抄都应先「只打印 would」，真变更要显式 `DRY_RUN=false` / `--force`。

```bash
DRY_RUN=${DRY_RUN:-true}

deploy_host() {
  if [[ "$DRY_RUN" == true ]]; then
    log "[DRY-RUN] would reload $host"
    return 0
  fi
  # 真执行
}
```

> 📝 **面试**：「与三开关、失败 exit 1 同一套：错就停、默认不伤人。」

### 再追问

**演练也要跑脚本，默认 true 会不会烦？**——烦但安全；真执行一行 `DRY_RUN=false -f` 写进变更单。

## Q2

**★★★★★｜`getopts` 能直接解析 `--dry-run` 吗？怎么做长选项？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、解析：`getopts` 与长选项](知识点.md)

### 完整解答

> 🎯 **一句话**：**不能**——`getopts` 只处理 `-` 单字母；长选项用 **`while case $1 in --dry-run)`** 或先扫长选项。

```bash
while [[ $# -gt 0 ]]; do
  case $1 in
    -d|--dry-run)  DRY_RUN=true; shift ;;
    -f|--force)    FORCE=true; shift ;;
    -h|--help)     usage ;;
    *)             break ;;
  esac
done
```

```bash
# 仅短选项
while getopts ':dfh' opt; do ...; done
```

> ⚠️ **别混**：文档写 `--dry-run` 但代码只认 `-d` = 运维事故。

### 再追问

**GNU getopt 长选项？**——部分环境有，不可移植——SRE 脚本优先手写 `case`。

## Q3

**★★★★★｜`getopts` 循环结束后为什么要 `shift $((OPTIND - 1))`？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [三、解析：`getopts` 与长选项](知识点.md)

### 完整解答

> 🎯 **一句话**：`OPTIND` 指向下一个未处理参数——**shift 掉已吃的选项**，`$1` 才变成 `hosts.txt`。

```bash
# ./deploy.sh -d -j 10 hosts.txt
while getopts ':dj:' opt; do
  case $opt in
    d) DRY_RUN=true ;;
    j) PARALLEL=$OPTARG ;;
  esac
done
shift $((OPTIND - 1))
echo "hosts file=$1"    # hosts.txt
```

不 shift：`$1` 仍是 `-d`，文件校验失败或误把选项当文件名。

### 再追问

**`OPTIND=1` 何时需要？**——函数内重复解析前要重置，否则第二次调用错位。

## Q4

**★★★★☆｜`usage` 为什么写 stderr 且 `exit 2`？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [五、usage 与退出码](知识点.md)

### 完整解答

> 🎯 **一句话**：**stderr** 不污染 stdout 管道；**exit 2** 表示用法错误，与业务失败 **1** 区分。

```bash
usage() {
  cat >&2 <<EOF
Usage: $0 [OPTIONS] hosts.txt
EOF
  exit 2
}
```

```bash
./deploy.sh; echo $?    # 2 ← 调用方知道是参数问题
```

> 📝 **面试**：「CI 包装脚本可根据 2 提示改 Jenkins 参数，不必当部署失败去 rollback。」

### 再追问

**`-h` 算错误吗？**——对用户是帮助，仍可用 exit 0；很多脚本统一 exit 2 或 0，团队定一种并写文档。

## Q5

**★★★★★｜`DRY_RUN=false` 但没有 `--force`，脚本该不该执行危险操作？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [四、默认值：`DRY_RUN` 与危险操作默认 false](知识点.md)

### 完整解答

> 🎯 **一句话**：**不该**——推荐双闸门：非 dry-run 且危险动作必须 **`FORCE=true`**。

```bash
if [[ "$DRY_RUN" != true && "$FORCE" != true ]]; then
  echo "refusing: need --force for real run" >&2
  exit 1
fi
```

防「环境变量里残留 `DRY_RUN=false`」单独误触。

### 再追问

**只 force 不关 dry-run？**——dry-run 为 true 时仍只打印——force 不应绕过 dry-run，除非文档明确「force = 跳过二次确认但仍 respect dry」——一般 force 与 execute 联用。

## Q6

**★★★★☆｜`DRY_RUN=false ./script.sh` 和 `./script.sh --execute` 谁优先？**

**覆盖**：常用 ｜ **对应**：知识点 [四、默认值：`DRY_RUN` 与危险操作默认 false](知识点.md)

### 完整解答

> 🎯 **一句话**：团队要**文档化优先级**——常见约定：**命令行 `--execute` 覆盖环境默认**，环境在解析前设初值。

```bash
DRY_RUN=${DRY_RUN:-true}    # 环境
# parse: --execute → DRY_RUN=false  # 命令行覆盖
```

`-h` 里写一句：`CLI flags override environment`。

### 再追问

**CI 只设环境不设旗标？**——可以，但危险操作建议 CI 也要 `--force` 人工审批 gate。

## Q7

**★★★★☆｜`./deploy.sh hosts.txt` 通过校验应检查哪几条？**

**覆盖**：必会 ｜ **对应**：知识点 [五、usage 与退出码](知识点.md)

### 完整解答

> 🎯 **一句话**：**有且仅有一个位置参数、路径存在、文件非空、（可选）至少一行非注释 host**。

```bash
[[ $# -eq 1 ]] || usage
[[ -f "$1" && -s "$1" ]] || { echo "bad hosts: $1" >&2; exit 1; }
grep -v '^#' "$1" | grep -q . || { echo "no hosts" >&2; exit 1; }
```

无参 → `usage` exit 2；文件不存在 → exit 1（用法对但资源错）。

### 再追问

**传目录而非文件？**——`-f` 失败 exit 1，别误进 `usage`。

## Q8

**★★★★★｜`TARGET=/data/app` 未赋值时 `rm -rf "$TARGET"/*` 会怎样？怎么防？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [生产模板](知识点.md)

### 完整解答

> 🎯 **一句话**：`TARGET` 空 → **`rm -rf /*`**——用 **`set -u`**、**`${TARGET:?}`**、绝对路径检查、**dry-run + force**。

```bash
set -u
safe_rm_contents() {
  local dir=$1
  [[ -n "${dir:?}" ]]
  [[ "$dir" == /* && "$dir" != "/" ]] || exit 1
  if [[ "$DRY_RUN" == true ]]; then
    log "[DRY-RUN] would rm ${dir}/*"
    return
  fi
  [[ "$FORCE" == true ]] || exit 1
  rm -rf "${dir:?}"/*
}
```

> ⚠️ **别混**：`--force` 不能替代路径校验——force 是「人确认」，不是「允许删 /」。

### 再追问

**`rm -rf "${dir:?}/"` 够吗？**——仍要禁止 `dir=/`；多层检查。

## Q9

**★★★★☆｜`main "$@"` 和 `main $*` 在 host 名含空格时差在哪？**

**覆盖**：必会 ｜ **对应**：知识点 [二、出生：argv、`$0`、`$@`、`shift`](知识点.md)

### 完整解答

> 🎯 **一句话**：**`"$@"` 保留每个参数边界**；未引用的 `$*` 会按 IFS 拆碎含空格的 host（极少但致命）。

```bash
main() { echo "count=$# arg1=[$1]"; }
main "$@"    # 正确
# main $*    # 可能拆成多个参数
```

### 再追问

**`"$*"` 一行传？**——单字符串，通常不如 `"$@"`——统一 `"$@"`。

## Q10

**★★★★☆｜`--` 在参数解析里干什么？**

**覆盖**：常用 ｜ **对应**：知识点 [三、解析：`getopts` 与长选项](知识点.md)

### 完整解答

> 🎯 **一句话**：**结束选项解析**——后面全是位置参数，即使以 `-` 开头。

```bash
case $1 in
  --) shift; break ;;
esac
# 剩余 "$@" 给 REST
```

```bash
./script.sh -- -weird-hostname    # -weird-hostname 是 host 不是选项
```

### 再追问

**getopts 认 `--` 吗？**——`getopts` 遇 `--` 常停止——仍建议显式 `case --)`。

## Q11

**★★★★☆｜用户传 `./script.sh --dry-rn`（拼写错），脚本应怎样？**

**覆盖**：常用 ｜ **对应**：知识点 [三、解析：`getopts` 与长选项](知识点.md)

### 完整解答

> 🎯 **一句话**：**未知选项 → stderr 提示 + `usage`**，不要静默忽略当默认执行。

```bash
-?*|--*)
  echo "unknown option: $1" >&2
  usage
  ;;
```

静默忽略 = 用户以为开了 dry-run 实际真跑。

### 再追问

**模糊匹配建议 `--dry-rn` did you mean？**——友好但可选；至少不能 silent。

## Q13

**★★★★☆｜`getopts ':j:'` 用户只写 `-j` 没给数字，怎么报错？**

**覆盖**：必会 ｜ **对应**：知识点 [三、解析：`getopts` 与长选项](知识点.md)

### 完整解答

> 🎯 **一句话**：选项串前加 **`:`** → 缺参时 `opt=:`，`OPTARG` 是选项字母，进 `usage`。

```bash
while getopts ':j:' opt; do
  case $opt in
    j) PARALLEL=$OPTARG ;;
    :) echo "option -$OPTARG requires argument" >&2; usage ;;
    \?) echo "unknown -$OPTARG" >&2; usage ;;
  esac
done
```

### 再追问

**`PARALLEL` 非数字？**——解析后 `[[ "$PARALLEL" =~ ^[0-9]+$ ]]` 再校验。

## Q14

**★★★★★｜口述参数「安全」八条——各防什么坑？**

**覆盖**：核心 · 常考 ｜ **对应**：知识点 [七、收束：参数生命周期凭什么「安全」](知识点.md)

### 完整解答

> 🎯 **一句话**：**默认 dry · 长选项 case · usage exit2 · force 双闸 · 文件校验 · 审计日志 · -u/:? · 复杂换 Python**。

| 条 | 坑 |
|----|-----|
| DRY_RUN 默认 true | 手滑真执行 |
| case 长选项 | 文档与行为不一致 |
| usage stderr exit 2 | CI 分不清参数错 |
| --force | 环境残留 false |
| 位置参数校验 | 空 hosts 误跑 |
| 审计日志 | 无法定责 |
| `${d:?}` | rm -rf /* |
| 子命令过多 | bash 不可维护 |

### 再追问

**画主图**：标一次事故是卡在「默认值」还是「缺 force」。
