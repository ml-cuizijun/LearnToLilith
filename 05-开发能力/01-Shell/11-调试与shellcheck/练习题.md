## Q1

**★★★★★｜发版脚本 CI 红了，同事说直接 `bash -x` 打满日志——正确排错顺序是什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [一、一张图](知识点.md)

### 场景

新人跳过静态检查，在生产等价环境开全程 `-x`，Jenkins 归档 2GB 且含 API token。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**复现 → `bash -n` → `shellcheck` → 局部 `set -x`**；xtrace 不进 CI 默认流水。

```bash
bash -n deploy.sh
shellcheck -S warning -x deploy.sh
DEBUG=true DRY_RUN=true bash -x deploy.sh 2>/tmp/trace.log
```

> 📝 **面试**：「静态先行、跟踪兜底、秘密不进日志。」

### 再追问

能否用 `strace` 代替 `-x`？——看系统调用，不懂 Shell 展开；互补而非替代。

## Q2

**★★★★☆｜`bash -n` 通过了，运行仍报 `unbound variable`——为什么？**

**覆盖**：必会 · 常考 | **对应**：知识点 [三、静态第一关](知识点.md)

### 场景

脚本有 `set -u`，CI 未 export `STAGE`，`-n` 绿、运行红。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`-n` 只解析语法，不执行**——`set -u`、分支逻辑、文件是否存在都是运行时。

```bash
bash -n script.sh   # 过
STAGE= ./script.sh  # 可能 unbound variable
```

修法：shellcheck + 集成测试；缺参用 `${STAGE:?}`。

> ⚠️ **别混**：语法错 vs 运行时错——工具不同阶段不同。

### 再追问

`bash -n` 能发现 `if` 少 `fi` 吗？——能，属于语法树错误。

## Q3

**★★★★★｜shellcheck 报 SC2086，代码是 `rm -rf $dir/*`——错在哪、怎么改？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、静态第二关](知识点.md)

### 场景

`dir` 为空时 glob 变 `/*`，活动前差点删根（与 03 章联动）。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**SC2086 = 变量未双引号**；改为 **`rm -rf "${dir:?}"/*`** 且先测目录非空。

```bash
# 错
rm -rf $dir/*

# 对
[[ -n "${dir:-}" && -d "$dir" ]] || exit 1
rm -rf "${dir}"/*
```

### 再追问

为什么 shellcheck 不报错 `rm -rf "${dir}"/*` 的 glob？——`*` 在引号外是**刻意** glob；`$dir` 必须引号。

## Q4

> 开头「密码进 Jenkins」就在这题。

**★★★★★｜`set -x` 后 Jenkins 日志出现数据库密码——怎么发生的、怎么防？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、跟踪](知识点.md)

### 场景

`mysql -p"$DB_PASS"` 在 `-x` 下展开为明文参数行。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`-x` 打印展开后的命令行**；防：**局部 `-x`**、**`BASH_XTRACEFD` 专文件**、**staging only**、**用配置文件而非 `-p` 参数**。

```bash
export BASH_XTRACEFD=19
exec 19>/tmp/xtrace.log
set -x
# 敏感段
set +x
```

> 📝 **面试**：「生产常驻 ERR trap，不用全程 -x。」

### 再追问

`set +x` 在函数 return 前忘了关会怎样？——后续全跟踪；用 `local _x=$-` 模式或 `trap` 收尾。

## Q5

**★★★★☆｜日志里只有 `+ ssh ...` 不知道对应脚本哪一行——PS4 怎么写？**

**覆盖**：必会 · 常用 | **对应**：知识点 [五、跟踪](知识点.md)

### 场景

500 行脚本 xtrace 上千行，无法对应 `deploy.sh` 源码。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`export PS4='+(${BASH_SOURCE##*/}:${LINENO}): '`** 再 `set -x`。

```text
+(deploy.sh:142): ssh -n game-01 nginx -t
# ← 直接跳源码 142 行
```

可加 `${FUNCNAME[0]}` 显示函数名。

### 再追问

子 shell `( set -x; cmd )` 行号准吗？——子 shell 内行号仍有效，但 `BASH_SOURCE` 可能变。

## Q6

**★★★★☆｜`set -v` 和 `set -x` 区别？排错用哪个？**

**覆盖**：必会 · 常考 | **对应**：知识点 [五、跟踪](知识点.md)

### 场景

笔试题：「解释 bash 调试选项。」

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`-v` 打印原始输入行**；**`-x` 打印展开后将要执行的命令**——排错几乎只用 **`-x`**。

```bash
name=world
set -v; echo hello $name; set +v
# echo hello $name          ← -v：原始

set -x; echo hello $name; set +x
# + echo hello world        ← -x：展开后
```

### 再追问

能同时 `-vx` 吗？——可以，日志更吵；一般不需要。

## Q7

> 开头有人喊「去掉 set -e」——高频错答。

**★★★★★｜「把 `set -e` 注释掉更好调试」——对吗？应该怎么调试？**

**覆盖**：核心 · 必会 | **对应**：知识点 [六、运行时](知识点.md)

### 场景

发版脚本去掉 `-e` 后第 10 台失败仍继续，CI 却绿了。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**不对**——用 **`DRY_RUN`**、**局部 `set -x`**、**单函数调试**；保持三开关和退出码契约。

```bash
DRY_RUN=true ./deploy.sh           # 不看效果看路径
bash -x -c 'source deploy.sh; deploy_host game-01'
```

### 再追问

`set -e` 下如何单步？——`bash -x` 看每步展开，不是去掉 `-e`。

## Q8

**★★★★☆｜如何把 shellcheck 进 GitLab CI？最少要写哪几步？**

**覆盖**：必会 · 常用 | **对应**：知识点 [七、收敛](知识点.md)

### 场景

团队脚本质量参差，MR 想挡明显引号 bug。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：镜像装 **shellcheck**；job 里 **`find ... | xargs bash -n`** + **`shellcheck -S warning -x`**；失败 **`exit 1`**。

```yaml
shell-lint:
  image: koalaman/shellcheck-alpine:latest
  script:
    - find scripts -name '*.sh' -exec bash -n {} \;
    - shellcheck -S warning -x scripts/*.sh
```

配合 pre-commit 本地先跑。

### 再追问

`allow_failure: true` 可以吗？——过渡期可以；稳定后必须 false 才真门禁。

## Q9

**★★★★☆｜`cmd | tee log` 失败但 `$?` 是 0——shellcheck 会提示什么？**

**覆盖**：必会 · 常考 | **对应**：知识点 [四、静态第二关](知识点.md)

### 场景

与 06 章 `pipefail` 联动：左端 `kubectl` 失败，CI 绿。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**SC2181** 警告误用 `$?` 测管道；修法 **`set -o pipefail`** 或查 **`PIPESTATUS`**。

```bash
set -o pipefail
kubectl apply -f app.yaml | tee apply.log
# 或
kubectl apply -f app.yaml | tee apply.log
[[ ${PIPESTATUS[0]} -eq 0 ]]
```

### 再追问

已有 `pipefail` 还会 SC2181 吗？——可能仍提示，按语义改写法或定向 disable。

## Q10

**★★★★☆｜本地 `./deploy.sh` 成功，CI `sh deploy.sh` 失败——排错从哪查？**

**覆盖**：必会 · 常用 | **对应**：知识点 [二、出生](知识点.md)

### 场景

`[[` syntax error，与 01 章 shebang 题联动。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**对齐解释器**——CI 是否 `sh` 忽略 shebang；查 `readlink /bin/sh`、`bash --version`。

```bash

```

同时打印：`echo "BASH=$BASH_VERSION CI=$CI"`

### 再追问

## Q11

**★★★★☆｜ERR trap 和 `set -x` 在生产各扮演什么角色？**

**覆盖**：必会 | **对应**：知识点 [六、运行时](知识点.md)

### 场景

问能否用 ERR trap 完全替代 xtrace。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**ERR trap** 仅在失败点打行号/命令，**轻量可常驻**；**`-x`** 打全过程，**仅排错短期开**。

```bash
trap 'log "ERR $LINENO: $BASH_COMMAND"' ERR   # 生产 OK
set -x                                         # staging 短期
```

### 再追问

`set -E` 干什么？——函数内错误是否继承 ERR trap（高级场景）；简单脚本 log 即可。

## Q12

**★★★★☆｜动态 `source "$CONF"` 导致一片 SC1091——怎么处理才专业？**

**覆盖**：常用 | **对应**：知识点 [四、静态第二关](知识点.md)

### 场景

`CONF` 路径运行时才有，shellcheck 报找不到文件。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`-P SCRIPTDIR` 加搜索路径**；或**单行 disable 并注释原因**；别全局关规则。

```bash
# shellcheck source=scripts/lib.sh
# shellcheck disable=SC1091 -- CONF path is runtime-only
source "$CONF"
```

```bash
shellcheck -P scripts -x deploy.sh
```

### 再追问

disable 要不要 code review？——要，每条 disable 是技术债，需理由。

## Q13

**★★★★☆｜脚本「行为怪」但无语法错——60 秒排障剧本？**

**覆盖**：常用 · 必会 | **对应**：知识点 [八、作战](知识点.md)

### 场景

oncall 接手，不能长时间停 CI。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**0–10s `bash -n`；10–25s `shellcheck`；25–45s staging `PS4+bash -x`；45–60s dry-run 回归**。

| 时段 | 动作 |
|------|------|
| 0–10s | `bash -n` |
| 10–25s | `shellcheck -S warning` |
| 25–45s | `DEBUG=true bash -x` 到专文件 |
| 45–60s | 修 + `DRY_RUN` 重跑 |

### 再追问

xtrace 2GB 怎么办？——缩小复现输入（单 host、单函数 `debug_wrap`）。

## Q14

**★★★★★｜白板：画「一次脚本排错的一生」并说明每阶段工具与禁忌。**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [一、一张图](知识点.md)、[七、收敛](知识点.md)

### 场景

终面 SRE 手写题。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**复现 → -n → shellcheck → 局部 -x/PS4 → 修 → CI lint**；禁忌：**生产全程 -x、去 -e、全局 disable shellcheck**。

```mermaid
flowchart LR
    A[复现] --> B[bash -n]
    B --> C[shellcheck]
    C --> D[set -x 局部]
    D --> E[CI 固化]
```

纪律四件套：静态先于 -x；-x 不泄密；不修 -e；CI 固化 shellcheck。

> 📝 **面试**：「SC2086 未引号、SC2181 管道 $?，背两个就够值班。」

### 再追问
