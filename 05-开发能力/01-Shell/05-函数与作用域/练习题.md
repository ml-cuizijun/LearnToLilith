## Q1

**★★★★★｜Bash 函数能 return 一个字符串给调用方吗？如果不能，正确做法是什么？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [七、返回：退出码怎么传回去](知识点.md)

### 场景

同事写 `get_env() { return "$1"; }`，想 `ver=$(get_env prod)` 拿到 `prod`，结果变量是空的，`echo $?` 却是 0。他说「Bash 函数和 Python 一样能 return 值」。

### 完整解答

> 🎯 **一句话**：`return` 只能传 **0–255 退出码**；字符串必须走 **stdout**，日志走 **stderr**。

```bash
get_env() {
  printf '%s\n' "$1"    # ← 数据走 stdout
}

ver=$(get_env prod)
echo "ver=$ver"         # ver=prod
```

`return` 的参数被当作**无符号 8 位整数**：

```bash
bad() { return "prod"; }   # ← bash: numeric argument required
```

调用方接法分两种：

| 要什么 | 怎么接 |
|--------|--------|
| 成败 | `if func; then` 或 `func; echo $?` |
| 数据 | `var=$(func)` |
| 原因 | 看 stderr 或配合非零退出码 |

> ⚠️ **别混**：`echo $?` 读到 0 不代表「拿到了字符串」——只说明最后一条命令成功。

> 📝 **面试**：「Bash 函数返回值」= 退出码 + stdout 数据通道，不是 Python 的 `return obj`。

### 再追问

**能否 `return` 两个值？**——不能。要么 stdout 打 TAB/JSON 一行，要么故意用全局变量（要文档化副作用），要么换 Python/Go。**不要**用 `return` 传业务错误码 404——会 `404 % 256 = 148`。

## Q2

**★★★★★｜函数里忘写 local，线上会出现什么怪现象？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [四、作用域：变量在哪活着](知识点.md)

### 场景

巡检脚本里 `retry=3`，`wait_service` 里写了 `retry=0` 没加 `local`，导致后面 `for ((i=0; i<retry; i++))` 一次都不跑，却没有任何报错。

### 完整解答

> 🎯 **一句话**：Bash 函数内赋值**默认全局**——函数是全局变量的写穿器，必须用 `local` 隔离。

```bash
retry=3
broken() {
  retry=0              # ← 污染全局
}
broken
echo "$retry"          # 0
```

修法：

```bash
fixed() {
  local retry=0
  # ...
}
```

> 🔍 **现场**：

```bash
bash -x script.sh 2>&1 | grep retry=
```

> 📝 **面试**：进函数第一件事——给会改的变量加 `local`；故意改全局的函数命名成 `set_*` 让人一眼看出副作用。

### 再追问

**`local` 写在函数外？**——直接报错 `local: can only be used in a function`。**不要**用 `export` 掩盖作用域问题。

## Q3

**★★★★★｜`host=$(get_ip)` 拿到空，但单独跑 `get_ip` 终端有输出，怎么回事？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [六、输出：stdout 与 stderr 两条路](知识点.md)

### 场景

```bash
get_ip() {
  echo "detecting..."           # ← 进度
  ip route get 1.1.1.1 | awk '{print $7; exit}'
}
host=$(get_ip)
curl "http://$host/health"    # curl: (3) URL using bad/illegal format
```

### 完整解答

> 🎯 **一句话**：`$()` 只捕 **stdout**；进度和错误必须 `>&2`，stdout 只留**一行干净数据**。

```bash
get_ip() {
  echo "detecting..." >&2
  ip route get 1.1.1.1 2>/dev/null | awk '{print $7; exit}'
}
```

更糟的情况：多行 stdout 全进变量：

```bash
host=$(get_ip)
# host='detecting...\n10.0.0.5'  ← curl 必挂
```

> ⚠️ **别混**：终端「看得见」≠ `$()` 「捕得到」——终端同时显示 stdout+stderr，变量只有 stdout。

### 再追问

**怎么同时要数据和成败？**——`if host=$(get_ip); then ...`：退出码看 `ip|awk` 最后一条命令，数据在变量里。**不要**在 stdout 打 `ERROR:` 再指望 `if` 自动失败——除非最后命令非零。

## Q4

**★★★★☆｜库函数里写 `exit 1` 和 `return 1` 差在哪？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [七、返回：退出码怎么传回去](知识点.md)

### 场景

`source lib/deploy.sh` 后，里面 `deploy()` 校验失败 `exit 1`，整个发版终端脚本直接退出，连 `trap` 清理都没跑完。

### 完整解答

> 🎯 **一句话**：`return` 只结束**当前函数**；`exit` 结束**整个 shell 进程**（含 source 进来的主脚本）。

| 关键字 | 影响范围 |
|--------|----------|
| `return N` | 弹出函数栈，回到调用方 |
| `exit N` | 进程退出码 N，脚本终止 |

库函数、可被 `source` 的片段：**只 `return`**。`exit` 留给 `main` 最外层。

> 📝 **面试**：这是 Shell 面试高频 P0——库函数 `exit` 等于「拉闸」。

### 再追问

**子 shell 里 `exit`？**——只结束子 shell，不影响父脚本（见 [07](../07-进程作业与subshell/) Q3）。但 `source` 没有子 shell。

## Q5

**★★★★☆｜生产函数日志应该 echo 到哪？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [六、输出：stdout 与 stderr 两条路](知识点.md)

### 完整解答

> 🎯 **一句话**：**数据 stdout，日志 stderr**——三者分工：stdout 给 `$()`/管道，stderr 给人眼，退出码给 `if`。

```bash
log() { printf '[%s] %s\n' "$(date +%H:%M:%S)" "$*" >&2; }

fetch() {
  log "GET $1"
  curl -sf "$1"
}
```

重定向脚本日志时常用：

```bash
exec >>"$LOG" 2>&1    # ← 此后 log 若在 stderr 也会进文件（见 06 章）
```

### 再追问

**为什么不用 `echo` 打日志？**——`echo -n "$var"` 选项注入；用 `printf '%s\n'`。**不要**把 JSON 日志和返回值混在同一通道无标记输出。

## Q6

**★★★★☆｜透传参数为什么要 `"$@"` 而不是 `$*`？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [三、调用：参数怎么进门](知识点.md)

### 场景

`run_ssh host rm -rf /data/backup 2024-01-01` 路径里有空格时被拆成两个参数，误删目录。

### 完整解答

> 🎯 **一句话**：`"$@"` 保持「每个参数一个单词」；`$*` 受 `IFS` 影响合成一串。

```bash
wrapper() {
  ssh "$1" -- "${@:2}"    # ← 推荐：主机 $1，其余原样透传
}
```

对比：

```bash
# 假设只有一个参数含空格 "a b"
for x in "$@"; do echo ">$x<"; done   # >a b<
for x in $*;   do echo ">$x<"; done   # >a< >b<  拆坏了
```

> 📝 **面试**：透传永远 `"$@"`；需要丢弃 `$0` 时用 `shift` 或 `"${@:1}"`。

### 再追问

**`$#` 为 0 怎么报错？**——`${1:?usage: cmd HOST ...}` 或 `[[ $# -lt 1 ]] && usage && return 1`。

## Q7

**★★★★☆｜`set -e` 开着，函数里某条命令失败会怎样？**

**覆盖**：必会 ｜ **对应**：知识点 [五、执行体：函数里命令怎么跑](知识点.md)

### 完整解答

> 🎯 **一句话**：与函数外相同——非零即弹栈返回，**除非**在 `if`/`while` 条件或 `|| true` 后。

```bash
set -e
f() {
  false              # ← 函数在此 return 1，不会继续下一行
  echo never
}
f || echo "caught"
```

管道要特别小心：中间失败默认不触发 `-e` → 见 [06](../06-管道重定向与PIPESTATUS/)，`pipefail` 必开。

### 再追问

**想在函数内容忍失败？**——`if ! cmd; then ...` 或 `cmd || return 1`，**不要**全局 `set +e`。

## Q8

**★★★☆☆｜`source lib.sh` 和 `bash lib.sh` 对函数注册差在哪？**

**覆盖**：常用 ｜ **对应**：知识点 [二、定义：函数怎么登记入口](知识点.md)

### 完整解答

> 🎯 **一句话**：`source` 在**当前 shell** 注册函数；`bash lib.sh` 在**子进程**里注册，结束就销毁。

```bash
source ./lib.sh
declare -F check_disk    # ← 有

bash ./lib.sh
declare -F check_disk    # ← 无（除非 lib 里 export -f，极少用）
```

### 再追问

**库文件如何避免被直接执行时跑主逻辑？**——`[[ "${BASH_SOURCE[0]}" == "${0}" ]] || return` 或只在 `main` 块调用。

## Q9

**★★★☆☆｜`return 300` 调用方 `echo $?` 看到多少？**

**覆盖**：常考 ｜ **对应**：知识点 [七、返回：退出码怎么传回去](知识点.md)

### 完整解答

> 🎯 **一句话**：退出码模 256 → `300 % 256 = 44`。

```bash
f() { return 300; }
f
echo $?    # 44
```

业务 HTTP 码、自定义大整数**不要**用 `return` 传。

### 再追问

**正确传错误分类？**——stderr 打 `reason=...` + 约定小整数表（1=网络 2=权限），或 stdout 打 JSON。

## Q10

**★★★★☆｜两个函数共用计数器 `n`，交替调用结果错乱，怎么查？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [四、作用域：变量在哪活着](知识点.md)

### 场景

`inc_a`/`inc_b` 都写 `n=$((n+1))` 没 `local`，嵌套调用后 `n` 不是预期累加。

### 完整解答

> 🎯 **一句话**：要么各自 `local n`（互不影响），要么故意共享全局但要改名 `global_retry` 并注释。

排查：

```bash
grep -n 'n=' script.sh | grep -v local
bash -x script.sh 2>&1 | grep '^+ n='
```

### 再追问

**需要共享状态？**——显式全局 + 命名空间前缀 `G_`，或改用一个 `state_` 函数封装，**不要**隐式写穿。

## Q11

**★★★★★｜设计一个 HTTP 探活函数，上层要能 `if check URL; then` 又能打日志**

**覆盖**：核心 · 必会 · 🔧 ｜ **对应**：知识点 [八、组合模式：数据与成败拆开](知识点.md)

### 完整解答

> 🎯 **一句话**：日志 `>&2`；成功 `return 0`；失败 `return 1`；**不要**在 stdout 打无关字。

```bash
check_http() {
  local url=$1 code
  echo "probe $url" >&2
  code=$(curl -o /dev/null -sf -w '%{http_code}' --max-time 3 "$url" || echo "000")
  if [[ "$code" == "200" ]]; then
    return 0
  fi
  echo "FAIL $url code=$code" >&2
  return 1
}
```

### 再追问

**还要返回 response body？**——成功时 body 走 stdout，调用方 `body=$(check_http ...)` 与 `if` 不能同时简单做——要分 `check_http`（只看码）和 `fetch_http`（输出 body）两个函数。**不要**一个函数又判码又 echo 多行 body 除非文档约定。

## Q12

**★★★☆☆｜`name=-n; echo "$name"` 为什么不换行？函数里怎么避免？**

**覆盖**：常用 ｜ **对应**：知识点 [六、输出：stdout 与 stderr 两条路](知识点.md)

### 完整解答

> 🎯 **一句话**：`echo` 把以 `-` 开头的变量当选项；生产用 `printf '%s\n' "$var"`。

```bash
safe_out() {
  printf '%s\n' "$1"
}
```

### 再追问

**`echo -e` 呢？**——不同系统行为不一致；格式化用 `printf`。

## Q13

**★★★★☆｜`source deploy.sh` 一加载就部署，怎么改？**

**覆盖**：必会 · 🔧 ｜ **对应**：知识点 [九、生产模板](知识点.md)

### 完整解答

> 🎯 **一句话**：主逻辑放进 `main`，文件末尾用 `BASH_SOURCE` 守卫，仅直接执行时才 `main`。

```bash
deploy() { ... }

if [[ "${BASH_SOURCE[0]}" == "${0}" ]]; then
  deploy "${1:?}"
fi
```

`source` 时 `BASH_SOURCE[0]` ≠ `$0`，跳过 `main`。

### 再追问

**还能 `export -f` 吗？**——可以传给子 bash，但 SSH 远程默认不行；远程用 scp 脚本或内联函数定义。

## Q14

**★★★★☆｜函数体和 `$()` 谁开 subshell？对变量赋值有什么影响？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [四、作用域：变量在哪活着](知识点.md)

### 完整解答

> 🎯 **一句话**：**函数体不开** subshell；**`$()` 和 `( )` 开** subshell——里面的 `export`/`变量` 默认带不出（除非写管道/命令替换捕获 stdout）。

```bash
f() { x=1; }
( x=1 )
echo "$x"    # 空

f
echo "$x"    # 仍空——因为 f 里没写 local 且 x 未预先存在？ actually x=1 in f without local creates global x
```

更准确示例：

```bash
g() { local y=2; }
g
echo "${y:-}"   # 空

h() { y=2; }    # 全局
h
echo "$y"       # 2
```

```bash
$( y=3 )          # 无效语法；应是 ( y=3 ) 或 y=$(subcmd)
( y=3 )
echo "${y:-}"     # 空
```

> 📝 **面试**：函数改全局、命令替换不开口传变量——要靠 stdout 或故意全局。

### 再追问

详情 → [07 进程作业与 subshell](../07-进程作业与subshell/)。**不要**在 `$()` 里指望 `export` 影响父 shell。
