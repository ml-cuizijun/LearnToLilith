## Q1

**★★★★★｜`false | true` 执行完 `echo $?` 输出多少？为什么？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、管道：| 怎么接力](知识点.md)

### 场景

新人写单元测试式脚本 `false | true`，断言「管道应该失败」，却发现 `$?` 是 0，认为 bash 有 bug。

### 完整解答

> 🎯 **一句话**：默认 `$?` 只等于**管道最后一个命令**的退出码——`true` 是 0，前面的 `false` 被吞。

```bash
false | true
echo $?    # 0

true | false
echo $?    # 1
```

要看第一节：

```bash
false | true
echo "${PIPESTATUS[@]}"    # 1 0
```

> 📝 **面试**：中间失败静默是设计行为，不是 bug；生产用 `pipefail` 或 `PIPESTATUS`。

### 再追问

**`false | false` 呢？**——`$?` 仍是 1（最后一个 false）。**不要**以为「两个都错会叠加成 2」。

## Q2

**★★★★★｜`cmd >file.log 2>&1` 和 `cmd 2>&1 >file.log` 差在哪？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [四、合并：2>&1 的顺序](知识点.md)

### 场景

cron 任务把 `backup.sh` 输出重定向到 `/var/log/backup.log`，文件里只有错误行，成功备份列表在邮件里（cron 把 stderr 发邮件）。

### 完整解答

> 🎯 **一句话**：`2>&1` 是复制**当时** fd1 的指向——必须先让 fd1 指向文件，再让 fd2 跟随。

```bash
# ✅ stdout+stderr 都进 file
cmd > file.log 2>&1

# ❌ stderr 仍去终端/邮件；只有 stdout 进 file
cmd 2>&1 > file.log
```

口诀：**先定 stdout 落点，再 `2>&1`**。

> ⚠️ **别混**：中文「把 2 合并到 1」容易理解成「合并到 1 的文件」——实现上是**复制 fd 指针**。

### 再追问

**bash `&>> file`？**——等价 `>> file 2>&1`（追加版）。POSIX 脚本仍写 `>>file 2>&1`。

## Q3

**★★★★★｜`set -o pipefail` 打开后，`false | true` 的 `$?` 是多少？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [七、pipefail：任一节失败，全线失败](知识点.md)

### 完整解答

> 🎯 **一句话**：`pipefail` 让 `$?` 取最右非零节；全 0 才 0——`false | true` 变成 **1**。

```bash
set -o pipefail
false | true
echo $?    # 1

true | false
echo $?    # 1
```

与三开关：

```bash
set -euo pipefail
false | true    # ← 脚本直接退出（不在 if 里）
```

> 📝 **面试**：生产默认三开关，`pipefail` 专治「中间 kubectl 挂了 grep 还绿」。

### 再追问

**`pipefail` 会让 `grep` 无匹配不算失败吗？**——不会消除；无匹配 exit 1 仍可能让管线失败——要分项看 `PIPESTATUS`（Q8）。

## Q4

**★★★★★｜`PIPESTATUS` 数组下标怎么对应管道里的命令？什么时候读？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [六、PIPESTATUS：每一节的黑匣子](知识点.md)

### 完整解答

> 🎯 **一句话**：从左到右 0、1、2…；**下一条命令执行前**立刻读，否则被覆盖。

```bash
false | true | wc -l
echo "${PIPESTATUS[@]}"    # 1 0 0
echo $?                    # 0（wc 的码）
```

保存：

```bash
cmd1 | cmd2
save=("${PIPESTATUS[@]}")
echo "c0=${save[0]} c1=${save[1]}"
```

> ⚠️ **别混**：`$?` ≠ `PIPESTATUS[0]`——发版失败要查的是**上游** `[0]`。

### 再追问

**中间插 `echo debug`？**——`PIPESTATUS` 已被 `echo` 覆盖成 `echo` 的码。**不要**在管道和读取之间插任何命令。

## Q5

**★★★★★｜`kubectl apply -f bad.yaml | grep -q .` 失败，怎么判断是 apply 还是 grep？**

**覆盖**：核心 · 必会 · 🔧 ｜ **对应**：知识点 [九、生产模板](知识点.md)

### 场景

CI 里 apply 无效 YAML，流水线红在 grep 步骤，运维却去查 grep 版本。

### 完整解答

> 🎯 **一句话**：立刻 `echo ${PIPESTATUS[0]} ${PIPESTATUS[1]}`——`[0]` 是 kubectl，`[1]` 是 grep。

```bash
kubectl apply -f bad.yaml 2>&1 | grep -q .
k=${PIPESTATUS[0]} g=${PIPESTATUS[1]}
if [[ $k -ne 0 ]]; then
  echo "apply failed rc=$k" >&2
  exit "$k"
fi
```

开 `pipefail` 时整条非零，但仍应用 `[0]` 写清楚错误来源。

```bash
set -o pipefail
kubectl apply -f bad.yaml | grep -q .
echo $?    # 非零，但不知道是 kubectl 还是 grep——仍要 PIPESTATUS
```

> 📝 **面试**：`pipefail` 告诉你「失败了」；`PIPESTATUS` 告诉你「谁失败了」。

### 再追问

**能否 `kubectl apply ... | grep -q . || true`？**——会吞掉 apply 失败。**不要**在发版路径用 `| true` 糊弄。

## Q6

**★★★★☆｜为什么 `ls /nope 2>/dev/null | wc -l` 看不到错误？怎么让错误也进管道？**

**覆盖**：必会 ｜ **对应**：知识点 [二、出生：三个标准流](知识点.md)

### 完整解答

> 🎯 **一句话**：`|` 只连接 **fd1→下一节 fd0**；stderr 默认仍上终端。

```bash
ls /etc /nope 2>/dev/null | wc -l    # stderr 被丢弃，$? 可能仍非零（ls）

# 让 stderr 也进管道
ls /etc /nope 2>&1 | grep -c 'No such'
# 或 bash
ls /etc /nope |& grep -c 'No such'
```

### 再追问

**排障时故意只看 stderr？**——`cmd >/dev/null` 保留 stderr 在终端。

## Q7

**★★★★☆｜`set -e` 开着，为什么 `false | true` 不退出脚本？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [七、pipefail](知识点.md)

### 完整解答

> 🎯 **一句话**：默认管道 `$?` 是 0（true），`-e` 认为成功；加 **`pipefail`** 后 `$?` 变 1 才会触发 `-e`。

```bash
set -e
false | true
echo still here    # 会执行

set -o pipefail
false | true       # ← -e 触发，脚本退出
```

例外：`if false | true; then ...` 里不触发 `-e`。

### 再追问

**管道在函数里？**——规则相同；库函数 + 管道更要 `pipefail`（链 [05](../05-函数与作用域/) Q7）。

## Q8

**★★★★☆｜管道末尾 `grep -q pattern` 无匹配导致失败，算 bug 吗？**

**覆盖**：常用 · 常考 ｜ **对应**：知识点 [五、管道：| 怎么接力](知识点.md)

### 完整解答

> 🎯 **一句话**：`grep` 无匹配 **exit 1 是约定**，不是错误——但会让整条管线在 `pipefail` 下失败。

```bash
set -o pipefail
kubectl get pod badname 2>/dev/null | grep -q Running
echo $? PIPESTATUS=${PIPESTATUS[*]}
# 要分辨：PIPESTATUS[0] 是 kubectl 错还是 grep 没匹配
```

修法：不用 `grep -q` 收尾判存在，改 `kubectl get ... &>/dev/null` 或查 `[0]`。

> ⚠️ **别混**：不要用 `| true` 消灭 grep 1——会把上游失败也变成 0。

### 再追问

**`grep -c` 无匹配？**——输出 `0` 但 exit 1，同样坑。

## Q9

**★★★☆☆｜既要终端看输出又要落盘，怎么重定向？**

**覆盖**：常用 · 🔧 ｜ **对应**：知识点 [九、生产模板](知识点.md)

### 完整解答

> 🎯 **一句话**：`tee` 旁路一份到文件；或 `exec > >(tee -a log) 2>&1`（进程替换细节见 [07](../07-进程作业与subshell/)）。

```bash
deploy.sh 2>&1 | tee -a deploy.log
# 注意：管道 $? 默认是 tee 的码；上游失败要 pipefail
```

```bash
set -o pipefail
deploy.sh 2>&1 | tee -a deploy.log
echo ${PIPESTATUS[0]}    # deploy 的码
```

### 再追问

**`tee` 成功但 deploy 失败？**——默认 `$?` 是 tee 的 0——**必须 pipefail + PIPESTATUS[0]**。

## Q10

**★★★☆☆｜`mysql < schema.sql` 和 here-doc 什么时候用？**

**覆盖**：常用 ｜ **对应**：知识点 [三、重定向：数据改道](知识点.md)

### 完整解答

> 🎯 **一句话**：`< file` 把 **stdin** 绑到文件；`<<EOF` 是内联 stdin，引号 `<<'EOF'` 禁止变量展开。

```bash
mysql db < schema.sql

mysql db <<'SQL'
SELECT 1;
SQL
```

here-doc 适合小 SQL/配置片段；大文件用 `<`。

### 再追问

**缩进 `<<-EOF`？**——去掉行首 tab，适合嵌进脚本块。

## Q11

**★★★★☆｜10GB 日志 `sort access.log | head` OOM，管道哪一段有问题？**

**覆盖**：常用 ｜ **对应**：知识点 [九、生产模板](知识点.md)

### 完整解答

> 🎯 **一句话**：`sort` 常需全量内存——应先 `grep` 缩小再 `awk` 计数，**禁止**对大文件直接 sort（见 [04 正则](../../04-正则与文本处理/)）。

```bash
# ✅
grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log \
  | awk '{c[$1]++} END{for(k in c) print c[k],k}' \
  | sort -rn | head -10
```

`pipefail` 下任一节读盘失败都会暴露。

### 再追问

**`cat big | grep`？**——多此一举，写 `grep pat big`。**不要**无意义加 `cat`。

## Q12

**★★★★☆｜`curl -sf url | jq .` 空输出且 `$?` 是 0，curl 其实 404，怎么认？**

**覆盖**：必会 · 🔧 ｜ **对应**：知识点 [六、PIPESTATUS](知识点.md)

### 完整解答

> 🎯 **一句话**：`curl -f` 遇 HTTP 错误非零，但若被 `jq` 收尾且 `pipefail` 未开，`$?` 可能是 jq 的 0——看 **`PIPESTATUS[0]`**。

```bash
curl -sf http://example/missing | jq .
echo "last=$? ps=${PIPESTATUS[*]}"
# 可能 last=0 ps=22 0

set -o pipefail
curl -sf http://example/missing | jq .
echo $?    # 非零
```

### 再追问

**jq 解析失败？**——`PIPESTATUS[1]` 非零；仍要先确认 `[0]` curl 成功。

## Q13

**★★★☆☆｜`cmd &>/dev/null` 之后怎么排障？**

**覆盖**：常用 ｜ **对应**：知识点 [二、出生：三个标准流](知识点.md)

### 完整解答

> 🎯 **一句话**：静音只用于**确认成功/失败**的路径；排障时去掉重定向或只丢 stdout `>/dev/null` 保留 stderr。

```bash
# 探活只要码
curl -sf http://svc/health &>/dev/null && echo up

# 排障
curl -v http://svc/health 2>&1 | head -20
```

### 再追问

**生产脚本长期 `&>/dev/null`？**——事故黑盒。**不要**在发版/迁移路径永久静音。

## Q14

**★★★★★｜说出管道可靠性三件套，各解决什么问题？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [八、收束：管道可靠性三件套](知识点.md)

### 完整解答

> 🎯 **一句话**：① `pipefail` 改 `$?` 语义；② `PIPESTATUS` 分段定责；③ `>log 2>&1` 正确顺序保日志完整。

```text
① set -o pipefail     — 中间挂 → 整条非零 → 配合 -e 真失败
② PIPESTATUS[i]       — 知道是 kubectl 还是 grep
③ >file 2>&1          — stdout/stderr 都进文件
```

三开关记忆：`set -euo pipefail` → [02](../02-脚本骨架与三开关/)。

> 📝 **面试**：背三件套比背 `2>&1` 语法更重要——体现「静默故障」意识。

### 再追问

**第四件常加什么？**——避免 `cat |`、大文件先 `grep`、发版不用 `| true`。**不要**为了绿而绿。
