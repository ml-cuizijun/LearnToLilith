## Q1

**★★★★★｜`requests.get(url)` 不设 timeout 在生产 cron 里最大的风险是什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：构造一次请求](知识点.md)

### 场景

Prometheus 侧网络抖动，脚本进程一直阻塞，下一个 cron 又起一份，节点 load 飙升。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**默认 `timeout=None` 可能永久阻塞**，cron 重叠、文件句柄与连接耗尽。

```python
TIMEOUT = (3.05, 27)  # connect, read
resp = session.get(url, timeout=TIMEOUT)
```

connect 短、read 略长：连不上快失败，慢查询给读 body 时间。

> 📝 **面试**：「timeout 不是可选优化，是运维脚本硬契约。」

### 再追问

单数字 `timeout=10` 与元组区别？——单数字同时限制 connect+read；元组可分别调。

## Q2

**★★★★★｜拿到 `response` 后为什么要 `raise_for_status()`？只判断 `status_code == 200` 够吗？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、读响应：状态码与 raise_for_status（⭐常考）](知识点.md)

### 场景

API 返回 204 No Content，脚本当失败；或 500 仍 `json()` 解析报错信息混乱——这是 Q1 结论的加深版。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**`raise_for_status()` 把非 2xx 统一成 `HTTPError`**；200  alone 漏 201/204。

```python
resp = session.get(url, timeout=TIMEOUT)
resp.raise_for_status()
if resp.content:
    data = resp.json()
```

`resp.ok` 等价于 200–399（含 3xx 已 follow 后的最终响应）。

### 再追问

想区分 404 与其它 4xx？——`except HTTPError as e: e.response.status_code`。

## Q3

**★★★★★｜哪些 HTTP 状态/异常应进入重试？哪些应立刻失败？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [六、重试：可重试边界与退避（🔥难点）](知识点.md)

### 场景

404 被放进 `status_forcelist`，日志里 404 重试 5 次后仍失败，浪费 30 秒。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**重试：连接错误、超时、429、502/503/504 等 5xx；不重试：400/401/403/404/422 等客户端错**。

```python
RETRYABLE = {429, 500, 502, 503, 504}
```

401/403 应修 token/权限，不是退避能解决的。

> ⚠️ **别混**：404 是资源或路径错，重试无意义。

### 再追问

500 一定重试？——有限次数；若 body 说明「配置永久无效」应停。

## Q4

**★★★★☆｜循环检查 200 个 URL，裸 `requests.get` 与 `Session` 差在哪？**

**覆盖**：必会 · 常用 | **对应**：知识点 [三、发出：Session 与连接池（必会）](知识点.md)

### 场景

同一 Prometheus 主机 200 条 query，脚本比 curl 慢很多，TIME_WAIT 暴增。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**`Session` 复用 TCP/TLS 连接池**，裸 get 每条新建连接。

```python
with requests.Session() as session:
    for url in urls:
        r = session.get(url, timeout=(3, 10))
        r.raise_for_status()
```

可设 `User-Agent`、默认 Header 一次。

### 再追问

多线程共享 Session？——requests Session 非完全线程安全，每线程独立 Session 或加锁。

## Q5

**★★★★★｜POST 创建告警工单失败，连接超时后重试，可能出什么问题？怎么设计？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [六、重试：可重试边界与退避（🔥难点）](知识点.md)

### 场景

第一次 POST 服务端已创建，响应丢包；客户端重试又建一条，oncall 收到重复工单。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**POST 非幂等，盲重试可能重复副作用**；用 Idempotency-Key、或 GET 查再 POST、或 urllib3 不把 POST 放进 allowed_methods。

```python
headers = {"Idempotency-Key": incident_id}
session.post(url, json=payload, headers=headers, timeout=TIMEOUT)
```

连接层失败（未收到任何响应）才可谨慎重试，且要有幂等键。

> 📝 **面试**：「GET/HEAD 重试相对安全；POST 默认不重试是对的。」

### 再追问

PUT 与 POST？——PUT 带固定资源 ID 时可设计为幂等，仍要读 API 文档。

## Q6

**★★★★☆｜指数退避为什么要加 jitter？手写公式怎么写？**

**覆盖**：必会 · 常考 | **对应**：知识点 [六、重试：可重试边界与退避（🔥难点）](知识点.md)

### 场景

发布窗口 50 个脚本同时 502，同步 sleep 1/2/4 秒，网关第二拨峰值更惨。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**jitter 打散重试时刻**，避免 thundering herd。

```python
import random
sleep = min(CAP, BASE * (2 ** (attempt - 1)))
sleep *= random.uniform(0.5, 1.5)
time.sleep(sleep)
```

还要有 `MAX_ATTEMPTS` 与 `CAP` 上限。

### 再追问

full jitter vs equal jitter？——full 更散；运维脚本 equal 够用。

## Q7

**★★★☆☆｜`urllib3.util.retry.Retry` 挂 `HTTPAdapter` 后还要注意什么？**

**覆盖**：常用 | **对应**：知识点 [六、重试：可重试边界与退避（🔥难点）](知识点.md)

### 场景

配了 `max_retries=3`，仍收到 502 时脚本不抛错，后面 `json()` 解析 HTML 错误页。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**适配器重试后仍要 `raise_for_status()`**；`raise_on_status=False` 时 502 不自动抛。

```python
retry = Retry(total=3, status_forcelist=[502, 503, 504], backoff_factor=0.5)
session.mount("https://", HTTPAdapter(max_retries=retry))
resp = session.get(url, timeout=TIMEOUT)
resp.raise_for_status()
```

检查 `allowed_methods` 是否误含 POST。

### 再追问

`total` 与 `connect/read/status` 关系？——urllib3 分类型计数，以文档为准，生产要测。

## Q8

**★★★★☆｜400 Bad Request 被重试 5 次，问题在哪？应如何处理？**

**覆盖**：必会 · 常考 | **对应**：知识点 [四、读响应：状态码与 raise_for_status（⭐常考）](知识点.md)

### 场景

query 参数拼错，网关返回 400，脚本仍退避重试。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**4xx（除 429）是客户端错，修请求不重试**。

```python
except HTTPError as e:
    if e.response.status_code in RETRYABLE_STATUS:
        ...  # 退避
    raise
```

400 应打日志 body 片段、修参数、`return 2`（用法错）。

### 再追问

422 Unprocessable Entity？——同样不重试，修 payload。

## Q9

**★★★☆☆｜收到 429 时除了退避还应看什么？**

**覆盖**：常用 | **对应**：知识点 [六、重试：可重试边界与退避（🔥难点）](知识点.md)

### 场景

API 返回 `Retry-After: 120`，脚本仍按 0.5s 指数退避，继续被限流。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**优先遵守 `Retry-After` Header**（秒或 HTTP-date），再叠加 jitter 上限。

```python
ra = resp.headers.get("Retry-After")
if ra and ra.isdigit():
    time.sleep(min(int(ra), CAP))
```

### 再追问

没有 Retry-After？——指数退避 + 减少并发（09 与 10 章结合）。

## Q11

**★★★☆☆｜内网 API 证书是企业 CA 签发，Python 报 `SSLError`，怎么处理？**

**覆盖**：常用 | **对应**：知识点 [七、TLS、代理与敏感信息（常用）](知识点.md)

### 场景

同事建议 `verify=False` 先跑通。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**指定 CA bundle 路径 `verify='/path/ca.pem'`**；`verify=False` 仅本地临时，禁止进生产。

```python
resp = session.get(url, timeout=TIMEOUT, verify="/etc/ssl/certs/company-ca.pem")
```

或 `REQUESTS_CA_BUNDLE` 环境变量。

> ⚠️ **别混**：TLS 错不是重试能解决的（除非证书刚轮换中间态）。

### 再追问

客户端证书 mTLS？——`cert=(client.pem, key.pem)`。

## Q14

**★★★★★｜读代码找 bug：**

```python
def check_api(session, url):
    for i in range(10):
        try:
            r = session.post(url, json={"action": "page"}, timeout=5)
            if r.status_code == 200:
                return True
        except Exception:
            pass
        time.sleep(0.1)
    return False

def main():
    with requests.Session() as s:
        ok = check_api(s, ALERT_URL)
    return 0 if ok else 0
```

**覆盖**：核心 · 必会 | **对应**：知识点 [五、判失败：RequestException 家族（必会）]、[六、重试：可重试边界与退避（🔥难点）](知识点.md)、[04 退出码](../04-异常与退出码/)

### 场景

告警 API 500 时静默成功，且可能重复 paging。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**POST 无退避紧重试 10 次**；**吞异常**；**失败仍 return 0**；应 GET/幂等键、区分 status、失败 return 1。

```python
def check_api(session, url) -> None:
    request_with_retry(session, "GET", f"{url}/health", ...)  # 或幂等 POST

def main() -> int:
    try:
        with build_session() as s:
            run(s)
    except requests.RequestException:
        log.exception("api check failed")
        return 1
    return 0
```

> 📝 **面试**：「三 bug：POST 重试、except pass、失败 exit 0。」

### 再追问

若必须 POST？——Idempotency-Key + 只重试连接/超时且未收到响应。
