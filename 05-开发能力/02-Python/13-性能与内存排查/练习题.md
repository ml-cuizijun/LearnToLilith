### 场景

同事建议「给 CronJob 加 CPU limit」。你还没看过脚本内部。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**staging 复现 + `perf_counter` 分段**，分清 CPU、I/O、内存，再选 cProfile 或 tracemalloc。

```python
t0 = time.perf_counter()
```

## Q2

复现之后——会读 pstats。

**★★★★★｜pstats 里 `cumtime` 和 `tottime` 有什么区别？优化时先看哪个？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [三、成长：cProfile 找 CPU 热点](知识点.md)

### 场景

`print_stats` 输出里 `main` 的 tottime 很小，但 cumtime 很大。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`tottime` 不含子调用；`cumtime` 含子调用——入口优化先看 cumtime**。

```text
ncalls  tottime  cumtime  function
    1    0.002  412.150  main          ← cumtime 大：时间花在子函数
500000    2.100  380.500  normalize   ← 子函数 cumtime 高才是真热点
```

> ⚠️ **别混**：只看 main 的 tottime 会误以为 main 本身很快就不用管了。

### 再追问

何时看 ncalls？——小函数被调用百万次时，优先减调用次数或内联逻辑。

## Q4

顶部全是 I/O 时别空优化。

**★★★★★｜cProfile 顶部全是 `socket.read` / `sleep`，说明什么？该不该继续优化 Python 循环？**

**覆盖**：核心 · 常考 | **对应**：知识点 [一、一张图：cProfile / tracemalloc 排查的一生](知识点.md)、[二、出生：复现与粗定位](知识点.md)

### 场景

你对 `aggregate()` 做了算法优化，总时间几乎不变。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**瓶颈在 I/O 等待，cProfile 对 I/O 脚本误导性强——应减 API 次数、分页、缓存，而非抠 Python 循环**。

何时才值得 cProfile Python 逻辑？——分段显示 aggregate CPU 段占主导时。

## Q5

CPU 线走完，换内存线。

**★★★★★｜如何用 tracemalloc 找出「哪一行代码」多分配了内存？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、壮年：tracemalloc 找内存增长](知识点.md)

### 场景

脚本跑完 RSS 涨 500 MB，怀疑某次 list 累积。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**start → snapshot1 → work → snapshot2 → `compare_to(snap1, 'lineno')` 看 top**。

```python
import tracemalloc, gc

gc.collect()
tracemalloc.start(25)
s1 = tracemalloc.take_snapshot()
run_audit()
gc.collect()
s2 = tracemalloc.take_snapshot()
for stat in s2.compare_to(s1, "lineno")[:10]:
    print(stat)  # audit.py:42: +48.2 MiB
```

> 📝 **面试**：「双快照对比增量，比单次 snapshot 更能定位增长点。」

### 再追问

为何前后 `gc.collect()`？——减少未回收垃圾干扰对比。

## Q6

就是「不信 getsizeof」那一问。

**★★★★☆｜`sys.getsizeof(big_list)` 很小，但进程 RSS 很大，为什么？**

**覆盖**：必会 · 常考 | **对应**：知识点 [四、壮年：tracemalloc 找内存增长](知识点.md)

### 场景

面试追问：你怎么证明 list 是内存大户？

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**getsizeof 只算 list 对象头，不算百万个元素——用 tracemalloc 看分配栈**。

```python
import sys
big = [0] * 10**6
sys.getsizeof(big)   # 约 8MB 量级，不是 8MB×元素
```

> ⚠️ **别混**：RSS 还含解释器、库、碎片；tracemalloc 看 Python 分配，不是完整 RSS 会计。

### 再追问

要看进程总 RSS？——`/usr/bin/time -v` 或容器 metrics，与 tracemalloc 互补。

## Q7

开头全量 list OOM 的修法。

**★★★★★｜K8s 巡检脚本 `all_pods.extend(page)` 攒全量，集群变大后 OOM，怎么改？**

**覆盖**：核心 · 必会 · 常用 | **对应**：知识点 [四、壮年：tracemalloc 找内存增长](知识点.md)、[12 K8s与云SDK调用](../12-K8s与云SDK调用/)

### 场景

cProfile 不慢，但 tracemalloc 显示 extend 行持续增长。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**改生成器流式处理 + 分页 list，边拉边写报告，不攒全量**。

```python
def iter_rows(v1, ns):
    for pod in iter_pods_paginated(v1, ns, limit=200):
        yield row_from_pod(pod)

for row in iter_rows(v1, ns):
    write_row(row)
```

> 📝 **面试**：「和 12 章分页是一件事：API 层 limit，脚本层 yield。」

### 再追问

必须全量排序怎么办？——外排写临时文件，或限制 namespace，别进内存。

## Q8

生产已卡住时的采样路径。

**★★★★☆｜生产 CronJob 进程已卡住，不能改代码重启，如何采样看卡在哪个函数？**

**覆盖**：常用 · 常考 | **对应**：知识点 [五、老去：行级与外部工具](知识点.md)

### 场景

staging 难复现，只有线上一个 PID。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**py-spy 采样 attach，不注入 cProfile**。

```bash
py-spy record -o /tmp/flame.svg --pid {PID} --duration 30
py-spy top --pid {PID}
```

需容器权限与安全审批；30 秒采样通常够看热点。

> ⚠️ **别混**：cProfile 要改代码或重启；py-spy 是外部采样。

## Q10

优化必须可回归。

**★★★★★｜优化 `normalize_label` 后，如何证明真的变快且没破坏结果？**

**覆盖**：核心 · 必会 | **对应**：知识点 [六、死亡：验证修复与回归](知识点.md)

### 场景

开发者说「感觉快多了」，CI 没有门禁。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**同输入跑 before/after：wall time + tracemalloc peak + 输出 hash 一致**。

```python
def benchmark(fn, label):
    tracemalloc.start()
    t0 = time.perf_counter()
    out = fn()
    elapsed = time.perf_counter() - t0
    _, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    return elapsed, peak, out

# assert hash_output(before_out) == hash_output(after_out)
```

cProfile 对比：原热点应退出 cumtime top5。

如何进 CI？——见 [14 测试与类型标注](../14-测试与类型标注/) pytest + 阈值。

## Q11

ncalls 爆炸怎么砍。

**★★★★☆｜cProfile 显示某函数 ncalls=2_000_000，cumtime 很高，优先怎么优化？**

> 🎯 **一句话**：**减调用次数：提到循环外、缓存结果、换数据结构，而不是微调函数内部一行**。

## Q14

读代码找可 profile 点。

**★★★★★｜读代码：这段审计脚本有什么问题？你怎么 profile？**

**覆盖**：核心 · 必会 · 读代码 | **对应**：知识点 [四、壮年：tracemalloc 找内存增长](知识点.md)、[七、收束：与 09/10/11 串联](知识点.md)

### 场景

```python
CACHE = {}
def audit(pods):
    results = []
    for p in pods:
        key = json.dumps(p.metadata.labels)
        if key not in CACHE:
            CACHE[key] = expensive_parse(p)
        results.append(CACHE[key])
    return results
```

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**无界 CACHE + 热循环 `json.dumps`——tracemalloc 看 CACHE 涨，cProfile 看 dumps/parse ncalls**。

排查顺序：
- `perf_counter` 看 `expensive_parse` vs `json.dumps`
- cProfile 看 `json.dumps` ncalls
- tracemalloc 对比多轮 audit 后 CACHE 增长
- 修法：TTL/LRU 限界；labels 用 tuple(sorted(...)) 作 key 避免重复序列化

> ⚠️ **别混**：CACHE 让第二次变快，但长期跑 RSS 线性涨——典型「越跑越慢/越涨」。

### 再追问

如何写回归测试？——14 章 fixture 固定 pods 列表，断言 peak 内存或耗时上限。
