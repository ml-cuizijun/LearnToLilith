## Q1

**★★★★★｜生产运维脚本为什么不用 `print` 而用 `logging`？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [能力边界](知识点.md)、[二、出生：Logger 与级别](知识点.md)

### 场景

ELK 里无法按 `ERROR` 过滤，因为全是 `print("ERROR: disk full")` 字符串。

### 完整解答

> 🎯 **一句话**：**`logging` 有级别、模块名、统一格式**，采集侧可过滤；`print` 无契约。

```python
log = logging.getLogger(__name__)
log.error("disk critical path=%s usage=%s", path, usage)
```

```bash
# 可按 level 调
LOG_LEVEL=WARNING python check.py
```

> 📝 **面试**：「print 适合本地调试；自动化环境要 logging。」

### 再追问

指标和日志分工？——指标聚合数值，日志讲事件与上下文。

## Q2

**★★★★★｜为什么推荐 `logging.getLogger(__name__)` 而不是 `getLogger("myapp")`？**

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生](知识点.md)

### 场景

想对 `lib.k8s` 开 DEBUG、对其它包保持 INFO。

### 完整解答

> 🎯 **一句话**：**`__name__` 对应模块层次**，可按包细调级别、传播到 root。

```python
# lib/k8s_checks.py
log = logging.getLogger(__name__)   # lib.k8s_checks
```

```python
logging.getLogger("lib.k8s_checks").setLevel(logging.DEBUG)
```

### 再追问

`propagate=False` 何时用？——子树独立输出、测试隔离。

## Q3

**★★★★☆｜Logger level 设 DEBUG、Handler level 设 INFO，debug 日志能看见吗？**

**覆盖**：必会 · 常考 | **对应**：知识点 [二、传播 propagate](知识点.md)

### 场景

开发开了 logger DEBUG，handler 仍只打 INFO，抱怨「debug 没了」。

### 完整解答

> 🎯 **一句话**：**两道闸都要过**——logger 放行后 handler 再滤。

```python
log.setLevel(logging.DEBUG)
handler.setLevel(logging.INFO)   # debug 到此被挡
```

修法：对齐两级，或只调 root/handler。

> ⚠️ **别混**：不是「设了 logger 就一定出」。

### 再追问

`basicConfig(level=INFO)` 管谁？——默认 root logger 和首个 StreamHandler。

## Q4

**★★★★★｜`log.exception("failed")` 和 `log.error("failed")` 区别？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、干活：消息怎么写](知识点.md)

### 场景

except 里只 `log.error`，oncall 看不到栈。

### 完整解答

> 🎯 **一句话**：**`exception` = ERROR + `exc_info=True`**，自动附 traceback。

```python
try:
    client.list_pods()
except ApiException:
    log.exception("kubernetes api failed cluster=%s", cluster)
```

等价：`log.error("...", exc_info=True)`。

### 再追问

在 except 外调 `log.exception`？——仍会打栈，但无当前异常上下文，不推荐。

## Q5

**★★★★★｜同一条日志打印两行，最常见原因？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [三、重复 handler 陷阱](知识点.md)

### 场景

每次 cron 跑完，INFO 成双。

### 完整解答

> 🎯 **一句话**：**Handler 被重复 `addHandler` 或多次 `basicConfig` 叠挂**。

```python
if not logging.getLogger().handlers:
    logging.basicConfig(...)
```

或统一 `dictConfig` + `disable_existing_loggers`。

```python
logging.getLogger().handlers   # 看有几个
```

### 再追问

测试里 caplog 与真实 handler 冲突？——`caplog` 或 `logging.disable`。

## Q6

**★★★★☆｜日志打 stdout 还是 stderr？管道场景怎么选？**

**覆盖**：必会 · 常用 | **对应**：知识点 [六、落盘](知识点.md)

### 场景

`python check.py | jq .` 把日志混进 JSON 管道。

### 完整解答

> 🎯 **一句话**：**日志走 stderr，stdout 留给机器可读结果**。

```python
logging.basicConfig(stream=sys.stderr, ...)
```

```bash
python check.py 2>run.log | jq .
```

### 再追问

容器里 kubectl logs 收哪？——通常进程 1 的 stdout+stderr 都收。

## Q7

**★★★☆☆｜为什么推荐 `log.debug("x=%s", x)` 而不是 `log.debug(f"x={expensive()}")`？**

**覆盖**：常用 · 常考 | **对应**：知识点 [四、懒格式化](知识点.md)

### 场景

生产 INFO 级别，`expensive()` 仍每次执行拖慢巡检。

### 完整解答

> 🎯 **一句话**：**懒格式化在级别不够时不求值 f-string 参数**。

```python
log.debug("pods=%s", len(list_all_pods()))  # DEBUG 关则不 list
```

### 再追问

f-string 何时可用？——确定会打的 ERROR 且无副作用时。

## Q8

**★★★★★｜Authorization header、kubeconfig、DB 密码能写进日志吗？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、密钥永不出现](知识点.md)

### 场景

`log.info("request headers %s", headers)` 把 Bearer token 打进 ELK。

### 完整解答

> 🎯 **一句话**：**绝不**；打码或只记 key 名。

```python
safe = {k: ("***" if k.lower() == "authorization" else v) for k, v in headers.items()}
log.debug("headers=%s", safe)
```

### 再追问

审计需要谁访问？——记 principal/id，不记 secret。

## Q9

**★★★☆☆｜何时用 `dictConfig` 代替 `basicConfig`？**

**覆盖**：常用 | **对应**：知识点 [五、dictConfig](知识点.md)

### 场景

既要 stderr 又要轮转文件，还要不同 formatter。

### 完整解答

> 🎯 **一句话**：**多 handler、多 formatter、团队统一配置时用 dictConfig**。

```python
import logging.config
logging.config.dictConfig(LOGGING)
```

小脚本单次 `basicConfig` 够用。

### 再追问

YAML 外挂配置？——加载后 `dictConfig(yaml.safe_load(...))`。

**覆盖**：核心 · 必会 | **对应**：知识点 [七、收束](知识点.md)、[04 异常与退出码](../04-异常与退出码/知识点.md)

### 场景

与 04 章假绿场景联动。

### 完整解答

> 🎯 **一句话**：**不能**——门禁看 `$?`，日志给人和检索。

```python
log.error("check failed")

```

## Q11

**★★★☆☆｜JSON 行日志对 Loki/ELK 有什么好处？**

**覆盖**：常用 | **对应**：知识点 [六、JSON 行](知识点.md)


## Q14

**★★★★★｜读代码找问题：**

```python
import logging
logging.basicConfig(level=logging.INFO)

def run():
    print("starting check")
    try:
        check()
    except Exception as e:
        logging.error(str(e))
    logging.basicConfig(level=logging.DEBUG)
    logging.getLogger().addHandler(logging.StreamHandler())

if __name__ == "__main__":
    run()
```

**覆盖**：核心 · 必会 | **对应**：知识点 [三、五、六](知识点.md)

### 场景

双份日志、无栈、print 混用。

### 完整解答

> 🎯 **一句话**：**print 应改 log；except 用 `exception`；`basicConfig`/`addHandler` 不应在 `run` 里重复**。

```python
log = logging.getLogger(__name__)

def setup_logging():
    if logging.getLogger().handlers:
        return
    logging.basicConfig(level=logging.INFO, stream=sys.stderr)

def run() -> int:
    setup_logging()
    log.info("starting check")
    try:
        check()
    except Exception:
        log.exception("check failed")
        return 1
    return 0
```

### 再追问

`main` 应 `raise SystemExit(run())`？——对，见 04 章。
