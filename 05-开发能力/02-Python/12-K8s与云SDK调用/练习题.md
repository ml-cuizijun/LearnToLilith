## Q1

**★★★★★｜CronJob 里 Python 脚本报 `Unauthorized` 或读不到集群，第一检查什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：加载配置](知识点.md)

### 场景

本地 `python check.py` 正常，装进 Pod 失败——脚本只用 `load_kube_config()`。

### 完整解答

> 🎯 **一句话**：**Pod 内用 `config.load_incluster_config()`**，挂载 SA token；本地才 kubeconfig。

```python
try:
    config.load_incluster_config()
except config.ConfigException:
    config.load_kube_config(context=os.environ.get("KUBE_CONTEXT"))
```

CronJob 要配 `serviceAccountName` 与 RoleBinding。

> 📝 **面试**：「Pod 里没有 ~/.kube/config。」

### 再追问

SA 没挂 token？——看 `automountServiceAccountToken` 与 projected volume。

## Q2

**★★★★★｜K8s Python 客户端 HTTP 错误抛什么异常？如何取状态码？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、读响应：ApiException](知识点.md)

### 场景

`except requests.HTTPError` 永远捕不到 K8s 404。

### 完整解答

> 🎯 **一句话**：**`kubernetes.client.exceptions.ApiException`**，**`.status`** 为 HTTP 码，`.body` 常为 JSON。

```python
from kubernetes.client.exceptions import ApiException

try:
    v1.read_namespaced_pod(name, ns)
except ApiException as e:
    log.error("status=%s reason=%s", e.status, e.reason)
    raise
```

> ⚠️ **别混**：不是 requests 异常。

### 再追问

`.reason` 与 body JSON 的 `reason`？——都可能有用，排障看 body 解析。

## Q3

**★★★★★｜ApiException status 403 与 503 分别应如何处理？能都用 09 式重试吗？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、读响应：ApiException](知识点.md)

### 场景

403 脚本 sleep 退避 5 分钟仍失败，浪费 CI。

### 完整解答

> 🎯 **一句话**：**403 = RBAC/Forbidden，修 RoleBinding，不重试**；**503 可有限退避重试**。

```bash
kubectl auth can-i get pods --namespace=app -as=system:serviceaccount:app:checker
```

403 与 401（token 无效）都要修身份/权限，不是等。

### 再追问

409 Conflict？——更新冲突，视业务 merge 或单次重读再 patch。

## Q4

**★★★★☆｜read Pod 返回 404，该重试还是改脚本？**

**覆盖**：必会 · 常考 | **对应**：知识点 [四、读响应：ApiException](知识点.md)

### 场景

刚 delete 后 read，或 namespace/name 拼错，脚本 retry 10 次。

### 完整解答

> 🎯 **一句话**：**404 = 资源不存在**，修 name/namespace/时机；**不是 apiserver 瞬态**。

```python
except ApiException as e:
    if e.status == 404:
        raise ResourceNotFound(name) from e
```

若等业务创建，用 **11 章 poll** 等出现，不是 404 上 HTTP 重试。

### 再追问

跨 namespace 查？——确认 `metadata.namespace` 与 RBAC scope。

## Q5

**★★★★★｜`list_pod_for_all_namespaces()` 无 limit 在大集群会怎样？怎么改？**

**覆盖**：核心 · 必会 | **对应**：知识点 [五、列表与分页](知识点.md)

### 场景

巡检脚本 8GB OOM，apiserver etcd 压力飙升。

### 完整解答

> 🎯 **一句话**：**一次拉全量易 OOM/压 API**；用 **`limit` + `_continue` 翻页**，加 `label_selector` 过滤。

```python
token = None
while True:
    resp = v1.list_namespaced_pod(namespace=ns, limit=200, _continue=token)
    for pod in resp.items:
        process(pod)
    token = resp.metadata._continue
    if not token:
        break
```

### 再追问

只要数量？——`list` + 计数也可，仍要分页。

## Q6

**★★★★☆｜脚本 `ApiException 403` on list pods，运维如何 60 秒内验证 RBAC？**

**覆盖**：必会 · 实操 | **对应**：知识点 [九、作战：Unauthorized、OOM、403 重试](知识点.md)

### 场景

新 CronJob 未绑 Role。

### 完整解答

> 🎯 **一句话**：**`kubectl auth can-i`** 用相同 SA 模拟。

```bash
kubectl auth can-i list pods -n app \
  --as=system:serviceaccount:app:my-sa
kubectl describe rolebinding -n app
```

代码侧 catch 403 打 `PermissionDenied`，`return 2`。

### 再追问

ClusterRole vs Role？——list 全 NS 要 ClusterRole + Binding。

## Q7

**★★★☆☆｜读 PrometheusRule CRD 应用哪个 API？参数有哪些？**

**覆盖**：常用 | **对应**：知识点 [三、发出：API 类与 namespace](知识点.md)

### 场景

用 CoreV1Api 读 CRD 必然 404。

### 完整解答

> 🎯 **一句话**：**`CustomObjectsApi.get_namespaced_custom_object`**，需 **group、version、plural**。

```python
crd = client.CustomObjectsApi()
crd.get_namespaced_custom_object(
    group="monitoring.coreos.com",
    version="v1",
    namespace="monitoring",
    plural="prometheusrules",
    name="example",
)
```

### 再追问

group/version 从哪来？——`kubectl api-resources` 或 CRD manifest。

## Q8

**★★★☆☆｜create 资源前如何 server-side dry-run？**

**覆盖**：常用 | **对应**：知识点 [三、发出：API 类与 namespace](知识点.md)

### 场景

误把 Pod create 到 prod namespace。

### 完整解答

> 🎯 **一句话**：**`dry_run="All"`**（K8s 1.18+ server dry-run）。

```python
v1.create_namespaced_pod(namespace=ns, body=pod, dry_run="All")
```

Client dry-run 不校验 admission/webhook 同样路径——server dry-run 更真。

### 再追问

kubectl 等价？——`kubectl apply --dry-run=server`。

## Q9

**★★★★☆｜watch Pod 与 11 章 poll read status，各何时用？**

**覆盖**：必会 | **对应**：知识点 [六、watch 与 poll](知识点.md)

### 场景

简单 CI 等 3 Pod Ready，同事强推 watch 增加复杂度。

### 完整解答

> 🎯 **一句话**：**短门禁 poll + read 够用**；**大量事件/减 QPS 用 watch**；watch 要处理 **410 Gone 重连 + deadline**。

```python
for event in watch.Watch().stream(v1.list_namespaced_pod, namespace=ns, timeout_seconds=600):
    ...
```

### 再追问

watch 超时？——`timeout_seconds` 与 11 budget 对齐，超时继续或 fail。

## Q10

**★★★☆☆｜boto3 调 EC2 与 K8s client 在「心态」上哪三点一致？**

**覆盖**：常用 | **对应**：知识点 [七、云 SDK：boto3 同一心态](知识点.md)

### 场景

复制 K8s 脚本改 AWS，未设 region，捕 `Exception` 吞掉 `UnauthorizedOperation`。

### 完整解答

> 🎯 **一句话**：**显式配置（region/IAM）**；**结构化异常（ClientError code）**；**分页（paginator）**。

```python
ec2 = boto3.client("ec2", region_name="ap-southeast-1")
except ClientError as e:
    code = e.response["Error"]["Code"]
```

Permission 类错误不重试。

### 再追问

STS assume role？——`boto3.Session` 链式 credential，仍要 region。

## Q11

**★★★☆☆｜CI 连错集群把 prod Deployment scale 了，脚本层如何防？**

**覆盖**：常用 | **对应**：知识点 [二、出生：加载配置](知识点.md)

### 场景

kubeconfig 默认 context 是 prod。

### 完整解答

> 🎯 **一句话**：**显式 `KUBE_CONTEXT` / `load_kube_config(context=...)`**，启动时校验 cluster name 或 server URL。

```python
ctx = os.environ["KUBE_CONTEXT"]  # 必填 staging
config.load_kube_config(context=ctx)
_, active = config.list_kube_config_contexts()
assert active["name"] == ctx
```

危险操作前 `kubectl config view --minify` 等价打印到日志（脱敏）。

### 再追问

in-cluster 单集群——靠 namespace 隔离 + RBAC 最小权限。

## Q12

**★★★★☆｜apiserver 429 + Python 脚本 OOM 同时出现——查什么？**

**覆盖**：实操 | **对应**：知识点 [五、九](知识点.md)

### 场景

发布日多个 list 全量脚本叠加。

### 完整解答

> 🎯 **一句话**：**list 是否分页**、**并发是否过高（10 章）**、**poll 是否 1s（11 章）**、**内层 HTTP retry 是否过多（09 章）**。

降 QPS、label_selector、合并脚本、用 watch 或 informer（进阶）。

### 再追问

apiserver request timeout？——client 侧 timeout 与 429 退避配合。

## Q14

**★★★★★｜读代码找 bug：**

```python
config.load_kube_config()
v1 = client.CoreV1Api()

def audit():
    pods = v1.list_pod_for_all_namespaces(watch=False)
    for p in pods.items:
        if p.status.phase != "Running":
            print("bad", p.metadata.name)

def main():
    try:
        audit()
    except Exception as e:
        log.info("ignored %s", e)
    return 0
```

**覆盖**：核心 · 必会 | **对应**：知识点 [二、四、五](知识点.md)、[04 退出码](../04-异常与退出码/)

### 场景

CronJob 在集群内 OOM；403 被吞仍绿。

### 完整解答

> 🎯 **一句话**：**应用 in-cluster**；**全量 list 无分页**；**捕 Exception 吞 403**；**失败仍 return 0**；Running 非 Ready。

```python
def load_k8s_config(): ...
def iter_all_pods(v1): ...  # 分页

def main() -> int:
    try:
        load_k8s_config()
        audit(client.CoreV1Api())
    except ApiException as e:
        log.error("k8s %s", e.status)
        return 1
    except Exception:
        log.exception("audit failed")
        return 1
    return 0
```

> 📝 **面试**：「四 bug：config、分页、吞异常、exit 0。」

### 再追问

改用 11 poll Ready？——audit 与 wait 分工不同，audit 应用 Ready condition。
