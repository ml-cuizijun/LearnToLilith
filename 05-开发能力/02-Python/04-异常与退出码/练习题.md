## Q1

**★★★★★｜运维 Python 脚本「失败」对 cron/Jenkins 的契约是什么？只打 ERROR 日志够不够？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、交卷：退出码与 sys.exit](知识点.md)

### 场景

巡检脚本日志里满屏 `ERROR disk 90%`，Jenkins 构建仍是绿色，oncall 没收到失败通知。

### 完整解答

> 🎯 **一句话**：**失败必须非 0 退出码**；日志给人看，**门禁认 `$?`**。

```python
def main() -> int:
    if disk_usage() > 90:
        print("disk critical", file=sys.stderr)
        return 1
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

```bash
python check_disk.py
echo $?   # 1 才应触发 CI 失败
```

> 📝 **面试**：「调度器/automation 默认只看退出码，不解析日志级别。」

### 再追问

Kubernetes Job `restartPolicy: Never` 如何判断失败？——容器进程非 0 退出。

## Q2

**★★★★★｜为什么推荐 `raise SystemExit(main())` 而不是 `main()` 后直接结束？**

**覆盖**：核心 · 必会 | **对应**：知识点 [五、交卷](知识点.md)

### 场景

`main()` 返回 `1`，但进程退出码仍是 0，CI 不红。

### 完整解答

> 🎯 **一句话**：**`return 1` 只在 `main` 函数内有效**；必须把 int 转成进程退出状态。

```python
def main() -> int:
    return 1

if __name__ == "__main__":
    raise SystemExit(main())   # 进程 exit 1

# 错误
if __name__ == "__main__":
    main()   # 返回 1 被丢弃，进程 exit 0
```

`sys.exit(main())` 等价（`sys.exit(None)` 才是 0）。

### 再追问

测试里如何测退出码？——`pytest` 用 `pytest.raises(SystemExit)` 或直接 `assert main(...) == 1` 不测进程。

## Q3

**★★★★★｜这段代码为什么导致 CI 假绿？怎么改？**

```python
def main():
    try:
        run_all_checks()
    except Exception:
        pass
    return 0
```

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [六、反模式：吞异常与假绿](知识点.md)

### 场景

`run_all_checks` 里 API 抛错，脚本静默成功。

### 完整解答

> 🎯 **一句话**：**`except: pass` 吞掉所有异常**，仍 `return 0`。

```python
import logging
log = logging.getLogger(__name__)

def main() -> int:
    try:
        run_all_checks()
    except Exception:
        log.exception("checks failed")
        return 1
    return 0
```

或让 `run_all_checks` 抛 `CheckFailed`，在 main 边界映射退出码。

> ⚠️ **别混**：宽捕可以，**不能空 pass**。

### 再追问

循环里单台失败 `continue` 可以吗？——可以，但循环结束要 `return 1 if any_failed`。

## Q4

**★★★★☆｜`try/except/else/finally` 各在什么情况下执行？`else` 是「否则」吗？**

**覆盖**：必会 · 常考 | **对应**：知识点 [三、捕获：try / except / else / finally](知识点.md)

### 场景

面试白板写 `try: open; read; parse` 结构，有人把 `parse` 放进 `except`。

### 完整解答

> 🎯 **一句话**：**else = try 块无异常时**；**finally = 无论如何都执行**。

```python
try:
    fh = open(path)
    data = fh.read()
except OSError:
    return 1
else:
    parse(data)       # 仅 read 成功
finally:
    if 'fh' in dir() and fh:
        fh.close()
```

更简：`with open(path) as fh: data = fh.read(); parse(data)`。

> ⚠️ **别混**：`else` 不是 `if` 的 else。

### 再追问

`finally` 里 `return 0` 会怎样？——会覆盖 try/except 的 return（避免在 finally return）。

## Q5

**★★★★☆｜`raise CheckFailed("api down") from e` 比 `raise CheckFailed("api down")` 好在哪里？**

**覆盖**：必会 · 常用 | **对应**：知识点 [四、传播：raise 与异常链](知识点.md)

### 场景

oncall 只看到 `CheckFailed: api down`，看不到底层 `Connection refused`。

### 完整解答

> 🎯 **一句话**：**`from e` 保留 `__cause__` 链**，`log.exception` / traceback 显示嵌套原因。

```python
try:
    client.list_pods()
except ApiException as e:
    raise CheckFailed("kubernetes api unavailable") from e
```

`raise ... from None` 可显式隐藏原因（慎用）。

### 再追问

`log.exception` 和 `log.error` 区别？——前者自动带 `exc_info` 栈。

## Q6

**★★★★★｜100 台主机检查，3 台失败，脚本应 exit 几？代码结构怎么写？**

**覆盖**：核心 · 必会 | **对应**：知识点 [六、反模式](知识点.md)、[生产模板 2](知识点.md)

### 场景

当前实现第一台失败就 `sys.exit(1)`，后面 97 台没扫，报告不全。

### 完整解答

> 🎯 **一句话**：**应 exit 1**；循环内捕获单台失败，**汇总后统一 return 1**。

```python
def main() -> int:
    failures: list[str] = []
    for host in hosts:
        try:
            check(host)
        except CheckFailed as e:
            failures.append(f"{host}: {e}")
    if failures:
        for line in failures:
            print(line, file=sys.stderr)
        return 1
    return 0
```

### 再追问

既要「任一台失败即非 0」又要「扫完全部」？——上面模式；不要第一台 `exit` 除非时间紧急。

## Q7

**★★★☆☆｜退出码 0、1、2 你如何约定？举例。**

**覆盖**：常用 | **对应**：知识点 [五、交卷](知识点.md)

### 场景

README 写「失败返回 1」，但用法错误也返回 1，自动化无法区分重试还是修参数。

### 完整解答

> 🎯 **一句话**：**0 成功；1 运行时/检查失败；2 用法或配置错误**（团队写入 README）。

```python
def main() -> int:
    try:
        args = parse_args()
    except UsageError:
        return 2
    if not run_checks():
        return 1
    return 0
```

Shell 里 `$?` 对 256 取模，别用 300 表达细粒度语义。

### 再追问

与 `sysexits.h` 的 EX_USAGE 类比？——同一思想，Python 无强制标准，靠文档约定。

## Q8

**★★★★☆｜未捕获的 `ZeroDivisionError` 进程退出码一般多少？能依赖它代替 `return 1` 吗？**

**覆盖**：必会 · 常考 | **对应**：知识点 [五、交卷](知识点.md)

### 场景

开发说「抛异常就行不用写 exit」，生产 cron 邮件刷整页 traceback。

### 完整解答

> 🎯 **一句话**：一般 **1**；**不能依赖**——应顶层处理，给简短 stderr + 明确码。

```bash
python -c "1/0"; echo $?
# Traceback ... 
# 1
```

生产：`main` 边界 `except Exception: log.exception; return 1` 或让关键路径显式 `raise CheckFailed`。

### 再追问

`KeyboardInterrupt` 退出码？——约 130（128+SIGINT），不要捕后继续跑。

## Q9

**★★★☆☆｜什么时候定义 `CheckFailed`、`ConfigError` 这类自定义异常？**

**覆盖**：常用 | **对应**：知识点 [四、自定义异常](知识点.md)

### 场景

全用 `RuntimeError("...")` 字符串，main 无法区分配置错还是检查失败。

### 完整解答

> 🎯 **一句话**：**在 main 边界要映射不同退出码或处理策略时**定义语义化异常。

```python
class ConfigError(Exception):
    pass

class CheckFailed(Exception):
    pass

def main() -> int:
    try:
        ...
    except ConfigError as e:
        print(e, file=sys.stderr)
        return 2
    except CheckFailed as e:
        print(e, file=sys.stderr)
        return 1
```

库代码 `raise CheckFailed`，不要 `sys.exit`。

### 再追问

继承 `Exception` 还是 `ValueError`？——业务失败用独立类更清晰。

## Q10

**★★★★☆｜为什么库函数里避免 `sys.exit(1)`？**

**覆盖**：必会 | **对应**：知识点 [五、return vs sys.exit](知识点.md)

### 场景

`lib/k8s_client.py` 里连接失败直接 `sys.exit`，被 Flask 接口 import 时整个 worker 进程退出。

### 完整解答

> 🎯 **一句话**：**库应 raise**，由调用方（或 `main`）决定退出还是重试。

```python
# lib
def list_pods():
    if not config:
        raise ConfigError("missing kubeconfig")

# script main
def main() -> int:
    try:
        list_pods()
    except ConfigError as e:
        print(e, file=sys.stderr)
        return 2
```

### 再追问

CLI 工具 `click`/`typer` 如何处理退出码？——内部转 `SystemExit`，仍遵循同一契约。

## Q11

**★★★☆☆｜`except OSError` 写在 `except FileNotFoundError` 前面会怎样？**

**覆盖**：常考 | **对应**：知识点 [三、多 except 与顺序](知识点.md)

### 场景

想分别处理文件不存在和其它 OS 错误，顺序写反。

### 完整解答

> 🎯 **一句话**：**子类必须先于父类**，否则 `FileNotFoundError` 永远进 `OSError` 分支。

```python
try:
    open(path)
except FileNotFoundError:
    return 2
except OSError:
    return 1
```

### 再追问

多个 except 会都执行吗？——不会，匹配第一个即停。

## Q14

**★★★★★｜读代码找 bug：**

```python
def main():
    errors = 0
    for cluster in clusters:
        try:
            check(cluster)
        except Exception:
            errors += 1
    if errors:
        print(f"{errors} clusters failed")
    return 0
```

**覆盖**：核心 · 必会 | **对应**：知识点 [六、反模式](知识点.md)、[Q6](练习题.md)

### 场景

三个集群失败，打印了 `3 clusters failed`，流水线仍成功。

### 完整解答

> 🎯 **一句话**：**统计了 errors 仍 `return 0`**；应 `return 1`，并 `file=sys.stderr`。

```python
def main() -> int:
    errors = 0
    for cluster in clusters:
        try:
            check(cluster)
        except Exception:
            log.exception("cluster %s", cluster)
            errors += 1
    if errors:
        print(f"{errors} clusters failed", file=sys.stderr)
        return 1
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

> 📝 **面试**：「有失败计数必须映射到退出码。」

### 再追问

`except Exception` 不 log 栈可以吗？——至少 `log.exception` 一次，否则排障盲。
