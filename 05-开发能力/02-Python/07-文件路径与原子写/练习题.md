## Q1

**★★★★★｜更新 `status.json` 为什么不能直接 `open(path, "w")`？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、核心：原子写（🔥难点 · ⭐常考）](知识点.md)

### 场景

进程写到一半被 kill，下游 `json.load` 报 `JSONDecodeError`。

### 完整解答

> 🎯 **一句话**：**`w` 立刻截断目标**，崩溃后读者见空文件或半截。

```python
# 反模式
with open(path, "w") as f:
    f.write(partial_json)

# 正例：tmp + os.replace
atomic_write_text(path, full_json)
```

### 再追问

读者何时见新版本？——`replace` 一瞬间原子切换。

## Q2

**★★★★★｜原子写的标准三步是什么？`os.replace` 和 `shutil.move` 何时不同？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、核心：原子写（🔥难点 · ⭐常考）](知识点.md)

### 场景

面试白板写原子写流程。

### 完整解答

> 🎯 **一句话**：**写 tmp → flush/fsync → `os.replace(tmp, target)`**；同 FS 上 `replace` 原子，`move` 跨设备可能 copy+unlink。

```python
with tmp.open("w", encoding="utf-8") as f:
    f.write(content)
    f.flush()
    os.fsync(f.fileno())
os.replace(tmp, path)
```

### 再追问

Windows 上 `replace`？——3.3+ 亦支持覆盖替换。

**★★★★☆｜临时文件为什么必须和目标同一目录？**

tmp 在 `/tmp`，目标在 `/var/lib`，`replace` 变慢且语义变 copy。

## Q6

**★★★☆☆｜`flush` 之后为什么还要 `os.fsync`？**

**覆盖**：常用 · 常考 | **对应**：知识点 [四、核心：原子写（🔥难点 · ⭐常考）](知识点.md)

### 场景

机器掉电后 tmp 有内容但 replace 前丢数据。

### 完整解答

> 🎯 **一句话**：**`flush` 到内核缓冲，`fsync` 尽力落盘**，再 `replace` 更稳。

```python
f.flush()
os.fsync(f.fileno())
```

对状态文件值得做；超高频写可权衡性能。

### 再追问

`os.replace` 后还要 fsync 目录？——极端一致性问题才 `fsync` 父目录。

## Q7

**★★★★★｜两个 cron 同时 atomic_write 同一文件，会损坏吗？会丢更新吗？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、核心：原子写（🔥难点 · ⭐常考）](知识点.md)

### 场景

以为原子写等于事务 merge。

### 完整解答

> 🎯 **一句话**：**不会半截**；**最后 replace 者赢，可能丢中间更新**。

要读-改-写一致：文件锁、单写者、或外部存储。

> ⚠️ **别混**：原子写防崩溃，不防并发逻辑合并。

### 再追问

`fcntl.flock` 典型用法？——写前 `LOCK_EX`，写完释放。

## Q9

**★★★★☆｜用户传入 `../../etc/passwd` 如何防路径逃逸？**

**覆盖**：必会 · 常考 | **对应**：知识点 [二、出生：pathlib 路径（⭐常考）](知识点.md)

### 场景

脚本接受 `--file` 相对路径，读取任意系统文件。

### 完整解答

> 🎯 **一句话**：**`resolve` 后确认仍在 `base` 目录下**。

```python
def safe_under(base: Path, user_path: Path) -> Path:
    base = base.resolve()
    target = (base / user_path).resolve()
    if not str(target).startswith(str(base)):
        raise ValueError("path escape")
    return target
```

### 再追问

符号链接？——`resolve` 会跟随，敏感场景要 `is_relative_to`（3.9+）更严。

## Q10

**★★★☆☆｜`tempfile.mkstemp` 与 `NamedTemporaryFile(delete=False)` 在原子写里怎么用？**

**覆盖**：常用 | **对应**：知识点 [五、临时文件：tempfile（🔧实操）](知识点.md)

### 场景

不想手写 `.tmp` 后缀名冲突。

### 完整解答

> 🎯 **一句话**：**在 `path.parent` 建 tmp，`delete=False`，写完 `replace` 后 tmp 名消失**。

```python
fd, name = tempfile.mkstemp(dir=path.parent, prefix=".tmp_")
os.close(fd)
tmp = Path(name)
# write, fsync, os.replace(tmp, path)
```

异常时 `tmp.unlink(missing_ok=True)`。

### 再追问

`with NamedTemporaryFile(delete=False)` 等价思路。

## Q14

**★★★★★｜读代码找 bug：**

```python
def save(path, data):
    tmp = "/tmp/out.tmp"
    with open(path, "w") as f:
        json.dump(data, f)
    os.rename(tmp, path)
```

**覆盖**：核心 · 必会 | **对应**：知识点 [四、核心：原子写 · 五、tempfile](知识点.md)

### 场景

多重错误：截断、tmp 未用、跨目录 rename、无 encoding。

### 完整解答

> 🎯 **一句话**：**先 w 截断 path；tmp 从未写入；rename 跨目录**。

```python
def save(path: Path, data: dict) -> None:
    tmp = path.with_suffix(".json.tmp")
    content = json.dumps(data) + "\n"
    with tmp.open("w", encoding="utf-8") as f:
        f.write(content)
        f.flush()
        os.fsync(f.fileno())
    os.replace(tmp, path)
```

### 再追问

改用 `path.write_text`？——仍非原子，状态文件不要。
