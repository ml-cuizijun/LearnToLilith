## Q1

**★★★★★｜CPython 的 GIL 是什么？为什么多线程不能加速纯 Python CPU 循环？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：GIL 是什么（⭐常考）](知识点.md)

### 场景

面试：「加 32 线程做日志正则匹配，为什么比单线程还慢？」

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**GIL 使同一进程仅一个线程执行 Python 字节码**；纯 CPU 循环不释 GIL，多线程只增加切换开销。

I/O 阻塞（网络、sleep、部分 C 扩展）会释放 GIL，其它线程可运行。

> 📝 **面试**：「GIL 是 CPython 实现细节，Jython 无 GIL，但运维主流 CPython。」

### 再追问

numpy 矩阵运算一定并行？——取决于 op 是否在 C 层释 GIL，不能假设。

## Q2

**★★★★★｜批量 HTTP 健康检查 vs 纯 Python 哈希 500 万行，分别用什么并发模型？**

**覆盖**：核心 · 必会 | **对应**：知识点 [三、选型：I/O bound vs CPU bound（🔥难点）](知识点.md)

### 场景

团队把两种任务都写成 `ThreadPoolExecutor(64)`——这是 Q1 结论的加深版。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**HTTP = I/O bound → ThreadPool（8–32）+ 09 Session/timeout**；**哈希/解析 = CPU bound → ProcessPool 或 rg/awk**。

```python
# I/O
with ThreadPoolExecutor(max_workers=16) as ex:
    ex.map(check_url, urls)

# CPU
with ProcessPoolExecutor(max_workers=os.cpu_count()) as ex:
    ex.map(hash_chunk, chunks)
```

### 再追问

为何不用 asyncio 做 HTTP？——可以 httpx async；同步 requests 用线程更省事。

## Q3

**★★★★★｜500 台主机 SSH/HTTP 巡检，线程数怎么估？过大有什么后果？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、执行：ThreadPoolExecutor 模式（⭐常考）](知识点.md)

### 场景

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**从 8–32 起调**，受目标 QPS、文件描述符、09 退避约束；过大打挂对端。

```python

def work(n):
```

## Q6

**★★★★☆｜`executor.map` 与 `submit` + `as_completed` 怎么选？**

**覆盖**：必会 | **对应**：知识点 [四、执行：ThreadPoolExecutor 模式（⭐常考）](知识点.md)

### 场景

500 任务中第 1 个 hang 住，`map` 看起来「卡住」。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**`map` 简单、顺序返回、异常晚**；**`as_completed` 流式、可先处理已完成、易加 per-future timeout**。

```python
for fut in as_completed(futs):
    host, err = fut.result(timeout=120)
```

巡检汇总失败用 `as_completed`。

### 再追问

`map` 会保序吗？——结果顺序与输入一致，完成顺序不一定。

## Q7

**★★★★★｜多线程共用一个 `requests.Session()` 可能出什么问题？怎么改？**

**覆盖**：核心 · 必会 | **对应**：知识点 [四、执行：ThreadPoolExecutor 模式（⭐常考）](知识点.md)

### 场景

高并发间歇 `SSL: WRONG_VERSION_NUMBER` 或连接错乱。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**Session 非完全线程安全**；用 **threading.local()** 每线程一个 Session。

```python
_thread_local = threading.local()

def get_session():
    if not hasattr(_thread_local, "session"):
        _thread_local.session = requests.Session()
    return _thread_local.session
```

或降并发 + 单线程 Session（失去并发意义）。

### 再追问

urllib3 连接池与线程？——同 pool 并发连接需正确配置 pool_maxsize。

## Q8

**★★★★☆｜worker 里抛了异常，主线程不调用 `fut.result()` 会怎样？**

**覆盖**：必会 · 常考 | **对应**：知识点 [八、收束：异常在 Future 里](知识点.md)

### 场景

线程池跑完 `return 0`，其实 20 台 check 失败。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**异常存在 Future 里，必须 `result()` 才会 re-raise**；否则假绿。

```python
for fut in as_completed(futs):
    try:
        fut.result()
    except Exception as e:
        failures.append(str(e))
```

### 再追问

`future.exception()`？——可 inspect 不抛，汇总时常用 `result()`。

## Q9

**★★★☆☆｜`Semaphore(8)` 在并发脚本里解决什么？**

**覆盖**：常用 | **对应**：知识点 [七、线程安全与限流（必会）](知识点.md)

### 场景

ThreadPool 32 路同时打同一 API，无限流。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**限制同时 in-flight 的请求数**，保护对端与本地 fd。

```python
sem = Semaphore(8)

def bounded_check(url):
    with sem:
        return get_session().get(url, timeout=TIMEOUT)
```

可与 ThreadPool workers > 8 配合：任务多但同时在飞 ≤8。

### 再追问

与 09 Retry 关系？——限流减少 429，429 仍要退避。

## Q10

**★★★☆☆｜运维脚本何时值得上 asyncio？最小代码长什么样？**

**覆盖**：常用 | **对应**：知识点 [六、asyncio 最小集（常用）](知识点.md)

### 场景

已有 200 行 requests 同步代码，同事建议全改 async。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**新写高并发 I/O 或已有 async 栈时**；存量同步用 ThreadPool 成本更低。

```python
async def run():
    async with httpx.AsyncClient() as client:
        await asyncio.gather(*[fetch(client, u) for u in urls])

asyncio.run(run())
```

阻塞库（同步 requests）不能直接 `await`，会卡死 loop。

### 再追问

`gather(return_exceptions=True)`？——单任务失败不拖垮全部，便于汇总。

## Q14

**★★★★★｜读代码找 bug：**

```python
session = requests.Session()
failures = []

def check(url):
    r = session.get(url, timeout=5)
    r.raise_for_status()

with ThreadPoolExecutor(32) as ex:
    futs = [ex.submit(check, u) for u in urls]
print("done")

def main():
    run_checks()
    return 0
```

**覆盖**：核心 · 必会 | **对应**：知识点 [四、执行：ThreadPoolExecutor 模式（⭐常考）]、[七、线程安全与限流（必会）]、[八、收束：异常在 Future 里](知识点.md)

### 场景

随机失败、有时假绿。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**共享 Session 32 线程**；**未 wait/result Futures**；**异常未捕获**；**failures 未用仍 return 0**。

```python
def main() -> int:
    failures = run_checks()  # as_completed + result + thread-local session
    return 1 if failures else 0
```

> 📝 **面试**：「并发三件套：线程安全、result、退出码。」

### 再追问

用 `with ex:` 退出时会 wait 吗？——会等 submitted 任务完，但仍需 result 取异常。
