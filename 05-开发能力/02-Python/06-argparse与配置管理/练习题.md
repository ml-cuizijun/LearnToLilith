## Q1

**★★★★★｜配置来源 default、file、env、CLI 的覆盖优先级？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [一、一张图：配置从 CLI/env/file 合并的一生](知识点.md)

### 场景

README 没写优先级，staging 文件里 `cluster: a`，env `CLUSTER=b`，命令 `--cluster c`，最终连哪？

### 完整解答

> 🎯 **一句话**：**CLI > env > file > default**——答案是 **c**。

```python
p.add_argument("--cluster", default=os.environ.get("CLUSTER") or file_cfg.get("cluster", "staging"))
# CLI 解析后覆盖 default
```

团队写入 README 防扯皮。

### 再追问

为何 CLI 最高？——显式意图，适合临时覆盖与 CI 参数化。

## Q2

**★★★★★｜如何不写 `mock sys.argv` 就测 CLI？**

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生：argparse 基础（⭐常考）](知识点.md)

### 场景

单元测试要测缺 `--cluster` 报错。

### 完整解答

> 🎯 **一句话**：**`parse_args(['--cluster','x'])` 传入 list**。

```python
def test_cluster():
    args = parse_args(["-c", "staging"])
    assert args.cluster == "staging"

def test_missing():
    with pytest.raises(SystemExit) as exc:
        parse_args([])
    assert exc.value.code == 2
```

### 再追问

`main(argv)` 传参模式？——`raise SystemExit(main(["-c","x"]))`。

## Q3

**★★★★☆｜`--dry-run` 应该用 `action='store_true'` 还是 `type=bool`？**

**覆盖**：必会 · 常考 | **对应**：知识点 [二、出生：argparse 基础（⭐常考）](知识点.md)

### 场景

`--dry-run False` 字符串被 `bool()` 当成 True。

### 完整解答

> 🎯 **一句话**：**布尔开关用 `store_true`/`store_false`**，别 `type=bool`。

```python
p.add_argument("--dry-run", action="store_true")
# 出现即 True，不出现 False
```

### 再追问

默认 dry-run=True 防误操作？——`action="store_false", dest="dry_run"` + `--execute` 或 `--no-dry-run`（显式命名）。

## Q4

**★★★★★｜API token 应放在 argparse default、yaml 还是环境变量？**

**覆盖**：核心 · 必会 | **对应**：知识点 [三、上路：环境变量层（⭐常考）](知识点.md)

### 场景

`config.yaml` 和 `--token` 都提交进了 Git。

### 完整解答

> 🎯 **一句话**：**仅环境变量或 Secret 挂载**；不进 repo、不进 CLI 历史。

```python
def require_token() -> str:
    t = os.environ.get("API_TOKEN")
    if not t:
        raise ConfigError("API_TOKEN not set")
    return t
```

## Q5

**★★★★☆｜先读 `--config` 路径再 merge 文件默认，为什么要 `parse_known_args`？**

**覆盖**：必会 · 常用 | **对应**：知识点 [四、进门：配置文件 YAML/TOML（🔥难点）](知识点.md)

### 场景

完整 parser 还不知道 config 文件在哪，无法填 default。

### 完整解答

> 🎯 **一句话**：**两阶段解析**——先抠 `--config`，再带 file default 建主 parser。

```python
pre = argparse.ArgumentParser(add_help=False)
pre.add_argument("--config", type=Path, default=Path("config.yaml"))
pre_args, rest = pre.parse_known_args(argv)
file_cfg = load_yaml(pre_args.config)
args = build_parser(file_cfg).parse_args(rest)
```

### 再追问

`safe_load` 为何？——防 YAML 任意对象执行。

## Q6

**★★★★☆｜解析完 Namespace 后为何转 `Config` dataclass？**

**覆盖**：必会 · 常用 | **对应**：知识点 [五、干活：dataclass 与校验（⭐常考）](知识点.md)

### 场景

业务到处 `args.cluster`，有人拼写 `args.cluser`。

### 完整解答

> 🎯 **一句话**：**类型化、不可变、校验集中**；业务不碰 `sys.argv`。

```python
@dataclass(frozen=True)
class Config:
    cluster: str
    dry_run: bool
```

## Q7

**★★★☆☆｜argparse 用法错误进程退出码一般多少？与运行时失败如何区分？**

**覆盖**：常用 · 常考 | **对应**：知识点 [五、干活：dataclass 与校验（⭐常考）](知识点.md)、[04 章](../04-异常与退出码/知识点.md)

### 场景

自动化想对用法错误不重试，对检查失败可重试。

### 完整解答

> 🎯 **一句话**：**argparse 错误 exit 2**；检查失败 `return 1`；成功 0。

```python
except ConfigError:
    return 2
except CheckFailed:
    return 1
```

`parser.error("msg")` 亦 exit 2。

## Q8

**★★★★☆｜`opsctl check` 和 `opsctl deploy` 怎么组织？**

**覆盖**：必会 · 常用 | **对应**：知识点 [六、分支：subparsers 子命令（🔥难点）](知识点.md)

### 场景

一个脚本两个子命令，参数不同。

### 完整解答

> 🎯 **一句话**：**`add_subparsers(dest="command", required=True)`** 各挂子 parser。

```python
sub = p.add_subparsers(dest="command", required=True)
check = sub.add_parser("check")
check.add_argument("--cluster", required=True)
```

```bash
python opsctl.py check --cluster staging
```

### 再追问

未指定子命令？——`required=True` 直接报错。

## Q9

**★★★☆☆｜`choices` 和 `type=int` 各解决什么？**

**覆盖**：常考 | **对应**：知识点 [二、出生：argparse 基础（⭐常考）](知识点.md)

### 场景

`--port abc` 和 `--env prodction`  typo。

### 完整解答

> 🎯 **一句话**：**`type` 做转换校验；`choices` 限制枚举**。

```python
p.add_argument("--port", type=int, default=443)
p.add_argument("--env", choices=["staging", "prod"])
```

非法值 argparse 打印 error 并 exit 2。

### 再追问

自定义 type 函数？——可，返回转换后值或抛 `ArgumentTypeError`。

事故后怀疑 Jenkins 参数或 env 注入错。

### 完整解答

## Q12

**★★★★☆｜互斥 `--staging` / `--prod` 怎么写？**

**覆盖**：实操 | **对应**：知识点 [生产模板 3](知识点.md)

### 场景

不能同时指定两个环境 flag。

### 完整解答

> 🎯 **一句话**：**`add_mutually_exclusive_group(required=True)`**。

```python
g = p.add_mutually_exclusive_group(required=True)

g.add_argument("--prod", action="store_true")
```

## Q14

**★★★★★｜读代码找 bug：**

```python
def main():
    p = argparse.ArgumentParser()
    p.add_argument("--cluster", default="prod")
    p.add_argument("--token", default="sk-live-xxx")
    args = p.parse_args()
    run(args.cluster, args.token)
```

**覆盖**：核心 · 必会 | **对应**：知识点 [三、上路：环境变量层（⭐常考）]、[四、进门：配置文件 YAML/TOML（🔥难点）]、[五、干活：dataclass 与校验（⭐常考）](知识点.md)

### 场景

仓库泄露 token；本地忘参数就连 prod。

### 完整解答

> 🎯 **一句话**：**token 不应在代码/default；prod 不应硬默认**；应 env + `Config` + 缺参报错。

```python
p.add_argument("--cluster", default=os.environ.get("CLUSTER"))
# 无 token 参数
token = require_token()
cfg = Config(cluster=args.cluster, ...)  # frozen
if not cfg.cluster:
    p.error("--cluster or CLUSTER required")
```

默认 `staging` 或强制显式 `--cluster`。

### 再追问

`return 2` 与 `parser.error`？——配置/用法错用 2。
