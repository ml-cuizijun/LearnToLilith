# 08｜subprocess 执行外部命令 · SRE 开发能力

> 大家好，欢迎来到这次分享。开讲之前，先带大家回到一个很多值班同学都踩过的现场：
> 巡检脚本 `os.system("kubectl get pods")` 把 shell 注入面全打开；有人 `subprocess.run(..., shell=True)` 拼用户输入导致 RCE；`Popen` 只读 stdout 不读 stderr，子进程写满管道死锁挂死——群里已经有人在喊「脚本卡死杀进程」。
> 这一章讲完，你会知道当时那几个人各自错在哪——运维脚本调外部命令的契约是：列表形式传参、显式超时、检查退出码、分清 stdout/stderr。
> **本章回答的问题**：一次外部命令从 `subprocess.run` 派生、经管道 I/O 到 `returncode` 交给 Python 的一生。
> **本章不讲**：Shell 管道与 `PIPESTATUS` → [01-Shell 06 管道](../../01-Shell/06-管道重定向与PIPESTATUS/)；Python 退出码 → [04 异常与退出码](../04-异常与退出码/)；原子写结果文件 → [07 文件路径与原子写](../07-文件路径与原子写/)。

**怎么听这场分享**：先把「外部命令一生」主图装进脑子——run → 管道 I/O → returncode；放慢 PIPE 死锁与 shell 注入；作战节回到开头那个挂死/注入现场。每一节讲完会提示对应练习题，趁热打铁。


## 面试怎么考

| 标记 | 考点 |
|------|------|
| **核心** | `subprocess.run([...])`；**不用 shell=True 拼用户输入**；`check=True`；`timeout` |
| **必会** | `capture_output=True, text=True`；读 `returncode`；`CalledProcessError` |
| **常用** | `stdin=subprocess.DEVNULL`；环境 `env=`；`cwd=`；流式 `Popen` |
| **常考** | 列表 vs 字符串；PIPE 死锁；退出码与 04 章映射 |

**30 秒怎么说**：调命令用 **`subprocess.run(["kubectl","get","pods","-n",ns], ...)`**——argv 列表，**默认 `shell=False`**。设 **`timeout`** 防挂死；要失败即异常用 **`check=True`**，或看 `returncode` 映射 `main` 的 `return 1`。捕获输出 `capture_output=True, text=True`（或分别 `stdout=PIPE`）。大量输出用 `Popen` 流式读，避免 PIPE 塞满死锁。别把用户输入塞进 shell 字符串。子进程非 0 要向上汇报，别假绿。

## 能力边界

| 维度 | subprocess 列表 | shell=True 字符串 | 纯 Python 库 |
|------|-------------------|-------------------|--------------|
| **适合** | kubectl/curl/tar 等 CLI | 内置复杂 shell 特性 | 有官方 SDK 时 |
| **不适合** | 无必要时的 shell | 含用户输入 | 强行 exec 代替 SDK |
| **契约** | 退出码+输出可控 | 注入风险高 | 首选 |

| API | 场景 |
|-----|------|
| `run` | 大多数一次性命令 |
| `check_output` | 只要 stdout 且要检查码 |
| `Popen` | 长输出流、双向交互 |
| `os.system` | **遗留，别用** |

> ⚠️ **别混**：**Python 进程的退出码由你的 `main` 决定**——子命令失败要显式转成 `return 1`（04 章）。

## 语言最小集

| 零件 | 示例 | 含义 |
|------|------|------|
| run | `subprocess.run(["ls","-l"], ...)` | 等待结束 |
| check | `check=True` | 非 0 抛异常 |
| capture_output | `capture_output=True` | 收 stdout/stderr |
| text | `text=True` | str 而非 bytes |
| timeout | `timeout=30` | 秒，超时 `TimeoutExpired` |
| returncode | `r.returncode` | 退出码 |
| stdout | `r.stdout` | 标准输出 |
| DEVNULL | `stdin=subprocess.DEVNULL` | 关闭 stdin |
| env | `env={**os.environ, "K": "v"}` | 环境 |
| cwd | `cwd="/tmp"` | 工作目录 |

```python
import subprocess

def kubectl_get(ns: str) -> str:
    r = subprocess.run(
        ["kubectl", "get", "pods", "-n", ns, "-o", "wide"],
        capture_output=True,
        text=True,
        timeout=60,
        check=True,
    )
    return r.stdout
```

## 一、一张图：一次外部命令从 spawn 到 exitcode 的一生

> 🎯 **一句话**：**run/Popen → fork+exec → 子进程执行 → 管道 I/O → wait → returncode 回 Python**。

```mermaid
flowchart LR
    A[subprocess.run argv] --> B[fork exec]
    B --> C[子进程 CLI]
    C --> D[stdout stderr 管道]
    D --> E[父进程 wait]
    E --> F{returncode}
    F -->|check=True 非0| G[CalledProcessError]
    F -->|映射| H[main return 1]
```

**读图**：脚本「成功」但集群实际失败，查 **F** 是否被忽略，或 **G** 被 `except` 吞掉（04 章）。挂死常在 **D** 管道未读满。

## 二、出生：subprocess.run 基础（⭐常考）

> 🎯 **一句话**：**argv 列表 + `shell=False`（默认）** 是最安全的默认姿势。

```python
import subprocess

result = subprocess.run(
    ["df", "-h", "/"],
    capture_output=True,
    text=True,
    timeout=10,
)
print(result.returncode)   # 0
print(result.stdout)
```

```bash
# 等价 shell
df -h /
echo $?   # 0
```

### 列表形式 vs shell 字符串

```python
# 对：无 shell，无注入
subprocess.run(["grep", pattern, path], check=True)

# 危险：pattern 含 ; rm -rf /
subprocess.run(f"grep {pattern} {path}", shell=True)
```

若必须用 shell（管道、重定向），**固定模板 + `shlex.quote` 用户片段**，仍不如拆成多次 `run` 或 Python 处理。

> 💡 **打个比方**：`shell=True` 相当于把用户输入直接交给 `/bin/sh -c` 当脚本跑——等于让陌生人帮你按电梯，你不知道他按了哪层。argv 列表则是你亲手把参数一个个塞进电梯，别人按不了。

### shell=True 的注入面（🔥难点）

`shell=True` 时整个字符串交给 `/bin/sh -c`，其中 `;`、`|`、`$()`、反引号、`&&` 都是 shell 元字符：

```python
# 用户输入 ns="x; rm -rf /tmp/y"
ns = "x; rm -rf /tmp/y"
subprocess.run(f"kubectl get pods -n {ns}", shell=True)
# 实际执行: /bin/sh -c "kubectl get pods -n x; rm -rf /tmp/y"
# ← 两 条命令，第二条 rm 生效
```

```python
# 安全：argv 列表，分号只是 ns 的字面值
subprocess.run(["kubectl", "get", "pods", "-n", ns], check=True)
# ← ns="x; rm -rf /" 当普通字符串传给 kubectl，kubectl 报错
```

> ⚠️ **别混**：`shell=False`（默认）下 argv 列表的参数**不经过 shell 解析**——`;` `|` `$` 都只是普通字符，不会被执行。

> 📝 **面试**：「`shell=True` + 用户输入 = RCE。要管道就拆成多次 `run`，或固定模板 + `shlex.quote`。」

## 三、上路：check、输出与超时（⭐常考）

> 🎯 **一句话**：**`check=True` 非 0 抛 `CalledProcessError`**；**`timeout` 防挂死**。

```python
try:
    subprocess.run(["kubectl", "get", "nodes"], check=True, timeout=30)
except subprocess.CalledProcessError as e:
    log.error("kubectl failed code=%s stderr=%s", e.returncode, e.stderr)
    return 1
except subprocess.TimeoutExpired:
    log.error("kubectl timeout")
    return 1
```

`check_output` = `run(..., check=True, stdout=PIPE).stdout` 语法糖。

```python
out = subprocess.check_output(["hostname"], text=True).strip()
```

### capture_output 与 text

```python
r = subprocess.run(["ls", "missing"], capture_output=True, text=True)
# r.returncode == 2
# r.stderr 含错误信息
```

Python 3.7+：`capture_output=True`；老代码 `stdout=PIPE, stderr=PIPE`。

> ⚠️ **别混**：**`check=False`（默认）** 非 0 不抛异常——要自己看 `returncode`。

## 四、进门：stdin、env、cwd（🔧实操）

> 🎯 **一句话**：**不需要交互时 `stdin=DEVNULL`**；改环境用 `env`；改目录用 `cwd`。

```python
import os

subprocess.run(
    ["python", "worker.py"],
    stdin=subprocess.DEVNULL,
    cwd="/opt/job",
    env={**os.environ, "LOG_LEVEL": "DEBUG"},
    check=True,
)
```

传密码用 env，不要 argv（`ps` 可见）——更好用临时文件或 SDK。

```python
#  kubectl 用 KUBECONFIG 环境指向文件
env = {**os.environ, "KUBECONFIG": str(kubeconfig_path)}
subprocess.run(["kubectl", "get", "ns"], env=env, check=True)
```

## 五、干活：PIPE 死锁与流式 Popen（🔥难点）

> 🎯 **一句话**：**大量输出时别同时 PIPE 且不读**——缓冲区满子进程阻塞。

🔥 **PIPE 死锁** = 子进程往 stderr 写满管道缓冲区，父进程却只读 stdout，两边互相等。大白话：两个人同时打电话，都在等对方先开口。⭐ 这是线上挂死的高频根因。

很多人会答「再开个线程读就行」——有时可以，但运维脚本优先 `capture_output=True` 或把输出重定向到文件。

```python
# 危险：输出极大时可能死锁
p = subprocess.Popen(["find", "/"], stdout=subprocess.PIPE, stderr=subprocess.PIPE)
out, err = p.communicate()   # communicate 会读光管道
```

`run(capture_output=True)` 内部处理好了——**一次性中等输出**用 `run`。

流式处理大日志：

```python
with subprocess.Popen(
    ["kubectl", "logs", pod, "-f"],
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
) as p:
    assert p.stdout is not None
    for line in p.stdout:
        process_line(line)
    rc = p.wait()
```

或直接把 stdout 接到文件：

```python
with open("out.log", "w", encoding="utf-8") as f:
    subprocess.run(["heavy_cmd"], stdout=f, check=True)
```

> 💡 **打个比方**：PIPE 像窄水管——子进程拼命灌水，父进程不读就堵死；`communicate` 或写文件是放水。

### run / check_output / Popen 选型（🔥难点）

| API | 等待结束 | 捕获输出 | 失败抛异常 | 典型场景 |
|-----|:--------:|:--------:|:----------:|----------|
| `run` | 是 | 可选 | `check=True` | **默认首选** |
| `check_output` | 是 | stdout only | 是 | 只要 stdout 字符串 |
| `check_call` | 是 | 否 | 是 | 只关心成功 |
| `Popen` | 手动 wait | 手动读 | 手动 | 流式、双向交互 |

```python
# 语法糖关系
out = subprocess.check_output(["hostname"], text=True)
# ≡ run(..., check=True, stdout=PIPE).stdout

subprocess.check_call(["true"])
# ≡ run(..., check=True) 且不要输出
```

`CompletedProcess` 字段：`args`、`returncode`、`stdout`、`stderr`——日志里常打后三者。

### 编码与 errors（⭐常考 · 🔥难点）

```python
r = subprocess.run(
    ["legacy_tool"],
    capture_output=True,
    text=True,
    encoding="utf-8",
    errors="replace",    # 非法字节 →，脚本不崩
)
```

子进程输出非 UTF-8 时，`text=True` 默认 strict 可能 `UnicodeDecodeError`——运维工具链杂时 `errors="replace"` 或 `backslashreplace`，并在日志标「输出可能有损」。

```python
# bytes 模式自己解码
r = subprocess.run(["tool"], capture_output=True)
text = r.stdout.decode("utf-8", errors="replace")
```

```python
# 🔧 实操：排查 legacy 工具编码
import subprocess

r = subprocess.run(
    ["iconv", "-l"],            # 列出支持的编码
    capture_output=True,
    text=True,
    encoding="utf-8",
    errors="replace",
)
for line in r.stdout.splitlines():
    print(line)                  # ← 逐行打印，非法字符显示 � 但不崩
```

> ⚠️ **别混**：**`text=True` 与 `universal_newlines=True`**（旧名）同义；Python 3.7+ 用 `text`。

> 💡 **打个比方**：`errors="strict"` 是个洁癖门卫——遇到不认识的字节就把门关了（崩）。`errors="replace"` 换成宽容门卫——不认识就贴个 `�` 标签放行，你至少知道这里有个坏字节。

### 遗留 API 别用

```python
# 遗留 — 无捕获、走 shell、难测
os.system("kubectl get pods")          # ← 只返回 exit code，无 stdout/stderr
os.popen("kubectl get pods").read()   # ← 只读 stdout，走 shell，异常静默
commands.getoutput("kubectl get pods")  # ← Python 2 遗物，已删

# 现代替代
subprocess.run(["kubectl", "get", "pods"], check=True, capture_output=True, text=True)
# ← 拿到 CompletedProcess：returncode + stdout + stderr 全有
```

| 遗留 API | 问题 | 现代替代 |
|----------|------|----------|
| `os.system` | 无捕获、走 shell、只返回码 | `run([...])` |
| `os.popen` | 只读 stdout、走 shell | `run(capture_output=True)` |
| `os.spawn*` | 接口笨重、跨平台不一致 | `run` / `Popen` |
| `commands.*` | Python 2 已删 | `run` / `check_output` |

> 🔍 **现场**：代码评审见 `os.system`——一律要求改 `subprocess.run` 列表形式。`os.popen` 同理。

## 六、退出码：与 main 契约（⭐常考）

> 🎯 **一句话**：**子进程 `returncode` 非 0 → 脚本应 `return 1` 或 `raise`**。

```python
def run_check() -> int:
    r = subprocess.run(["bash", "-c", "test -f /ready"], capture_output=True)
    if r.returncode != 0:
        log.error("not ready stderr=%s", r.stderr)
        return 1
    return 0
```

| 子进程码 | 常见含义 | Python 侧 |
|----------|----------|-----------|
| 0 | 成功 | 继续 |
| 1 | 一般错误 | `return 1` |
| 2 | 用法错误 | 可映射 `return 2` |
| 127 | command not found | 配置/镜像问题 |
| 137 | SIGKILL（128+9） | OOM 杀 |

```python
def main() -> int:
    try:
        subprocess.run(["./check.sh"], check=True, timeout=120)
    except subprocess.CalledProcessError as e:
        log.error("check.sh exit %s", e.returncode)
        return 1
    return 0
```

> ⚠️ **别混**：**Shell 管道假绿**（01-Shell）——Python 里单条 `run` 没有管道问题；若 `shell=True` 跑 `"a | b"`，只有最后命令码。

## 七、收束：外部命令凭什么不拖垮脚本（⭐常考）

```mermaid
flowchart TB
    subgraph 安全
        L[argv 列表]
        N[no shell 注入]
    end
    subgraph 可靠
        T[timeout]
        C[check returncode]
    end
    subgraph I/O
        R[capture 或流式]
        D[DEVNULL stdin]
    end
    L --> T
    N --> T
    T --> C
    R --> C
    D --> C
    C --> M[main exit 码]
```

**可背清单（六件套）**：

1. `run([cmd, arg1, ...])`，避免 `shell=True`
2. 总是 `timeout`（长命令除外要有理由）
3. 失败处理：`check=True` 或判 `returncode`
4. 大输出流式或写文件，防 PIPE 死锁
5. 秘密走 env/文件，不进 argv
6. 子失败映射 `main return 1`（04 章）

## 八、作战：挂死、注入、假绿

**现象 · 先做 · 别做**

| 现象 | 先做 | 别做 |
|------|------|------|
| 脚本 hang | 是否 PIPE 未读；无 timeout | kill -9 了事 |
| 命令注入 | 搜 `shell=True` + f-string | 继续拼用户输入 |
| CI 绿检查失败 | `returncode` 是否检查 | 只看 stdout 有字 |
| 127 not found | 镜像 PATH；绝对路径 | shell 别名 |
| 输出乱码 | `text=True` + encoding | 默认 bytes 当 str |

**60 秒剧本** 🔧：

| 时段 | 动作 |
|------|------|
| 0–10s | 手动跑同一条 CLI 看 `$?` |
| 10–25s | 代码 `shell=True`/`os.system` |
| 25–40s | 加 `timeout=30` 复现 |
| 40–60s | 失败路径 `echo $?` 非 0 |

```bash
python -c "import subprocess; r=subprocess.run(['false']); print(r.returncode)"
# 1

python -c "import subprocess; subprocess.run(['sleep','99'], timeout=1)"
# TimeoutExpired
```

现在再看群里那句「脚本卡死杀进程」，你知道该怎么拦住他了——先查 shell=True 与 PIPE，再查 timeout 与 returncode。下面是可复制的生产模板（代码块一字不改，直接拿走）。

## 生产模板

### 模板 1：安全 run 包装

```python
from __future__ import annotations

import logging
import subprocess

log = logging.getLogger(__name__)


def run_cmd(
    argv: list[str],
    *,
    timeout: int = 60,
    check: bool = True,
    cwd: str | None = None,
) -> subprocess.CompletedProcess[str]:
    log.debug("exec argv=%s", argv)
    return subprocess.run(
        argv,
        capture_output=True,
        text=True,
        timeout=timeout,
        check=check,
        cwd=cwd,
        stdin=subprocess.DEVNULL,
    )
```

### 模板 2：main 映射退出码

```python
def main() -> int:
    try:
        run_cmd(["kubectl", "get", "nodes"], timeout=30)
    except subprocess.CalledProcessError as e:
        log.error("kubectl failed rc=%s stderr=%s", e.returncode, e.stderr)
        return 1
    except subprocess.TimeoutExpired:
        log.error("kubectl timeout")
        return 1
    return 0
```

### 模板 3：不 check 手动分支

```python
r = subprocess.run(["test", "-f", path], capture_output=True)
if r.returncode == 0:
  ...
elif r.returncode == 1:
  ...
else:
  log.error("unexpected rc=%s", r.returncode)
  return 1
```

### 模板 4：大输出写文件

```python
with open(out_path, "w", encoding="utf-8") as out:
    subprocess.run(
        ["journalctl", "-u", "myservice", "--no-pager"],
        stdout=out,
        stderr=subprocess.STDOUT,
        check=True,
        timeout=300,
    )
```

## 踩坑清单

| 现象 | 原因 | 修法 |
|------|------|------|
| 死锁 | PIPE 未读 | communicate/流式/写文件 |
| 注入 | shell=True + 用户输入 | argv 列表 |
| 假绿 | 忽略 returncode | check 或判断 |
| 永久挂 | 无 timeout | timeout= |
| 编码错 | bytes 当 str | text=True |
| 秘密进 ps | 密码在 argv | env 或文件 |
| os.system 无输出 | 老 API | 改 run |
| 127 | 命令不在 PATH | 绝对路径或 which |

## 合上书，问自己

学到这里，先别急着翻下一章。合上书，试试下面这几件事能不能做到——能做到，这章才算真的听懂了。卡住的那一条，就回到对应的小节再听一遍：

- [ ] 画出命令一生：run → I/O → returncode。（对应练习题 Q13）
- [ ] 为什么禁止 shell=True 拼用户输入？（Q1、Q2）
- [ ] timeout 与 check 各防什么？（Q3、Q4）
- [ ] PIPE 死锁怎么形成？怎么避？（Q6、Q7）
- [ ] stdout/stderr 怎么交给 logging？（Q5）
- [ ] 子进程非 0 如何映射到 main？（Q8、Q9）
- [ ] 挂死 60 秒怎么查？（Q10、Q12）
- [ ] 假绿是否忘了 check returncode？（Q11）

全部打勾之后，给自己出一个终极测试：找一位同事，十分钟讲清「开头那个死锁/注入现场，为什么列表传参、为什么要 timeout」。讲得下来，你就是下一个能拦住「shell=True」的人。
