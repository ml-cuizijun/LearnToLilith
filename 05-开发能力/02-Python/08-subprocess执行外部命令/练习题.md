## Q1

**★★★★★｜`subprocess.run(["kubectl","get","pods"])` 和 `run("kubectl get pods", shell=True)` 差在哪？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [二、出生：subprocess.run 基础（⭐常考）](知识点.md)

### 场景

用户输入的 namespace 拼进 shell 字符串。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**列表无 shell、防注入**；`shell=True` 经 `/bin/sh -c`，用户输入可 RCE。

```python
# 对
subprocess.run(["kubectl", "get", "pods", "-n", ns], check=True)

# 危险
subprocess.run(f"kubectl get pods -n {ns}", shell=True)
```

### 再追问

真要管道怎么办？——多次 `run`、Python 处理、或固定模板+`shlex.quote`。

## Q2

**★★★★★｜默认 `check=False` 时，子进程 exit 1 会怎样？**

**覆盖**：核心 · 必会 | **对应**：知识点 [三、上路：check、输出与超时（⭐常考）](知识点.md)

### 场景

> 🎯 **一句话**：**不抛异常**，只设 `returncode=1`——必须自己判断或 `check=True`。

**★★★★★｜外部命令可能挂死，应用什么参数？超时异常叫什么？**

**覆盖**：核心 · 必会 | **对应**：知识点 [三、上路：check、输出与超时（⭐常考）](知识点.md)

### 完整解答

> 🎯 **一句话**：**`timeout=秒`**；超时抛 **`subprocess.TimeoutExpired`**。


## Q4

**★★★★★｜PIPE 死锁怎么发生？`run(capture_output=True)` 为何常够用？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、干活：PIPE 死锁与流式 Popen（🔥难点）](知识点.md)

### 场景

`Popen` 大 `find /` 输出，父子都阻塞。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**子写满管道缓冲、父不读则双方阻塞**；`run`/`communicate` 内部读光。

```python
# 中等输出
subprocess.run(["cmd"], capture_output=True, text=True)

# 超大：流式或写文件
with open("out.log", "w") as f:
    subprocess.run(["heavy"], stdout=f, check=True)
```

### 再追问

同时 PIPE stdout+stderr 都不读？——必死锁，用 `communicate()`。

## Q5

**★★★★☆｜`capture_output=True` 和 `stdout=PIPE, stderr=PIPE` 关系？`text=True` 干嘛？**

**覆盖**：必会 · 常用 | **对应**：知识点 [三、上路：check、输出与超时（⭐常考）](知识点.md)

### 场景

3.6 老代码与 3.7+ 写法混用。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**`capture_output=True` 等价双 PIPE**；`text=True` 得 str 而非 bytes。

```python

r.stdout   # 'hi\n'
```

### 再追问

只要 stderr？——`stderr=subprocess.PIPE, stdout=DEVNULL`。

## Q6

**★★★★★｜子检查脚本 `check.sh` exit 1，Python `main` 应怎样？**

**覆盖**：核心 · 必会 | **对应**：知识点 [六、退出码：与 main 契约（⭐常考）](知识点.md)、[04 章](../04-异常与退出码/知识点.md)

### 场景

与 logging 满屏 ERROR 但 CI 绿联动。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**映射 `return 1`**，别吞 `CalledProcessError`。

```python
def main() -> int:
    try:
        subprocess.run(["./check.sh"], check=True, timeout=120)
    except subprocess.CalledProcessError as e:
        log.error("check.sh rc=%s stderr=%s", e.returncode, e.stderr)
        return 1
    return 0
```

### 再追问

部分步骤失败汇总？——类似 04 章 `any_failed`。

**★★★★☆｜`kubectl logs -f` 持续输出，用 `run` 还是 `Popen`？**

**覆盖**：必会 · 常用 | **对应**：知识点 [五、干活：PIPE 死锁与流式 Popen（🔥难点）](知识点.md)

### 完整解答

> 🎯 **一句话**：**`Popen` 迭代 `stdout` 行**，或重定向到文件。

```python

    ["kubectl", "logs", pod, "-f"],

    text=True,

    rc = p.wait()
```

## Q14

**★★★★★｜读代码找 bug：**

```python
def run_check(user_ns):
    cmd = f"kubectl get pods -n {user_ns}"
    p = subprocess.Popen(cmd, shell=True, stdout=subprocess.PIPE, stderr=subprocess.PIPE)
    out = p.stdout.read()
    return 0
```

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生：subprocess.run 基础（⭐常考）](知识点.md)、[三、上路：check、输出与超时（⭐常考）](知识点.md)、[五、干活：PIPE 死锁与流式 Popen（🔥难点）](知识点.md)、[六、退出码：与 main 契约（⭐常考）](知识点.md)

### 场景

注入、死锁风险、忽略 returncode、永远 return 0。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**shell+用户输入注入；只读 stdout 可能死锁；未 wait/未 check；永远成功**。

```python
def run_check(user_ns: str) -> int:
    r = subprocess.run(
        ["kubectl", "get", "pods", "-n", user_ns],
        capture_output=True,
        text=True,
        timeout=60,
    )
    if r.returncode != 0:
        log.error("kubectl failed stderr=%s", r.stderr)
        return 1
    process(r.stdout)
    return 0
```

### 再追问

`validate_ns` 正则限制？——纵深防御，仍不用 shell。
