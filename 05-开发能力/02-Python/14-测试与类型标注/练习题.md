## Q2

为什么测 → 怎么拆成可测。

**★★★★★｜200 行全写在 `main()` 里，如何改成可测？**

**覆盖**：核心 · 必会 | **对应**：知识点 [二、出生：可测结构](知识点.md)

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**抽出 `filter_unready(rows, cfg) -> list[PodRow]` 等纯函数；main 只编排 IO**。

```python

    cfg = load_config()

```

**★★★★☆｜如何测 `parse_ratio("2")` 必须抛 ValueError？**

### 完整解答

> 🎯 **一句话**：**复用 setup，避免 copy-paste 假数据**。

## Q6

这是 Q2 的 main 退出码版。

**★★★★★｜如何测 `main()` 在不连 K8s 时返回 1？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [四、壮年：fixture 与 mock](知识点.md)

### 场景

CI 没有 kubeconfig。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**monkeypatch 替换 `fetch_rows` 和 `report`**。

```python
def test_main_returns_1(monkeypatch, sample_rows):
    monkeypatch.setattr("audit.fetch_rows", lambda cfg: sample_rows)
    monkeypatch.setattr("audit.report", lambda bad: None)
    assert main([]) == 1
```

字符串路径要对：**被测模块里引用的名字**（`audit.fetch_rows`），不是定义处模块名。

> 📝 **面试**：「挡 IO，不挡我的分支逻辑。」

### 再追问

还要测 env `NAMESPACE`？——`monkeypatch.setenv("NAMESPACE", "staging")`。

## Q7

多组输入用 parametrize。

**★★★★☆｜用 parametrize 测多组 ratio 输入是否合法。**

**覆盖**：常用 · 常考 | **对应**：知识点 [四、壮年：fixture 与 mock](知识点.md)

### 场景

边界：0、1、负数、大于 1。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**`@pytest.mark.parametrize` 一张表驱动多 case**。

```python
@pytest.mark.parametrize("raw,ok", [("0", True), ("1", True), ("-0.1", False)])
def test_parse_ratio(raw, ok):
    if ok:
        assert parse_ratio(raw) == float(raw)
    else:
        with pytest.raises(ValueError):
            parse_ratio(raw)
```

避免复制四个几乎相同的 test 函数。

### 再追问

case 太多怎么读？——用 `ids=` 参数给每个 case 起名。

## Q9

类型锁形状——TypedDict。

**★★★★★｜`dict` 行记录为什么推荐 TypedDict？mypy 能帮你什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、老去：类型标注与静态检查](知识点.md)

### 场景

重构把 `ready` 改成 `is_ready`，静默返回全空。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**TypedDict 固定 key 名和类型，改名漏改时 mypy 报错**。

```python
class PodRow(TypedDict):
    name: str
    namespace: str
    ready: bool

def f(row: PodRow) -> str:
    return row["name"]
# row["is_ready"]  # mypy: KeyError
```

> ⚠️ **别混**：TypedDict 运行时仍是普通 dict；校验靠 mypy 或 pydantic。

### 再追问

何时用 dataclass？——需要方法和不可变对象时；JSON 行用 TypedDict 更轻。

就是开头满屏 Any 现场。

**★★★★☆｜同事满屏 `Any` 和 `# type: ignore`，你怎么推进？**

**覆盖**：必会 · 常考 | **对应**：知识点 [五、老去：类型标注与静态检查](知识点.md)、[八、作战：没测试的 PR、类型全 Any、CI 红](知识点.md)

### 场景

老仓库 mypy 一开就 300 错误。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**新代码禁止新增 Any；旧文件渐进；CI 先对 `audit.py` 开 mypy**。

策略：
- `pyproject.toml` 设 `warn_return_any = true`
- 新函数全标注
- 禁止无注释 `# type: ignore`

## Q11

Protocol + Fake client。

**★★★★☆｜Protocol 和 unittest.mock 假 client 怎么配合？**

**覆盖**：常用 · 常考 | **对应**：知识点 [五、老去：类型标注与静态检查](知识点.md)

### 场景

不想依赖 kubernetes 包做单元测试。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**定义 `PodLister` Protocol，生产传真 client，测试传 FakeLister**。

```python
class PodLister(Protocol):
    def list_pods(self, namespace: str) -> list[PodRow]: ...

class FakeLister:
    def list_pods(self, namespace: str) -> list[PodRow]:
        return [{"name": "p", "namespace": namespace, "ready": True}]

def test_audit_ok():
    assert audit(FakeLister(), cfg) == 0
```

比 mock 任意 MagicMock 更类型安全。

### 再追问

和 monkeypatch 选哪个？——注入更适合新设计；老代码用 monkeypatch 更快。

## Q14

读测试代码找坏味道。

**★★★★★｜读代码：这份测试有什么问题？如何改？**

**覆盖**：核心 · 必会 · 读代码 | **对应**：知识点 [四、壮年：fixture 与 mock](知识点.md)、[踩坑清单](知识点.md)

### 场景

```python
def test_audit():
    os.environ["NAMESPACE"] = "prod"
    assert main([]) == 0  # 开发者本机有 kubeconfig，CI 随机失败
```

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。

### 完整解答

> 🎯 **一句话**：**触真集群 + 污染全局 env + 无 assert 隔离——应用 monkeypatch 且 mock fetch**。

```python
def test_audit_ok(monkeypatch):
    monkeypatch.setenv("NAMESPACE", "prod")
    monkeypatch.setattr("audit.fetch_rows", lambda c: all_ready_rows)
    monkeypatch.setattr("audit.report", lambda b: None)
    assert main([]) == 0
```

问题列表：
- 依赖外部 K8s → flaky
- 直接改 `os.environ` 不恢复 → 污染其他测试
- 未测失败分支

> ⚠️ **别混**：应用 `monkeypatch.setenv`，不要手写 environ。

### 再追问

如何补失败分支测试？——fixture 含 not-ready Pod，assert `main()==1`。
