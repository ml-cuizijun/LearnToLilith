## Q1

**★★★★★｜为什么禁止在跳板机上 `sudo pip install kubernetes`？正确做法是什么？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [三、筑基：venv 与解释器选择](知识点.md)

### 场景

活动前有人在生产跳板机全局装了 `kubernetes==27.x`，另一个发版脚本要求 `28.x`，`pip check` 报依赖冲突，夜间 oncall 装装卸卸。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**污染系统 site-packages**，多项目版本打架且难复现；应在**项目 venv** 或**容器**里 `pip install -r requirements.txt`。

```bash
cd ~/ops-scripts
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -U pip
pip install -r requirements.txt
```

> 📝 **面试**：「系统 Python 留给发行版包管理；应用依赖进 venv 或镜像。」

### 再追问

没有写权限创建 venv 怎么办？——用 `pip install --user` 仅作权宜，或改跑 K8s Job/容器，长期仍要隔离。

## Q2

**★★★★☆｜`requirements.txt` 里写 `requests` 和 `requests>=2.31.0,<3` 有什么区别？生产推荐哪种？**

**覆盖**：必会 · 常考 | **对应**：知识点 [四、锁依赖：requirements 与版本](知识点.md)

### 场景

半年前 `pip install -r` 能跑，今年重装拉到大版本升级，HTTP 客户端行为变了，脚本静默失败——这是 Q1 结论的加深版。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：只写包名会装**当前最新**；生产应**钉版本或范围**，避免不可控升级。

```text
# 不推荐
requests

# 推荐
requests>=2.31.0,<3
kubernetes>=28.1.0,<29
```

全量复现可用 `pip-compile` 生成 lock 文件；小运维仓顶层范围约束通常够用。

### 再追问

`pip check` 干什么？——检查已装包声明的依赖是否冲突。

## Q3

**★★★★★｜去掉 `if __name__ == "__main__":` 守卫，把 `main()` 写在文件末尾直接调用，会有什么后果？**

**覆盖**：核心 · 必会 · 常考 | **对应**：知识点 [五、入口：shebang、main 与 __main__](知识点.md)

### 场景

`lib/k8s_client.py` 里为了「方便测试」在底部写了 `main()` 并直接调用；别的模块 `from lib.k8s_client import list_pods` 时意外连上集群。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**被 import 时也会执行** `main()`，副作用在导入阶段爆发。

```python
# 错误
def main():
    ...

main()

# 正确
if __name__ == "__main__":
    raise SystemExit(main())
```

测试应 `from lib.k8s_client import main` 后显式 `main(["--dry-run"])`。

> ⚠️ **别混**：守卫只防「导入时执行」；模块顶层其它代码（读配置、连 API）仍会在 import 时跑——尽量把副作用放进 `main`。

### 再追问

`python -m package.module` 时 `__name__` 是什么？——`__main__`（当以模块方式运行时）。

## Q4

**★★★★☆｜`#!/usr/bin/env python3` 和 `#!/usr/local/bin/python3.11` 怎么选？`chmod +x` 忘了会怎样？**

**覆盖**：必会 · 常用 | **对应**：知识点 [五、入口：shebang、main 与 __main__](知识点.md)

### 场景

Docker 里脚本 shebang 指向不存在的路径；本地 `chmod +x` 忘了，文档写 `./check.py` 报 Permission denied。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：推荐 **`env python3` 便携**；写死路径仅当必须锁小版本。没 `+x` 用 `python check.py` 仍可跑。

```bash
chmod +x scripts/check.py
./scripts/check.py
# 或
python3 scripts/check.py
```

> 📝 **面试**：「shebang 在直接执行时生效；`python script.py` 不读 shebang。」

### 再追问

与 Shell 的 `#!/usr/bin/env bash` 类比？——同一思路，用 PATH 找解释器。

## Q5

**★★★★☆｜十个运维脚本、一个共享 `k8s_client.py`，目录怎么搭？**

**覆盖**：必会 · 常用 | **对应**：知识点 [二、出生：目录布局怎么选](知识点.md)

### 场景

团队新建 `ops-scripts` 仓，不想过度工程化，但要 CI 能跑。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**`scripts/` + `lib/` + `requirements.txt` + README**，`PYTHONPATH=lib` 或后续 `pip install -e .`。

```text
ops-scripts/
├── README.md
├── requirements.txt
├── .gitignore
├── scripts/
│   └── healthcheck.py
└── lib/
    ├── __init__.py
    └── k8s_client.py
```

```bash
source .venv/bin/activate
PYTHONPATH=lib python scripts/healthcheck.py
```

脚本超过 ~15 个、要上测试再迁 `src/` + `pyproject.toml`。

### 再追问

`lib` 要不要 `__init__.py`？——3.3+ 隐式 namespace 可以不要，但显式 `__init__.py` 更清晰。

## Q6

**★★★★★｜本地能跑，GitLab CI 报 `ModuleNotFoundError`，你会对齐哪三样东西？**

**覆盖**：核心 · 常用 | **对应**：知识点 [六、交付：README 与 CI 同一套命令](知识点.md)

### 场景

开发者 Mac 上在 venv 里装过包，CI 镜像只有 `python:3.11-slim`，脚本没 `pip install -r`。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**Python 小版本、安装命令、工作目录/PYTHONPATH** 必须与 README 一致。

```yaml
script:
  - python -m venv .venv
  - . .venv/bin/activate
  - pip install -U pip -r requirements.txt
  - PYTHONPATH=lib python scripts/healthcheck.py
```

本地打印 `python --version`、`which python`、`pip list` 与 CI 日志逐项对比。

### 再追问

CI 要不要缓存 `.venv`？——可缓存 pip wheel，但 install 步骤不能省。

## Q7

**★★★★☆｜`ImportError: No module named 'lib.k8s_client'` 在跳板机第一次出现，排查顺序？**

**覆盖**：常用 · 实操 | **对应**：知识点 [八、作战](知识点.md)

### 场景

新人按 README clone 后直接 `python scripts/healthcheck.py`。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**激活 venv → 装依赖 → 设 PYTHONPATH 或 editable 安装**。


## Q8

**★★★★☆｜`.gitignore` 至少应忽略哪些？误提交 `venv/` 后怎么处理？**

**覆盖**：必会 | **对应**：知识点 [二、出生：目录布局怎么选](知识点.md)

> 🎯 **一句话**：忽略 **`.venv/`、`__pycache__/`、`.env`、构建产物**；已提交用 `git rm -r --cached .venv`。

## Q9

**★★★☆☆｜`pip freeze > requirements.txt` 适合什么时候用？有什么坑？**

**覆盖**：常考 | **对应**：知识点 [四、锁依赖](知识点.md)

### 场景

有人 freeze 后 requirements 里出现 `file:///local/path/package` 或 `-e git+ssh://...`。

## Q10

**★★★☆☆｜`PYTHONPATH=lib` 和 `pip install -e .` 各解决什么问题？**

**覆盖**：常用 | **对应**：知识点 [五、入口](知识点.md)

### 场景

平铺布局不想打包，但又要 `from k8s_client import ...`。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**PYTHONPATH** 临时把 `lib` 加进 `sys.path`；**editable 安装**把包注册进 venv，import 路径更标准。

```bash
# 临时
PYTHONPATH=lib python scripts/healthcheck.py

# 长期（有 pyproject）
pip install -e .
```

### 再追问

生产 CronJob 里更推荐哪种？——镜像构建时 `pip install .`，运行时不再依赖 PYTHONPATH。

## Q11

**★★★☆☆｜`pyproject.toml` 里 `[project.scripts]` 是干什么的？**

### 完整解答

> 🎯 **一句话**：声明**控制台入口点**，`pip install` 后在 venv 的 `bin/` 生成可执行脚本。

## Q12

**★★★★☆｜接到「bad interpreter: No such file or directory」执行 `./check.py`，60 秒怎么做？**

**覆盖**：实操 | **对应**：知识点 [八、作战](知识点.md)

### 场景

从 mac 拷到 Linux 的脚本，或 shebang 指向已删除的 pyenv 路径。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：看 **shebang 第一行** 路径是否存在；临时用 `python3 check.py` 绕过。

```bash

# #!/Users/foo/.pyenv/versions/3.11.8/bin/python3  ← Linux 上不存在

# 修法：改为 #!/usr/bin/env python3
```

### 再追问

`env: python3\r` 错误？——Windows CRLF，用 `dos2unix` 或编辑器改 LF。

## Q14

**★★★★★｜设计一个「集群巡检」仓：目录、requirements、README 三节、CI 一条 script，口述即可。**

**覆盖**：核心 · 场景设计 | **对应**：知识点全章

### 场景

团队要从零建 `cluster-inspect`，含 `check_pods.py`、`check_nodes.py`、共享 `kube.py`。

先自己试试：不看下面，你能口述答案吗？讲完再对「完整解答」。


### 完整解答

> 🎯 **一句话**：**平铺 + venv + 版本钉死的 kubernetes/requests + README 三步 + CI 镜像 python:3.11**。

```text
cluster-inspect/
├── README.md
├── requirements.txt      # kubernetes>=28,<29
├── scripts/check_pods.py
├── scripts/check_nodes.py
└── lib/kube.py
```

README：venv → pip install → `PYTHONPATH=lib python scripts/check_pods.py`。

CI：`venv` + `pip install -r` + 同上命令；失败非 0 门禁红。

> 📝 **面试**：强调**不提交 venv**、**不用 sudo pip**、**main 返回退出码**。

### 再追问

多集群 kubeconfig 怎么注入？——环境变量 `KUBECONFIG` 或 CI secret 挂载，不写进 Git。
