## Q1

**★★★★★｜grep 默认什么模式？`grep 'error+'` 为什么匹配不到 `errorr`？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [原理讲透](知识点.md) · [语法必会](知识点.md)

### 场景

笔试填空 + 现场排障。有人用 `grep 'error+' app.log` 找 ERROR 行，结果为空，以为日志里没有 error。

### 完整解答

**一句话**：grep 默认 **BRE**，`+` 是字面量；要 `grep -E 'error+'` 或 `grep 'error\+'`。

| 模式 | 标志 | `+` 的含义 |
|------|------|-----------|
| BRE | 无（默认） | 字面量 `+` |
| ERE | `-E` | 一个或多个前一个字符 |

```bash
grep -E 'error+' file   # 匹配 error, errorr ...
grep 'error\+' file     # BRE 下转义 + 也行
```

生产 one-liner **一律 `-E`**。RE2 vs PCRE：RE2 线性无灾难回溯；PCRE 功能全但可能回溯爆炸。

## Q2

**★★★★★｜读代码：下面正则为什么把 CPU 打满？怎么改？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [原理讲透](知识点.md)

### 场景

活动夜几 GB 游戏 error.log 处理卡住，大厅 502 还没统计出来。同事代码：

```python
import re
pat = re.compile(r'(.*:)+$')
with open("app.log") as f:
    for line in f:
        m = pat.match(line)
        if m:
            print(m.group())
```

畸形行（超长、冒号数量异常）上 CPU 100%。

### 完整解答

**一句话**：嵌套量词 `(.+)+` / `(.*:)+` 灾难回溯；改明确字符类 + 截断超长行 + 先 grep 过滤。

改法：

```python
safe = re.compile(r'^[^:]+(:[^:]+)*$')
with open("app.log") as f:
    for line in f:
        if len(line) > 8192:
            continue
        m = safe.match(line.rstrip("\n"))
```

额外：先 `grep -E 'ERROR|FATAL|/login'` 缩小；`.*` 抽 URL 改 `[^"]*`。

## Q3

**★★★★★｜Nginx access.log，$9 是 status 还是 $10？怎么确认？**

**覆盖**：核心 · 必会 · 常用

**对应**：知识点 [原理讲透](知识点.md) · [语法必会](知识点.md)

### 场景

登录 502。有人抄博客用 `$10` 当状态码，统计显示没有 5xx。`head -1` 一看 combined 格式 status 在 `$9`。

### 完整解答

**一句话**：列号以你们 `log_format` 为准；现场 `head -1` + `awk '{print $1,$7,$9}' | head` 对列再计数。

combined 常见映射：

| 字段 | 常见列 | 示例 |
|------|--------|------|
| client IP | `$1` | 192.168.1.10 |
| 时间 | `$4` | [28/Aug/2026:10:00:01 |
| request path | `$7` | /login |
| status | `$9` | 502 |
| RT | 看 format | 可能在 `$NF` 前 |

```bash
head -1 access.log
awk '{print $1, $7, $9}' access.log | head -5

awk '$9 ~ /^5/ {count[$1]++} END {for (ip in count) print count[ip], ip}' access.log \
  | sort -rn | head -10
```

```text
192.168.1.10 /login 502
842 203.0.113.50
156 198.51.100.22
```

### 再追问

- 自定义 log_format？——偏移全变，必须重算。

## Q4

**★★★★★｜用 sed 批量改 max_connections。`-i` 的风险？路径里有 `/` 呢？**

**覆盖**：核心 · 必会 · 常用

**对应**：知识点 [语法必会](知识点.md) · [生产模板](知识点.md)

### 场景

有人 `sed -i 's/100/500/g' my.cnf`，把 `port=3100`、`wait_timeout=100` 全改了。没有备份，100 台回滚靠手工。

### 完整解答

**一句话**：sed 三步——预览 diff、匹配完整键、`-i.bak`；路径含 `/` 换 `|` 分隔符。

```bash
# 1. 预览
sed 's/max_connections=100/max_connections=500/' my.cnf | diff -u my.cnf -

# 2. 备份写入
sed -i.bak 's/max_connections=100/max_connections=500/' my.cnf

# 3. 路径替换
sed 's|/var/log/nginx|/data/log/nginx|g' nginx.conf
```

多机走 Ansible / Git（见 04）。预览过了生产仍要 bak。

## Q5

**★★★★☆｜jq 列出非 Running Pod、restartCount > 0、所有容器镜像。**

**覆盖**：必会 · 常用

**对应**：知识点 [语法必会](知识点.md) · [生产模板](知识点.md)

### 场景

`kubectl get pods -A` 宽表截断镜像名；Pending Pod 上 jq 报 `null` 错误。

### 完整解答

**一句话**：kubectl `-o json` + jq 流式筛选；Pending 先判 `containerStatuses != null`。

```bash
# 非 Running
kubectl get pods -A -o json | jq -r '
  .items[]
  | select(.status.phase != "Running")
  | "\(.metadata.namespace)/\(.metadata.name)\t\(.status.phase)"
'

# 所有镜像
kubectl get pods -A -o json | jq -r '.items[].spec.containers[].image' | sort -u

# restartCount > 0
kubectl get pods -A -o json | jq -r '
  .items[]
  | select(.status.containerStatuses != null)
  | select(.status.containerStatuses[].restartCount > 0)
  | .metadata.name
'
```

```text
default/nginx-deploy-abc12    CrashLoopBackOff
registry.example.com/app:v1.2.3
nginx-deploy-abc12
```

镜像审计应对 Deployment/StatefulSet 模板。Pending 先判 `containerStatuses != null`。

## Q6

**★★★★★｜Python 用命名组提取 error log 的时间、级别、消息。search 和 match？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [语法必会](知识点.md) · [原理讲透](知识点.md)

### 场景

日志行前有 syslog 前缀 `[host app]:`，`re.match` 从行首匹配全部 None。改用 `.*` 抽消息，两条 ERROR 糊在一起。

### 完整解答

**一句话**：`(?P<name>...)` 命名组 + `search` 任意位置匹配；用 `[^"]*` / 明确分隔符代替贪婪 `.*`。

```python
import re

pat = re.compile(
    r'\[(?P<ts>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})\]'
    r'\s+\[(?P<level>\w+)\]'
    r'\s+(?P<msg>.*)'
)

with open("app.log") as f:
    for line in f:
        m = pat.search(line)   # search：行内任意位置
        # m = pat.match(line)  # match：只从行首——有前缀会失败
        if m:
            d = m.groupdict()
            if d["level"] in ("ERROR", "FATAL"):
                print(d["ts"], d["msg"][:100])
```

`search` 任意位置；`match` 只从行首——有 syslog 前缀会失败。`.*` 抽引号改 `[^"]*`。

## Q7

**★★★★☆｜现场 one-liner 得出 5xx Top IP，能不能直接 iptables 封禁？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [踩坑清单](知识点.md) · [必会 · 常考](知识点.md)

### 场景

Top 5xx IP 里有 LB 健康检查（10.0.0.5）和公司 NAT 出口（203.0.113.0/24）。有人立刻封禁，玩家登录全挂。

### 完整解答

**一句话**：one-liner **只解释现象**；封禁是变更——排除探活/NAT、走变更单、可回滚。

判断流程：

1. Top URL 是 `/login` 且 5xx 集中 → 可能上游挂，不是扫号
2. Top IP 极分散、path 随机 → 更像扫号，仍要人工确认
3. 5xx 也可能是自己服务挂了，IP 是玩家和探活

```bash
# 统计时排除已知探活网段（例子，以你们为准）
awk '$1 !~ /^10\./ && $9 ~ /^5/ {count[$1]++} END {for (ip in count) print count[ip], ip}' access.log \
  | sort -rn | head
```

结论进 Git/Runbook。封禁前确认探活/NAT；WAF 限流往往比 iptables 合适。

## Q8

**★★★★☆｜单文件 10GB access.log，统计 5xx Top IP 和每小时 QPS，内存 4GB 跳板机怎么写？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [原理讲透](知识点.md) · [生产模板](知识点.md)

### 场景

有人 `sort access.log` 或 `python open().readlines()`，跳板机 OOM，SSH 断开。

### 完整解答

**一句话**：先过滤再聚合——禁止全文件 sort / 进内存；顺序 `head -1` → grep 5xx → awk 计数。

```bash
# 0. 对格式
head -1 access.log

# 1. 5xx Top IP（grep 缩小后再 awk）
grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log \
  | awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' \
  | sort -rn | head -10

# 2. 每小时 QPS（全量可 awk 流式，不必 grep）
awk '{k=substr($4,14,2); count[k]++} END {for (h in count) print h, count[h]}' access.log | sort -n

# 3. 压缩日志
zgrep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log.gz | awk '...'
```

纯过滤 grep+awk > Python 逐行。跨天 QPS：`substr($4,2,11) substr($4,14,2)` 做 key。

## Q10

**★★★★☆｜笔试：手写正则（ERE）完成下列匹配。**

**覆盖**：必会 · 常考

**对应**：知识点 [原理讲透](知识点.md) · [原理讲透](知识点.md)

### 场景

运维开发笔试，不允许跑代码，纸面写 regex。

### 题目

1. 匹配 access log 中 HTTP **5xx** 状态码
2. 匹配 IPv4（简化，不要求 0–255 严格）
3. 匹配非 `#` 开头且非空的配置行
4. 从 `"GET /api/v1/login?uid=1 HTTP/1.1"` 提取 path
5. 说明为何不用 `(.+)+` 匹配冒号分隔字段

### 完整解答

**一句话**：ERE 写 5xx/IP/去注释；path 用分组；嵌套量词笔试必扣分。

1. `HTTP/[0-9.]+" 5[0-9][0-9]`
2. `([0-9]{1,3}\.){3}[0-9]{1,3}`
3. `grep -vE '^\s*(#|$)'`
4. `grep -oE '"(GET|POST) (/[^? ]*)'`
5. `(.+)+` → 灾难回溯；改 `[^:]+(:[^:]+)*`

易错：IP 的 `.` 未转义；path 用贪婪 `.*`；回溯只写「慢」不写「指数级」。

## Q11

**★★★★☆｜10GB 日志搜 5xx，grep 要 3 分钟，ripgrep 能快多少？什么时候仍用 grep？**

**覆盖**：必会 · 常用

**对应**：知识点 [踩坑清单](知识点.md) · [必会 · 常考](知识点.md)

### 场景

跳板机只有 `grep`，有人 `grep -E 'HTTP/... 5[0-9][0-9]' access.log` 跑 10GB 要 3 分钟以上。另一台装了 `rg`，同样模式 30 秒内出结果。

### 完整解答

**一句话**：大文件优先 **ripgrep（RE2 线性）**——mmap + SIMD，常比 grep 快 **3～7 倍**；没装 `rg` 才 `grep -E`，且用 `grep pat file` 别 `cat | grep`。

```bash
time grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log | wc -l
# real    3m12s

time rg 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log -c
# real    0m28s
```

仍用 grep 的场景：极简环境没 `rg`、要 BRE/ERE 与线上脚本一致、管道里已有前序过滤且文件不大。`rg` 默认读 `.gitignore`——要扫被忽略目录用 `--no-ignore` 或指定路径。

### 再追问

**rg 和 grep -P 呢？**——`grep -P` 是 PCRE，有回溯风险；`rg` 是 RE2 线性，畸形行更安全。生产大文件搜日志优先 `rg`。

## Q12

**★★★★☆｜CSV 导出里字段含逗号，`awk -F','` 为什么列号全错？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [踩坑清单](知识点.md)

### 场景

运营 CSV：`uid,name,remark`，remark 是 `"hello, world"`。有人 `awk -F',' '{print $1,$3}'` 统计，uid 和 remark 对不上，客服名单发错人。

### 完整解答

**一句话**：CSV **引号内逗号不是分隔符**——`awk -F','` 按字面逗号切，会把 `"hello, world"` 拆成两列；用 **csvkit / Python `csv` 模块**。

```bash
# 错
awk -F',' '{print $1,$3}' users.csv

# 对
csvcut -c uid,remark users.csv
# 或 Python csv.reader 逐行
```

awk 适合 Nginx combined（空白分列）和固定格式日志，**不是**通用 CSV 解析器。字段里可能有逗号、换行、引号时一律结构化解析。

### 再追问

**日志是 JSON 行呢？**——同样别 awk 硬拆，用 jq 或 `json.loads`（见 Q5、Q9）。

## Q13

**★★★★☆｜access.log 跨两天，按小时 QPS 为什么两天的 10 点加在一起？**

**覆盖**：必会 · 常用

**对应**：知识点 [生产模板](知识点.md) · [原理讲透](知识点.md)

### 场景

合并了昨天和今天的 access.log 做容量复盘。`awk '{h=substr($4,14,2); count[h]++} END ...'` 输出 `10` 一行数字特别大，以为是今天 10 点爆了。

### 完整解答

**一句话**：combined 的 `$4` 含 **日期+时间**——只取 2 位小时会把 **跨天同一小时加总**；key 用 `substr($4,2,11) substr($4,14,2)`（日期+小时）。

```bash
# 错：跨天 10 点合并
awk '{h=substr($4,14,2); count[h]++} END {for (h in count) print h, count[h]}' access.log

# 对：日期+小时
awk '{k=substr($4,2,11) substr($4,14,2); count[k]++} END {for (k in count) print k, count[k]}' access.log | sort
```

```text
02/Sep/2026:09 12450
02/Sep/2026:10 28901
01/Sep/2026:10 15234   ← 昨天 10 点单独一行
```

活动复盘要对 **活动日当天** 切片，或按文件分天再统计。

### 再追问

**分钟级呢？**——combined 分钟常用 `substr($4,14,5)`（含冒号，如 `10:00`），仍建议带日期前缀。

## Q14

**★★★☆☆｜`sed -i.bak` 改错了怎么回滚？macOS 和 Linux `sed -i` 差在哪？**

**覆盖**：必会 · 常考

**对应**：知识点 [语法必会](知识点.md) · [踩坑清单](知识点.md)

### 场景

有人 Linux 上 `sed -i 's/max_connections=500/max_connections=100/' my.cnf` 没备份，把已经正确的 500 改回 100。另一人在 macOS 上 `sed -i 's/a/b/' file` 报错或生成了怪文件。

### 完整解答

**一句话**：生产改文件 **先 diff 预览**，确认后 **`sed -i.bak`**；回滚用 **`.bak` 覆盖回去**；macOS BSD sed 要 **`sed -i ''`** 或统一写 **`sed -i.bak`**。

```bash
# 预览（不加 -i）
sed 's/max_connections=500/max_connections=100/' my.cnf | diff -u my.cnf -

# 确认后备份写入
sed -i.bak 's/max_connections=500/max_connections=100/' my.cnf

# 改错了回滚
cp my.cnf.bak my.cnf && diff -u my.cnf.bak my.cnf   # 应无差异
```

macOS：`sed -i` 把下一个参数当备份后缀——`sed -i '' 's/a/b/' file` 无备份；`sed -i.bak` 与 Linux 行为一致，跨平台脚本推荐 **`-i.bak`**。多机批量仍走 Ansible/Git，不是 SSH 裸 `sed -i`。

### 再追问

**没有 .bak 呢？**——从 Git 还原或配置中心拉上一版；这就是为什么变更要走 GitOps，本地 sed 只是应急刀。
