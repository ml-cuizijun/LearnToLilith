## ★★★★★ 必考

### Q1：控制面各组件分别干什么？只和谁通信？业务能不能直连 etcd？

**★★★★★**

**场景**  
有人给自研 Operator 配了 etcd 直连，「少走一跳 API」。先画分层再否决。

**完整解答**

没有箭头从 kubelet / 业务指向 etcd。

```
  Scheduler --> API Server <--> etcd      （控制面）
  Controller ------^
                    |
               Watch / 下发
                    v
         kubelet / kube-proxy            （只连 API）
```

1. **API Server**：唯一入口。认证 → 鉴权 → 准入 → 写 etcd。
2. **etcd**：唯一状态库。**只有 API Server 读写。**
3. **Scheduler**：写 `spec.nodeName`。不管镜像起没起来。
4. **Controller**：Reconcile 一类资源，不调 CRI。
5. **kubelet** 起容器；**kube-proxy** 把规则写进内核。

业务或 Operator **不能直连 etcd**：绕过认证、准入、审计，脏数据会被控制器「自愈」放大。

**再追问：Scheduler 绑成功但容器没起来，谁负责？**  
kubelet + 运行时 + 镜像 / CNI / CSI。Scheduler 不感知启动成败。

### Q2：etcd、API Server、Scheduler、kubelet 分别挂了，游戏服还在吗？还能发版吗？

**★★★★★**

**场景**  
合服窗口 API 全超时。群里要重启全部逻辑服「对齐状态」。玩家会不会掉线？

**完整解答**

拆三问，不要答「集群挂了」：**进程还在？能不能变更？流量还通？**  
口诀：控制面挂 = 失忆、不能决策；数据面进程不立刻死。

```
  组件挂了
     |
     +--> 已运行容器进程：通常还在
     +--> etcd / API：不能 apply / 扩容 / 自愈 / 合服
     +--> 只 Scheduler：新 Pod Pending
     +--> 只 kubelet：本节点 NotReady，进程还在（先别杀）
```

etcd / API 挂了：已经打上的长连接通常不掉；合服、热更、扩容、补副本全部停。不要为了「做点什么」去重启还活着的逻辑服。kubelet 挂了不会立刻踢玩家——失联约 40s 标 NotReady，约 5min 才驱逐（16）。先救 kubelet。

**再追问：为什么流量还能走？**  
kube-proxy 已把规则写进内核。控制面挂了，iptables / IPVS 和已有 conntrack 不会瞬间蒸发。变的是：**再也更新不了**。

### Q3：声明式和命令式差在哪？K8s 为什么用声明式？apply 会不会把 HPA 改过的副本数打回去？

**★★★★★**

**场景**  
流水线循环 `kubectl create`，已存在就报错。另一边 HPA 已扩到 20，Git 里仍写 `replicas: 3`。

**完整解答**

命令式说「怎么做」，做完就结束。声明式说「要什么」，控制器一直对齐：

```
  期望 YAML --> 看现状 --> 一致?
                         |否
                         v
                    创建/删除/更新 --> 再看
```

重复 apply 结果一样，才能自愈和 GitOps。应急可以 `scale`，当天必须把声明改掉。

HPA 和 YAML 抢同一个字段：下次 apply 可能把 20 打回 3。工作负载 YAML 不要把 replicas 当唯一真相，或用 SSA 让 HPA 管这个字段。

**再追问：声明式是不是不能 kubectl edit？**  
能，那是止血。24 小时内补回 Git，否则下次同步把热修盖掉。

### Q4：一个 Pod 从 apply 到接上 Service 流量，经过哪些步？卡在哪怎么判断？

**★★★★★**

**场景**  
开服大厅 `apply` 之后 Service 一直没有 Endpoints。有人说调度坏了。

**完整解答**

```
  ① apply 写 etcd
  ② Controller 建 Pod
  ③ Scheduler 写 nodeName          ← 到这里还没有容器
  ④ kubelet 配网 / 拉镜像 / 起容器
  ⑤ Ready? --否--> 不进 Endpoints
  ⑥ EndpointSlice --> kube-proxy 更新规则
```

1. **Pending**（无 nodeName）：资源、污点、亲和、PVC。这才是调度。
2. **ContainerCreating**（已有 nodeName）：镜像、CSI、CNI。Scheduler 已干完。
3. **Running 但 Endpoints 空**：readiness 失败，或 selector 和 Label 对不上。
4. **Endpoints 有仍不通**：kube-proxy、CNI、端口。

**再追问：Scheduler 成功了容器没起来，谁的责任？**  
kubelet + 运行时。Scheduler 不感知启动成败。

### Q5：etcd 挂了玩家会掉线吗？为什么必须奇数节点？

**★★★★★**

**场景**  
3 节点 etcd 丢了 Leader 所在盘。运营问「全区会不会立刻掉线」；有人建议加第 4 台「更稳」。

**完整解答**

etcd 挂 ≠ 数据面立刻死。已运行进程和已写入内核的转发规则还在；不能发版、扩容、自愈、合服。已经打上的战斗长连接通常不马上掉。先救 quorum 和盘，不要重启还活着的逻辑服。

Raft 靠多数派：`N/2+1`。偶数多一台机器，容错台数不变。

```
  3 节点：quorum=2，容 1     （生产最小）
  4 节点：quorum=3，仍容 1   （浪费一台）
  5 节点：quorum=3，容 2     （要抗 2 个故障才上）
```

同城 3 够用。控制面 etcd 不要跨地域。多数派还在时换坏节点，不要 restore。

**再追问：3 丢 2 还能写吗？**  
不能。多数派没了只能停写，靠演练过的快照 restore。不要对剩下那一台乱 `member add`。

### Q6：请求过 API 的链路？Webhook Fail 会怎样？

**★★★★★**

**场景**  
刚装 Validating Webhook，创建 Deployment 全部失败。有人说 API Server 挂了。

**完整解答**

三道门串行，任何一步停：

```
  kubectl --> 认证 401 --> 鉴权 403
                --> Mutating（先改）--> Validating（再拒）
                --> 写 etcd
```

`failurePolicy: Fail` 且 Webhook 挂 / 超时 = **创建更新全拒**，比业务先把写路径焊死。单副本 Webhook 没有 PDB，是经典事故形状。

紧急：临时改 `Ignore` 或删 Configuration（要审批、留窗口），修完改回 Fail。改 Ignore 的代价是策略失效。

**再追问：metrics-server 挂了算 API 挂了吗？**  
不算。`top` 失败、HPA 变 unknown，业务对象仍可读写。

### Q7：三探针区别？能不能共用一条业务健康？

**★★★★★**

**场景**  
逻辑服把 liveness / readiness 配成同一条「依赖 Redis 的健康检查」。Redis 抖一下，全区被重启。

**完整解答**

三条问的不是同一件事，不要配成同一条 URL。

```
  startup   启动完了没有？通过前不跑另外两条；失败 → 重启
  liveness  进程还活着吗（死锁/假死）？失败 → 重启；不负责「忙」
  readiness 现在能不能接新请求？失败 → 摘 Endpoints，不重启
```

错误：liveness 打依赖；没有 startup 却把 liveness delay 拉到 120s；readiness 永远成功。  
正确：startup 护启动；liveness 只探死锁（浅）；readiness 问依赖、预热、队列。

**再追问：readiness 失败会杀进程吗？**  
不会。只摘流。摘流 ≠ 杀进程。有状态逻辑服更要配 readiness，没准备好不应进 Endpoints。

### Q8：优雅退出顺序？preStop 和 SIGTERM 谁先谁后？

**★★★★★**

**场景**  
滚动一堆 502。YAML 里写了 preStop sleep 5，有人以为「sleep 完才发 SIGTERM」。

**完整解答**

**preStop 不是「跑完再发 SIGTERM」，两者同时开始。**

```
  删 Pod / 滚动 / HPA 缩容
        |
        v
  从 Endpoints 摘除（异步，kube-proxy / LB 要几秒）
        |
        +---- 同时 ----+
        |              |
     preStop        SIGTERM
     （常 sleep 等摘流）  停接新连接、刷脏
        |
        v
  grace 超时 --> SIGKILL（137）
```

kube-proxy 摘流要几秒，应用立刻退出 → 路上的包打空连接 → 502。生产：`terminationGracePeriodSeconds` 大于 preStop + 刷盘；应用必须处理 SIGTERM（PID 1 要能收到）。

**再追问：sleep 还没完就被 137？**  
grace 短于 preStop。把 grace 拉过 sleep + 刷盘，不要再加一层 sleep 幻想能挡住 SIGKILL。

### Q9：游戏有状态逻辑服能随便上 liveness、随便杀吗？

**★★★★★**

**场景**  
战斗服按 Web 默认配了 liveness，一次假死把整房玩家踢光。有人说「换 STS 就不会被杀」。

**完整解答**

无状态：杀一个，Service 换另一个。逻辑服：对局在 **进程内存**，杀进程 = 踢对局。

1. liveness 慎配，或只探死锁且阈值拉宽；不要把「队列长 / Redis 抖」写成 liveness。
2. 杀之前：停匹配、禁新进、等对局结束或持久化。
3. 大厅 / 网关可按 Web 滚；绑定房间的进程按有状态来。
4. **readiness 仍要配**——没准备好不应进 Endpoints。
5. 换 STS 仍会按序杀 Pod，不是免死金牌。核心服 QoS 用 Guaranteed。

**再追问：HPA 缩容算不算「杀」？**  
算。HPA 直接改 replicas，控制器删进程；PDB 挡不住。房间服不要挂自动缩。

### Q10：CrashLoop 第一刀？退出码 137 / 1 / 139？

**★★★★★**

**场景**  
大厅反复 CrashLoop。有人先 `rollout restart`，日志没了，退出码也没人看。

**完整解答**

第一刀永远是 `logs --previous` + Last State 退出码。重启会丢掉证据，有状态还会踢玩家。

```
  137 = 128+9 SIGKILL     OOM 或 grace 超时强杀
  143 = 128+15 SIGTERM
  139                     段错误
  1 / 2                   应用自己退：配置、依赖、命令
```

137 先看 Reason 是不是 OOMKilled；没有则多半是 grace 用尽。Events 有 Unhealthy → liveness 误杀。刚启动就退 → startup 不够或依赖没起。

**再追问：没有日志怎么办？**  
先看 command / env / volume / 退出码，不要先加内存。P0 先把 `describe` 落盘再重启。

### Q11：Deploy / STS / DS 怎么选？STS 是游戏服免死金牌吗？

**★★★★★**

**场景**  
战斗服要稳定身份和独立盘，有人说「上了 STS 就可以当 Web 默认滚」。

**完整解答**

```
  跑完就停 ------------> Job / CronJob
  每节点都要有 --------> DaemonSet（日志 / CNI）
  固定名字、有序、独立盘 -> StatefulSet
  副本可互换、无状态 ----> Deployment
  不要手建 ReplicaSet
```

可互换 → Deploy。固定身份和独立盘 → STS（必须 Headless）。每节点 → DS。STS 解决身份和盘，**滚动仍按序换 Pod，对局里的进程一样会被杀**。还要业务侧停匹配 / 热迁。

**再追问：删 STS 默认会删 PVC 吗？**  
不会。缩容也不自动删高序号 PVC。要释放费用必须显式删；Retain 还要再删云盘。

### Q12：maxSurge / maxUnavailable？怎样接近零停机？

**★★★★★**

**场景**  
大厅滚动 502。策略是 25%/25%，没有 readiness。有人说「surge 开大一点就零停机」。

**完整解答**

surge = 额外能起多少；unavailable = 同时允许多少不可用。滚动等的是 **Ready**，不是 Running。

```
  unavailable=0 + surge=1   先起再杀，容量不掉，多吃 1 个副本
  surge=0 + unavailable=1   先杀再起，有缺口
```

零停机四件套：unavailable=0、**readiness**、preStop + SIGTERM、grace 够。没有探针，K8s 把 Running 当可接流量。`minReadySeconds` 防「Ready 立刻又挂」。卡住不会自动 undo。

**再追问：surge 开大了滚动卡住？**  
资源紧时新 Pod Pending，看起来像滚动死了，其实是调度。先看 Events，不要再加大 surge。

### Q13：PDB 管什么？不管什么？drain 被挡住怎么办？

**★★★★★**

**场景**  
维护 drain 卡死。有人准备删 PDB「先把节点腾出来」。HPA minReplicas=1，PDB minAvailable=2。

**完整解答**

PDB 只拦 **自愿中断**（drain、部分升级驱逐）。不管宕机、OOM、磁盘坏，也 **不管 HPA 改 replicas**。

```
  drain：再赶一个会低于 minAvailable？会 → 挡住
  节点断电 / OOM / HPA 缩容：PDB 不管
```

挡住先看是不是保护生效：扩容、迁玩家、等迁移，不要先删 PDB。HPA `minReplicas` 必须 ≥ PDB minAvailable，否则永远赶不走。单副本战斗服 `minAvailable: 1` 会让 drain 直接卡死——这是保护。没有 readiness，PDB 按 Running 计数，账面满足、流量已 502。

**再追问：HPA 把副本缩到 PDB 下面会怎样？**  
缩得成。PDB 不拦控制器改 replicas。房间服不要靠 PDB 防 HPA。

### Q14：Pending 怎么查？Scheduler 看 top 还是 request？

**★★★★★**

**场景**  
节点 `top` 还空，新大厅一直 Insufficient cpu。有人要给节点加 CPU。

**完整解答**

先 `describe` Events，分清「没绑上节点」还是「绑了但 kubelet 卡住」。

```
  无 nodeName：资源 / 亲和 / 污点 / PVC / 0/N nodes
  有 nodeName：镜像 / sandbox（CNI）/ 挂卷
  全体新 Pod Pending：scheduler 在不在
```

Scheduler 看 **request vs Allocatable**（Capacity − kubeReserved − systemReserved − eviction 预留），不看 `top`。`top` 是瞬时用量；request 之和把 Allocatable 吃满就会 Insufficient。硬反亲和在节点不够时也会永远 Pending。

**再追问：PVC 显示 waiting for first consumer 算故障吗？**  
不算。WFFC 要等 Pod 落到 AZ 再建盘。先把引用它的 Pod 创建出来。

### Q15：Service Endpoints 为空，第一刀看什么？

**★★★★★**

**场景**  
ClusterIP 能 ping，玩家进不去。有人要重启 kube-proxy。

**完整解答**

Endpoints = **Ready 且 selector 命中的 Pod**。空 = 不转发。Service 对象在、VIP 通，也不等于有后端。

```
  selector: app=logic
     |
     +-- labels 命中且 Ready --> 进 Endpoints
     +-- 打在 annotation 上 / 拼错字母 --> 空
     +-- Running 但 readiness 失败 --> 空
     +-- 搞错 Namespace --> 空
```

先修探针 / 标签，不是先重启 kube-proxy。有 Endpoints 仍不通：targetPort、listen、NP、CNI。先 Pod 内 curl localhost，再从另一 Pod 打 ClusterIP。

**再追问：滚动时打到正在退出的 Pod？**  
摘除和 IPVS 更新有延迟。靠 readiness 先摘 + preStop 等待。不要让应用立刻退出。

### Q16：Service 到 Pod 怎么走？iptables 和 IPVS 差在哪？

**★★★★★**

**场景**  
Service 过千以后，节点 kube-proxy CPU 飙、同步规则变慢。有人说数据包都挤在 kube-proxy 进程里。

**完整解答**

数据包不经过 kube-proxy 用户态。它只更新本机规则。

```
  DNS --> ClusterIP --> 本机 DNAT --> Pod IP
                         （跨节点走 CNI）
```

iptables 查找近似 O(n)，更新常整表刷新。IPVS 哈希 O(1)，大集群评估切换。userspace 已废弃。切 IPVS 要内核模块，改 CM 后重启 kube-proxy DS。

**再追问：kube-proxy 挂了，已在线的长连接会怎样？**  
规则已在内核，存量往往还能走；新登录、滚动后的新 Pod 会出问题。先拉起 proxy，不要重启游戏进程。

### Q17：四种 Service？Headless 的 DNS 回什么？

**★★★★★**

**场景**  
STS 的 mysql-0 被配了 ClusterIP，「连指定 ordinal」却连错人。

**完整解答**

```
  ClusterIP     集群内 VIP，最常用
  NodePort      节点高端口，仍有 ClusterIP；生产少裸奔
  LoadBalancer  云 LB 对外；配额用尽会一直 Pending
  Headless      clusterIP: None，DNS 回 Pod IP 列表
```

Headless 没有 VIP，kube-proxy 几乎不管负载均衡。STS 靠它解析 `mysql-0.mysql-headless.ns.svc.cluster.local`。要用 ClusterIP 当「连指定 ordinal」会连错人。客户端不直打 ClusterIP；游戏长连接走网关 / L4 LB。

**再追问：LoadBalancer 一直 Pending 是 K8s 坏了吗？**  
多半是云 controller 没拿到 LB（配额）。先看云控制台，不要重启 API。

### Q18：CNI 和 kube-proxy 分工？网络三原则？

**★★★★★**

**场景**  
新 Pod `FailedCreatePodSandBox`，有人去翻业务日志，又去重启 kube-proxy。

**完整解答**

三原则：一 Pod 一 IP；互访无 NAT；节点 Agent 能碰到 Pod。

```
  Ingress / 云 LB     南北向入口
  Service VIP         kube-proxy 写内核规则
  Pod IP <-> Pod IP   CNI（东西向）
  名字                CoreDNS
```

IP 不是 kube-proxy 发的。kubelet 起 sandbox 时调 CNI：IPAM → veth → 路由。sandbox 失败时业务容器还没开始。`kubeadm --pod-network-cidr` 必须和 CNI 清单一致。

**再追问：同节点通、跨节点不通先 ping 哪？**  
节点 ↔ 节点，再隧道口，再对端 Pod。常见漏 VXLAN 4789 / IPIP 协议 4 / BGP 179。

### Q19：NetworkPolicy 默认行为？裸 Flannel 能用吗？

**★★★★★**

**场景**  
给支付 NS 上了 Ingress 规则，全集群名字解析挂了。CNI 是裸 Flannel。

**完整解答**

无 NP = 全通（跨 NS 也通）。Pod 被某方向规则选中后，**该方向默认拒**，只放行写过的。多条是并集。

```
  落地：CNI 必须支持 NP → 默认拒入站 → 先放行 DNS 53
        → 再放行网关 → 再放行 backend→DB
```

裸 Flannel 通常 **不生效**（YAML 能 apply）。要 NP 用 Calico / Cilium。刚上 NP 全网名字挂 = 没放行 53。改 NP 即时生效，误加 deny-all 是秒级事故。

**再追问：有 RBAC 还要 NP 吗？**  
要。RBAC 不管包；NP 不管 kubectl。支付最低配是独立 NS + 最小 RBAC + NP 默认拒。

### Q20：滚动 502 和就绪探针是什么关系？

**★★★★★**

**场景**  
大厅滚动期间 502 尖刺。新 Pod 已经 Running，旧的还在 TERM。

**完整解答**

没有 readiness，K8s 把 Running 当可接流量，未就绪就进 Service。滚动 502 四件套缺一不可：

1. `maxUnavailable: 0`（先起后杀）
2. **readiness** 挡住未就绪
3. preStop + 处理 SIGTERM，grace 够
4. 摘流完成前进程不要立刻退出

liveness 过严会在滚的过程中杀新 Pod。surge 过大导致 Pending 时，看起来像滚动卡死，先看调度。

**再追问：Endpoints 里还有正在退出的 Pod？**  
摘除异步。preStop sleep 几秒等 kube-proxy / LB，应用处理 SIGTERM 停接新连接。

### Q21：drain 一台节点会怎样？能不能裸关机？

**★★★★★**

**场景**  
夜班直接 shutdown 战斗节点「反正有副本」。PDB 也没配。

**完整解答**

不要裸关机。正确顺序：cordon → drain → 维护 → uncordon。

```
  cordon     不接新 Pod，已有还在跑
  drain      驱逐业务 Pod，尊重 PDB 和 grace
             DS 通常留（本节点仍要日志 / CNI）
  uncordon   再接调度
```

drain 卡住先查 PDB、裸 Pod、emptyDir、STS 绑盘，不要 `--force` 开路。游戏单进程区服：drain 前先迁玩家。裸关机：约 40s NotReady，约 5min 驱逐；双节点同时核，PDB 也救不了。

**再追问：drain 会杀 DaemonSet 吗？**  
通常不杀。`--ignore-daemonsets` 是让 drain 不要卡在 DS 上。CNI / 日志还要留在本机。

### Q22：排障三宝？什么时候才能重启？

**★★★★★**

**场景**  
夜班只留下「我重启好了」。早会复盘没有 Events，也没有 `--previous`。

**完整解答**

定域顺序：Events → spec/status → 节点 / CNI / CSI → 应用日志。不要一上来重启。

```
  describe  Events、探针、退出码、调度失败
  logs --previous   上次崩溃；多容器必须 -c
  exec              进得去才有用；走 API → kubelet
```

Pending 走调度树；CrashLoop 先退出码；OOMKilled ≠ Evicted；Running 不通走分层（本机 → ClusterIP → 跨节点）。P0 先把 `describe` / events 落盘。有状态重启 = 踢玩家。

**再追问：exec 进不去先怀疑什么？**  
RBAC（缺 pods/exec）、NetworkPolicy、API / kubelet。生产先只读。

### Q23：etcd 备份没演练算有吗？compact 和 defrag 差什么？

**★★★★**

**场景**  
文档写着「每 6h snapshot」。从没 restore 过。有人要在开服高峰对 Leader 做 defrag。

**完整解答**

没演练过的备份等于没有。季度要测 RTO：restore 步骤、token、证书、谁执行、业务怎么广播「这段不能发版」。

多数派还在：`member remove` + `member add`，不要 restore。多数派没了才 snapshot restore。

```
  compact  删旧 revision，逻辑空间下降（K8s 通常自动）
  defrag   整理碎片，阻塞该成员；维护窗口逐节点
```

只 compact 不 defrag，磁盘占用下不来。高峰 defrag = 主动丢一台。

**再追问：Watch 报 too old revision 是 etcd 坏了吗？**  
不是。revision 被 compact 掉，客户端重新 List。compact 过猛会让 Informer 同时打满 List，表象是 API 429。

### Q24：API 变慢先看谁？429 怎么办？

**★★★★**

**场景**  
kubectl 偶发超时，P99 从 20ms 到 2s。CPU 不忙。刚装 Webhook。有人要加 API 副本、加大 inflight。

**完整解答**

十次里九次是 **etcd 磁盘 fsync** 或 **准入 Webhook 超时**，不是 API CPU。

```
  kubectl --> API --> Webhook --> etcd fsync
               |         |            |
            自己很少瓶颈  超时=写路径死  盘慢=全集群慢
```

LB 探活要用 `/readyz`，只探 6443 TCP 会把「进程在、不能写」的实例留在池里。429 是 APF / inflight 队列满：找肇事客户端（坏 CI、只轮询的 Informer），不要无脑加大 inflight——那只是推迟打爆 etcd。只加 API 副本，肇事者会一起锤 etcd。

**再追问：Webhook 和 etcd 怎么一眼分开？**  
看 Webhook 延迟 / 超时日志 vs etcd WAL fsync P99（>25ms 就要处理）。先 `iostat` etcd 那块盘。

### Q25：QoS 三级怎么分？核心战斗服用哪级？

**★★★★**

**场景**  
节点内存紧，BestEffort 的边角服务和没写 request 的战斗服一起被赶。

**完整解答**

Scheduler 看 request 记账；节点内存不够时 kubelet 按 QoS 赶人。

```
  requests == limits     Guaranteed   节点 OOM 最后杀
  有 request、不等于 limit Burstable    中间
  都没设                 BestEffort   先被杀 / 先被 Evict
```

CPU 超 limit：throttle，不杀。内存超 limit：OOMKill。核心战斗服、支付用 Guaranteed。没写 request，调度当 0，HPA 算不了利用率，容易超卖后 Evict。

**再追问：limit 按堆大小填够吗？**  
不够。limit 按 cgroup 总量（堆外、缓冲、运行时）。Java / Go 通常留 30–50%。

### Q26：OOMKilled 和 Evicted 差在哪？

**★★★★**

**场景**  
战斗服没了。有人说「内存不够」，分不清是容器超限还是节点压力。

**完整解答**

| | OOMKilled | Evicted |
|--|-----------|---------|
| 谁动手 | 本容器超了自己的 memory **limit** | 节点 Memory / Disk / PID Pressure |
| 先看 | describe Last State；RSS 趋势 | describe node Conditions |
| 处理 | limit 过小还是泄漏 | 清镜像 / 日志 / emptyDir，或扩节点 |

RSS 持续涨是泄漏；启动就顶满是 limit 不够或启动峰值。别只说「加内存」。DiskPressure 常清 containerd 镜像和容器日志。这和「整机还空、容器被杀」可以同时成立。

**再追问：CPU 超 limit 会 OOM 吗？**  
不会。CPU 是 throttle。杀进程的是内存 limit 或节点压力驱逐。

### Q27：required 和 preferred 差什么？NoExecute 会赶已有 Pod 吗？

**★★★★**

**场景**  
大厅 3 副本配了硬反亲和 `topologyKey: hostname`，集群只有 2 个节点，第 3 个永远 Pending。

**完整解答**

硬（required）不满足 → Pending。软（preferred）只加分，节点不够也能上。无状态优先 topologySpread，硬 anti-affinity 留给「必须不同节点」且节点数 ≥ 副本。

污点 Effect：

```
  NoSchedule       新的不来，已有不动
  PreferNoSchedule 尽量不来，已有不动
  NoExecute        不来，且驱逐无容忍的已有 Pod
```

改亲和 / 选择器只影响下一轮调度；要搬家靠驱逐或滚动。NoExecute 除外。节点 NotReady 时控制面会打 NoExecute 类污点（16）。

**再追问：GPU 节点怎么防大厅 HPA 占上去？**  
节点打 NoSchedule 污点，只有带对应 toleration 的 Pod 能上。不要靠口头约定。

### Q28：HPA 公式？为什么必须有 requests？

**★★★★**

**场景**  
HPA 目标 60% CPU，指标一直 `<unknown>`。Pod 没写 resources.requests。

**完整解答**

`desired = ceil(当前副本 × 当前值 / 目标值)`。多指标各算一遍取 **max**，再夹在 min～max。例：3 副本、CPU 90%、目标 60% → `ceil(3×90/60)=5`。

利用率分母是 **request**。没写 request，资源 HPA 算不了。条件看 `AbleToScale` / `ScalingActive` / `ScalingLimited`。指标 unknown = metrics-server / Adapter 挂了，或没 requests。

扩快缩慢。开服提前把 min 拉到峰值 1.2–1.5 倍，不要等 15s 环在进服瞬间再扩。

**再追问：只看 CPU 给网关做 HPA 行吗？**  
长连接、等后端时 CPU 不高但连接已满，只看 CPU 会误缩。网关更常看 QPS / 连接数 / 排队。

### Q29：HPA 解决不了有状态游戏服什么？

**★★★★**

**场景**  
房间服挂了 70% CPU 的 HPA。活动后自动缩容，正在打的玩家被踢。

**完整解答**

HPA 假设副本可互换、杀谁都行、状态在外面。战斗 / 房间不满足。

```
  扩：新副本不会自动分走已有房间
  缩：随机杀 Pod = 踢正在打的玩家
  PDB：挡不住 HPA 改 replicas
```

接入层 / 大厅 / HTTP 商城可以 HPA（缩要慢，配 PDB）。有状态逻辑服：容量靠开服规划 + 分服；扩 = 新进程接新房间；缩 = 只缩 CCU=0 的，或自研控制器。被缩光：立刻把 min 拉回或删 HPA，停匹配。

**再追问：Cluster Autoscaler 能解决绑本地盘的战斗服吗？**  
不能。Pending 才加节点；本地盘过不去新节点。CA 解决的是「要更多 Node」，不是迁盘。

**完整解答**

### Q31：ndots:5 会怎样？CoreDNS 挂了业务还通吗？

### Q32：跨节点不通怎么拆？sandbox 失败看什么？

**★★★★**

**场景**  
同节点 Pod 能 ping，跨节点全不通。有人在业务容器里抓了半天应用包。

**完整解答**

先分同节点 / 跨节点，不要一上来抓业务包。

```
  ① node-A ping node-B          物理 / VPC
  ② ping 对端隧道口 / VTEP
  ③ Pod-A ping Pod-B            完整 CNI 路径
```

只跨节点：隧道 / BGP / 安全组（VXLAN 4789、IPIP 协议 4、BGP 179）/ MTU（小包通大包丢）。sandbox 失败：CNI 插件挂、IP 池耗尽、pause 拉不下来、maxPods 和 CIDR 不一致。业务日志此时没有用。

**再追问：Overlay 仍用 MTU 1500？**  
VXLAN 要减（常见 1450）。`ping -M do -s 1400` 能复现。TCP 会表现为奇怪超时，不像完全 ping 不通。

### Q33：PVC / PV / SC 各是什么？RWO 能给 Deploy 多副本用吗？

**★★★★**

**场景**  
大厅 3 副本挂同一块云盘。只有 1 个 Running，另外两个 Pending。

**完整解答**

PVC 是申请（容量、accessMode、SC 名）；PV 是实际卷；SC 是自动建盘模板（provisioner、回收、绑定模式）。应用只引用 PVC 名。绑定一对一。

RWO = 单节点读写。Deploy 多副本抢同一块 RWO → 其余 Pending。一人一盘走 STS `volumeClaimTemplates`。共享文件才上 RWX（NFS / EFS），不要把云盘 SC 改成 RWX 幻想会变共享。

**再追问：两个 Pod 抢盘怎么确认？**  
看 accessMode 是 RWO 还是 ReadWriteOncePod，以及盘当前 attach 在哪台节点。不要先重启 kubelet。

### Q34：生产 ReclaimPolicy 为什么用 Retain？WFFC 是什么？

**★★★★**

**场景**  
测试习惯 Delete。有人在生产删了 PVC，云盘一起没了。另一边 PVC 一直 `waiting for first consumer`。

**完整解答**

Delete：删 PVC 连底层云盘一起毁。Retain：PV 变 Released，数据还在，人清。生产库、战斗回放盘必须 **Retain + 备份**。Released 要清 `claimRef` 才能复用，或删 PV 留云盘再静态导入。

WFFC：等 Pod 落到某 AZ 再建盘。Immediate 会先在 A 区建盘，Pod 调到 B 区永远 FailedAttachVolume。看到 waiting for first consumer **不是故障**，先把 Pod 创建出来。

**再追问：误删 PVC 后空 PVC Bound 算修成功吗？**  
不算。先看云盘回收站 / 快照，再谈回档。游戏先停服再挂旧盘，避免双写。

### Q35：Secret 加密吗？env 改了会热更新吗？

### Q36：RBAC 四件套？最小权限怎么落地？

**★★★★**

**场景**  
CI 拿着 cluster-admin 到处 apply。业务 default SA 也能 list secrets。

**完整解答**

Role / ClusterRole 是规则；RoleBinding / ClusterRoleBinding 才是发卡。绑错范围就是提权。

1. 人走 OIDC，不共享 kubeconfig。

### Q37：PSS 三级？PSP 还能用吗？

**★★★★**


### Q38：Ingress 没有 Controller 会怎样？502 先看什么？长连接走七层吗？

**★★★★**

**场景**  
apply 了 Ingress，没有 ADDRESS。另一边入口 502。战斗长连接被 nginx `proxy-read-timeout` 掐断。

**完整解答**

Ingress 是规则，**Controller 是执行者**。没有 Controller，规则不生效。`ingressClassName` 不对也会「规则在、流量不来」。

HTTP 大厅、商城走七层；战斗长 TCP 走 L4 NLB / Gateway TCPRoute。不要所有流量一层 nginx：读超时、缓冲、reload 都会断长连接。单副本入口一 reload，长连接全断。

**再追问：undo Deploy 之后 Ingress 还 502？**  
可能 CM / 端口 / Endpoints 仍空。undo 不回入口和配置。先 `get ep`。

### Q39：蓝绿 vs 金丝雀？undo 不够时还要回什么？

**★★★★**

**场景**  
`rollout undo` 代码回去了，登录仍失败——CM 和表结构已经是新的。有人说「再观察 10 分钟」。

**完整解答**

观察窗口看错误率、P99、登录成功率、CCU，不要只看 Pod Ready。

```
  滚动     同一 Deploy 逐步换；靠四件套接近零停机
  蓝绿     两套齐活，切 selector / Ingress；回切秒级，双倍资源
  金丝雀   入口 weight 准，副本比例粗；5% 已坏就归零
```

`rollout undo` 只回工作负载 revision。CM、Secret、CR、DB schema、客户端版本不在里面。数据已写新 schema：停写，评估正向修，禁止盲 undo 代码。historyLimit=0 无法 undo。

**再追问：蓝绿切流后 DB 不兼容怎么回？**  
selector 切回蓝只回流量。表结构要双版本兼容窗口：先加列 → 发代码 → 再删旧列。道具表乱改是回滚死局。

### Q40：游戏战斗服怎么灰度？热更等于滚动吗？

**★★★★**

**场景**  
战斗服按大厅的 10% 金丝雀滚。对局被杀。运营以为「昨天热更过了所以这次滚动无感」。

**完整解答**

对局在内存里。滚 = 杀进程。新副本不会自动接手旧房间。

```
  1. 停匹配 / 禁新进
  2. 新实例只接新房间，或等对局结束
  3. 旧进程自然空了再下
  4. 协议不兼容 → 客户端门闸，不是多滚几个 Pod
```

看 CCU / 登录成功率，不只 Ready。热更是配置 / 脚本热加载、进程不杀；下一次 Deploy 仍会杀进程。两套通道写在同一张发布单上。开服当天禁止普通灰度，只留 hotfix。

**再追问：只滚服务端 10%，客户端 100% 打到新入口？**  
入口没切分就会这样。用 header 圈内部号，或 Gateway weight + 客户端版本门闸同时开。

### Q41：集群升级顺序？kubelet 能不能比 API 新？

**★★★★**

**场景**  
托管点了「升级控制面」。有人先把战斗节点 kubelet 升上去「试试看」。

**完整解答**

先控制面，后节点；一次一小版本。**kubelet 不能新过 API Server**（可落后约 2 个小版本）。反过来节点先升，会出现奇怪的 API 错误。

```
  1. 发行说明：CNI / CSI / Operator 兼容
  2. 备份 etcd
  3. 升控制面（API / controller / scheduler）
  4. 逐节点：drain → runtime → kubelet / kube-proxy → 健康检查 → uncordon
  5. 再升 CNI、CoreDNS、metrics-server
```

战斗服单独池、单独窗口，先空服再升。厂商不会 drain 你的战斗服。一次并行 drain 多台 = 自己做故障演练。

**再追问：升级后 Pod 起不来先对哪几项？**  
skew（节点新过 API）→ cgroup driver → pause 镜像 → CNI 版本。

### Q42：节点失联约 40s / 5min 各发生什么？进程还在吗？

**★★★★**

**场景**  
kubelet 进程没了。有人要立刻删 Pod「让控制器在别的节点拉起来」。玩家还在打。

**完整解答**

kubelet 挂了 **进程通常还在**。控制面不会立刻杀容器。

```
  ~40s   node-monitor-grace-period
         节点 Ready=False / Unknown，打上 NoExecute 污点
  ~5min  默认容忍结束，不容忍的被驱逐，控制器在别处重建
```

这窗口里长连接可能还活着。先救 kubelet / 磁盘 / 网络 / CNI，不要先删业务 Pod 对齐状态。答题说「约 40s 标 NotReady，约 5min 开始驱逐」，不要说立刻死。证书过期、PLEG unhealthy 同样心跳失败。

**再追问：这和 kubelet 压力驱逐是一路吗？**  
不是。Memory/Disk/PID Pressure 是 kubelet 按 QoS 赶人（04），和「失联后控制面打污点再驱逐」分开。

### Q43：conntrack 满了什么现象？游戏网关为什么必监控？

**★★★★**

**场景**  
登录间歇超时，存量长连接还在。dmesg 有 `nf_conntrack: table full`。默认 max 65536。

**完整解答**

满了：新连接失败 / 间歇超时，**旧长连接往往还在**。K8s SNAT / DNAT 必占表。游戏网关 CCU 高，默认 65k 不够。

止血：调高 max；长期降 established 超时、查短连接泄漏。监控 `nf_conntrack_count / max`，>80% 告警。不要先重启游戏进程——那会主动拆掉还活着的连接。

**再追问：只某节点的玩家进不去？**  
对照该节点 conntrack、kube-proxy 规则和 EndpointSlice。部分节点不通常常是本机规则或表满，不是全集群 Service 坏了。

### Q44：Namespace 是安全边界吗？战斗服和支付怎么隔离？

**★★★★**

**场景**  
「支付单独一个 NS 就合规了吧？」跨 NS 默认能不能连？

**完整解答**

**不是安全边界。** NS 是逻辑隔离：配额、RBAC 范围、人好找。跨 NS 默认三层能通；cluster-admin 也能动别的 NS。

```
  ns:hall  <-->  ns:battle  <-->  ns:pay
           （默认能通，没有 NP 就不是墙）
```

最低配：独立 NS、最小 RBAC、NP **默认拒绝**、独立节点池 / 污点、合规要数据不共盘 → 拆集群。同一 NS 里两个 Deployment 默认也通。

**再追问：有 ResourceQuota 算硬墙吗？**  
不算。Quota / LimitRange 是账本，防一个 NS 吃光节点。敌对租户、审计分开，拆集群。

## ★★★ 加分

### Q45：何时拆集群？同集群租户怎么做？联邦要背吗？

**★★★**

**场景**  
每个业务线都要独立集群「更安全」。另有人要上联邦「一个控制面管全球」。

**完整解答**

规模、合规硬墙、爆炸半径才拆。不要跳级：

```
  共享 NS → 独立 NS+配额 → 独立节点池/污点 → 独立集群
```

同集群租户：NS + ResourceQuota + LimitRange + RBAC + NetworkPolicy。没有 Quota，一个忘写 limit 的作业能吃光节点。

**不背联邦 CR。** 多集群主流是 GitOps 多目标（22），不是联邦对象模型。拆了集群，Q2 的影响面仍然要会讲——控制面挂 ≠ 进程立刻死。

**再追问：支付只建一个 NS 算合规吗？**  
不算。最低仍是 01 那五条；真要硬墙再拆集群，不是只加 NS 名字。

### Q46：何时写 Operator？只渲染 YAML 呢？

**★★★**

**场景**  
有人要把开服脚本翻译成常驻 Operator，「每 15s 调和一次更高级」。

**完整解答**

CRD 只让 API 认识新 kind。没有控制器，它就是一坨数据。Operator = CRD + 领域 Reconcile（Observe → Diff → Act）。

```
  只渲染 YAML、装一次     → Helm / Kustomize / GitOps
  开服、合服、一次性迁库 → Job / 流水线（失败可重跑）
  持续决策（failover、证书、扩分片）且有人 oncall → 才值得写
```

合服要人工确认，15s 调和一次会在半成功状态上反复 Act。引入上游 Operator 先问：它建哪些 STS/PVC？失败日志在哪？CRD 升级谁测？

**再追问：Operator 挂了，CR 还在不在？**  
对象还在 etcd。停的是调和：掉了不补、删了卡 Terminating。不要先手抠 finalizer。

### Q47：网格 Sidecar 成本？房间长连接默认上不上？

**★★★**

**场景**  
要给每个战斗服注入一个代理「统一观测和重试」。不默写网格 CR。

**完整解答**

网格把超时、重试、mTLS、观测收到数据面（sidecar 或 Cilium 无 sidecar）。它是增强不是前提。

成本：每 Pod 额外 CPU / 内存、每跳延迟、注入 Webhook 走写路径。房间长连接默认不上——多一跳、reload / 重试还可能双发或断流。游戏大部分场景：入口限流 + SDK 降级 + 业务开关 + K8s 资源隔离。

要上：服务真多、有人值班、先无状态接入层。Cilium 无 sidecar + Hubble 见 23。不要背网格 CR。

**再追问：网格默认重试支付 POST？**  
危险。重试只对幂等；支付 POST 默认不安全。重试 + 熔断同时开，Open 还重试就是打下游。

### Q48：对象一直 Terminating，能不能手抠 finalizer？

**★★★**

**场景**  
PVC 删了十分钟还在。有人准备 patch 把 finalizers 置空。Namespace 也卡着。

**完整解答**

先看 `deletionTimestamp` 和 `metadata.finalizers`。有 finalizer = 控制器还在清外部资源（卸卷、删云盘、Operator 清 RDS）。

```
  delete --> deletionTimestamp --> finalizers 空?
                                      |否 --> 查 CSI / Operator
                                      |是 --> etcd 里删除
```

手抠 = 告诉 API「外部已清完」。云盘还在会留孤儿。先确认外部已无、业务允许，留变更记录。不要当第一反应。NS 一直 Terminating：先列这个 NS 里卡死的对象，不要先删 NS 本身。集群内子资源靠 ownerReferences，缺 owner 留下孤儿 STS。

**再追问：控制器挂了会怎样？**  
finalizer 永远摘不掉，对象永远 Terminating。先救控制器，再考虑补救。

### Q49：cgroup driver 为什么要对齐？1.24+ 还用 docker 排障吗？

**★★★**

**场景**  
新节点 CreateContainerError。kubelet 用 systemd，containerd 还是 cgroupfs。夜班在找 `docker ps`。

**完整解答**

kubelet 走 CRI 调 containerd，再调 runc。**两边 cgroupDriver 都用 systemd**。一边 systemd、一边 cgroupfs，典型就是 CreateContainerError。

1.24 起 dockershim 没了，节点上看容器用 **crictl**（namespace `k8s.io`），不是 docker。`crictl ps / pods / logs / inspect / pull` 复现拉镜像、看沙箱。不要用 `crictl rm` 代替 kubectl——绕过控制器留脏对象。pause 镜像拉不下来，sandbox 全失败。

**再追问：IfNotPresent + latest 改了镜像节点不拉？**  
可变 tag 被当成已有。生产钉 digest 或不可变 tag。节点上 `crictl pull` 能复现。

### Q50：Webhook 或网格注入失败，为什么比业务故障更致命？

**★★★**

**场景**  
注入 Webhook 单副本挂了。创建、滚动、连「把 Webhook 改 Ignore」的 apply 全部失败。战斗服还在跑。

**完整解答**

写路径过准入。`failurePolicy: Fail` 且 Webhook 挂 / 超时 = **全集群不能发版、不能扩、不能修**（除非破窗改 Ignore 或从控制面摘掉 Configuration）。业务进程可能还在（对齐 Q2），但你失去了变更能力。网格注入同样走 Mutating Webhook，注入失败比「某个大厅 5xx」更先焊死集群。

Webhook 要多副本 + PDB，超时 <3s。破窗是止血：审批、留窗口、修完改回 Fail。改 Ignore 的代价是特权 Pod / latest 可能被放进来。

**再追问：控制面挂着，已经在跑的游戏服怎么办？**  
不要重启还活着的逻辑服。讲清「不能发版但长连接可能还在」，先救 Webhook / etcd / API，再谈变更。
