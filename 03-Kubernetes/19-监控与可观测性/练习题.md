## Q1

**★★★★★｜K8s 监控体系怎么分层？Prometheus 在图里哪一段？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 [三、原理](知识点.md) · [二、架构图](知识点.md)


### 场景

开场就问：「你们集群监控是怎么设计的？」有人开始背 grafana.com 的安装步骤。

### 完整解答

**一句话**：Prometheus 负责拉存算规则，Alertmanager 叫人，Grafana 给人看；分四层指标。

先画采集，再答四层。Prometheus 负责拉、存、算规则；叫人是 Alertmanager；给人看的是 Grafana。主机日常看盘在 02-21。

```mermaid
flowchart LR
    sd[发现] --> pull[拉 /metrics]
    pull --> tsdb[TSDB]
    tsdb --> am[Alertmanager]

    class pull,tsdb a
```

| 层 | 看什么 | 工具 |
|----|--------|------|
| 基础设施 | CPU/内存/盘/网/conntrack | node-exporter |
| 中间件 | 连接数、命中率、堆积 | 各 exporter |
| 应用 | 四金信号、GC | 埋点 |
| 业务 | CCU、支付/匹配成功率 | 自定义 metrics |

每层有自己的告警。P0 打电话，P2 进工作时间。指标太多：按服务做 Dashboard，核心四金信号必上，定期删废弃 target。

### 再追问

告警太多？——基于症状、加 `for`、inhibit、月度噪音率。不要把节点 CPU 当业务 P0。

## Q2

**★★★★★｜metrics-server 和 Prometheus 差在哪？HPA unknown 先看谁？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 [四、安装部署](知识点.md)


### 场景

`kubectl top` 没数据，HPA 全 unknown。有人去重启 Prometheus。Grafana 却有图。

### 完整解答

**一句话**：metrics-server 给 HPA/top 瞬时聚合不存历史；Prometheus 是 TSDB，重启 Prometheus 修不好 top。

metrics-server 只提供当前聚合值，走 Metrics API，给 HPA 和 top，**不存历史**。Prometheus 是 TSDB，给人看、告警、长期存。重启 Prometheus 修不好 top。两套管线可以一个挂一个活。

top 不工作：metrics-server Pod → kubelet `/metrics` 可达 → 证书信任。HPA unknown 还要看 Pod 有没有 request（07）。可以用 adapter 接自定义指标，但默认 CPU HPA 仍吃 Metrics API。

### 再追问

验收 Prometheus 装好了看 Grafana 空图？——看 target 是否 UP，不是有一张空 Dashboard。

## Q3

**★★★★★｜告警怎么分级？什么情况才半夜打电话？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 [三、原理](知识点.md)


### 场景

磁盘 82%、某测试 NS 一个 Pod 重启、生产支付 5xx 到 8%，三条一起响。

### 完整解答

**一句话**：告警按用户是否受损分级；P0 是核心中断且可行动，节点 CPU 90% 不是 P0。

按用户是否受损分级，不按机器是否忙。叫人：用户/收入正在受损 + 有动作可做 + 不是回声。

| 级 | 定义 | 响应 |
|----|------|------|
| P0 | 核心中断或即将中断 | 5 分钟，电话 |
| P1 | 核心受损可降级 | 15 分钟 |
| P2 | 有风险不影响用户 | 工作时间 |
| P3 | 趋势 | 周巡检 |

支付 5xx 8% 是 P0/P1。磁盘 82% 是 P2。测试 NS 重启是 P3 或不告。每条要有 Runbook。节点挂了 inhibit 该节点 PodDown。维护窗口 silence，结束解开。P0 不能定义为 CPU >90%。

### 再追问

登录 SLO 健康、节点 CPU 90%，该不该 P0 打断发版？——不该。看四金信号。

## Q4

**★★★★★｜SLO、SLI、Error Budget？游戏登录怎么用？滚动踢玩家算不算？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 [三、原理](知识点.md)


### 场景

产品要把可用性写成 99.99%。研发想周五晚上发战斗服热更。没有人能说出这个月还能「坏」多久。同一周还要 drain 战斗节点。

### 完整解答

**一句话**：Error Budget = 1−SLO；滚动/drain 踢玩家计入非自愿断线，预算尽了冻结发布。

SLI 是怎么量，SLO 是目标，SLA 是合同。Error Budget = 1 − SLO。99.9% 大约月 43.2 分钟；99.95% 约 21.6 分钟。预算尽了冻结发布。

登录成功且 小于 3 秒 可作 SLI。热更 / 合服 / **滚动踢玩家 / drain 战斗节点** 计入非自愿断线，不能开除。SLO 用近三个月实际再留余量。活动高峰单独看燃烧率。只看 28 天慢烧不够，再加短窗口高燃烧率。

### 再追问

预算谁用？——研发拿它排期，SRE 看消耗速率。和 15 冻结窗口对齐。

## Q5

**★★★★★｜Prometheus 为什么是 Pull？短 Job 怎么办？**

**覆盖**：核心 · 必会 · 常用
**对应**：知识点 [三、原理](知识点.md)


### 场景

有人要把游戏服改成往 Prometheus 推指标，「和以前 StatsD 一样」。离线结算 Job 跑 30 秒就结束。

### 完整解答

**一句话**：Prometheus 主动 Pull，target 不健康可见；短 Job 用 Pushgateway 且用完清理。

Prometheus 主动拉 `/metrics`。拉不到 = target 不健康，不会因业务忘了推而静默。调试就是 curl 那个端口。NAT 后面拉不到才需要 Pushgateway 或反向连接。短 Job：结束前 push 到 Pushgateway，**用完清理**。大规模 target 要分片。双副本同一条告警 AM 去重，不是两套独立电话。

### 再追问

长生命周期服务推进 Pushgateway？——不要。假活，target 健康模型失效。

## Q6

**★★★★☆｜node-exporter、kube-state-metrics、cAdvisor 各看什么？**

**覆盖**：必会 · 常用
**对应**：知识点 [三、原理](知识点.md)


### 场景

副本不够和容器 CPU 打满同时发生。有人只盯着 node-exporter 的 CPU。

### 完整解答

**一句话**：node-exporter 看 OS，kube-state-metrics 看对象状态，cAdvisor 看容器性能，三者不重叠。

node-exporter：节点 OS（CPU、盘、conntrack）。kube-state-metrics：对象状态（副本数、Pending、重启次数）。cAdvisor：容器性能（kubelet 内置）。不重叠：对象够不够 vs 容器用了多少。副本不足用 kube-state-metrics；CPU throttle 用 cAdvisor。Saturation：节点看 node-exporter；容器 CPU 看 throttle；「该有的副本没有」是容量，不是瞬时利用率。

### 再追问

metrics-server 算第四套吗？——给 HPA/top 的瞬时聚合，不进这三套「给人看历史」的分工。

## Q7

**★★★★☆｜Prometheus 怎么做 HA 和长期存储？200 万 series 是什么意思？**

**覆盖**：必会 · 常用
**对应**：知识点 [三、原理](知识点.md) · [七、生产排障](知识点.md)


### 场景

单盘 Prometheus 只留 15 天，查询跨月活动对比查不到。内存也开始 OOM。

### 完整解答

**一句话**：HA 靠双副本 + AM 去重；长期存储用 Thanos/VM；约 200 万 series 软上限要分片。

单实例是单点。HA：双副本 + Alertmanager / Query 层去重。长期：Thanos（sidecar 传 block 到对象存储）或 VictoriaMetrics。软上限约 200 万 series，超了分片或 remote-write。远程存储解决留存和全局查询，**不解决** `user_id` 当 label。已有 Prometheus 要全球查：Thanos。想少组件、大规模写入：VM。

### 再追问

双写同一块盘算 HA 吗？——不算。盘挂了两份一起没。

## Q8

**★★★★☆｜写一条容器 CPU 相对 limit 的告警，为什么用 rate 不用 irate？**

**覆盖**：必会 · 常用
**对应**：知识点 [六、命令与操作](知识点.md)


### 场景

看板用 irate，告警也抄过来，半夜抖了一分钟打了十个电话。

### 完整解答

**一句话**：告警用 rate 不用 irate；滤 container!="" 排除 pause。

```promql
sum(rate(container_cpu_usage_seconds_total{container!=""}[5m])) by(pod,namespace)
  / sum(kube_pod_container_resource_limits{resource="cpu"}) by(pod,namespace) * 100 > 80
```

`for: 10m`，annotation 放 runbook。`container!=""` 滤 pause。rate 是区间均值，适合告警；irate 看最近两点，适合实时看板，易抖。没有 limit 的 Pod 分母没有，另做配置缺失告警（P3）。

### 再追问

P99 用 histogram_quantile 打在 Counter 上？——没意义。必须 Histogram / Summary。

## Q9

**★★★★☆｜四金信号是什么？为什么延迟不看平均值？**

**覆盖**：必会 · 常考
**对应**：知识点 [三、原理](知识点.md)


### 场景

网关平均延迟 40ms，客服说卡。P99 已经 800ms。

### 完整解答

**一句话**：四金信号 Latency/Traffic/Errors/Saturation；延迟必须看分位数，平均值会淹长尾。

Latency、Traffic、Errors、Saturation。延迟必须看分位数。平均值把长尾淹了。Saturation 是离打满多远。每个服务 Dashboard 至少这四个 + 业务指标。游戏 HTTP 用 RED，机器和中间件用 USE。战斗服 Traffic：CCU、心跳、进出房间；错误用非自愿断线，不要硬套 HTTP 5xx。

### 再追问

先 RED 再 USE 的那次 GC 事故怎么讲？——P99 升、CPU 不高、GC 飙；Heap 512Mi vs RSS 1.5Gi。

## Q10

**★★★☆☆｜高基数把 Prometheus OOM 了，第一刀是什么？**

**覆盖**：必会 · 常用
**对应**：知识点 [三、原理](知识点.md)


### 场景

有人把 `user_id` 打进 `http_requests_total`。`prometheus_tsdb_head_series` 一夜翻倍。

### 完整解答

**一句话**：高基数第一刀停错误指标或 drop relabel，user_id 不能当 label。

先停掉错误指标或 drop relabel 买时间，加内存只是缓冲。label 只留低基数；user_id 进日志和 Trace。route 用 `/user/:id` 模板。Recording rule 不降已经炸了的 ingest。OTel 自动插桩开太全、span 属性乱打，同样爆。入口头采样、敏感字段脱敏、C++ 战斗服只埋出入口和 DB。

### 再追问

Thanos 能救已经打进去的高基数吗？——不能当许可证。先停 ingest。

## Q11

**★★★☆☆｜讲一次用监控发现并修掉的故障，三支柱怎么串？top 空怎么办？**

**覆盖**：常用 · 常考
**对应**：知识点 [八、必会 · 常考](知识点.md)


### 场景

复盘要求「不是只看 CPU」。上周网关延迟事故。另一次 HPA unknown。

### 完整解答

**一句话**：三支柱：指标发现、日志对时间线、Trace 定位跳；HPA unknown 查 metrics-server 不是 Grafana。

Metrics：网关 P99 50ms → 800ms（P1）。CPU 不高，GC 时间飙。Logs：按时间对齐 Full GC。Traces：慢在进程内，不在下游 Redis。止血：扩副本、改 Heap。根因：Heap 512Mi vs RSS 1.5Gi。预防：GC 告警、Heap 与 limit 对齐。发现用指标，原因用日志，定位跳用 Trace。Trace ID 打进日志（19）。没有数字就讲分钟级和量级变化。

HPA unknown / top 空：metrics-server，不是 Grafana 挂了。两套管线。

### 再追问

排障决策树还走 17 吗？——走。监控只告诉你哪一层先坏，五棵树仍在 17。

## Q13

**★★★★☆｜开服值班看板最少要有哪四块？**
