## Q1

**★★★★★｜为什么要多集群？和单集群多命名空间怎么选？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [二、动机：为什么要多集群](知识点.md)

### 场景

「每个业务线独立集群更安全。」另一人说「我们五个服没必要多集群」。

### 完整解答

> 🎯 **一句话**：多集群为故障域、合规驻留、地域延迟、团队边界、升级金丝雀；服务少、同法域用 ns+NP 往往够。

| 单集群 ns | 多集群 |
|-----------|--------|
| 软隔离 | 独立控制面 |
| 运维低 | 运维 N 倍 |
| 中小团队 | 多地域/合规 |

> 📝 **面试**：「不是 apiserver 不够就先拆；能 ns 隔离就别急着多集群。」

### 再追问

- **多集群自动更高可用？** 是故障域隔离，复杂度上升，不是魔法冗余。

## Q2

**★★★★★｜Argo CD 多集群怎么下发同一应用？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [三、出生：意图从哪来——GitOps 与 Karmada](知识点.md)

### 场景

运维对每个集群手写 `kubectl apply` 同一 YAML，SEA 因 StorageClass 失败。

### 完整解答

> 🎯 **一句话**：ApplicationSet 按集群列表生成 Application，每区 Kustomize overlay 处理差异，Git 单源。

```yaml
# generator: list 含 cn-prod / sea-prod
# template.source.path: overlays/{{cluster}}/lobby
```

```bash
argocd app diff lobby-sea-prod
# 看 live vs desired，别在 cn 上重复 apply
```

详见 [23](../23-GitOps-ArgoCD与Tekton/)。

### 再追问

- **kubeconfig 多集群？** [14](../14-证书与kubeconfig/) context 切换，值班先确认 current-context。

## Q3

**★★★★★｜Karmada 是什么？和 GitOps 二选一吗？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [三、出生：意图从哪来——GitOps 与 Karmada](知识点.md)

### 场景

「我们上 Karmada 就不用 Argo 了。」

### 完整解答

> 🎯 **一句话**：Karmada 在 Host 统一 API，PropagationPolicy 选成员集群，OverridePolicy 做差异；常与 GitOps 组合，非二选一。

**GKE Fleet** 是谷歌托管的类似舰队治理面。Member 集群落地真实 workload；Host 挂了下发停，成员仍跑。

> ⚠️ **别混**：不背 kube Federation v1/v2 CRD。

### 再追问

- **副本按集群权重？** `replicaScheduling` 在 PropagationPolicy 里配。

## Q4

**★★★★☆｜多集群哪些配置必须一致、哪些必须不同？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [四、同步：配置一致性怎么保](知识点.md)

### 场景

SEA 手工 `kubectl edit` ConfigMap 修时区，一周后 Argo OutOfSync 与 cn 行为不一致。

### 完整解答

> 🎯 **一句话**：结构/探针/镜像 tag 策略一致；SC、replicas、区服地址、pull Secret 按区不同。

对账：`argocd app diff`；禁止生产 hand-edit。CRD/版本矩阵维护各集群 Istio/K8s 版本——否则同 YAML 一区成功一区失败。

### 再追问

- **哈希 last-applied 不同是事故吗？** 不一定，overlay 本就不同；要比是否符合 Git。

## Q5

**★★★★★｜跨集群能直接用 ClusterIP 调 Service 吗？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、联通：跨集群流量与服务发现](知识点.md)

### 场景

排行榜服务在 global 集群，战斗服在 cn 集群写死 `10.96.x.x` ClusterIP。

### 完整解答

> 🎯 **一句话**：ClusterIP 不跨集群；用 MCS ServiceExport/Import、Submariner 或显式 API 网关 URL。

```bash
kubectl --context=cn get serviceexports -A
kubectl --context=global get serviceimports -A
# Import 的 Endpoints 应指向源集群 Pod IP
```

玩家入口用 GSLB（[01-15](../../01-基础底座/15-DNS与CDN/)），不是 MCS。

### 再追问

- **Karmada 复制 Deployment 够吗？** 不够，还要服务发现或网关。

## Q6

**★★★★☆｜GSLB 和 MCS 各解决什么问题？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [五、联通：跨集群流量与服务发现](知识点.md)

### 场景

「上了 GeoDNS，SEA 战斗服就能调 cn 的 ClusterIP 了。」

### 完整解答

> 🎯 **一句话**：GSLB 分玩家到最近区入口；MCS 分集群间 Service 发现，两者不互相替代。

MCS DNS 形如 `svc.clusterset.local`。GSLB 切流后仍要查该区 [15](../15-Ingress与流量管理/) Endpoints。

### 再追问

- **CIDR 重叠？** 隧道互调必须规划不重叠的 Pod/Service CIDR（[10](../10-CNI与网络策略/)）。

## Q7

**★★★★☆｜游戏国服/东南亚多区，K8s 层怎么挂？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [六、游戏：多区服怎么挂在这条主线上](知识点.md)

### 场景

活动模板要全球同步，有人想 `--context` 循环 apply 同一文件。

### 完整解答

> 🎯 **一句话**：一区一集群（或强隔离）；活动 YAML Git 同步 + 区服 overlay；合服先数据后 GSLB；跨区 API 用网关/MCS。

区内：玩家 [15](../15-Ingress与流量管理/)，互调 [08](../08-Service与kube-proxy/) 或 [24](../24-ServiceMesh-Istio与Envoy/)。热更仍走游戏通道，K8s 管进程与配置载体。

### 再追问

- **区服标识三层？** overlay 目录、K8s label、应用 ConfigMap 同名。

## Q8

**★★★★☆｜ApplicationSet 开 automated prune 有什么风险？**

**覆盖**：常用 ｜ **对应**：知识点 [三、出生：意图从哪来——GitOps 与 Karmada](知识点.md)

### 场景

MR 误删 Git 里一个 Deployment，合并后全球 lobby 同时消失。

### 完整解答

> 🎯 **一句话**：prune 会在**所有**目标集群删除 Git 中已删对象；变更要走 MR+审批，活动期冻结。

恢复：Git revert + sync，不是只救一个区。dry-run：`argocd app sync --dry-run`。

### 再追问

- **先删 cn 测试？** 用 staging 集群 wave，不要直接动 prod 全集。

## Q9

**★★★★☆｜两集群 Pod CIDR 都是 10.244.0.0/16，Submariner 会怎样？**

**覆盖**：常考 ｜ **对应**：知识点 [五、联通：跨集群流量与服务发现](知识点.md)

### 场景

第二套集群从模板复制网络规划，跨区隧道已建，路由混乱。

### 完整解答

> 🎯 **一句话**：CIDR 重叠导致隧道路由冲突，跨集群 Pod 互调不可达或走错集群。

规划阶段强制 **每成员集群 Pod/Service CIDR 唯一**；扩集群先查 IPAM 表。

### 再追问

- **单集群多 AZ 可同 CIDR 吗？** 同集群内由 CNI 划分；**跨集群** 必须不重叠。

## Q10

**★★★★★｜cn-prod Synced Healthy，sea-prod OutOfSync Degraded，先做什么？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、作战：定责](知识点.md)

### 场景

全球监控平均错误率正常，SEA 玩家实际上登录失败。

### 完整解答

> 🎯 **一句话**：确认 context，只对 sea 做 `argocd app diff` 和 `kubectl get pods`，别在 cn 重复 apply。

常见 SEA 独有：镜像 pull secret、SC 名、nodeSelector 机型。修好 overlay 再 sync。

```bash
kubectl config use-context sea-prod
argocd app diff lobby-sea-prod
kubectl get pods -n game -l app=lobby
```

### 再追问

- **合成监控没带 cluster 标签？** 会误判全球健康——告警必须带 cluster。

## Q11

**★★★★☆｜Karmada Host 控制面挂了，成员集群游戏服会停吗？**

**覆盖**：必会 ｜ **对应**：知识点 [三、出生：意图从哪来——GitOps 与 Karmada](知识点.md)

### 场景

Host 集群 etcd 故障，on-call 喊「全球下线」。

### 完整解答

> 🎯 **一句话**：成员集群存量 Pod 仍运行；不能下发新变更，类似单集群 etcd 挂（[02](../02-etcd/)）。

新发布、扩缩容、修复 drift 会停；已建立玩家连接由各区数据面扛着。GSLB 仍可切流，但目标区若无 Ready Pod 仍 502。

### 再追问

- **和成员集群控制面挂的区别？** 成员自己控制面挂只影响该区变更与调度。

## Q12

**★★★★☆｜两区合服，K8s 和 DNS 顺序？**

**覆盖**：常用 ｜ **对应**：知识点 [六、游戏：多区服怎么挂在这条主线上](知识点.md)

### 场景

先 GSLB 把玩家切到 cn，再 merge 数据库，出现双写。

### 完整解答

> 🎯 **一句话**：先数据 merge + 停写旧区，再缩容旧区 Deployment，最后 GSLB 权重归零；顺序反了双写。

K8s 层：旧区 `scale 0` + Argo 冻结旧 overlay。数据层是主矛盾，K8s 不替 DB 合服。

### 再追问

- **只 scale cn lobby？** 还要确保 SEA 入口不再接新玩家（DNS/权重）。

## Q14

**★★★★★｜四张跨区工单定责**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、作战：定责](知识点.md)

### 场景

| 工单 | 现象 |
|------|------|
| A | SEA 镜像 ImagePullBackOff，cn 正常 |
| B | 跨区排行榜 API 超时 |
| C | 活动后全球 lobby 版本不一致 |
| D | GSLB 切到 SEA 后 502 |

### 完整解答

> 🎯 **一句话**：A→SEA overlay pull secret；B→MCS/CIDR/网关；C→Git revision 与 Argo sync；D→SEA Ingress Endpoints（08/15）。

- **A**：`kubectl --context=sea` 看 Events；patch `imagePullSecrets` in overlay。
- **B**：`serviceexports/imports`、隧道、是否写死 ClusterIP。
- **C**：对比 `argocd app get` revision；禁 hand-edit。
- **D**：SEA 区内 Endpoints，不是 cn 集群。

### 再追问

- **四张都改 global Git 一条？** 先分区 diff，再改对应 overlay。
