## Q1

**★★★★★｜从点图标到进大厅，鉴权有哪几跳？一跳超时玩家看到什么？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 §3.1

### 场景

开服三分钟全员「登录失败」。有人重启账号服，有人重启战斗服。没有人拿出分跳成功率。

### 完整解答

**一句话**：登录六跳要分跳看成功率，客户端只显示登录失败，不能先重启战斗。

渠道 SDK → 账号换 token → 目录选服 → 排队领票 → Gate 建连 → 大厅拉角色。客户端通常只显示登录失败，必须看每跳成功率和延迟，不能只说「登录挂了」。

```mermaid
flowchart LR
    a[① 渠道] --> b[② 账号]
    b --> c[③ 目录]
    c --> d[④ 排队]
    d --> e[⑤ Gate]
    e --> f[⑥ 大厅/库]
    classDef e fill:#334155,stroke:#0F172A,stroke-width:2px,color:#fff
    classDef s fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef q fill:#D97706,stroke:#92400E,stroke-width:2px,color:#fff
    class a e
    class b,c s
    class d q
```

渠道故障要公告，同时防用户狂点打爆账号。支付和风控不要同步塞进登录事务。Gate / 大厅失败才是进服问题，不要先重启战斗。`min_client_version` 放目录 / 登录。

### 再追问

怎么快速判断是渠道还是自家？——看渠道 SDK 耗时和错误码 vs 账号服 QPS / 5xx。渠道挂时，过了 SDK 之后的自家成功率仍正常。对端再问渠道。

## Q2

**★★★★★｜登录打爆为什么不能只扩登录 Deployment？**

**覆盖**：核心 · 必会 · 常考
**对应**：知识点 §3.2

### 场景

登录 HPA 从 10 扩到 80。排队器按登录集群空闲发票。新服创角把单库打穿，老服目录开始 500。有人说「弹性扩容已经生效」。

### 完整解答

**一句话**：登录好扩但放行后打 Gate/创角/DB，不排队等于把洪峰送给有状态层。

登录无状态好扩，但放行后打的是 Gate、创角写库、大厅。不排队等于把洪峰原样送给有状态层。登录 QPS 日常 20～100×，重试再乘；CCU 爬升是分钟级。

```
  登录 QPS 日常 20～100×，重试再乘
           |
           +-- 账号按 QPS 扩          ← 好扩
           +-- 排队按每秒放行         ← 保护有状态
           +-- Gate 按连接
           +-- 单服 DB 按创角写       ← 硬顶
```

容量分桶。开服只答 HPA 而不提排队，按没管过开服打。重试：客户端指数退避；服务端对同一账号限。无限重试是自己做 CC。

### 再追问

重试怎么处理？——客户端指数退避；服务端对同一账号限流。协议定死 ticket 重用还是重新排队，弱网否则把放行速率乘上去。

## Q3

**★★★★★｜排队令牌怎么发？重连为什么不能进同一队？排队器挂了呢？**

**覆盖**：核心 · 必会 · 常用 · 常考
**对应**：知识点 §3.3

### 场景

Gate 抖了 30 秒。重连玩家被打进和登录同一个队列，队伍从 2 万涨到 80 万。已经在线的人掉线后更登不回来。有人要把排队器摘掉「先让人进去」。

### 完整解答

**一句话**：ticket 短 TTL 一次性绑账号+服+nonce，重连走快通道，排队器挂宁停进服。

按目标服可消化速率发短 TTL、一次性、绑定账号 + 服 + nonce 的 ticket。持有 session 的重连走快通道。重连进队会把 Gate 抖动变成全员登不回来。

```
  新登录 --> 按服分桶排队 --> ticket --> Gate
  重连   --> 快通道（有效 session），不进队
  成功率掉 --> 只降速，不加速清队列
  排队器挂 --> 目录标维护，禁止裸放
```

计数必须中心化（Redis / 专用），每 Pod 内存排队会超发。按服分桶，S1 爆了不能卡住 S2。位置展示单调不增。消化速率：压测进服成功率 ≥ 99%、P95、DB 连接 &lt; 70% 时的每秒进服人数，再打 0.7。动态跟成功率，不跟队列长度。

排队器挂了默认停进服。裸放会把逻辑和 DB 打死，恢复更长。备用可以是静态全局限速配置，但不能直接穿过。

### 再追问

消化速率怎么定？——压测：进服成功率 ≥ 99%、P95 进大厅、DB 连接 &lt; 70% 时的每秒进服人数，再打 0.7。动态跟成功率，不跟队列长度。队列再长也不许涨速去「消化」。

## Q4

**★★★★★｜选服推荐如何避免全员挤爆新服？目录 DB 被打穿怎么办？**

**覆盖**：核心 · 必会 · 常用
**对应**：知识点 §3.4

### 场景

三个新服同时开，列表默认高亮第一个。推荐标一直挂着。S1 创角打满，S2 / S3 空。目录主库 CPU 打满，列表接口 500。

### 完整解答

**一句话**：新服推荐带 CCU 阈值打散，目录可缓存降级不可 500。

新服推荐带 CCU 阈值自动摘标；多新服按账号哈希打散；爆满只进已有角色。目录可缓存降级，不可 500。

```
  推荐标 --CCU 阈值--> 自动摘掉
  多新服 --账号哈希--> 打散，不要默认点第一个
  爆满   --已有角色可进，禁止创角
  目录挂 --返回最后成功列表，TTL + 版本号
```

ticket 绑服，防改包进未开放服 / 测试服。合服后旧 ID 跳目标服。维护状态变更要主动失效缓存。开服写入不该和玩家选服共用一条无保护的写路径。

### 再追问

目录 DB 被打穿怎么办？——返回最后成功列表。错误列表用版本号控制。宁可短暂看到已维护服，也不要登录总入口 500。

## Q5

**★★★★☆｜session、ticket、Gate 连接三者怎么拆？全服踢人步骤？**

**覆盖**：必会 · 常用 · 常考
**对应**：知识点 §3.5

### 场景

一个 JWT 从账号一路传到战斗。要封禁某人时，删了账号 token，旧 Gate 连接还在，重连又把人拉回来。

### 完整解答

**一句话**：账号 token、进服 ticket、Gate session 三者拆开，全服踢人先断入口。

账号 token 长；进服 ticket 短且一次性；Gate session 随连接。一个 JWT 打通导致踢人和封禁吊销不干净。顶号要带 epoch，防旧连接重连回来。

```
  账号 token  --长--> 证明你是谁
  进服 ticket --短、一次性、绑 server_id--> 证明排队器放行
  Gate session --随连接--> 长连接身份
```

全服踢人：目录维护 → Gate 广播断连 → 短时拒新 ticket。只杀进程会立刻重连打爆。单账号踢下线：删 Gate 绑定 + 失效 ticket。

### 再追问

全服踢人只杀进程行不行？——不行。进程没了客户端会立刻重连，打爆登录和排队。必须先切断入口（目录维护 + 拒 ticket），再断连。

## Q6

**★★★★☆｜开服后 5 分钟你盯哪些图？为什么不要改推荐算法？**

**覆盖**：必会 · 常用
**对应**：知识点 §6.1

### 场景

开服 3 分钟，有人在尖峰上热更推荐权重，有人在调排队阈值「消化队列」。看板开了二十个，没有人盯进服成功率。

### 完整解答

**一句话**：开服后 5 分钟只盯每跳成功率和队列，尖峰不改推荐算法。

盯每跳登录成功率、队列和放行、创角 QPS、单服 CCU 爬升、DB 连接。不在尖峰改推荐算法或热更。重连 QPS 占比突升说明 Gate / 逻辑在抖，不是没人来。

开服前 30 分钟：登录副本就位、排队阈值按预案、目录缓存预热、创角开、告警按服路由。开服后 5 分钟只允许看成功率和队列。T0 可以按预案降速，不要涨速清队列。阈值变更也要有人记账。

### 再追问

重连占比升高和新登录失败怎么分？——重连升高 = 已在线的人在掉，查 Gate / 逻辑。新登录失败 = 鉴权 / 排队 / 目录。两个桶，两套止血，不要用一个「登录失败」总数。

## Q7

**★★★★☆｜排队器挂了为什么宁可停进服？**

**覆盖**：必会 · 常用 · 常考
**对应**：知识点 §3.3

### 场景

排队 Redis 主从切换失败。有人把登录直接绕过排队打到 Gate，「先让人玩起来」。

### 完整解答

**一句话**：排队器挂裸放会打死逻辑和 DB，目录标维护是可控损失。

裸放会把逻辑和 DB 打死，恢复更长。目录标维护是可控损失。备用可以是静态全局限速配置，但不能「直接穿过」。

```
  排队器挂
      |
      +-- 错：裸放 --> Gate fd / 创角写 / 大厅一起死，老服也被带崩
      +-- 对：目录标维护，或静态全局限速（仍有上限）
```

以排队器为准，宁少发。计数不准时按少的那份发。

### 再追问

静态限速配多少？——按压测可消化速率的保守值（例如 0.5～0.7），按服写死。没有预案就停进服，不要现场拍一个「看起来很大」的数。

## Q8

**★★★★☆｜创角热点怎么降？爆满服还让进吗？**

**覆盖**：必会 · 常用
**对应**：知识点 §3.4

### 场景

新服全员创角。每条创角事务同步初始化背包、导新手邮件、跑一遍活动注册。主库行锁等待飙升。

### 完整解答

**一句话**：创角热点限放行+异步初始化，爆满服已有角色可进禁止创角。

新服全员创角是写放大。限放行、预建号段、初始化背包异步、新手邮件批量。不要在创角事务里同步走一遍全活动。

爆满服：已有角色可进，禁止创角。排队按该服消化速率降，不要为了队列长度涨速。

### 再追问

预建号段会不会和真实 uid 冲突？——号段要纳入 `server_id` 命名空间，和合服映射同一套 ID 纪律。创角只是领取，不是现场自增撞车。

## Q9

**★★★☆☆｜多渠道限流为什么要汇到账号维度？验证码挂了怎么降级？**

**覆盖**：常用 · 常考
**对应**：知识点 §4

### 场景

国内渠道、海外商店、游客各做一套限流。一个渠道被打，羊毛号换游客入口照进。验证码服务账单先于 CPU 爆炸，随后验证码挂了，老玩家也卡在登录。

### 完整解答

**一句话**：多渠道限流汇到账号维度，验证码挂只拦创角不拦重连。

三套入口汇到同一账号服后按账号维度限。否则一个渠道被打、另一个渠道的同一批号仍能进。

验证码：开服可对「新设备创角」加严，对已有角色进服放宽。验证码服务挂了：只拦创角，不拦重连。验证码被刷是 CC，费用会先于 CPU 爆炸，要单独账单告警。

### 再追问

游客账号怎么归并到账号维度？——设备指纹 / 游客 token 最终仍要落到一个 account id 再限。限在渠道入口上防不住换皮。

## Q10

**★★★☆☆｜ticket 重放和弱网重试怎么定协议？**

**覆盖**：必会 · 常用 · 常考
**对应**：知识点 §3.3

### 场景

弱网下客户端拿同一张 ticket 连打三次。排队器认为放了 1 人，Gate 实际建了 3 条握手，放行速率被乘上去。日志分不清「没拿到票」还是「票被用过」。

### 完整解答

**一句话**：ticket 一次使用防重放，弱网重试协议要定死，失败码四件套分开记。

ticket 一次使用、短 TTL、绑定 `account + server_id + nonce`。日志打 ticket id。客户端重试用同一 ticket 还是重新排队，协议要定死。

```
  第一次 Gate 校验成功 --> 票作废
  弱网重试同一票     --> 校验失败（已用过），客户端走重连或重新排队
  未定协议           --> 放行速率被乘，消化曲线失真
```

排障能区分「没拿到票」和「票被用过」，不要都记成登录失败。Gate 校验失败码四件套：过期、已用、server_id 对不上、nonce 重放。

### 再追问

ticket 绑服是为了防什么？——防改包进未开放服、进测试服、进已维护服。选服鉴权：只能进自己有角色的服，或当前开放创角的服。

## Q11

**★★★★☆｜ticket 超发或推荐权重发错，怎么回滚？**

**覆盖**：必会 · 常用
**对应**：知识点 §6.3

### 场景

放行配错大了一个数量级，票已经发出去。另一次尖峰上热更了推荐权重，人全挤进 S201。

### 完整解答

**一句话**：超发降 TTL 作废批次，错误推荐 reload 回上一版，回滚排队≠摘掉排队。

超发：立刻降 TTL、作废已发出的批次、按少的那份发，不要裸放清队列。错误推荐：停热更，配置 reload 回上一 version（03），不要在尖峰上再调一把。目录错误列表用版本号打回上一份成功缓存。

回滚排队器 ≠ 摘掉排队。摘掉就是裸放。

### 再追问

放行对、Gate 仍拒，先看什么？——ticket 校验失败码，不要先加 Gate。四件套分开记。
