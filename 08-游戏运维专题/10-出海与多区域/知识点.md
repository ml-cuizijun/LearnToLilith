## 1. 基本概念

跨洋 150～250ms 消不掉。专线稳的是丢包和抖动，不是光速。实时对战必须就近开房间；只把 Gate 放近、逻辑仍在远端，战斗 RTT 几乎不降。

游戏几乎不做「两个 region 双活写同一角色库」。有状态 + 经济对账，冲突和回档都无法收场。主流是 region 独立：坏了公告维护，玩家在其他 region 的号仍可玩。

数据驻留（data residency）：角色库、日志、备份、行为分析是否必须留在发行地。原则按发行地，不是按你机房在哪。生产默认 **数据不出域、最小权限、审计**。

| 在出海这一章 | 不在这一章当承诺 |
|--------------|------------------|
| 账号全局、角色落 region | 两个 region 双活写同一角色库 |
| 就近匹配、就近房间 | 专线把 200ms 变 20ms |
| 备份账号 + region + 有无跨账号复制 | 「数据在 S3」四个字 |
| 活动整点用当地时区 | 一份北京 cron 打全球 |

三个故障域不要混：

| 挂了谁 | 玩家看见 | 你做什么 |
|--------|----------|----------|
| **账号 region** | 全球登不上 | P0；靠账号自己的多 AZ，不是靠玩法散开 |
| **玩法 region** | 该区不可玩 | 目录摘掉该区，其他地区可玩 |
| **支付地区通道** | 该渠道储值失败 | 地区 P0；不要关全球登录、不要扩 Gate |

> **记住**：跨洋延迟消不掉。账号全局、角色落 region；别吹两个 region 双活写同一角色库。答备份要说清哪个账号、哪个 region。

## 3. 原理

原理只保留动手和面试会用到的：为什么 200ms 消不掉、数据为什么不能随便复制、合规高频坑、换区为什么不是改字段。

**本节 4 块：** 3.1 延迟 · 3.2 数据驻留 · 3.3 合规 · 3.4 账号 vs 玩法

### 3.1 延迟：先认物理

同城：10～30ms。跨大陆：150～250ms+。不要承诺「专线把 200ms 变 20ms」。专线稳的是丢包和抖动，不是光速。

美西玩家打日服房间，操作像幻灯片。只把 Gate 放到美西，逻辑和房间还在东京，战斗 RTT 几乎不降。就近 Gate 改善握手和大厅轻操作，对 Tick 同步帮助有限。别把它卖成「全球同服无延迟」。

预算（示例，用你自己的数）：

- 卡牌 / 回合：100～200ms 可玩，跨洋单 region 也能活
- 实时对战：50ms 内舒适，必须 **就近匹配、就近房间**
- 操作类 MMO：移动同步对抖动敏感，比平均 RTT 更重要

| 方案 | 适用 | 代价 |
|------|------|------|
| 单 region 全球连入 | 回合制、轻度 | 远距玩家体感差，运维简单 |
| 多 region 独立区服 | 主流 | 开合服、数据、运营都翻倍 |
| 就近 Gate + 中心逻辑 | 想骗自己 | 逻辑仍在远处，只优化握手，战斗照样迟 |
| 跨 region 同房间 | 几乎不要 | 状态同步和延迟补偿是研发专题，运维背不了 |

匹配按 region / 延迟档，不要全球随机房。跨战区是产品开关，默认关。跨 region 同房间不要当运维承诺。

运维能做：把 Gate 放到离玩家近的 region；选对加速与 peering；监控分地区 RTT / 登录成功率。做不到：让美东玩家打日服房间还感觉「和本地一样」。

延迟拨测要分地区、分协议（登录 HTTPS vs 战斗 TCP / UDP），不要只用国内探针代表全球。加速器会让「地区」失真，拨测点放在真实玩家网，不放在办公网（08）。

国内三 AZ 不算真出海。同城 / 同大陆延迟和合规都不是一回事。多 AZ 保的是机房，跨洋保不了 RTT。

延迟账要拆两跳，不要只报「玩家到机房 ping」：

```mermaid
flowchart LR
    p[玩家] --> g[Gate]
    g --> r[房间 / 逻辑]
    r --> db[本服库]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    class p,g a
    class r,db b
```

| 路径 | 典型 | 玩家感知 |
|------|------|----------|
| 玩家 → 就近 Gate | 可压到几十 ms | 登录、大厅轻操作变快 |
| Gate → 远端房间 | 跨洋 150～250ms 仍在 | 操作回包、Tick 同步仍幻灯片 |
| 房间 → 本服库 | 应同 region | 结算、发货；跨 region 写 = 经济事故 |

专线 / 加速器可以降丢包，把「200ms ± 80ms 抖动」变成「200ms ± 10ms」。平均 RTT 几乎不动。实时玩法怕的是抖动和丢包，回合制怕的才主要是平均 RTT。把专线卖成「变 20ms」，产品会对你验收一个物理上交不出的数。

### 3.2 数据驻留与跨境

数据驻留 = 哪类数据必须留在哪个法域。跨境传输即使加密，仍可能违规。备份复制是最常见的静默出域。

| 数据 | 驻留口径 | 翻车动作 |
|------|----------|----------|
| 角色 / 背包 / 邮件 | 落在玩法 region；不跨洋双写 | 角色库跨 region 同步「做 HA」 |
| 账号 / 绑定 | 账号 region；玩法服只认 token | 玩法服存第三方法人数据副本 |
| 日志 / 行为分析 | 默认不出发行地 | 生产日志打到国外 SaaS |
| 聊天 | 合规留存 vs 游戏 RTO 两套（07） | 送给境外大模型 |
| 备份 | **账号 + region + 有无跨账号复制** | S3 跨 region 复制勾上就把 PII 带出国 |
| 支付订单 | 发货在可审计区域完成；留存年限按当地 | 订单回写到国内账号 |

欧区要做备份。把 S3 跨 region 复制勾上，备份进了国内账号，账单导出里出现欧区 PII——这是合规事故，不是「备份做得更稳」。开复制前合规评估。

云账号按发行主体拆，避免欧区数据出现在国内账号账单导出里。申请权限写清 region，不要一个 Administrator 打全球。客服和 GM 按 region 分权：美西值班不该对欧区角色库有写。跨 region 查询走只读 + 审计。

答「数据在 S3」不够，要说 **哪个账号、哪个 region、有没有跨账号复制**。细节跟法务。没把握的话术：原则清楚，具体清单和法务 / 安全一起出。

驻留不是「机房在哪」一句话。运维要能指到四类处理：

| 处理 | 例子 | 默认 |
|------|------|------|
| 原地处理 | 角色写、战斗结算、发货 | 必须在玩法 region |
| 可出境（需评估） | 聚合后的非 PII 监控 | 法务点头才动 |
| 禁止出境 | 聊天原文、身份证、支付完整单 | 不进境外 SaaS / 大模型 |
| 备份复制 | 同账号同 region；跨 region 要 DPIA / 合同 | 默认关 |

GDPR / PIPL / PDPA 名字留给法务。你要会的是：哪张表、哪个桶、哪个日志管道出不出域。客服「整包下载玩家数据」是另一条出境通道，权限和审计按 region 切，和 GM 写权限同一套门禁。

### 3.3 合规：日志、支付、年龄、内容

高频坑：

- **数据驻留**：角色库、日志、行为分析能不能出发行地
- **日志出境**：生产日志打到国外 SaaS、玩家聊天送给境外大模型，都是合规事故
- **支付**：当地渠道、税、订单留存年限；发货必须在可审计的区域完成
- **账号实名 / 年龄**：按地区开关，不能一套国内实名打全球
- **内容与版号**：热更也是发行物，部分地区改数值要过审

运维清单：备份存在哪、谁有权拉、跨 region 复制有没有 PII、客服工具能不能下整包玩家数据。证据给安全厂商出境：默认最小字段、审计、不出域（08）。

证书和隐私政策页按发行地拆。商店过审周期按当地排强更，不要用国内过审完当天全球抬 min。

年龄 / 实名是开关不是文案。国内实名流程不能套到没有同等要求的地区；反过来，有年龄门的地区漏开关 = 合规事故，不是「登录 SLO 没破」。热更改数值在部分地区视同发行物，过审前不要全球切配置（03）。运维提供的是按 region 的开关和发布隔离，清单和法务一起出。

客服工具、日志平台、大模型助手，默认假设它们会把数据带出域。上线前问：数据在哪个账号、会不会进境外训练、能否按 region 关掉。答不出就先关。

### 3.4 账号全局 vs 玩法分区

```
  全局：账号、登录、好友关系（可选）、支付账户、封禁名单、渠道绑定
  分区：角色、背包、进度、区服经济、就近战斗
  目录：告诉客户端去哪个 region 的哪条服
```

绑定表在账号 region、有备份；玩法服只认账号 token，不存第三方法人数据副本。

不要把所有全局服务塞一个 region 又把玩法散一堆，却没有目录降级：账号挂了你散得再开也没人进得去。全局服务的 SLO 和多 AZ 要比玩法服更严。目录降级不能依赖「唯一账号 region 已死还想进服」——账号挂就是全球门关了，预案是账号 region 自己的多 AZ，不是靠玩法散开。

玩家要「换到美服」。改一行 `region` 字段 = 事故。换区 = 小型合服：停写、校验、映射、双备份。跨 region 迁角色按 [02](../02-开服合服/) 的纪律走。

你眼睛看到玩家说号没了：先查目录有没有指到目标 region，再查映射，不要先怀疑「跨洋同步丢了」——你们本来就不该跨洋同步写角色库。

主机主主解决的是无状态或可冲突合并的存储。角色库有会话、经济、回档位点。跨洋双写会：延迟里冲突、同一道具发两次、回档不知道以哪边为准、合规上数据已出境。只读副本放到远 region：排行、展示可以。写背包、扣费、结算不行。只读延迟也要进 SLA，免得玩家看见「旧背包」。

> **记住**：账号挂是全球 P0，玩法 region 可摘。换区是迁移作业，不是改一个字段。

## 4. 安装部署

### 4.1 生产怎么选

| 项 | 选 | 不选 |
|----|----|------|
| 实时玩法 | 就近匹配、就近房间 | 就近 Gate + 远端逻辑当「全球同服」 |
| 角色库 | region 独立；坏了维护 | 跨洋双活写 |
| 账号 | 全局多 AZ，SLO 更严 | 靠玩法散开救账号挂 |
| 备份 | 同发行地账号 + region | 全球复制勾上再说 |
| 云账号 | 按发行主体拆 | 一个 Administrator 打全球 |
| oncall | 跟随发行当地 | 白班北京扛美西下午 P0 |

### 4.2 多 region 落地你实际看到什么

架构题先画游戏约束（有状态、分服、目录、延迟、数据驻留），再填产品名。只报一串 AWS 服务名，没有延迟和数据边界，是云证书答题，不是游戏出海。

| 点 | 国内云习惯 | 出海 AWS 常见对应 | 翻车点 |
|----|------------|-------------------|--------|
| 网络 | VPC + 安全组 + 高防包 | VPC + SG + Shield/WAF + NLB | 安全组默认和连接跟踪 |
| 身份 | RAM / 子账号 | IAM + IRSA，禁把 AK 打进镜像 | 密钥随包体出海 |
| 容器 | ACK | EKS，控制面托管 | 节点组和 GPU 机型要提前 quota |
| 对象存储 | OSS | S3 同 region；跨 region 复制要合规评估 | 备份桶开了全球复制 |
| 合规 | 备案、等保 | 各地隐私法、支付 PCI | 日志采集器指到错误 region |
| 人 | 白班北京 | 跟随发行当地 oncall | 半夜没人理美西 P0 |

控制面托管了还要懂影响面。和 K8s 托管同一逻辑：你 ssh 不进 etcd，事故仍是你的玩家。

人：白班在北京，美西 P0 出在当地下午。跟随发行当地 oncall，权限和堡垒提前开通，不要事故里再申请跨账号。半夜没人理美西 P0，是组织问题，不是 Shield 没买对。

简历没写出海就不要主动展开。被问到讲国内多 AZ 和「真跨洋」的差别，标明未执刀。不编 region 故障故事。

验收：每 region 独立 CDN 指针可预热；备份能说出账号和 region；GM 写权限按 region 切开；拨测点在真实玩家网。

region 最小骨架（画图用，再填云产品）：

1. 账号 region：登录、绑定、封禁；多 AZ；SLO 最严
2. 每个玩法 region：角色库、战斗、本服支付发货、独立 CDN 指针与源
3. 目录：告诉客户端去哪；可摘某一玩法 region
4. 备份：落在该发行主体账号、该 region；跨 region 复制默认关
5. oncall：跟随该发行当地；权限不跨 region 写

缺第 4 条会在「备份更稳」时把 PII 带出国。缺第 5 条会在美西下午变成北京半夜没人理。缺第 2 条独立 CDN，切流量会变成登录 + 更新双事故。

## 5. 核心配置

| 项 | 生产怎么用 | 改错会怎样 |
|----|------------|------------|
| 目录 | 客户端听目录，不写死 IP | 切 DNS 到未预热 region = 双事故 |
| CDN 指针 | 每 region 独立预热 | 国内预热完当天全球切 |
| cron / 活动 | 当地时区 | 北京 05:00 = 美西黄金时段合服 |
| `min_client_version` | 按 region + uid 灰度 | 全球同时抬 min |
| S3 复制 | 默认关；开前合规评估 | PII 出域 |
| IAM | region 范围；禁 AK 进镜像 | 密钥随包体出海 |
| NTP | 跨 region 对时 | 活动已开但进不去；票据莫名过期 |
| 数据驻留 | 默认不出域；复制需评估 | 「数据在 S3」四字过关 |
| 换区 | 合服纪律；跨法域默认拒绝 | UPDATE region |

> **记住**：活动整点和合服用当地时区。CDN 指针按 region 独立预热，国内预热完不等于海外可切。

延迟预算写进匹配，不写进对玩家的「全球同服」文案。数据驻留写进备份作业和 IAM，不写进「我们用了 AWS」。两件事都是架构约束，不是上线后补的合规附件。

## 6. 常用命令

出海值班先问四句，不是先改 DNS。

| 目的 | 问什么 / 看什么 |
|------|-----------------|
| 延迟 | 分地区、分协议 RTT；点在玩家网 |
| 驻留 | 备份哪个账号、哪个 region、有无跨账号复制 |
| 目录 | 客户端被指到哪；目标版本 / CDN 是否就绪 |
| 支付 | 哪条渠道、发货延迟；不要看全球登录 |
| 合规 | 备份账号 / region / 复制开关；日志有没有出境 |

拨测不要从国内办公网出一跳 ping 代表全球。至少：各发行地真实玩家网、登录 HTTPS 和战斗 TCP/UDP 分开、加速器开/关各采一次。办公网 RTT 很好、玩家幻灯片，多半是加速器或就近房间没落地。

```
  错：cron 0 5 * * *   北京 05:00 = 美西下午，黄金时段合服
  对：活动整点按当地；运维窗口按当地低峰
      多 region 活动配置按时区拆，不要一份 cron 打全球
```

## 7. 常用操作

### 7.1 切流量：目录先于 DNS

客户端拿到的是目录，不是写死的 IP。切 region：改目录 / DNS，先保证目标侧容量、版本、CDN 指针一致。

```mermaid
flowchart LR
    A[目标版本 / 容量 / 指针就绪] --> B[目录改指向]
    B --> C[灰度 region + uid]
    C --> D[盯该区登录 / 更新 / 支付]
    classDef a fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class A,B,C,D a
```

1. 版本 / 配置 / 资源指针按 region 独立发布（03、06）
2. CDN 分区或多源，避免一个源站给全球回源
3. 灰度按 region + uid，不要一次全球抬 `min_client_version`
4. 目标未预热就切 DNS = 登录 + 更新双事故

容灾实话：热备双活写同一角色库，游戏几乎不这么干。常见是 region 独立，坏了公告维护。DNS 切走未预热的 region，给远距玩家制造登录 + 更新双事故。DNS 切完登录通了、更新全失败：目标 region 没有独立源 / 没预热。先回目录，不要再抬 min。

切流量不是「把人赶到还活着的 region 就能玩」。角色数据在源 region。目录把美西玩家指到欧区，若他的号不在欧区，结果是进错服或空号。容灾能做的是：摘故障玩法 region、让该区玩家看到维护；其他 region 的号不受影响。把人跨 region 改指向当双活，等于没做迁移就换区。

灰度按 region + uid，避开加速器出口导致的「按 IP 地区」错位（08）。一次全球抬 `min_client_version` 会把还在旧包的地区连同 CDN 未预热一起堵在门外。

### 7.2 换区迁移

和合服同一套门禁：

1. 目录摘源 region 该角色入口，停写
2. 双备份（源 + 目标），映射表落盘
3. 迁角色 / 背包 / 邮件，三道校验
4. 目标 region 冒烟通过再开放
5. 失败 → 恢复两份备份，禁止改字段再试一次

换区是数据驻留操作，不只是玩法操作。源 region 的角色行搬到目标 region，等于一次受控跨境（若两个 region 不同法域）。工单要写：数据从哪个账号哪个 region 到哪个；法务是否允许；备份两份都在合规位置。不能「先搬再补评估」——PII 已经出域。

同一发行主体、同一法域内的换区（例如美东 ↔ 美西）驻留压力小，仍按合服纪律走停写和映射。跨法域（欧 ↔ 美、欧 ↔ 国内）默认拒绝，除非产品 + 法务书面允许。运维不提供「改字段换区」这种看起来很便宜的捷径。

### 7.3 CDN 分区

每 region 独立指针和预热。全球一个源站会让远距回源变成更新事故。国内预热完成不等于海外可切指针。证书和隐私政策页按发行地拆。

驻留叠在 CDN 上：访问日志、回源日志、WAF 日志默认会进 CDN 厂商账号。问清日志落在哪个 region、会不会进全球分析。欧区玩家下载日志进国内账号，和备份跨 region 复制是同一类事故。预热 API 密钥不要全球一把，按发行主体拆。

### 7.4 时区与 NTP

活动整点按当地；运维窗口按当地低峰。多 region 活动配置按时区拆。token 过期、活动「已开但进不去」先看 NTP / 时钟偏移，再看代码。跨 region 对账先看时间。区服之间时钟偏到秒级，会出现「活动已开但进不去」或票据莫名过期。见 02-19。

### 7.5 支付地区 P0

出海支付失败是**地区 P0**，不要当成登录问题扩 Gate。每条渠道单独成功率和发货延迟。沙箱通了、正式包证书 / 回调 URL 错，是上线日经典事故——变更单要有正式环境回调验签。

你眼睛看到美西储值失败、亚太登录还绿：不要扩 Gate，不要关全球登录。按渠道看成功率和发货延迟，对账落在角色所在 region。发货必须在可审计的区域完成。订单留存按当地规则。

玩家重复点支付：渠道侧可能已扣款。对账补发，不要让玩家「再点一次试试」。和游戏内回档的二次伤害是同一类（07）。

### 7.6 权限与拨测

GM 写权限按 region 切开。美西值班不该对欧区角色库有写。跨 region 查询走只读 + 审计。这是合规也是误操作半径——回档和裸改的风险面被权限放大。应急临时开全球写：当变更，过期时间、审计、双人。不要把「临时」留成默认策略。

拨测分地区、分协议，点放在真实玩家网，不放在办公网。加速器会让「地区」失真（08）。

| 被问 AWS 架构 | 先约束再产品名 | 报一串服务名不提延迟 / 驻留 |

## 9. 必会 · 常考

白板和追问高频，能一口回：

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 专线能把跨洋 200ms 变 20ms | 错 | 光速下限；专线稳丢包 |
| 就近 Gate + 远端逻辑 = 全球同服 | 错 | 战斗 RTT 几乎不降 |
| 角色库跨洋双活写更稳 | 错 | 冲突、回档、合规全炸 |
| 账号挂了玩法散开还能进 | 错 | 账号挂 = 全球门关 |
| 换区改一个 region 字段 | 错 | 小型合服迁移 |
| 「数据在 S3」就够了 | 错 | 账号 + region + 复制 |
| 国内预热完切全球指针 | 错 | 海外独立源 / 预热 |
| 北京时间给美西合服 | 错 | 当地低峰 |
| 地区支付失败扩 Gate | 错 | 地区 P0，不是登录 |
| 国内三 AZ 等于多 region 出海 | 错 | 延迟和合规都不是一回事 |
| 没做过就编美东切流故事 | 错 | 标明未执刀 |
| GM 全球写方便值班 | 错 | 按 region 切开 |

数字：同城 **10～30ms**；跨大陆 **150～250ms+**；实时对战舒适约 **50ms**；回合制 **100～200ms** 可玩。

延迟账拆两跳（玩家→Gate、Gate→房间）。驻留账拆三问（账号、region、复制）。缺任何一问，出海架构都还没画完。

易混：就近 Gate vs 就近房间；多 AZ vs 多 region；SLO 账号 vs 玩法；备份复制 vs 驻留；目录切流 vs 只改 DNS；支付地区 P0 vs 登录 P0。

驻留面试一句收口：备份要能说出账号、region、有没有跨账号复制。延迟面试一句收口：就近的是房间，不是只就近 Gate。
