# 项目深挖模板 · Kubernetes 平台/故障

> **用途**：K8s 项目深挖。**数字全是占位符 `<...>`，答题前换成你真实值**。只挑一个你做过的改编：GitOps 发布 / CoreDNS 故障 / Pending·CrashLoop·OOM 治理。
>
> **口述**：主语「我」；≥2 个数字；讲权衡；扛 3 轮追问。方法论见 [01-职业发展/02-简历与项目](../01-职业发展/02-简历与项目/)。

## 候选（任选 1 个，别贪多）

| 方向 | 一句话电梯版 |
|------|-------------|
| **GitOps 发布** | 我把 **<N>** 个服务从人工 kubectl 迁到 GitOps，回滚 **<X→Y min>**，变更故障率 **<A%→B%>** |
| **CoreDNS 故障** | 我修过集群 DNS 超时，根因 **<ndots/缓存/上游>**，失败率 **<X%→0>** |

## STAR（GitOps 例，2 分钟）

| 阶段 | 替换占位符 |
|------|------------|
| **S** | **<N>** 套集群、**<M>** 服务、日发 **<K>** 次；人工 apply，**<X%>** 的 P0 来自误操作 |
| **T** | 我推 GitOps：可回滚、可审计、发布频率不腰斩 |
| **A** | ① 用 **<6 个月误操作占比>** 拿背书 ② 非核心先试点，回滚 **<X→Y min>** ③ 留热修通道，24h 补 Git（→ 05 工程化） ④ **<周期>** 全量 + drift 告警 |
| **R** | 回滚 **<X→Y min>**；故障 **<A%→B%>**；可审计 |

## 追问骨架

| 追问 | 答法 |
|------|------|
| Pending？ | describe Events：资源 / 亲和 / PVC / 污点（→ 06、17） |
| CrashLoop 第一刀？ | `logs --previous`；配置 / 探针 / 依赖（→ 04、17） |
| OOM 是 limit 还是泄漏？ | RSS 趋势 + cgroup 总量，不是只看堆（→ 04） |
| 为何不一直 kubectl？ | 不可审计、难回滚；热修通道是权衡（→ 05 工程化） |
| drain 注意？ | PDB、DS、本地盘、有状态服先迁（→ 05、16） |
| Service→Pod？ | DNS→VIP→kube-proxy DNAT→Pod；空 EP 先看探针（→ 08、09） |
| 游戏服能 HPA 缩吗？ | 无状态可以；房间服缩=杀对局（→ 07、15） |
