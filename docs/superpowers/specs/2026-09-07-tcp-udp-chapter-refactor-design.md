# TCP 与 UDP 章节重构设计

## 目标

重构 `01-基础底座/13-TCP与UDP/知识点.md`，让第一次系统学习 TCP/UDP 的读者能顺着一条主线读懂，同时保留高级运维面试与生产排障所需的核心知识。

验收标准：

- 正文从约 1000 行压缩到 600～700 行。
- 主线仍是：选型 → 建连 → 传输 → 保活 → 关闭 → UDP/KCP/QUIC → 排障。
- 每个机制只完整讲一次，不再用图、ASCII、表格和总结重复表达同一内容。
- 握手、挥手、滑动窗口、重传、流量控制、拥塞控制、心跳、TIME_WAIT/CLOSE_WAIT 等高频考点不丢失。
- 读者读完能回答“为什么”“现场怎么看”，而不只是背定义。

## 范围

本轮只修改 `知识点.md`。保留现有顶层节名和顺序，避免 `练习题.md` 中按节名建立的引用立即失效。练习题待用户认可知识点质量后再同步。

不新增、删除或重命名章节目录，不扩写网络栈、抓包、conntrack 等相邻章节负责的内容。

## 结构

1. 一张图：用连接生命周期建立全局心智模型。
2. 选型：TCP 字节流、UDP 报文以及粘包/拆包。
3. 出生：TCP 头最小知识、三次握手、状态与握手失败。
4. 干活：滑动窗口、`rwnd/cwnd`、重传、拥塞控制和可靠性收束。
5. 老去：半打开、应用心跳、NAT/LB 空闲超时、Nagle、切网。
6. 死亡：四次挥手、半关闭、TIME_WAIT/CLOSE_WAIT 和必要的复用选项。
7. 另一条路：UDP、KCP、QUIC 的能力与边界。
8. 作战：以连接阶段和可观测证据定责。
9. 收口：命令、面试锚点、易错项、数字墙与合上书。

## 写法

每个核心机制采用同一条短链：

1. 先抛出读者能感知的现象或问题。
2. 用一句白话给结论。
3. 必要时只保留一张标准图。
4. 解释关键因果，不复述图中文字。
5. 给出一个可靠的现场判据或边界。

删除大段讲师串场、重复的“读图”复述、同义双图和重复面试答案。类比只用于滑动窗口、三次握手、拥塞控制等少数难点。

## 技术准确性修订

- 不再把 `ss -ti` 的 `rcv_space` 直接解释为对端通告窗口，也不据此单独判定 ZeroWindow。
- ZeroWindow 以抓包中的接收窗口通告、发送受限指标及对端应用读取情况交叉确认。
- KCP 是否退让取决于其配置；明确它有可选拥塞控制，不能笼统描述为“没有拥塞控制”。
- 对 Nagle、Delayed ACK、MSL、TIME_WAIT 等数字使用“常见值/实现相关”口径，避免把经验值写成协议固定值。
- `ss` 字段解释与当前 Linux/iproute2 语义保持一致。

## 验证

- 检查总行数在 600～700 行。
- 检查必要术语仍存在：三次握手、四次挥手、字节流、粘包、滑动窗口、流量控制、拥塞控制、RTO、快速重传、SACK、TIME_WAIT、CLOSE_WAIT、心跳、KCP、QUIC。
- 检查所有 Mermaid 代码块闭合，内部无自定义配色。
- 检查跨章链接仍指向现有目录。
- 检查顶层标题与练习题现有“对应”节名一致。
