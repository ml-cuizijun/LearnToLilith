## Q1

**★★★★★｜什么是 Vibe Coding？和「AI 替我写代码」差在哪？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：AI 辅助排障/编码的一生](知识点.md)

### 场景

新人说 Vibe Coding 就是不用懂 bash，让 Cursor 直接上生产。


先自己试试，再往下看解答。

### 完整解答

> 🎯 **一句话**：自然语言出草稿，人 review+测试+合入；两端必须是人。

模型管中间稿；需求、验收、变更责任在人。不懂的代码不能合。

> 📝 **面试**：提效重复劳动，不替值班签字。

### 再追问

**谁管两头？**——人写工单、人过 checklist、人 MR/apply。

## Q2

**★★★★★｜排障用 AI 应该怎么开场？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [二、人收证据：排障先有人，再要 AI 假设](知识点.md)

### 场景

有人对 ChatGPT 说「大厅挂了怎么办」，模型编了一套 cordon 步骤。


排障开场——承接主线。

先自己试试，再往下看解答。

### 完整解答

> 🎯 **一句话**：人先贴 3~5 条证据，再要 3~5 假设+只读命令；不要 apply/delete。

正确开场含：指标、变更时间、Pod 状态、边界「只要只读」。

> ⚠️ **别混**：RAG 开卷查手册（03）；闭卷会幻觉。

### 再追问

**delete 能在自动路径吗？**——不能，和 Agent（06）同一红线。

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [五、人 review：七条 checklist](知识点.md)

### 场景

工单四要素。

先自己试试，再往下看解答。

### 完整解答

> 🎯 **一句话**：euo pipefail、引号、无密钥、幂等、dry-run 默认、对照官方文档、未知标待核实。

## Q12

**★★★★｜AI 出的 Ingress YAML apply 报 unrecognized apiVersion，怎么验？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [五、人 review：七条 checklist](知识点.md)

### 场景

Cursor 生成 `extensions/v1beta1 Ingress`，staging apply 失败；有人说「AI 笨，换模型」。


先自己试试，再往下看解答。

### 完整解答

> 🎯 **一句话**：`kubectl apply --dry-run=server` 对照集群 API；模型常用过期写法，review 第六条必做。

```bash
kubectl api-resources | grep ingress
kubectl apply --dry-run=server -f deploy-draft.yaml -n staging
```

> ⚠️ **别混**：client dry-run 不比 server 严——合入前用 server。

### 再追问

**Helm 草稿怎么验？**——`helm template | kubectl apply --dry-run=server -f -`。

## Q14

**★★★★｜Claude Code 配置了 auto git push，活动前夜怎么收口？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [七、合入或丢：MR 文化，禁止 auto apply](知识点.md)


先自己试试，再往下看解答。

### 完整解答

> 🎯 **一句话**：关 autoPush；本地 commit 可快，push/MR/merge 必须人；`git diff main...HEAD` 查 secret/delete。

```bash
git diff main...HEAD | grep -iE 'password|secret|kubeconfig|delete pod'
```

Vibe 闭环：W 和 R→M 必须是人，Agent auto push 是危险品。

### 再追问

**cron 跑的脚本 hash 怎么验？**——`md5sum` 对比 git main 版本，不是 Cursor 临时 buffer。
