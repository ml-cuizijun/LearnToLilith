## Q1

**★★★★★｜Function Calling 是什么？模型会自己执行 kubectl 吗？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：一次 Tool Call 的一生](知识点.md)

### 场景

「我们上了 AI 自动扩容」。

### 完整解答

> 🎯 **一句话**：FC = 模型出 **tool_calls JSON**；**执行器**校验后打 API——**没有箭头从模型连 apiserver**。

模型是点菜员，不是厨师。

> 📝 **面试**：意图与执行分离。

### 再追问

**和 ChatGPT Plugin 像吗？** 机制类似；运维强调 RBAC+审计。

## Q2

**★★★★★｜口述 FC 七步循环。**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [三、意图：模型出 tool_calls](知识点.md)

### 场景

白板题。

### 完整解答

> 🎯 **一句话**：定义 schema → 提问 → 模型 tool_calls → **校验** → 执行 → tool_result 回喂 → 结束或达 max_steps。

写操作走 propose 支路，不在裸 execute。

### 再追问

**tool_result role？** `role: tool` 回喂 messages。

## Q3

**★★★★｜schema description 为什么重要？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [二、定义：schema 与 description](知识点.md)

### 场景

`description:"查询数据"` 导致乱调工具。

### 完整解答

非法 args → 403 回喂模型改参。

### 再追问

**参数能从日志原文来吗？** 禁止；防注入。

## Q4

**★★★★★｜运维工具怎么分级？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [四、校验：执行器是信任根](知识点.md)

### 场景

工具列表有 `restart_pod` 可 auto。

### 完整解答

> 🎯 **一句话**：**L0 只读** auto；**L2 写** 仅 `propose_*`+人批；**L3 delete** 不出现在列表。

只读 SA，无 cluster-admin。

| 级别 | 策略 |
|------|------|
| L0 | query/get/search 限流 |
| L2 | propose+变更单 |

### 再追问

**L1 敏感读？** secret metadata 可审计+审批只读。

## Q5

**★★★★★｜写操作怎么设计才不误执行？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [六、写操作：propose 与审批闸门](知识点.md)

### 场景

有人复制 bot 的 delete 建议。

### 完整解答

> 🎯 **一句话**：`propose_restart_pod` → 变更单 **CHG-xxx** → 飞书批 → **变更 SA** 执行——模型无写凭证。

写操作 **不自动重试**。

### 再追问

**批了谁执行？** 变更系统，非 LLM 再 call。

## Q6

## Q7

**★★★★｜tool 4xx/5xx 怎么处理？**

**覆盖**：必会 ｜ **对应**：知识点 [五、执行与回喂：tool_result 闭环](知识点.md)

### 场景

search_logs 连续 15 次 400。

### 完整解答

> 🎯 **一句话**：**4xx** 回喂改参，**同类 2~3 次熔断**；**5xx** 有限退避；**写不重试**；max_steps **8~12**。

别打满 Prom/Loki。

### 再追问

**步数打满？** 停 auto tool，摘要+交人。

## Q8

**★★★★｜一次返回两个 tool_calls 怎么办？**

**覆盖**：常用 ｜ **对应**：知识点 [五点五、并行调用、PromQL 闸门与可观测](知识点.md)

### 场景

get_pod + query_prometheus 同时返回。

### 完整解答

> 🎯 **一句话**：**独立只读可并行** 降 latency；有依赖必须串行两跳。

写禁止并行。

### 再追问

**10MB tool 结果？** 执行器截断+摘要再回喂。

## Q9

**★★★★★｜有 FC 为何摘要还写 CPU 90%？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [五、执行与回喂：tool_result 闭环](知识点.md)

### 场景

未调 Prom 就报数。

### 完整解答

> 🎯 **一句话**：**数值必须来自 tool_result**——Prompt 写死；闭卷总结仍可能编；audit 查有无 query_prometheus call。

接只读 PromQL FC。

### 再追问

**Prom 返回空？** 如实回喂；模型应说无数据。

## Q10

## Q11

**★★★★｜FC、MCP、Agent 各一句话？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [七、边界：SRE 该用与禁止](知识点.md)

### 场景

架构分层题。

### 完整解答

> 🎯 **一句话**：**FC=砖**（意图机制）；**MCP=插头**（发现复用）；**Agent=楼**（多步 max_steps）。

2~3 步只读用 FC；多 Host 共用工具上 MCP。

### 再追问

**MCP 替代 FC？** 不；call 后仍 FC 循环。

## Q13

**★★★★｜误执行 delete，60 秒查什么？**

**覆盖**：必会 ｜ **对应**：知识点 [八、作战：FC 事故定责](知识点.md)

### 场景

玩家掉线。

### 完整解答

> 🎯 **一句话**：audit **tool/approver/args** → 写 tool 是否裸暴露 → 是否 propose 流 → 回滚+下架写 tool。

```text
0–10s audit  10–30s 写路径?  30–45s 注入/枚举  45–60s hotfix
```

### 再追问

**谁背锅？** 流程+审批；不是「模型坏了」。
