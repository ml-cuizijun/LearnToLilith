## Q1

**★★★★★｜LLM 和搜索引擎的本质区别是什么？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：一次推理的一生](知识点.md)

### 场景

面试官白板：「你们用 GPT 查 wiki，和 Google 有什么不一样？」有人答「都是找答案，GPT 更智能」。

### 完整解答

> 🎯 **一句话**：搜索引擎检索索引返回已有文档；LLM 是 **自回归** 闭卷续写下一个 token，不查库时不接触外部事实。

搜索引擎：问句 → 倒排索引 → 返回 **已收录** 网页链接，新鲜度靠爬虫。LLM：文本 → Tokenizer → Transformer → 词表概率 → 采样 → **生成** 像答案的文本——训练学的是「下一个 token 分布」，不是「查表返事实」。运维用途：摘要、分类、草稿；查实时状态要靠 FC，查 SOP 要靠 RAG。

> ⚠️ **别混**：「像 SRE 会怎么写」≠「你们集群真是这样」；像不像和对不对是两件事。

> 📝 **面试**：「LLM 闭卷续写器，不是搜索引擎；实时和文档分别靠 FC 和 RAG。」

### 再追问

**GPT 能联网是不是就变成搜索引擎了？**

联网/FC 是应用层给材料，**生成机制仍是续写**——材料错了或没有，照样会编。和搜索引擎的索引检索仍是两码事。

## Q2

**★★★★★｜一条 1.2 万字符的脱敏告警 JSON，为什么要先 Tokenizer 试算？128K 窗口是不是能塞 128K 汉字？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [二、入场：Token 与 Tokenizer](知识点.md)

### 场景

脚本把整段 Alertmanager 输出塞进 prompt，网关 bill 暴涨；Junior 说「128K 窗口够大，全塞进去最省事」。

### 完整解答

> 🎯 **一句话**：模型按 **token** 计费占窗口，不是按字符；中文+JSON 常 **字符×1.5~2**，128K 窗口远塞不满 128K 汉字，且 input+output **共享**。

```bash
python3 -c "import tiktoken; e=tiktoken.encoding_for_model('gpt-4o'); t=open('/tmp/alerts.json').read(); print(len(t), len(e.encode(t)))"
# 12450 18230  ← token 比字符多 46%
```

试算后才能知道：① 会不会超窗；② 还剩多少给 `max_tokens`；③ 账单预估。JSON 缩进、符号、长 label 特别费 token。正确做法：规则提取 firing 告警 + 试算 < 窗口 50%。

> ⚠️ **别混**：token ≠ 字节 ≠ 汉字；不同模型 Tokenizer 切分不同，两家 API 同文本 token 数可能差很多。

### 再追问

**怎么在流水线里自动拦截超大 input？**

网关卡单请求 prompt_tokens 上限（如 32K），超过走摘要服务；caller 日配额防脚本死循环。

## Q3

**★★★★｜用 30 秒讲清 Self-Attention 直觉，需要推公式吗？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [三、理解：Embedding 与 Self-Attention](知识点.md)

### 场景

面试官：「Transformer 为什么比 RNN 适合长文本？」

### 完整解答

> 🎯 **一句话**：**Self-Attention** 让每个 token 通过 Q/K/V 看全文哪些位置重要，**并行**处理；多层堆叠从局部到全局——SRE 懂机制即可，不必推矩阵。

RNN 顺序传递，长依赖弱。Attention：`softmax(QK^T/√d_k)·V`，当前 token（Q）和所有位置（K）算相似度，加权聚合（V）。每层后接 FFN + 残差，×N 层。运维口径：「看上下文续写」，细节见 [01 知识点三节](知识点.md)。

> 📝 **面试**：「Q 查、K 比、V 抄；decoder-only LLM 推理主要是 Self-Attention。」

### 再追问

**Embedding 层和 RAG 的 Embedding 是一回事吗？**

不是。LLM 里 Embedding 是 token ID→向量查表；RAG 的 Embedding 模型把整段文本变成检索向量——见 [03 RAG](../03-RAG检索增强/)。

## Q4

**★★★★★｜值班说模型「眼瞎」，OOM 栈在日志里但就是答没有——可能是什么原因？**

**覆盖**：核心 · 常用 ｜ **对应**：知识点 [四、堆叠：Transformer 块与上下文窗口](知识点.md)

### 场景

40K token access log，唯一 OOM 栈在文件前 5%；API 返回 200，模型答「未发现 OOM」。有人要换 70B 模型。

### 完整解答

> 🎯 **一句话**：先查 **silent truncate** 和 **lost in the middle**——栈可能在被砍掉的头部，或埋在大段中间被稀释；不是模型「变小」。

```bash
curl -s .../v1/chat/completions -d @req.json | jq '.usage.prompt_tokens, .choices[0].finish_reason'
# prompt_tokens: 127500  ← 接近上限，早期 token 可能被截
# finish_reason: "length"  ← 也可能是输出截断
```

修复：① `grep OOMKilled` 提取片段再喂；② 重要信息放 prompt **首尾**；③ 预留 output token。别先换模型。

> ⚠️ **别混**：400 context length = 硬拒；200 + 高 prompt_tokens = 可能静默截断，更隐蔽。

### 再追问

**上下文窗口和训练 cutoff 区别？**

窗口是推理一次能看多少 token；cutoff 是训练知识截止日期——窗口再大也补不了 cutoff 之后的事件。

## Q5

**★★★★★｜temperature 设 0 是不是就不会胡说？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、出场：采样与下一个 token](知识点.md)

### 场景

Oncall 把分类流水线改成 `temperature=0`，仍出现编造的 CPU 90%；有人说「再降到 0 就行」。

### 完整解答

> 🎯 **一句话**：**temperature 只控随机性**，低温≈贪心选最高概率 token，**不控真实性**——训练分布里没有的事实仍会「像样地编」。

`temperature=0` 让同样输入输出更可复现，适合 JSON 分类；但闭卷问「etcd 版本」仍可能自信答错版本号。防胡说靠 RAG/FC/拒答/人审，不是调 temperature。

> 📝 **面试**：「低温求稳定，不是事实开关；该幻觉还会幻觉。」

### 再追问

**top-p 和 temperature 怎么配？**

流水线常见 `temperature=0.1~0.3` + `top_p=0.9~0.95`；创意文案才升温，且仍人审。

## Q6

**★★★★｜什么是幻觉？运维场景怎么挡？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [六、交付：输出、幻觉与 API 参数](知识点.md)

### 场景

RAG bot 引用不存在的 wiki 章节；告警摘要写「CPU 90%」但 Grafana 没有。

### 完整解答

> 🎯 **一句话**：幻觉是闭卷 **自信地错**——机制不是 bug；挡法 **材料层+约束层+人审层**，换大模型 alone 不够。

| 类型 | 例子 | 挡法 |
|------|------|------|
| 事实幻觉 | 编造 kubectl flag | FC 查 `--help` |
| 引用幻觉 | 「wiki 第 3 章」无此文 | RAG 强制 citation |
| 数值幻觉 | CPU 90% 未查 | 只读 PromQL FC |
| 时效幻觉 | 已下线架构 | 文档元数据+下架 |

数值类：**禁止模型报具体指标**，必须来自 tool_result。

### 再追问

**「请认真思考 step by step」能防幻觉吗？**

不能当架构依赖；链式思考可能让错误更「像真的」，仍要材料和校验。

## Q7

**★★★★★｜含 kubeconfig 的 kubectl describe 输出，能不能贴公有云 ChatGPT？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [七、边界：SRE 该用与禁止](知识点.md)

### 场景

Junior 在 P1 群贴完整 describe 到 ChatGPT 问扩容 YAML；安全扫描 `pii_detected=true`。

### 完整解答

> 🎯 **一句话**：**禁止**——生产数据/密钥 **不出域**；describe 含 SA、Env、内网信息，贴公有云 = 泄露 + 合规事故。

正确：内网私有模型或脱敏（去 IP 末段、hash 实例 ID、剥离 secret）后再调 API。AI 输出是草稿，**apply 必须人审**。出域后还要：轮换凭证、改网关路由、通报安全。

> 📝 **面试**：「红线第一条：含生产数据的默认不出域；不是谁模型强就用谁。」

### 再追问

**开源模型部署在内网就绝对安全吗？**

部署内网是数据路径可控；若应用仍把密钥写进 prompt 或日志，一样泄露——出域指数据离开受控边界。

## Q8

**★★★★｜开源私有和闭源 API，你怎么选？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [七、边界：SRE 该用与禁止](知识点.md)

### 场景

团队争论「Qwen 72B 私有 vs GPT-4o API 谁更强」，没人提合规。

### 完整解答

> 🎯 **一句话**：选型顺序 **合规→出域→成本→能力**——含 kubeconfig/UID 的默认内网私有；公开文案可用 API。

| 维度 | 闭源 API | 开源私有 |
|------|----------|----------|
| 数据 | 出域审 DPA | 留内网 |
| 成本 | 按 token | GPU+人力 |
| 能力 | 通常更强 | 7B~70B 看场景 |

POC：100 条告警摘要人工评分 + P99 延迟 + 月成本表写 ADR，不凭体感。

### 再追问

**7B 能不能上生产？**

可以辅助分类/摘要，要评测；关键路径 70B+ 或闭源 API；幻觉率通常 7B > 70B。

## Q9

**★★★★｜告警聚类 JSON 流水线突然 json.loads 失败，怎么查？**

**覆盖**：常用 · 必会 ｜ **对应**：知识点 [六、交付：输出、幻觉与 API 参数](知识点.md)

### 场景

`max_tokens=128` 上线后，响应里 JSON 缺闭合括号，finish_reason 异常。

### 完整解答

> 🎯 **一句话**：查 **`finish_reason=length`** 和 **`max_tokens` 太小**——输出 token 被截断，JSON 写一半。

```bash
curl -s ... | jq '{finish: .choices[0].finish_reason, content: .choices[0].message.content}'
# finish: "length"
# content: "{\"clusters\":[{\"name\":\"oom\"..."  ← 缺括号
```

改 `max_tokens=2048`，保留 `response_format=json_object` + Pydantic 校验。客户端 timeout 比网关 SLA 短 5~10s 便于重试。

### 再追问

**JSON mode 保证字段类型对吗？**

不保证；仍要代码侧 schema 校验和枚举检查。

## Q10

**★★★★｜多轮排障助手，第 1 轮贴错 Pod 名，第 5 轮纠正后仍被带偏——为什么？**

**覆盖**：常用 ｜ **对应**：知识点 [六、交付：输出、幻觉与 API 参数](知识点.md)

### 场景

应用把全文 5 轮 history 原样塞回 API；token 从 8K 涨到 35K。

### 完整解答

> 🎯 **一句话**：API **无状态**——「记忆」是应用层拼 history；早期错误滚进 context，还占窗口。

生产倾向 **单轮**（告警分类）或 **≤3 轮**；session 存结构化 `{"pod":"gw-2","oom":true}`，关键结论写工单，不靠模型记住。每轮只带摘要材料，不带全文对话。

### 再追问

**长 history 和 long context 模型关系？**

窗口再大也怕 lost in the middle；结构化 session 比无脑堆 history 稳。

## Q11

**★★★★★｜设计告警风暴下的群消息摘要，边界怎么划？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、边界：SRE 该用与禁止](知识点.md)

### 场景

200 条 Alertmanager 通知涌入飞书；有人想让 bot 自动 Silence 根因告警。

### 完整解答

> 🎯 **一句话**：摘要 = **脱敏 + 内网模型 + 低温 JSON + 人审草稿**；Silence/Scale/Rollback **必须人点**。

流程：聚合器脱敏 → `temperature=0.2` → 输出 clusters/hypothesis/suggested_panels → Oncall 人审 pin。System 禁 apply/delete/编造指标。跳过脱敏贴公有云 = 出域 + 编造命令双事故。

### 再追问

**摘要提到具体 Pod 能直接 cordon 吗？**

不能；人 `kubectl` 核实后再操作——摘要只是方向，不是执行依据。

## Q12

**★★★★｜LLM 网关账单环比 ×8，FinOps 质疑，你怎么查？**

**覆盖**：常用 ｜ **对应**：知识点 [七、边界：SRE 该用与禁止](知识点.md)

### 场景

活动后账单飙高；某「日志分析」脚本嫌疑最大。

### 完整解答

> 🎯 **一句话**：按 caller 聚合 **input tokens**——常见根因是脚本周期性送 **全量 log**；修法是上限+配额+先 grep 提取。

排查：audit log 按 `caller_id` sum(prompt_tokens)；发现每 5min 送全量 access log。加单请求 input 上限、日配额；改 grep ERROR + 超 8K 本地摘要。口径：「LLM 成本 = token×单价×QPS，窗口管理是 FinOps 问题。」

### 再追问

**响应缓存能降 bill 吗？**

相同 fingerprint 短期缓存可以，注意 stale；不能缓存含实时排障结论的请求。

## Q13

**★★★★★｜Oncall 说「摘要里 CPU 90% 但面板没有」——60 秒内你怎么定责？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [八、作战：推理问题定责](知识点.md)

### 场景

不要换模型；先分叉现象。

### 完整解答

> 🎯 **一句话**：① 查该次有无 **tool_result/PromQL** → 无则 **数值幻觉**；② 查 prompt 版本是否删「禁编指标」；③ 并行 audit **pii_detected**。

```text
0–10s  分型：格式/事实/漏信息/合规
10–30s jq usage + finish_reason
30–45s 无 FC 结果 → 闭卷幻觉；修 system + 接只读 query_prometheus
45–60s audit 路由；勿先换 70B
```

修复：数值必须来自 tool；摘要标注草稿。别加 temperature 当解法。

### 再追问

**有 RAG citation 但数字仍错？**

生成加戏——收紧「仅基于引用」+ 低温；仍要人对照源文档。

## Q14

**★★★★★｜2 分钟口述：LLM 是什么、不是什么，你们线上怎么用、红线是什么？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [九、收口](知识点.md)

### 场景

终面 SRE 加分项综合题。

### 完整解答

> 🎯 **一句话**：闭卷自回归续写器，不是搜索/执行器；我们用它做摘要和草稿，查事实靠 RAG/FC，变更人审，数据不出域。

2 分钟结构：机制（Tokenizer→Attention→采样→自回归）→ 窗口与 token 管理 → 幻觉与三层防护 → 选型（合规优先）→ 落地（告警摘要、Runbook 草稿）→ 红线四条。追问 temperature、Attention、和 RAG 关系都能接住。

> 📝 **面试**：背「闭卷续写四件套 + 不保证什么 + 红线四条」。

### 再追问

**和 RAG 什么关系？**

LLM 是生成器；RAG 先检索再给材料开卷，减闭卷幻觉——见 [03](../03-RAG检索增强/)。
