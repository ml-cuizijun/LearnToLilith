# LVS 与四层负载均衡

> 活动开闸，入口网卡双向打满、玩家进房超时；新人一看 `ipvsadm` 回包列 OutBytes 比 InBytes 还大，喊「加 RS」；另一次群里有半数玩家「进错房、会话乱」——真凶一个是在走 NAT 模式，一个是 ARP 里 VIP 对应两个 MAC。
> **本章回答**：一条战斗连接的一生——VIP 怎么找到、ipvs 怎么分房、NAT/DR/TUN 三种通路差在哪、后端生病怎么摘、VIP 漂移断不断存量。

**标记**：🎯重点 · 🔥难点 · ⭐常考 · 🔧实操

**读图**：

- 主线四段：**找门**（VIP 漂在哪台 LVS）→ **分房**（算法只管第一次分配）→ **通路**（NAT/DR/TUN 差在回程过不过 LVS）→ **干活/生病**（存量不搬家、探活只摘新分配）。

## 二、找门：VIP 与 keepalived ⭐

> 🎯 **一句话**：正常永远只有一台 LVS 持有 VIP；两台都有就是脑裂，立刻下一台。

先认三个角色，**别混为一谈**：

- **ipvs** = 内核里的四层转发模块（**IPVS，IP Virtual Server**），规则在内核里跑——**ipvsadm 挂了，正在转的连接通常还在**，和 kube-proxy 同一类影响面。
- **ipvsadm** = 用户态下规则、看 stats 的工具。
- **keepalived** = VIP 主备（VRRP）+ 常兼 RS 健康检查；conf 写法在 [20](../20-HAProxy与Keepalived/)。
- **VIP（Virtual IP）** = 对外虚拟 IP，客户端永远连它；**VS（Virtual Server）** = 一条 `VIP:port + 算法 + 一堆 RS` 的虚拟服务；**RS（Real Server）** = 真正干活的后端。

> 🔍 **现场**：玩家「一会儿能登、一会儿进错房」，第一刀在两台 LVS 同时敲：

```bash
ip addr show | grep 203.0.113.1
#    inet 203.0.113.1/32 scope global lo    ← 这台持有 VIP
ip neigh show | grep 203.0.113.1
#    203.0.113.1 dev eth0 lladdr aa:bb:cc:01:02:03 REACHABLE
#    ↑ ARP 里 VIP 出现两个 MAC = 会话分裂的铁证
```

**判读**：两台 LVS 都有 VIP / VIP 两个 MAC = **脑裂**——流量一半走一台、一半走另一台，会话全乱；VIP 不在任何一台 = keepalived/心跳问题；只有一台有 VIP、一个 MAC = 正常，继续往下查分房。

### 双 VIP 脑裂 vs RS 抢 ARP 🔥

「会话乱」有两个长得很像的病因，第一刀分清：

| 对比 | 双 VIP（脑裂） | RS 抢 ARP（DR 未抑制） |
|------|----------------|------------------------|
| 发生在哪 | 两台 **LVS** 都持 VIP | **RS** 的物理口在答 VIP 的 ARP |
| `ip addr` | 两台 LVS 都有 VIP | LVS 一台有；RS lo 也有 VIP（DR 正常现象） |
| `ip neigh` | VIP → **两个 LVS MAC** | VIP → 飘到某台 **RS** 的 MAC |
| 第一刀 | **立刻下一台 LVS** | 修 RS `arp_ignore`/`arp_announce`（四节） |
| 别做 | 先改算法、让玩家重连「试」 | 先加机器 |

脑裂机理：keepalived 两台**不算 quorum**，只是优先级 + 心跳；心跳一断，备机升级成主，两台都持 VIP。**VRRP 是 IP 协议 112，不是 UDP 端口 112**——防火墙/安全组要按**协议号**放行，这是心跳被吞的最常见原因。处理顺序六步：两台 `ip addr` 看是否双持 → 任意可达机 `ip neigh` 看 MAC 数 → 双主**立刻下一台**（选流量更乱的那台）→ 查安全组/防火墙是否丢了 IP 协议 112 → 修心跳链路、确认 `nopreempt` → 观察，**不要**先改算法、先让玩家重连试、先重启房间进程。防复发：心跳走独立链路或单播、`nopreempt`（主恢复不立刻抢回，避免第二次闪断）、监控「同时存在两个 VIP」。

### VIP 漂移会断存量 🔥

> ⚠️ **别混**：VIP 漂移**不是**完全无感——四层不会在 TCP 中途把连接搬到另一台（那是七层终结或应用自己的迁移）。漂移瞬间打到旧 MAC 的帧会丢；**NAT 模式下更狠**：conntrack 表在旧机上，回包对不上，断得更「齐」。旧主 `ipvsadm` 的 ActiveConn 可能仍 >0 但 `ip addr` 已无 VIP；新主有 VIP、新 SYN 开始涨。

> 📝 **面试**：「长连接建立后 LB 不会 mid-flight 换 RS；VIP 漂移会断存量，NAT 下 conntrack 在旧机断得更齐。Keepalived 两台不算 quorum，心跳断会双主；出现双主立刻下一台，VRRP 是 IP 协议 112 不是 UDP。」

## 三、分房：调度算法只管第一次 ⭐

> 🎯 **一句话**：算法只管第一次把连接分到哪台 RS；建立后不切后端，改算法不搬存量。

> 💡 **打个比方**：ipvs 像餐厅**排位员**——只在你进门那一刻发一次号，把你领到某桌；落座之后哪怕邻桌全空了，也不会有人中途把你连人带菜搬到另一桌。

| 算法 | 行为 | 何时用 | 坑 |
|------|------|--------|-----|
| **rr**（round robin） | 严格轮询 | 短连接、规格相同 | **刚加回的机器瞬间被灌满** |
| **wrr**（weighted rr） | 加权轮询 | 规格不同 | 同上，只是按比例 |
| **lc / wlc**（(weighted) least connection） | 最少连接 / 加权 | **长连接入口常用** | — |
| **sh**（source hashing） | 源 IP 哈希 | 想同 IP 粘同一 RS | **NAT 大出口后成千上万用户同 IP → 打到同一 RS 扎堆** |
| **dh**（destination hashing） | **目的** IP 哈希 | 按目的地址粘 RS（如缓存层） | 目的侧打偏时同样扎堆 |
| **-p persistent** | 持久化模板 | 短连接会话保持 | NAT 出口后同源 IP 同样扎堆 |

长连接默认选 **lc/wlc**：按当前连接数分，新机器权重正常时自然多接；`rr` 在「维护窗口摘机再加回」时会瞬间灌满刚回来的机器。`sh` 想做「同一玩家粘同一台」时注意：玩家 NAT 出口后共享一个公网 IP，哈希键全一样——**大出口后面不要用 sh / -p**。

### 现场：一台满两台闲 🔧

> 🔍 **现场**：三台 RS 规格相同权重相同，一台 CPU 打满、两台很闲。有人要改算法重建 VS——先看数据再动手。

```bash
ipvsadm -L -n --rate
```

```text
Prot LocalAddress:Port   CPS   InPPS  OutPPS  InBPS    OutBPS
TCP  203.0.113.1:7777    120   8000   120     12M      18M
  -> 10.0.0.11:7777      95    7200   90      10M      2M    ← CPS 95：新连接全灌这台
  -> 10.0.0.12:7777      12    400    15      800K     8M    ← 另两台 12~13
  -> 10.0.0.13:7777      13    400    15      800K     8M
```

**口算定责**：11 号 **CPS 95** vs 另两台 **12～13** → **新连接打偏**（rr/sh+NAT 这类）；若 CPS 已经均匀、**ActiveConn** 一台特别高 → 是**存量**，改算法帮不了——存量 TCP 不会搬家。

```bash
ipvsadm -E -t 203.0.113.1:7777 -s wlc    # -E 改调度器，不用重建 VS
```

改完等 **2～3 分钟**再看 `--rate`：新 CPS 应均匀；**11 号上的存量 ActiveConn 不会搬家**——要它消，只能等客户端重连、业务主动断、或进程重启。

> ⚠️ **别混**：改算法 ≠ 踢存量；权重 `-w` 只影响**新分配**比例，权 0 = 停止新分配（存量仍在，见六节）。

> 📝 **面试**：「长连接入口用 wlc；算法只管第一次分配，改 `-s` 不搬已有 TCP。一台满两台闲先看 `--rate`：CPS 一台特别高是新连接打偏，CPS 平而 ActiveConn 一台高是存量。」

## 四、通路：NAT、DR、TUN 三种模式 ⭐🔥

> 🎯 **一句话**：三模式差在 LVS↔RS 这一段怎么改包、回程过不过 LVS——回程决定瓶颈。

> 💡 **打个比方**：NAT 是**中转仓改地址**——去程改收件人、回程还得回仓改寄件人，进出都挤仓库；DR 是**换门牌直达**——只把包裹上的楼层门牌换成 RS 的，回件 RS 直接寄给客户，不回仓库；TUN 是**套一层信封**——把原始信件整个装进新信封寄到 RS，RS 拆封后回信也直接寄客户。

### 三模式对比表 ⭐

| 对比 | NAT（`-m`，Masq） | DR（`-g`，Route） | TUN（`-i`，Tunnel） |
|------|-------------------|-------------------|---------------------|
| LVS 改什么 | **改目的 IP**（DNAT），回包再 SNAT | **只改目的 MAC**，IP 仍是 VIP | **IPIP 封装**（外层 RS 真实 IP，内层仍是 VIP） |
| 回程 | **必过 LVS**（RS 网关常指 LVS） | **RS 直出客户端** | **RS 直出客户端** |
| 入口瓶颈 | **双向**（InBytes/OutBytes 都涨） | 仅入站（LVS OutBytes ≈ 0） | 仅入站 |
| RS 要求 | 网关指 LVS；可跨网段 | **同二层**；lo 配 VIP + 抑制 ARP | tunl0 解包；注意 MTU/rp_filter |
| 性能 | 中 | 高 | 高 |
| 场景 | 简单、端口映射 | **同二层最常用** | 跨网段又想直回 |

### 一条 SYN 在 DR 下的完整走读 🔥

**场景**：玩家 `198.51.100.8` 连战斗 VIP `203.0.113.1:7777`，DR 模式，三台 RS `10.0.0.11~13`，VIP 配在各 RS 的 `lo` 上。

```text
① 客户端 SYN → 目的 IP=VIP:7777
② 交换机按 VIP 的 MAC 送到「当前持有 VIP 的 LVS」
        （若两台都答 ARP → 脑裂，二节；若 ARP 飘到某 RS → RS 抢 ARP，下文）
③ LVS ipvs：按算法（wlc）选 RS，比如 10.0.0.11
        DR：只改 目的 MAC → RS11；IP 目的仍是 VIP
④ 同二层帧到达 RS11 物理网卡；RS 看目的 IP=VIP，本机 lo 上有 VIP → 收下
⑤ RS11 房间进程 accept / read（后续 ESTAB 的窗口/心跳 → 13）
⑥ 回包：源 IP=VIP、目的=玩家，从 RS11 直出
        不经过 LVS → 所以 LVS --stats 的 OutBytes ≈ 0
⑦ 客户端以为整条会话都在跟 VIP 说话
```

**读图**：DR 的七步里，**只有 ③⑥ 两步随模式变**——认准这两步，三模式就分清了。

**NAT 走读（③⑥ 两步都变）**：

```text
③ LVS ipvs：按算法选 RS 后改的是 目的 IP（DNAT）
        内核 conntrack 记一张「VIP:7777 ↔ 10.0.0.12:7777」的账（→ 17）
        RS 收到的包：目的=自己、源=玩家 —— IP 头被改过
⑥ 回包：RS 把包发给自己的默认网关 = LVS
        LVS 查 conntrack 逆写，把源 IP 改回 VIP，再发给玩家
        → NAT 下 LVS 的 InBytes 与 OutBytes 都在涨
```

**读图**：NAT 的「改回去」完全靠 conntrack 那行账——**NAT 模式下 conntrack 表就长在 LVS 上**，长连接多了会表满（[17](../17-iptables与conntrack/) 的「新挂旧不挂」在 LVS 上重演）；RS 网关必须指 LVS，指错就是回包黑洞。代价全在 **⑥**：回包挤回同一台机器。

**TUN 走读（只有 ③ 变）**：

```text
③ LVS ipvs：把原包（目的仍是 VIP）整个塞进一层外层 IP 包
        外层目的 = RS 真实 IP（10.0.0.13），外层源 = LVS 自己
        包可跨三层路由（跨网段/跨机房都行），RS 的 tunl0 解封装
        内层目的仍是 VIP → 本机 lo 的 VIP 认领
⑥ 回包：和 DR 一样用 VIP 直出，不经 LVS
```

**读图**：TUN 和 DR 一样**不吃回程**，差别只在入站多了一层「信封」——所以它的坑也全在信封上：MTU 少了 ~20 字节、rp_filter 严格模式会把解出来的包当伪造、防火墙要放行 **IPIP（IP 协议 4）** 而不只是 TCP 口。

### stats 怎么认模式 🔧

> 🔍 **现场**：入口网卡双向打满，或怀疑「DR 其实配成了 NAT」，两条命令定模式：

```bash
ipvsadm -L -n; ipvsadm -L -n --stats
```

```text
# NAT 味道
  -> 10.0.0.12:7777             Masq    5     1200        80
Prot LocalAddress:Port          Conns   InPkts  OutPkts  InBytes  OutBytes
TCP  203.0.113.1:7777           50000   2.1M    2.0M     180G     420G
#                                              ↑ 进出都涨：回包过 LVS，双向挤入口

# DR 味道
  -> 10.0.0.11:7777             Route   5     1200        80
TCP  203.0.113.1:7777           50000   2.1M    12K      180G     2G
#                                              ↑ OutBytes ≈ 0：回包直出
```

**判读**：`Masq` + OutBytes≈InBytes = NAT；`Route` + OutBytes≈0 = DR；`Tunnel` = TUN（接着查 tunl0、MTU、rp_filter）。**OutBytes 是 InBytes 的 2～3 倍** = 游戏回包大于请求（客户端小包上行、房间大包下行）——NAT 下**入口网卡先满，加 RS 治不了根**，因为瓶颈在 LVS 这台机器的回程，不在后端。

### DR 后端必须做的两件事 🔧

```bash
# 1) VIP 配在 lo（/32，不要配在对外物理网卡上抢 ARP）
ip addr add 203.0.113.1/32 dev lo

# 2) 抑制 ARP：all 和 lo 都设（落盘 → 24）
net.ipv4.conf.all.arp_ignore = 1
net.ipv4.conf.all.arp_announce = 2
net.ipv4.conf.lo.arp_ignore = 1
net.ipv4.conf.lo.arp_announce = 2
```

`arp_ignore=1`：只在目标 IP 配在**入接口**上才答 ARP——VIP 在 lo、问包从物理口进，物理口就不答，RS 闭嘴。`arp_announce=2`：宣告时用更合适的源地址，避免拿 VIP 当源去喊。**不抑制 → RS 对外宣布「VIP 在我这」→ 和 LVS 抢地址 → 会话全乱**（症状像脑裂，但 `ip neigh` 里 MAC 飘到的是 RS——二节的对照表）。

### 三个易错钉死 🔥

> ⚠️ **别混**：**DR 抓包源 IP 是 VIP 是设计**，不是「NAT 没改干净」——RS 用 VIP 作源，客户端才认「还是同一条会话」；排障看帧的**源 MAC 是 RS 不是 LVS**，别去加 SNAT「修源 IP」，会把 DR 打成四不像。**跨网段不能硬 DR**——「改 MAC 送达」只在同二层成立，跨 VLAN/机房改 TUN 或 NAT。**TUN 三个额外坑**——外层封装多 ~20 字节，不分片就要调小 MTU/MSS（深排 → [16](../16-网络排障与抓包/)）；`rp_filter` 过严会把「源是 VIP、从物理口出」的回包当伪造丢掉；安全组要放行 **IPIP（IP 协议 4）**，不只是业务 TCP 口。

### NAT 入口打满现场与 NAT→DR 切换 🔧

NAT 入口打满四步：① `ipvsadm -L -n` 看 `Masq` 确认模式；② `--stats` 看 OutBytes≈InBytes 或更大，证明回程也过 LVS；③ 确认瓶颈是 LVS 网卡/机器而不是 RS（RS CPU 闲就是铁证）；④ 评估改 DR。

低峰 NAT→DR 最小五步：

```text
1. 所有 RS 先配好 lo VIP + arp_ignore/arp_announce
2. 验证：二层上只有 LVS 答 VIP 的 ARP（ip neigh / 交换机 MAC 表）
3. ipvsadm 把 RS 从 -m 改成 -g（或重建 VS）
4. --stats 看 LVS OutBytes 应掉下去；业务抽样连通
5. 活动中不做 NAT↔DR 切换——只低峰、走变更窗口
```

### 收束：三模式一张可背清单 🎯⭐

面试问「NAT/DR/TUN 怎么选」，答这张清单——**先回程、再拓扑、后配置**：

```mermaid
flowchart TB
    A["LVS 选模式"] --> B{"回包远大于请求？<br/>（游戏下行大）"}
    B -->|是| C["避开 NAT：回程别过 LVS"]
    B -->|否| D["NAT 也能用：最简单、可跨网段"]
    C --> E{"LVS 和 RS 同二层？"}
    E -->|是| F["DR：只改 MAC<br/>RS lo VIP + 抑制 ARP"]
    E -->|否| G["TUN：IPIP 封装<br/>tunl0 · MTU · rp_filter · 放行协议4"]
    F --> H["验证：LVS OutBytes ≈ 0"]
    G --> H
```

**读图**：第一问回程（决定瓶颈在哪），第二问拓扑（决定 DR 还是 TUN），最后的验证动作统一是 `--stats` 看出站——入站涨、出站几乎没有，DR 才算真配对了。NAT 不是错，是**回包大 + 双向挤入口**的场景错。

> ⚠️ **别混**：这套选型**不保证**「配对模式就万事大吉」——DR 忘了 ARP 抑制照样会话乱（二节）、TUN 忘了放行协议 4 直接不通、NAT 下 conntrack 表满新连接挂（[17](../17-iptables与conntrack/)）。模式只定通路，通路上还有别的坑。

> 📝 **面试**：「三模式差在回程过不过 LVS。同二层战斗入口我选 DR：LVS 只改 MAC，回包 RS 用 VIP 直出，入口只扛入站；NAT 双向过 LVS，状态同步回包大先把入口网卡打满，加 RS 治不了根；跨网段要直回就 TUN，IPIP 封装、注意 MTU 和 rp_filter。」

## 五、干活：连接表与存量 ⭐

> 🎯 **一句话**：连接建立后绑死在 RS 上——存量不搬家，改算法、改权重、摘机都只动新连接。

### ipvsadm -L -n 怎么读 🔧

```bash
ipvsadm -L -n
```

```text
TCP  203.0.113.1:7777 wlc
  -> 10.0.0.11:7777             Route   5     1200        80
  -> 10.0.0.12:7777             Route   5     1180        75
  -> 10.0.0.13:7777             Route   0        0         0
```

**读输出**：第一行是 VS（VIP:port + 算法 `wlc`）；每行一个 RS——`Route/Masq/Tunnel` 是模式、权重列 `5`/`0` 是新分配比例（**权 0 = 不再分新连接，但行还在、存量还在**）、`ActiveConn` 是当前活跃连接（**存量**，改算法不搬家）、`InActConn` 是非活跃（辅助，别当唯一依据）。

### 权重 0、-d 和存量 🔥

| 状态 | ipvsadm 里 | 存量 TCP | 新连接 |
|------|-----------|----------|--------|
| 权重 0（`-w 0`） | 行还在，权重列 0 | **仍在 RS 上** | 不再分配 |
| 从表删除（`-d`） | 无此行 | **仍在 RS 上** | 不再分配 |

四层**不会**把一条 TCP mid-flight 搬到另一台——存量要消，只有三条路：自己断、超时、进程没了。验证存量在不在，**到 RS 上看**：

```bash
ss -ant | grep ':7777' | wc -l     # RS 上仍有几百条 = 存量还挂着
```

### 四层 vs 七层（值班怎么选）⭐

| 对比 | 四层（本章，LVS/云 NLB） | 七层（[19](../19-Nginx/)） |
|------|--------------------------|------------------------------|
| 看什么 | IP + 端口、五元组 | URL / Header / Host / Cookie |
| 适合 | 战斗长连接、高并发直通 | 登录、支付、按路径灰度 |
| 容量感 | 内核转发，量级高 | 解析+缓冲，差一个数量级常见 |
| 用户态挂了 | ipvsadm 挂，转发常仍在（规则在内核） | 进程挂，连接常断 |

🔥 长连接塞七层：超时、缓冲、连接重建会变成事故源——**不是**「Nginx 也能 stream 所以就统一入口」。灰度做在登录的七层，不要牺牲战斗口；七层的证书/Host 在 [14](../14-HTTP与TLS/)、[19](../19-Nginx/)。

> ⚠️ **别混**：`ipvsadm` 挂了 ≠ 玩家立刻掉——规则在内核里转；大面积掉线先查 VIP（没了/双了）再查进程。**VRRP 通也不等于后面房间进程活着**——VIP 漂得动只说明二节那层健康，还要探活和 `ss`。

> 📝 **面试**：「战斗长连接走 LVS 四层直通，登录 HTTP 可以四层后再进 Nginx；ipvsadm 挂不会立刻踢玩家，双 VIP 才要立刻下一台。」

## 六、生病：探活摘除与误摘 🔥

> 🎯 **一句话**：探活摘的是新分配；存量 TCP 和 DNS TTL 内的流量不归探活管。

> 💡 **打个比方**：健康检查像餐厅**关掉取号机**——新客不再发号到那桌，但已经坐着的客人不会被赶走，得等他们自己吃完走人。想立刻清场，只能服务员（进程）下班。

### 探活失败之后发生什么

```mermaid
flowchart LR
    A["探活失败<br/>连续 3~5 次 · 间隔 1~5s"] --> B["权重变 0 或从 ipvs 删除"]
    B --> C["新连接不再分过来"]
    B --> D["存量 TCP 还在旧 RS 上<br/>直到自己断 / 超时 / 进程没了"]
```

**读图**：摘除动作只有一个效果——**停新分配**。若探活已摘、玩家仍报「卡在 11」，两件事要同时查：RS 上 `ss -ant | grep ':7777' | wc -l`（存量还在），和 DNS `dig +short fight.example.com`（解析还指旧 VIP、TTL 没过期）。

**摘流量公式**（一例钉死：探活已摘仍有人打到死机器——权重 0 + `dig` 仍旧 VIP + TTL 3600，三样都对上才是完整证据链）：

```text
摘流量 = ipvs 摘后端（权 0 / -d）
       + （如有）DNS / VIP 级摘
存量 TCP 还在旧后端，直到自己断、超时或进程没了
```

只改 DNS 不摘 ipvs：新解析的用户仍打同一 VIP，LVS 还可能分到坏后端；只摘 ipvs 不动 DNS：TTL 内解析仍指旧入口。**两边都要摘**（TTL 纪律 → [15](../15-DNS与CDN/)）。

### 探针层级与误摘 🔥

| 层 | 例子 | 假活 / 误摘 |
|----|------|-------------|
| 进程 | `killall -0` | 进程在但不 accept |
| TCP | `TCP_CHECK` 连业务端口 | 端口开着、逻辑已死 |
| HTTP | `HTTP_GET /health` → 200 | 静态 200、房间已挂 |
| 外部脚本 | `MISC_CHECK` | **探活打 8080、战斗口 7777 → 活房间被误摘光** |

生产纪律四条：探针打**业务端口**（或业务 `/health`）；连续失败 **3～5 次**再摘、间隔 **1～5s**——失败一次就切会在活动里抖动；摘机走**先权 0、观察、再 `-d`**；怀疑误摘时自检清单——conf 里探活端口是 7777 还是 8080、`/health` 是不是静态 200、连续失败次数是不是 1、`dig` 是否还指旧 IP、ipvs 表权重是否已 0。

### 云 NLB 侧 🔧

云上多数场景用 NLB 就够，但三件事仍是你的：健康检查端口/路径（目标组 healthy，别只看实例 running）；**空闲超时必须 ≥ 游戏心跳间隔**，否则连接被云侧无故断（心跳机制 → [13](../13-TCP与UDP/)）；后端安全组/ARP（云网络 → [06-01](../../06-云平台/01-云网络与安全/)）。kube-proxy 的 IPVS 模式同属这章的机制（→ [03-08](../../03-Kubernetes/08-Service与kube-proxy/)）。

> 📝 **面试**：「健康检查失败只停新分配；权重 0 后存量还在，要配合 DNS TTL 才算摘干净。探针必须打业务端口，连续失败 3～5 次再摘。云 NLB 的空闲超时要 ≥ 心跳，否则玩家被无故断。」

## 七、落地：加机、摘机与升级 🔧

> 🎯 **一句话**：加机先配 RS 侧再入表、摘机先权 0 再 -d，活动中不切模式。

### 建表与选型

```bash
ipvsadm -A -t 203.0.113.1:80 -s wlc                       # 建 VS，算法 wlc
ipvsadm -a -t 203.0.113.1:80 -r 10.0.0.1:80 -g -w 5      # -g = DR，权重 5
ipvsadm -a -t 203.0.113.1:80 -r 10.0.0.2:80 -g -w 3      # 规格低给 3
```

选型口径：长连接入口 = 云 NLB 或自建 LVS+**DR**（同二层）/**TUN**（跨网段）；算法 lc/wlc 不用默认 rr；HA = 两台 LVS + keepalived（心跳独立、nopreempt、监控双 VIP）；RS = lo VIP + 抑制 ARP + 探活打业务口。验收**不是**「进程在」：`--stats` 看入站在涨、权重符合预期、DR 下出站≈0、RS `ip addr` 能看到 lo 的 VIP、**二层上只有 LVS 答 VIP 的 ARP**。

### 加一台 RS（DR）五步

```bash
# 1) 新 RS 上：lo VIP + ARP 抑制
ip addr add 203.0.113.1/32 dev lo
sysctl -w net.ipv4.conf.all.arp_ignore=1
sysctl -w net.ipv4.conf.all.arp_announce=2
# 2) 确认业务口在听
ss -lnt | grep 7777
# 3) LVS 上：先低权重入表
ipvsadm -a -t 203.0.113.1:7777 -r 10.0.0.14:7777 -g -w 1
# 4) 看 stats/rate 确认有流量、观察正常
ipvsadm -L -n --rate | grep 10.0.0.14
# 5) 再提权重到与同伴一致；探活脚本覆盖新机器
```

### 摘一台（维护窗口）

```bash
ipvsadm -e -t 203.0.113.1:7777 -r 10.0.0.14:7777 -g -w 0   # 先权 0：停新分配
# 等 ActiveConn 自己消 / 业务侧优雅踢
ipvsadm -d -t 203.0.113.1:7777 -r 10.0.0.14:7777           # 再删行
```

直接 `-d` 只停新分配、存量仍在，且表项没了更难看清——**先权 0 再删**是纪律。高峰别用 rr 猛灌刚加回的机器：用 wlc 或先低权重观察。

### VIP 切换、升级、回滚、迁移

- **VIP 切换**：主挂 → VRRP 漂移。切完验证三样：只有一台 `ip addr` 有 VIP、ARP 只有一个 MAC、`ipvsadm` 规则在新主上。双主按二节六步处理。
- **升级滚动**：先把 VIP 赶到另一台或逐台权 0 → 升备验证 → 再切升原主；**不要两台同时换内核模块**；RS 逐台权 0 再升。
- **回滚**：`ipvsadm`/keepalived.conf 回上一份 reload，看 stats；VIP 已在备上且正常，**不要为「主必须是原机」再抢一次**（nopreempt 同理）；模式改错要**同时回滚 RS 侧**的网关/ARP 配置。
- **迁移**：换 LVS 先备后切；NAT→DR 低峰按四节五步；跨网段不硬 DR；上云 NLB 对齐健康检查与空闲超时；架构级迁移当项目做，**活动中不做**。

> ⚠️ **别混**：**不要只 `ping VIP` 当验收**——ICMP 通和「TCP 战斗口能建连」不是一条规则；探活、`curl` 业务口、`--stats` 计数才是证据。keepalived 的影响面（VRRP 持 VIP、双主、`virtual_server` 探活、`nopreempt`、notify 脚本）本章到行为为止，conf 写法在 [20](../20-HAProxy与Keepalived/)。

## 八、作战：定责

> 🎯 **一句话**：三问定责——VIP 在不在？新连接能不能分？长连接通不通？

```mermaid
flowchart TB
    A["报障：进错房 / 会话乱 / 入口满 / 掉线"] --> B{"哪类流量"}
    B -->|"战斗长连接"| C{"ip addr + ip neigh"}
    B -->|"登录 HTTP"| N["Nginx / 证书 / upstream → 19"]
    C -->|"两台 LVS 都有 VIP / ARP 两个 MAC"| D["脑裂：立刻下一台<br/>查 IP 协议 112 心跳"]
    C -->|"ARP 飘到某 RS 的 MAC"| I["RS 抢 ARP：修 arp_ignore/announce"]
    C -->|"VIP 正常、一个 MAC"| F{"ipvsadm --stats / --rate"}
    F -->|"一台 CPS 特别高"| G["算法打偏：rr / sh+NAT → 改 wlc"]
    F -->|"CPS 平、ActiveConn 一台高"| G2["存量不搬家：等重连 / 优雅踢"]
    F -->|"Masq + OutBytes≈InBytes<br/>入口双向满"| H["其实在走 NAT：评估 DR"]
    F -->|"权重 0 仍有人打到死机"| J["DNS TTL + 存量 TCP：两边都摘"]
    F -->|"活房间被摘光"| K["探活口 ≠ 业务口：修探针"]
```

**读图**：入口事故按「流量类型」分叉——战斗口往下走三问：VIP 层（脑裂/抢 ARP）、分配层（算法/存量）、通路层（NAT 回程/探活误摘）。**ipvsadm 用户态挂了 ≠ 立刻踢玩家**——先看 VIP 和规则还在不在，再决定动不动房间进程。

### 现象 · 先做 · 别做

| 现象 | 先做 | 别做 |
|------|------|------|
| 两台都有 VIP、ARP 两个 MAC | 立刻下一台，查 VRRP（IP 协议 112） | 让玩家重连试；先改算法 |
| DR 会话乱 | RS lo VIP 是否抑制 ARP（`ip neigh` 看 MAC 归属） | 先加机器 |
| 入口网卡双向满 | `--stats` 确认 Masq/OutBytes≈InBytes；评估 DR | 只加带宽 |
| 一台满两台闲 | `--rate` 看 CPS 打偏还是 ActiveConn 存量 | 改完算法指望旧连接搬家 |
| 探活已摘仍有人打到死机器 | DNS TTL + 存量 TCP；LB/DNS 两边都摘 | 只改 DNS 不摘 ipvs |
| 健康检查把活房间摘了 | 探活端口是否等于业务端口 | 关掉健康检查当修复 |
| DR 抓包源 IP 是 VIP | **这是设计**，看源 MAC 是 RS | 当 NAT 没改干净去加 SNAT |
| 云 NLB 空闲掉线 | 空闲超时 vs 游戏心跳 | 先重启房间进程 |
| ipvsadm 进程没了 | 看 VIP/规则是否还在（内核在转） | 立刻重启所有房间 |
| 活动高峰入口事故 | 确认 VIP 唯一 → 停发版 → stats 看模式和打偏 | 把战斗切到 Nginx 顶 |

### 60 秒剧本 🔧

> 🔍 **现场**：接到「进错房 / 掉线 / 入口满」报障，60 秒走完这条线再下结论。

```text
① 0–10s   两台 LVS：ip addr | grep VIP；任意机 ip neigh | grep VIP
          —— 双 VIP / 两个 MAC 当场现形（脑裂 → 立刻下一台）
② 10–30s  LVS：ipvsadm -L -n；ipvsadm -L -n --stats
          —— 模式（Masq/Route）· 回程方向（OutBytes）· 权重 0
③ 30–45s  ipvsadm -L -n --rate
          —— CPS 打偏 vs ActiveConn 存量，一台满两台闲在这分
④ 45–60s  RS：ip addr show lo；sysctl arp_ignore/arp_announce；ss -ant | grep :7777 | wc -l
          —— DR 后端两件事 + 存量验证；还不清 → 抓包看回程 → 16
```

## 九、收口

### 命令速查 🔧

```bash
ipvsadm -L -n                      # VS/RS/模式/权重/ActiveConn
ipvsadm -L -n --stats              # 累计流量：认 Masq/Route、回程方向
ipvsadm -L -n --rate               # 实时速率：CPS 打偏 vs 存量
ipvsadm -E -t VIP:port -s wlc     # 改调度器（只影响新连接）
ipvsadm -e -t VIP:port -r RS:port -g -w 0    # 摘机先权 0
ipvsadm -d -t VIP:port -r RS:port            # 再删行
ip addr show                        # VIP 在谁身上（两台都敲）
ip neigh show | grep <VIP>          # VIP 几个 MAC、飘到谁
# RS 上
ip addr show lo                     # DR 的 VIP 在不在
sysctl net.ipv4.conf.all.arp_ignore net.ipv4.conf.all.arp_announce
ss -ant | grep ':7777' | wc -l      # 存量连接在不在
lsmod | grep ip_vs                  # 内核模块
conntrack -C                        # NAT 旧机表 → 17
```

### 面试锚点

| 问 | 30 秒答 |
|----|---------|
| 战斗长连接走四层还是七层？ | 四层直通；登录可再进七层；长连接别塞 Nginx。 |
| NAT/DR/TUN 差在哪？ | 回程过不过 LVS；DR 只改 MAC 回包直出；NAT 双向；TUN IPIP 跨网段。 |
| 游戏默认哪个模式？ | 同二层 DR：回包直出、入口只扛入站；跨网段 TUN。 |
| 为什么 DR 要抑制 ARP？ | 否则 RS 抢 VIP 的 ARP，会话全乱；arp_ignore=1、arp_announce=2。 |
| DR 源 IP 是 VIP 坏了吗？ | 设计如此，看源 MAC；别加 SNAT。 |
| 跨网段能 DR 吗？ | 不能；改 TUN 或 NAT。 |
| 长连接用什么算法？ | lc/wlc；rr 会把刚加回的机器瞬间灌满。 |
| sh 在 NAT 后会怎样？ | 出口 IP 相同 → 全哈希到同一 RS，扎堆；-p 同理。 |
| 改算法搬存量吗？ | 不搬；只影响新 SYN；存量等重连或优雅踢。 |
| 健康检查会踢存量吗？ | 不会，只停新分配；配 DNS TTL 才摘干净。 |
| 权重 0 和 -d 差在哪？ | 权 0 行还在；-d 表项没了；两者存量都还在。 |
| ipvsadm 挂了玩家立刻掉？ | 通常不会，规则在内核；VIP 没了/双了才大面积乱。 |
| VIP 漂移无感吗？ | 否，断存量；NAT 下 conntrack 在旧机断得更齐。 |
| VRRP 是 UDP 112 吗？ | 否，IP 协议 112；安全组按协议号放行。 |
| 双 VIP 和 RS 抢 ARP 怎么分？ | `ip addr` 两台 LVS 都有 = 脑裂下一台；`ip neigh` MAC 飘到 RS = 修 ARP 抑制。 |
| 云 NLB 还要懂这些吗？ | 要：健康检查端口、空闲超时≥心跳、后端 ARP 仍是你的。 |

### 易错一句话对照

- 战斗挂 Nginx 统一入口 → 四层直通，灰度别牺牲长连接
- DR 最常用因为配置简单 → 因为回包直出；前提同二层 + 抑制 ARP
- NAT 适合游戏大回包 → 双向过 LVS，入口先满，加 RS 治不了根
- TUN 也要求同二层 → IPIP 可跨网段，坑是 MTU/rp_filter/协议 4
- DR 源 IP 是 VIP 要 SNAT 修 → 设计如此，加了会话更乱
- 健康检查失败会踢存量 → 只停新分配
- 改算法旧连接就均衡了 → 存量不搬家
- 只改 DNS 就摘干净 → 还要 ipvs 摘，TTL 内仍有人打
- 摘机直接 -d 最干净 → 先权 0 观察，表项留着好排查
- 探针打管理口就行 → 探活口必须=业务口，否则误摘活房间
- ipvsadm 挂了玩家全掉 → 规则在内核，通常还在转
- VIP 漂移完全无感 → 断存量，NAT 更齐
- VRRP 是 UDP 112 → 是 IP 协议 112
- ping 通 VIP 就是验收 → ICMP 和业务 TCP 不是一个规则
- keepalived 在就能打 → VRRP 通 ≠ 房间进程活着
- 上云就不用懂 ARP → 健康检查、超时、后端仍是你的

### 数字墙

> VIP 示例 **203.0.113.1** · `-g` DR / `-m` NAT / `-i` TUN · DR 抑制 **arp_ignore=1、arp_announce=2**（all 和 lo 都设） · 探活连续失败 **3~5 次**、间隔 **1~5s** · VRRP 是 **IP 协议 112** · 权重示例 **5 和 3**、新 RS 先 **-w 1** 低权重 · 改算法后观察 **2~3 分钟** · TUN 封装开销 **~20 字节** · 云 NLB 空闲超时 **≥ 游戏心跳** · LVS 的 DR 验收 = OutBytes **≈ 0**

## 合上书

- [ ] **默画一节的图**：找门 → 分房 → 通路 → 干活/生病四段；战斗直通四层、登录可进七层、公告走 CDN。
- [ ] **口述找门**：ipvs/ipvsadm/keepalived 三个角色、双 VIP 和 RS 抢 ARP 怎么用 `ip addr` + `ip neigh` 分、脑裂六步、VRRP 是 IP 协议 112、漂移断存量。
- [ ] **口述分房**：算法只管第一次分配、rr/wrr/lc/wlc/sh/dh/-p 各自的坑、一台满两台闲用 `--rate` 的 CPS 还是 ActiveConn 分、改 `-s` 不搬存量。
- [ ] **默画四节走读**：同一条 SYN 在 DR 下七步（改 MAC、lo 收、源 IP=VIP 直出、OutBytes≈0）；NAT 和 TUN 各差在哪两步。
- [ ] **口述通路**：三模式对比表、stats 怎么认 Masq/Route、DR 后端两件事、TUN 三个坑、NAT→DR 低峰五步。
- [ ] **口述干活**：`ipvsadm -L -n` 每列含义、权重 0 和 `-d` 的区别、四层 vs 七层怎么选、ipvsadm 挂了断不断。
- [ ] **一例钉死误摘**：探活摘了仍有人打到死机器的三件证据（权重 0 + dig 仍旧 VIP + TTL 3600）、摘流量公式、探针层级、云 NLB 空闲超时。
- [ ] **口述落地**：加机五步、摘机先权 0 再 `-d`、升级怎么滚、活动中不做 NAT↔DR、不要只 ping VIP。
- [ ] **定责**：三问决策树怎么走、60 秒剧本敲什么、每个现象的「先做/别做」。
- [ ] **边界**：心跳/窗口 → [13](../13-TCP与UDP/)；conntrack 表 → [17](../17-iptables与conntrack/)；DNS TTL → [15](../15-DNS与CDN/)；抓包/MTU → [16](../16-网络排障与抓包/)；Nginx → [19](../19-Nginx/)；Keepalived conf → [20](../20-HAProxy与Keepalived/)；脑裂总论 → [33](../33-高可用与容灾/)；kube-proxy IPVS → [03-08](../../03-Kubernetes/08-Service与kube-proxy/)。
