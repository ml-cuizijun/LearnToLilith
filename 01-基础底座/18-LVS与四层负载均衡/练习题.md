## Q1

**★★★★★｜NAT、DR、TUN 三种模式差在哪？游戏战斗入口怎么选？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [四、通路：NAT、DR、TUN 三种模式](知识点.md)

### 场景

面试必问。追问准备：「LVS 改的是什么字段」「为什么 NAT 双向挤入口」「跨机房怎么办」。

### 完整解答

> 🎯 **一句话**：三模式差在 LVS↔RS 这一段怎么改包、回程过不过 LVS——回程决定瓶颈。

- **NAT（`-m`，Masq）**：LVS 改**目的 IP**（DNAT），回包再改源（SNAT），**双向都过 LVS**，RS 网关常指 LVS；可跨网段、可做端口映射，但入口双向挤。
- **DR（`-g`，Route）**：LVS **只改目的 MAC**，IP 仍是 VIP；RS 的 lo 配 VIP + 抑制 ARP，回包**直出客户端**（源 IP=VIP）；要求**同二层**；LVS `--stats` 的 OutBytes ≈ 0。
- **TUN（`-i`，Tunnel）**：**IPIP 封装**——外层目的 = RS 真实 IP，内层仍是 VIP；RS `tunl0` 解包后直回；可跨网段；坑是 MTU、`rp_filter`、放行 **IP 协议 4**。

选型口径：先问回程（游戏下行大 → 回包别过 LVS → 避开 NAT），再问拓扑（同二层 → DR；跨网段 → TUN 或 NAT）。**同二层战斗入口默认 DR**。

> 📝 **面试**：「NAT 改目的 IP 双向过 LVS；DR 只改 MAC 回包直出、要求同二层；TUN IPIP 封装可跨网段。回包大的场景别用 NAT，入口网卡先满。」

### 再追问

- LVS 在 DR 下改哪个字段？——只改目的 MAC，IP 头目的仍是 VIP。
- 为什么 NAT 双向挤入口？——回包也要回 LVS 逆写，InBytes 和 OutBytes 都算它的。
- 怎么用命令确认当前模式？——`ipvsadm -L -n` 看 `Masq/Route/Tunnel`，`--stats` 看回程方向（Q6）。

## Q2

**★★★★★｜同一条 SYN 在 DR 下怎么走？为什么抓包源 IP 是 VIP？后端要配什么？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [四、通路：NAT、DR、TUN 三种模式](知识点.md)

### 场景

白板题：玩家 `198.51.100.8` 连 VIP `203.0.113.1:7777`，DR 模式。追问准备：「RS 不配 ARP 抑制会怎样」「能不能加 SNAT 修源 IP」。

### 完整解答

> 🎯 **一句话**：LVS 只改 MAC，RS 的 lo 收下 VIP，回包用 VIP 直出——源 IP=VIP 是设计。

```text
① 客户端 SYN → 目的 IP = VIP:7777
② 交换机按 VIP 的 MAC 送到当前持有 VIP 的 LVS
③ ipvs 按算法选 RS（如 10.0.0.11），只改目的 MAC → RS11
④ 帧到 RS11 物理口；目的 IP=VIP、本机 lo 有 VIP → 收下
⑤ 房间进程 accept（后续窗口/心跳 → 13）
⑥ 回包：源 IP=VIP、目的=玩家，从 RS11 直出，不经 LVS
   → LVS --stats 的 OutBytes ≈ 0
⑦ 客户端以为整条会话都在跟 VIP 说话
```

**读图**：抓包看到「RS 回给玩家的包源 IP 是 VIP」**不是 NAT 没改干净**——排障时看帧的**源 MAC 是 RS 不是 LVS**；加 SNAT「修源 IP」会把 DR 打坏。后端两件事：`ip addr add 203.0.113.1/32 dev lo`（/32、配 lo 不配物理口）+ ARP 抑制（**arp_ignore=1、arp_announce=2，all 和 lo 都设**，落盘 → [24](../24-内核参数与sysctl/)）。不抑制 → RS 的物理口也答 VIP 的 ARP → 和 LVS 抢地址 → 会话全乱，`ip neigh` 里 VIP 的 MAC 飘到某台 RS（和脑裂的区分见 Q3）。

> ⚠️ **别混**：DR 的验收不是「能通」——是 `--stats` 里 LVS 的 **OutBytes ≈ 0** 加二层只有 LVS 答 VIP 的 ARP。

### 再追问

- arp_ignore=1 是什么意思？——只在目标 IP 配在入接口上才答 ARP；VIP 在 lo、问包从物理口进，物理口就不答。
- 跨网段能不能 DR？——不能，改 MAC 送达只在同二层成立；跨网段用 TUN 或 NAT（Q12）。
- TUN 回包源 IP 也是 VIP 吗？——是，直回客户端同样用 VIP；差在入站套了 IPIP 外层。

## Q3

**★★★★★｜VIP 脑裂是什么现象？和 RS 抢 ARP 怎么分？VRRP 是什么协议？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [二、找门：VIP 与 keepalived](知识点.md)

### 场景

群里半数玩家「进错房、会话乱」，有人喊被攻击，有人要重启房间进程。你只有跳板机。

### 完整解答

> 🎯 **一句话**：两台 LVS 都持 VIP 就是脑裂，立刻下一台；MAC 飘到 RS 是抢 ARP，修 sysctl。

```bash
# 两台 LVS 各敲
ip addr show | grep 203.0.113.1
# 任意可达机
ip neigh show | grep 203.0.113.1
```

| 对比 | 双 VIP（脑裂） | RS 抢 ARP（DR 未抑制） |
|------|----------------|------------------------|
| `ip addr` | 两台 LVS 都有 VIP | LVS 一台有；RS lo 也有（正常） |
| `ip neigh` | VIP → 两个 LVS MAC | VIP → 某台 RS 的 MAC |
| 第一刀 | **立刻下一台 LVS** | 修 RS `arp_ignore`/`arp_announce` |
| 别做 | 让玩家重连试、先改算法 | 先加机器 |

脑裂机理：keepalived 两台**不算 quorum**，只是优先级 + 心跳；心跳一断备机升主，双主。**VRRP 是 IP 协议 112，不是 UDP 端口**——安全组要按**协议号**放行，这是心跳被吞的最常见原因。处理六步：两台 `ip addr` → `ip neigh` 看 MAC 数 → 双主立刻下一台 → 查 IP 协议 112 放行 → 修心跳、确认 `nopreempt` → 观察。防复发：心跳独立链路或单播、`nopreempt`（主恢复不立刻抢回，避免二次闪断）、监控「双 VIP」。

**VIP 漂移断存量**：四层不会 mid-flight 搬连接；漂移瞬间打到旧 MAC 的帧丢；**NAT 模式下更狠**——conntrack 表在旧机上，回包对不上，断得更齐（conntrack 本身 → [17](../17-iptables与conntrack/)）。旧主 ActiveConn 可能仍 >0 但已无 VIP。

> 📝 **面试**：「Keepalived 两台不算 quorum，心跳断会双主；双 VIP 的处理是立刻下一台，不是改算法。VRRP 是 IP 协议 112，安全组按协议号放行。」

### 再追问

- 为什么 nopreempt？——主恢复立刻抢回 VIP 会造成第二次闪断；业务上「谁在跑谁继续」。
- 双 VIP 和 RS 抢 ARP 最像的地方？——都是「VIP 的 ARP 有问题」；判据是 MAC 归属：LVS×2 还是某台 RS。
- VRRP 通就万事大吉？——不：VRRP 通 ≠ 房间进程活着；VIP 漂得动只说明这层健康。

## Q4

**★★★★★｜调度算法怎么选？一台满两台闲怎么定责？dh 是什么？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [三、分房：调度算法只管第一次](知识点.md)

### 场景

三台 RS 规格权重相同，一台 CPU 打满、两台很闲。有人要改算法，有人要重启打满那台。追问准备：「sh 在 NAT 后会怎样」「-p persistent 是什么」。

### 完整解答

> 🎯 **一句话**：算法只管第一次分配；一台满两台闲用 `--rate` 分「CPS 打偏」还是「ActiveConn 存量」。

| 算法 | 行为 | 何时用 | 坑 |
|------|------|--------|-----|
| **rr** | 严格轮询 | 短连接、同规格 | 刚加回的机器瞬间被灌满 |
| **wrr** | 加权轮询 | 规格不同 | 同上，按比例 |
| **lc / wlc** | (加权)最少连接 | **长连接常用** | — |
| **sh** | 源 IP 哈希 | 想同 IP 粘同一 RS | **NAT 大出口同 IP → 扎堆一台** |
| **dh** | **目的** IP 哈希 | 按目的粘 RS（缓存层） | 目的侧打偏同样扎堆 |
| **-p persistent** | 持久化模板 | 短连接会话保持 | NAT 出口后同源 IP 扎堆 |

定责口算：`ipvsadm -L -n --rate` 看两列——**CPS** 一台 95、另两台 12~13 = **新连接打偏**（rr/sh+NAT 这类），改 `-s wlc`；CPS 已均匀、**ActiveConn** 一台特别高 = **存量**，改算法帮不了——存量 TCP 不搬家，等重连、优雅踢或进程重启。

```bash
ipvsadm -L -n --rate          # CPS 打偏 vs ActiveConn 存量，在这分
ipvsadm -E -t 203.0.113.1:7777 -s wlc    # 改调度器，不用重建 VS
```

> ⚠️ **别混**：改 `-s` / 改权重都只影响**新 SYN**；指望改算法把旧连接搬走是这一章最经典的错。sh 想做「同玩家粘同台」，但玩家 NAT 出口后共享公网 IP——**大出口后不要 sh / -p**。

### 再追问

- 为什么长连接不用默认 rr？——只看轮次不看存量，忙的照分；lc/wlc 按当前连接数分。
- dh 和 sh 差在哪？——哈希键一个目的、一个源；dh 常见于缓存层「同目标粘同缓存」。
- 改完算法多久见效？——新 CPS 立刻变，等 2~3 分钟看均匀度；旧 ActiveConn 不动。

## Q5

**★★★★★｜RS 健康检查失败后会发生什么？为什么摘了还有人打到死机器？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [六、生病：探活摘除与误摘](知识点.md)

### 场景

11 号机探活已摘，玩家仍报「卡在 11」。`ipvsadm` 里 11 的权重已是 0。追问准备：「探针打哪个口」「云 NLB 空闲超时」。

### 完整解答

> 🎯 **一句话**：摘除只停新分配；存量 TCP 和 DNS TTL 内的流量不归探活管。

**摘流量公式**（先背这句）：

```text
摘流量 = ipvs 摘后端（权重 0 / -d）
       + （如有）DNS / VIP 级摘
存量 TCP 还在旧后端，直到自己断、超时或进程没了
```

「探活已摘仍有人打到死机器」一例钉死：`ipvsadm` 里 11 权重 0（LB 已摘）+ `dig` 仍返回旧 VIP/旧入口（DNS 未切、TTL 3600）+ RS 上 `ss -ant | grep ':7777' | wc -l` 仍有几百条（存量）——三样都对上才是完整证据链，只改 DNS 或只摘 ipvs 都不干净。探针层级：进程（`killall -0`）→ TCP（`TCP_CHECK`）→ HTTP（`HTTP_GET` 要动态 `/health`，静态 200 是假活）→ 外部脚本（`MISC_CHECK`）；**探活口必须 = 业务口**——探活打 8080、战斗 7777，活房间会被误摘光。纪律：连续失败 **3~5 次**、间隔 **1~5s** 再摘；失败一次就切会在活动里抖动。

> ⚠️ **别混**：权重 0 ≠ `-d`——权 0 行还在表里、好排查；直接 `-d` 只停新分配、存量照样在，而且表项没了更难看清。**两者存量都不会被踢**，这是四层的设计不是 bug。

### 再追问

- 想立刻清存量怎么办？——四层做不到 mid-flight 踢；只能业务侧优雅踢（发重连指令）、等超时、或重启进程。
- 云 NLB 的坑？——健康检查看目标组 healthy（别只看实例 running）；**空闲超时必须 ≥ 游戏心跳**，否则被云侧无故断（心跳 → [13](../13-TCP与UDP/)）。
- 健康检查失败一次就摘会怎样？——抖动抖成雪崩：RS 短暂卡顿 → 被摘 → 恢复 → 再被摘。

## Q6

**★★★★☆｜值班三件套输出怎么读？怎么用 stats 认模式和回程？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [五、干活：连接表与存量](知识点.md)

### 场景

接手一台陌生 LVS，10 分钟内要能说出：什么模式、流量往哪、谁在被打偏。

### 完整解答

> 🎯 **一句话**：`-L -n` 看分到谁、`--stats` 看回程方向、`--rate` 看打偏，`ip addr`/`ip neigh` 看 VIP。

```bash
ipvsadm -L -n
```

```text
TCP  203.0.113.1:7777 wlc
  -> 10.0.0.11:7777             Route   5     1200        80
  -> 10.0.0.13:7777             Route   0        0         0
```

**读输出**：第一行 VS = VIP:port + 算法；每行 RS——`Route/Masq/Tunnel` 是模式、权重列 `5`/`0`（**权 0 = 停新分配，行还在**）、`ActiveConn` 是存量活跃连接（改算法不搬家）、`InActConn` 是非活跃（辅助，别当唯一依据）。

```text
# --stats 认模式：
#   Masq  + OutBytes ≈ InBytes   → NAT：回包过 LVS，双向挤入口
#   Route + OutBytes ≈ 0         → DR：回包直出（验收标准）
#   OutBytes 是 InBytes 的 2~3 倍 → 回包大于请求（游戏典型）：
#                                  NAT 入口网卡先满，加 RS 治不了根
# --rate 认打偏：
#   CPS 一台 95、另两台 12~13    → 新连接打偏（Q4）
#   CPS 平、ActiveConn 一台高    → 存量，改算法帮不了
```

> 📝 **面试**：「`ipvsadm -L -n` 四列：模式、权重、ActiveConn、InActConn；`--stats` 看回程方向认模式；`--rate` 的 CPS 和 ActiveConn 分打偏还是存量。」

### 再追问

- ipvsadm 进程挂了玩家掉吗？——通常不掉，规则在内核（ipvs 模块）里转；大面积掉先查 VIP 没了/双了。
- ActiveConn 怎么验证到 RS？——RS 上 `ss -ant | grep ':7777' | wc -l`，两边数量对得上。
- `-g -m -i` 是什么？——DR / NAT / TUN，和回包路径绑定，配错回包路径就错。

## Q7

**★★★★☆｜加一台 RS、摘一台 RS、滚动升级各怎么走？**

**覆盖**：必会 · 常用

**对应**：知识点 [七、落地：加机、摘机与升级](知识点.md)

### 场景

活动前扩一台、活动中摘一台坏机、季度升级两台 LVS。三件事各有纪律。

### 完整解答

> 🎯 **一句话**：加机先配 RS 侧再低权重入表；摘机先权 0 再 -d；升级滚动、活动中不切模式。

**加一台（DR）五步**：

```bash
# 1) 新 RS：lo VIP + ARP 抑制
ip addr add 203.0.113.1/32 dev lo
sysctl -w net.ipv4.conf.all.arp_ignore=1
sysctl -w net.ipv4.conf.all.arp_announce=2
# 2) 确认业务口在听
ss -lnt | grep 7777
# 3) LVS：低权重入表
ipvsadm -a -t 203.0.113.1:7777 -r 10.0.0.14:7777 -g -w 1
# 4) --rate 确认有流量、观察正常
# 5) 提权重到与同伴一致；探活脚本覆盖新机器
```

**摘一台**：先 `ipvsadm -e ... -w 0` 停新分配 → 等 ActiveConn 自己消 / 业务优雅踢 → 再 `ipvsadm -d ...`；直接 `-d` 丢掉表项、存量照样在、更难排查。**升级滚动**：先把 VIP 赶到另一台（或逐台权 0）→ 升备验证 → 再切升原主；不要两台同时换内核模块；RS 逐台权 0 再升。**回滚**：conf/规则回上一份 reload 看 stats；VIP 在备上正常就**不要为「主必须是原机」再抢回**；模式改错要**同时回滚 RS 侧**网关/ARP。**迁移**：NAT→DR 只低峰按五步（含验证二层只有 LVS 答 VIP ARP，Q11）；跨网段不硬 DR 走 TUN（Q12）；上云 NLB 对齐健康检查与空闲超时、当项目做。

> ⚠️ **别混**：**不要只 `ping VIP` 当验收**——ICMP 通和「TCP 战斗口能建连」不是一条规则；探活、`curl` 业务口、`--stats` 计数才是证据。

### 再追问

- 加机用 rr 会怎样？——新机器瞬间被灌满；用 wlc 或先低权重。
- 升级 LVS 会断玩家吗？——VIP 不动、只升备就不断；动 VIP 就断存量（Q3），所以先备后切。
- keepalived conf 写错了影响面？——VRRP 持 VIP、双主、探活误摘都可能是它；写法在 [20](../20-HAProxy与Keepalived/)，影响面在本章。

## Q8

**★★★★☆｜接到「进错房/掉线/入口满」报障，60 秒怎么走？**

**覆盖**：核心 · 必会

**对应**：知识点 [八、作战：定责](知识点.md)

### 场景

值班群三单：A「半数玩家进错房」、B「入口网卡打满」、C「新连接全超时、老玩家还在打」。你只有跳板机。

### 完整解答

> 🎯 **一句话**：三问定责——VIP 在不在？新连接能不能分？长连接通不通；顺序 ip addr → ipvsadm stats → RS 侧。

```text
① 0–10s   两台 LVS：ip addr | grep VIP；任意机 ip neigh | grep VIP
          —— 双 VIP / 两个 MAC 当场现形（答 A 的脑裂分支）
② 10–30s  LVS：ipvsadm -L -n；--stats
          —— 模式（Masq/Route）· 回程方向（OutBytes）· 权重 0（答 B：NAT 双向满）
③ 30–45s  ipvsadm -L -n --rate
          —— CPS 打偏 vs ActiveConn 存量（答 B 的算法分支）
④ 45–60s  RS：ip addr show lo；sysctl arp_ignore/announce；ss -ant | grep :7777 | wc -l
          —— DR 后端两件事 + 存量验证；还不清 → 抓包看回程 → 16
```

**读剧本**：三问对应三层——VIP 层（脑裂/抢 ARP）、分配层（算法/存量）、通路层（NAT 回程/探活误摘）。C 单如果是 conntrack 表满（新挂旧不挂的签名），那是 [17](../17-iptables与conntrack/) 的地盘——LVS 走 NAT 时表就在 LVS 上。**ipvsadm 用户态挂了 ≠ 立刻踢玩家**——先看 VIP 和规则在不在，再决定动不动房间进程。

> ⚠️ **别混**：60 秒里没有「重启房间进程」——重启销毁存量这个唯一证据，还制造第二轮重连风暴。

### 再追问

- 三单哪单最急？——脑裂（A）：立刻下一台，每分钟都在错乱累积；B/C 可以按剧本走。
- 为什么先看 VIP 再看 ipvsadm？——VIP 错了后面全白查；且 `ip addr` 一秒出结果。
- 什么时候上升到抓包？——回程方向存疑（谁在回包）、或 DR 源 MAC 归属要钉死时（→ [16](../16-网络排障与抓包/)）。

## Q9

**★★★★☆｜keepalived 在这套架构里的影响面？上云 NLB 还要懂什么？活动高峰什么不能做？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [二、找门：VIP 与 keepalived](知识点.md)（云 NLB 另见「六、生病」）

### 场景

新人问：上了 keepalived 是不是就高可用了？上云用 NLB 是不是就不用懂 ARP 了？

### 完整解答

> 🎯 **一句话**：keepalived 管 VIP 漂移和探活，不管 quorum 不搬连接；云 NLB 换了实现不换物理。

**keepalived 影响面**（conf 写法 → [20](../20-HAProxy与Keepalived/)）：VRRP 持 VIP（主备、优先级、`nopreempt`）；两台**不算 quorum**，心跳断会双主（Q3）；心跳走独立链路或单播、放行 **IP 协议 112**；兼做 `virtual_server` 探活（探活口=业务口、3~5 次 1~5s）；notify 脚本挂了不等于转发停——**规则在内核**。防脑裂三件：独立心跳、`nopreempt`、监控双 VIP（总论 → [33](../33-高可用与容灾/)）。

**云 NLB 侧**：实现换成云的，但健康检查端口/路径、**空闲超时 ≥ 心跳间隔**、后端安全组/ARP 仍是你的（云网络 → [06-01](../../06-云平台/01-云网络与安全/)）；kube-proxy IPVS 模式是同一族机制（→ [03-08](../../03-Kubernetes/08-Service与kube-proxy/)）。**活动高峰纪律**：不切模式、不换算法指望救场、不动 VIP、先停发版再排障——高峰的一切变更都要「能在一分钟内回滚」。

> 📝 **面试**：「keepalived 给的是 VIP 漂移 + 探活，不是无状态切换——存量连接不搬、双主要人下。云 NLB 空闲超时要 ≥ 心跳，否则玩家被云侧断。」

### 再追问

- VRRP 通就健康吗？——不：VRRP 通 ≠ 房间进程活；探活和 `ss` 才证明业务。
- 为什么 nopreempt + 独立心跳？——防「主恢复抢回」二次闪断 + 防「心跳和生产口互相挤」造成假死。
- 监控双 VIP 怎么做？——两台各自上报「我持有 VIP」，同时为真就告警。

## Q10

**★★★★☆｜战斗连接走四层还是七层？为什么不要统一到 Nginx？**

**覆盖**：必会 · 常考

**对应**：知识点 [五、干活：连接表与存量](知识点.md)

### 场景

架构评审：有人提议「统一入口，战斗口也挂 Nginx stream，方便按 Header 灰度」。

### 完整解答

> 🎯 **一句话**：战斗长连接四层直通，登录/支付可再进七层——分层是性能和语义共同决定的。

| 对比 | 四层（LVS/云 NLB） | 七层（[19](../19-Nginx/)） |
|------|---------------------|------------------------------|
| 看什么 | IP + 端口、五元组 | URL / Header / Host / Cookie |
| 适合 | 战斗长连接、高并发直通 | 登录、支付、按路径灰度 |
| 容量感 | 内核转发，量级高 | 解析+缓冲，差一个数量级常见 |
| 用户态挂了 | ipvsadm 挂，转发常仍在 | 进程挂，连接常断 |

「统一入口」的代价：长连接塞七层会遇到超时、缓冲、连接重建（证书/Host 语义 → [14](../14-HTTP与TLS/)）；灰度做在登录七层，不牺牲战斗口。正确分层：战斗 → 四层直通；登录/支付 HTTP → 可四层后再进 Nginx；公告/包体 → CDN（[15](../15-DNS与CDN/)），不是 LVS。HAProxy 的四层/七层怎么配 → [20](../20-HAProxy与Keepalived/)。

> ⚠️ **别混**：「Nginx 也能 stream 所以等价」——能转发 ≠ 该承载；四层内核态直通和七层用户态代理的容量、故障面不是一个量级。

### 再追问

- 灰度怎么做？——在登录七层按 Cookie/uid 分流；战斗口保持四层不感知内容。
- 什么时候四层前面还要加东西？——入口防护（SYN flood → [17](../17-iptables与conntrack/)）、就近接入（智能 DNS → [15](../15-DNS与CDN/)）。

## Q11

**★★★★☆｜NAT 模式入口网卡双向打满，怎么定责？加 RS 为什么治不了根？**

**覆盖**：必会 · 常用 · 常考

**对应**：知识点 [四、通路：NAT、DR、TUN 三种模式](知识点.md)

### 场景

活动开闸，LVS 入口网卡**双向**打满、玩家进房超时；三台 RS CPU 都很闲。有人提单加 RS。

### 完整解答

> 🎯 **一句话**：NAT 回包也过 LVS——游戏回包 2~3 倍于请求，入口先满；瓶颈在 LVS 不在 RS。

四步定责：① `ipvsadm -L -n` 看 `Masq` 确认在走 NAT；② `--stats` 看 **OutBytes ≈ InBytes 甚至更大**，证明回程也过 LVS；③ RS CPU 闲 = 铁证：后端有余量、转发机先死；④ 得出结论——**加 RS 治不了根**，要改 DR（回包直出）。

低峰 NAT→DR 最小五步（**活动中不做**）：

```text
1. 所有 RS 配 lo VIP + arp_ignore/arp_announce
2. 验证：二层上只有 LVS 答 VIP 的 ARP（ip neigh / 交换机 MAC 表）
3. ipvsadm 把 RS 从 -m 改成 -g（或重建 VS）
4. --stats 看 LVS OutBytes 应掉下去；业务抽样连通
5. 低峰窗口执行，留回滚
```

> ⚠️ **别混**：入口满 ≠ 带宽不够——先看 `--stats` 的方向再提单；「加带宽」和「加 RS」都治不了「回程挤在一台机器上」这个结构问题。

### 再追问

- NAT 下还有什么隐性风险？——conntrack 表在 LVS 上，长连接多了会表满「新挂旧不挂」（→ [17](../17-iptables与conntrack/)）。
- 改 DR 后验收看什么？——LVS OutBytes ≈ 0 + RS `ip addr show lo` 有 VIP + 只有一个 MAC 答 ARP。

## Q12

**★★★☆☆｜LVS 和 RS 不同机房/网段，还能 DR 吗？TUN 的三个坑是什么？**

**覆盖**：必会 · 常用

**对应**：知识点 [四、通路：NAT、DR、TUN 三种模式](知识点.md)

### 场景

扩容到第二个网段，有人把 DR 的 RS 直接加了进去，发现时通时不通。

### 完整解答

> 🎯 **一句话**：跨网段不能 DR——改 MAC 送达只在同二层成立；跨网段选 TUN 或 NAT。

**TUN（IPIP 封装）**：LVS 把原始包（目的仍是 VIP）整个装进外层 IP 包（外层目的 = RS 真实 IP），跨三层路由到 RS；RS 的 `tunl0` 解封装后按内层 VIP 处理，回包**直出客户端**（和 DR 一样不吃回程）。三个坑：

1. **MTU**：外层封装多 ~20 字节，隧道内不分片就要调小 MTU/MSS，否则表现为「小包通、大包挂」（PMTUD 深排 → [16](../16-网络排障与抓包/)）。
2. **rp_filter**：反向路径校验过严会把「源是 VIP、从物理口出」的回包当伪造丢掉——`rp_filter` 调 0 或 2（落盘 → [24](../24-内核参数与sysctl/)）。
3. **放行 IP 协议 4**：IPIP 不是 TCP/UDP，安全组/防火墙要按**协议号**放行——和 VRRP 是 IP 协议 112 同一类坑。

> 📝 **面试**：「同二层 DR、跨网段 TUN；TUN 三件事——MTU 减头、rp_filter 放宽、放行 IP 协议 4。回包都直出，只有 NAT 吃回程。」

### 再追问

- 为什么 TUN 也要求后端 lo 配 VIP？——解出来的内层包目的仍是 VIP，得有人认领。
- 时通时不通像什么？——MTU 类故障的典型签名：握手小包通、战斗大包丢。

## Q13

**★★★★☆｜VIP 不通、部分 RS 不通、全不通——60 秒 LVS 定责？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [八、作战：定责](知识点.md)

### 场景

战斗端口部分玩家进不去。有人要重启所有 RS。

### 完整解答

> 🎯 **一句话**：**ip addr 看 VIP → ipvsadm -Ln 看 RS 权重 → ip neigh 看 ARP → stats 认模式**。

```bash
ip -br addr | grep VIP
ipvsadm -Ln --stats
ip neigh | grep VIP
```

| 签名 | 定责 |
|------|------|
| VIP 不在本机 | keepalived/脑裂 → 20 |
| RS Weight 0 | 健康检查摘流 |
| 双 MAC 答 VIP | ARP 冲突/脑裂 |
| OutBytes 极大 | NAT 回程瓶颈 → 改 DR |

### 再追问

- 新挂旧不挂？——conntrack on LVS（→ 17），不是 RS 重启。

## Q14

**★★★★★｜白板：战斗连接一生 + NAT/DR/TUN 选型 + stats 认模式？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图](知识点.md) · [九、收口](知识点.md)

### 场景

白板 90 秒：「画 LVS 主图，说 DR 为什么回包不经过 LVS。」

### 完整解答

> 🎯 **一句话**：**找门(VIP) → 分房(算法) → 通路(NAT/DR/TUN) → 干活(连接表) → 生病(探活/脑裂)**。

```text
DR：改 MAC 送达，RS lo 绑 VIP，回包直出客户端
NAT：改 IP，回程过 LVS，易成瓶颈
TUN：跨网段，MTU/rp_filter/协议4
stats：OutBytes≈InBytes→NAT  OutBytes≈0→DR/TUN
```

> 📝 **面试**：调度只管第一次；长连接粘在原 RS。

### 再追问

- 四层 vs 七层？——战斗 TCP 直通；登录 HTTP 可 Nginx（Q10）。
