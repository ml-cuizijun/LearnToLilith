## Q1

**★★★★★｜「为什么生产必须唯一入口？把一次登录的一生讲一遍。」**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [一、一张图：一次人工登录的一生](知识点.md)

### 场景

面试开场题。追问准备：「图上为什么没有办公网直连生产的箭头」。

### 完整解答

> 🎯 **一句话**：唯一入口下走六步——工单 → 认证 → 授权 → 通道 → 会话 → 退场，全程留痕。

主线：① 实名 + OTP 认证（是本人）→ ② 人 × 资产 × 动作授权（只能干这个）→ ③ ProxyJump/Web 终端通道 → ④ 会话里命令记录 + 录像 + 传输审计 + 高危拦截 → ⑤ 录像归档 180 天+ → ⑥ 离职/到期回收。两条支线：正门挂了走破窗（云串口/紧急账号，五字段补审计）；key 被盗走吊销 + 查录像。

图上没有「办公网 → 生产」的直连箭头——**有这条箭头，后面五步全是摆设**：命令不经过堡垒，审计、拦截、回收一个都不生效。

> 📝 **面试**：「唯一入口把『谁能上生产』变成一个可运营的问题：认证收敛一处、授权带时间盒、操作全留痕、离职一键收。」

### 再追问

- 值班排查「这操作谁干的」照图怎么走？——先堡垒会话列表，再本机 `last` 对照；**堡垒无、本机有 = 直连事故**。
- 破窗和被盗在图的哪一段？——破窗挂在通道旁（正门挂了）；被盗挂在退场旁（吊销轮换）。

## Q2

**★★★★★｜直连生产到底死在哪？「本机有、堡垒无」是什么？**

**覆盖**：核心 · 必会

**对应**：知识点 [二、失控：直连生产的三宗罪](知识点.md)

### 场景

支付库被 DROP，堡垒查无此会话；本机 `last` 里有一条来自 203.0.113.77 的登录。有人安慰「可能是监控脚本」。

### 完整解答

> 🎯 **一句话**：直连三宗罪——无审计、凭据散落、口子失控；本机有堡垒无 = 直连事故。

三宗罪：① 出了事对不上人（history 可清可改、共享账号、last 只有 IP）；② 密码/key 散落 200 台机器，离职收不回、被拷没人知；③ 「就改一行」的安全组口子越开越多——面失控是一百次「就改一行」的合计。

```bash
last -a | head -5
# deploy  pts/2  203.0.113.77  Mon Sep  1 03:12  still logged in
# 堡垒会话列表（同时段过滤该资产）：无记录
# → 两边一对照：有人绕过唯一入口，当事故处理，不是口头提醒
```

> ⚠️ **别混**：直连不是「认证弱」的问题——全 key only 也照样没有命令记录与录像；**治理问题的解法是收通道（安全组只放堡垒），不是换更强的锁**。

### 再追问

- 「反正有 key」为什么不算理由？——key 失窃没有任何失败日志，直连 + 失窃 key = 无声入侵；这题在 [27](../27-Linux安全加固/)。
- 监控脚本怎么算？——机器对机器的通道走 CI/自动化账号，与人工通道分开治理、分开审计。

## Q3

**★★★★★｜跳板机和堡垒机差在哪？JumpServer 有哪些核心模块？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [三、演进：从跳板机到堡垒机](知识点.md)

### 场景

面试官：「我们现在是台跳板机，据说再买套堡垒就合规了——你觉得差什么？」

### 完整解答

> 🎯 **一句话**：跳板解决路径（只能从这走），堡垒解决可控可追责（知道你干了什么）。

| 对比 | 跳板机 | 堡垒机 |
|------|--------|--------|
| 解决什么 | 路径收敛 | 认证/授权/审计/回收体系 |
| 账号 | 机器上分散 | LDAP/SSO 实名 |
| 授权 | 登上基本都能去 | 人 × 资产 × 动作 × 时间盒 |
| 审计 | history（可清可改） | 命令 + 录像 + 传输审计 |
| 事后 | 对不上人 | 会话回放可当证据 |

JumpServer 类开源堡垒四个核心模块：**资产管理**（分组打标签，支付单独成组）、**用户与授权**（对接 LDAP，四维授权带有效期）、**会话与审计**（会话列表/命令记录/录像回放/传输日志——定责证据链）、**批量操作**（带审计的命令下发）。商业同类 CyberArk、BeyondTrust，云厂商有托管版。

> 📝 **面试**：「跳板让你只能从这走，堡垒还知道你干了什么——一句话分家；四个模块按『清单/钥匙/证据/批量』记。」

### 再追问

- 只买产品不改网络行吗？——不行；没把直连收干净，审计只覆盖守规矩的人（Q8）。
- 批量操作模块和 Ansible 什么关系？——定位是「带审计的 Ansible」：同一件事，但在堡垒里跑才留执行记录（Q9）。

## Q4

**★★★★☆｜OTP、MFA 开在哪？MFA 全员突然失败先查什么？**

**覆盖**：必会 · 常考

**对应**：知识点 [四、进门：认证收敛与动态令牌](知识点.md)

### 场景

周一早上全员登录堡垒全部「动态口令错误」，有人已经在工单系统申请「临时关闭 MFA」。

### 完整解答

> 🎯 **一句话**：MFA 开在登堡垒那一跳；全员失败先查时钟，不是先关 MFA。

**OTP**（One-Time Password，动态令牌）类型与强度：TOTP（时间窗 30s，主流）、HOTP（计数器）、FIDO/硬件 key（最强，钓鱼钓不走）、短信（弱，SIM 劫持可绕，只做兜底）、备份码（丢手机后路）。**MFA** 开在**登录堡垒那一跳**——不是每台生产机（生产机只认堡垒来的 key，[27](../27-Linux安全加固/)）；高危资产（支付库/GM 后台）再 **step-up** 验一次。

```bash
timedatectl
#  NTP service: inactive   ← 堡垒时钟漂移 > 30s，TOTP 窗口全员对不上
#  修 NTP（→ 32），不是关 MFA
```

> ⚠️ **别混**：OTP ≠ 改密码——一次性凭证替代不了凭据轮换；**MFA 与白名单是两层**：MFA 验「是不是本人」，授权验「本人能不能上这台」。

### 再追问

- 4A、SSO 各指什么？——4A = 账号/认证/授权/审计四个治理域；SSO = 一次登录通行所有系统，身份发放在 LDAP/AD。
- 手机丢了怎么进？——备份码走身份验证流程，验证后重绑；这本身就是审计事件。

## Q5

**★★★★☆｜授权怎么建模？from=、no-port-forwarding 各限什么？**

**覆盖**：必会 · 常考

**对应**：知识点 [五、放行：授权模型——人 × 资产 × 动作](知识点.md)

### 场景

安全审计问：「dba 和外包张三的权限分别怎么描述？」负责人答：「都能 ssh 上去看看。」

### 完整解答

> 🎯 **一句话**：默认拒绝；人 × 资产 × 动作 × 时间盒，四个维度缺一个都是事故。

dba = 实名组 dba → 资产组「生产·支付库（单独组）」→ 动作 SSH + SFTP 只读 → 季度审批 90 天；外包 = 外包-张三 → 测试环境 → SSH 无文件传输 → 合同到期日自动失效。**时间盒比「记得回收」可靠一个数量级**。

密钥侧最小权限（写进机器的 `authorized_keys`，细节在 [26](../26-SSH与远程访问/)）：

```text
from="10.0.0.0/8",no-port-forwarding,no-pty ssh-ed25519 AAAA... deploy@bastion
```

`from=` 限这把 key 只能从堡垒网段用；`no-port-forwarding` 禁当隧道跳板；`no-pty` 禁交互 shell；key 用 ED25519 且带 passphrase。批量铺 key 用 Ansible `authorized_key` 或 `AuthorizedKeysCommand` 对接 LDAP——人肉 append 是散落的开始。

> ⚠️ **别混**：能 SSH ≠ 能 SFTP ≠ 能 sudo——三个动作三个开关；文件传输（上传脚本、下载 dump）单独授权单独留痕。

### 再追问

- 为什么支付资产单独成组？——授权粒度按「环境」切：支付组的授权走独立审批 + step-up，不和游戏服混在一个筐里。
- 授权到期怎么落地？——堡垒侧时间盒自动失效 + 机器侧 `chage -E`（[27](../27-Linux安全加固/)）双保险。

## Q6

**★★★★★｜-J、-L、-R、-D 分别怎么用？怎么证明第二跳经堡垒？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [六、通道：ProxyJump、Web 终端与隧道政策](知识点.md)

### 场景

值班要连生产库排障；同一天有人申请「在生产机 -R 转发一个端口出来方便家里看 Grafana」。

### 完整解答

> 🎯 **一句话**：人走 -J；-L 工单化排障、-R 生产默认禁、-D 临时审批。

```bash
ssh -J moonton@bastion.corp deploy@10.0.0.21        # 日常唯一正道
ssh -J moonton@bastion.corp -L 15432:10.0.0.31:5432 deploy@10.0.0.21
psql -h 127.0.0.1 -p 15432 -U game -d payment       # 排障连库：本地 15432 → 堡垒 → 生产库
```

四件比方记方向：`-J` 刷门禁进大楼；`-L` 从工位接根管子到楼里数据库（你在外面喝）；`-R` 在门禁上开个洞朝外（外面的人摸进来）——生产默认禁，特殊场景逐台审批；`-D` 临时万能网线——审批 + 限时。业务机 `AllowTcpForwarding no`（[27](../27-Linux安全加固/)），隧道只从堡垒发起。`ServerAliveInterval 60 / CountMax 3` 保活、`ExitOnForwardFailure yes` 防假端口。

```bash
# 证明第二跳经堡垒：看生产机认证日志的来源 IP
grep 'Accepted publickey' /var/log/secure | tail -3
# from 10.0.0.5   ← 堡垒内网 IP = 通道合格；办公网/家宽 IP = 直连事故
```

> ⚠️ **别混**：`-L` 与 `-R` 方向相反、风险相反——`-L` 把内网服务接到你屏幕上，`-R` 把你的机器开给内网（经典后门通道）；「都是转发随手开」是隧道事故的统一开头。另外 `-L` 借道后**没有命令审计**（只审 SSH 登录），所以必须工单化。

### 再追问

- 为什么用 `-J` 不用先 ssh 堡垒再 ssh 目标？——一段命令一次认证、第二跳的 key 不落办公机、config 可复用可多跳。
- Web 终端和 SSH 会话谁审计？——都要进同一套审计；Web 终端的好处是办公机不存 key、录像天然全覆盖。

## Q7

**★★★★★｜审计三件套是什么？定责的对照套路怎么走？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [七、在场：会话审计三件套](知识点.md)

### 场景

安全部要一份「上周谁动过支付库」的操作清单；你只有堡垒控制台和机器 shell。

### 完整解答

> 🎯 **一句话**：命令记录、录像回放、文件传输审计——各回答一个问题，缺一件就有一段黑箱。

命令记录答「他敲了什么」；录像回放答「命令记录看不到的交互」（vim 里改了什么、less 里翻到什么）；传输审计答「他带走/放进了什么」。四条硬要求：**保留期 180 天+**、录屏卷**独立**且满盘**先拒新会话再告警**（不能静默停录）、**NTP 对齐**（→ [32](../32-NTP与时间同步/)）、**离机**集中存储（→ [23](../23-日志运维/)）；Web 终端与 SSH 会话都要进同一套审计。

对照套路：堡垒会话列表（who/资产/起止/命令数/录像）+ 生产机 `last -a`、`grep Accepted /var/log/secure`——**对得上 = 闭环；本机有堡垒无 = 直连事故；堡垒有本机无 = 查时间同步**。

> ⚠️ **别混**：会话审计 ≠ 本机 `history`（可清可改，[27](../27-Linux安全加固/)）；「会话列表有」≠「操作可回放」——列表只证来过，干了什么靠录像与命令记录。

### 再追问

- 四维闭环是哪四维？——认证 → 授权 → 审计 → 回收，首尾相接；只做前两个是「进门严出门没记录」，没有回收离职照样收不回。
- 四维闭环不保证什么？——只覆盖人工通道；CI/CD、kubectl exec、云控制台是另外几条门（Q13）。

## Q8

**★★★★☆｜「装了 JumpServer」为什么 ≠「做了堡垒」？**

**覆盖**：必会 · 常考

**对应**：知识点 [三、演进：从跳板机到堡垒机](知识点.md)

### 场景

公司买了堡垒机并部署完成，季度安全审计仍判「人工访问生产不可审计」。

### 完整解答

> 🎯 **一句话**：堡垒的生效前提是「生产只认堡垒」——直连没收干净，审计只覆盖守规矩的人。

验收不是「堡垒能登录」，而是**反向验证直连必失败**：

```text
验收清单：
① 办公网直连生产机 22 → 必须超时（安全组只放堡垒网段）
② 从堡垒 ProxyJump → 必须成功，且生产机 secure 日志来源 IP 是堡垒
③ 密码通道：PasswordAuthentication no（→ 27）
④ 离职演练：禁用 LDAP 账号后 5 分钟内既有会话应被断开
⑤ 破窗演练：堡垒全停时云串口 15 分钟内能进（Q11）
```

「就改一行」的安全组、给某人开的 IP 白名单、测试直连忘了删——每一行都是绕过堡垒的路；堡垒的权威来自**没有第二条路**。

> 📝 **面试**：「堡垒落地的验收不是功能演示，是攻击面收敛证明——办公网直连必失败才是过线标准。」

### 再追问

- 老机器上有历史铺的 key 怎么办？——Ansible 批量清理 + `AuthorizedKeysCommand` 收归 LDAP 统一发；保留「堡垒专用 key」以外的全部回收。
- 生产只认堡垒和紧急通道矛盾吗？——不矛盾；破窗是**预置、受控、留痕**的通道（Q11），不是第二条常规路。

## Q9

**★★★★☆｜高危命令怎么拦？批量下发有什么纪律？**

**覆盖**：必会 · 常用

**对应**：知识点 [八、拦截：高危命令与批量操作](知识点.md)

### 场景

值班新人准备在 50 台机器上批量执行清理脚本，脚本里有一行 `rm -rf $DIR/$ subpath`（变量拼写错了）。

### 完整解答

> 🎯 **一句话**：高危命令会话内实时拦截、批量先灰度再全量、执行记录入审计。

堡垒在会话流里做命令匹配，命中规则**先拦再放行**（弹审批/step-up），不是事后翻录像。拦截面：`rm -rf /`、`DROP TABLE`/`TRUNCATE`、`shutdown`、`mkfs`/`> /dev/sda`、`chmod -R 777 /`；两种模式：黑名单正则（拦已知高危，常用）+ 命令白名单（值班只准跑预案命令，更严）。批量两条纪律：**先灰度再全量**（先 1 台看输出）；**执行记录入审计**——在自己终端 `for h in ...; do ssh $h ...; done` 是无痕批量（机器上只有 last，没有命令归属）。高危拦截对批量任务在下发前生效——那行拼错的 `rm -rf` 应该在**下发前**被拦出来。

> ⚠️ **别混**：拦截 ≠ 替代审计——拦得住的是规则里的；没拦到的操作照样要有录像兜底，一个事前一个事后。

### 再追问

- 变量拼错这种怎么防？——白名单模式跑预案命令（不带自由变量）+ 灰度先行的输出比对；技术拦截不覆盖业务逻辑错误。
- 命令下发和 Ansible 怎么选？——堡垒下发赢在留痕和权限收敛，Ansible 赢在编排；正解是堡垒里串 playbook，两者都要审计。

## Q10

**★★★★★｜离职当天做什么？key 被盗怎么响应？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [九、退场：账号生命周期与权限回收](知识点.md)

### 场景

周四 18:00 HR 通知一名 DBA 当天离职；同月另一名在职员工的笔记本电脑（存有带 passphrase 的 key）丢失。

### 完整解答

> 🎯 **一句话**：离职当天五步全收；被盗先禁用再圈范围。

**离职当天**：① LDAP/SSO 禁用（认证收敛红利：一处断处处断）；② 堡垒侧授权删除、进行中会话强制断开；③ Ansible 批量清机器上的 `authorized_keys`；④ API token、云 AK/SK、GM 后台账号轮换或吊销；⑤ 录像与操作记录封存（离职后 30 天内出问题还要能查）。调岗**先收后加**；外包 `chage -E` 到期（[27](../27-Linux安全加固/)）+ 授权时间盒。

**被盗响应**：立即禁用账号 → 吊销相关 key/令牌 → 调录像与 `last` 圈定操作范围 → 查 `authorized_keys` 陌生行、crontab 有无植入 → 已有操作按可疑入侵处理（隔离取证 → [27](../27-Linux安全加固/)）。

> ⚠️ **别混**：回收 ≠ 删账号——LDAP 禁用 + 授权删除即生效且可恢复；`userdel` 删了 uid 可能被复用，取证期先禁用别删。

### 再追问

- 「当天」来得及吗？——认证收敛的设计就是为这一刻：LDAP 一处禁用，堡垒、SSO 全断；散落模式下「当天」做不到才是常态。
- 季度 review 看什么？——支付/GM/数据库三类授权清单，「他为什么还有这个权限」答不上来就收。

## Q11

**★★★★★｜堡垒挂了怎么办？break-glass 怎么做才不是「开 22」？**

**覆盖**：核心 · 必会 · 常考

**对应**：知识点 [十、破窗：break-glass，正门挂了](知识点.md)

### 场景

堡垒升级失败，全员进不了生产；群里已经有人贴出「先在安全组把 22 对 0.0.0.0/0 打开」的截图。

### 完整解答

> 🎯 **一句话**：破窗是预置、受控、留痕的紧急通道 + 五字段补审计；临时开 22 是焊开卷帘门。

允许与禁止：云串口/VNC 控制台（首选，不走网络不经堡垒）、紧急本地账号（密码密封/双人分管，用后即改、限时启用）**可用**；个人 IP 白名单（默认否，逐条审批+到期）、`0.0.0.0/0` 开 22、紧急账号长期 NOPASSWD **禁止**。用完补**五字段**：谁、何时、为何、命令摘要、影响面——缺字段等于白破窗。演练目标 **5~15 分钟**内进机器：通道真的通吗、账号密码真在保险箱吗、事后 `last` 与工单对得上吗。

> ⚠️ **别混**：break-glass ≠ 临时开 22——前者预置受控留痕，后者现场发明无审批收不回；「先开着回头再收」的回头永远不会来。

### 再追问

- 为什么串口是首选？——不依赖机器网络、不依赖 sshd、不经堡垒，云厂商控制台直达（→ [06-04](../../06-云平台/04-IAM与多账号/)）。
- 破窗期间的操作有录像吗？——没有堡垒录像，所以五字段补审计是硬要求；这也是破窗必须「预置+演练」而不是日常使用的原因。

## Q12

**★★★★☆｜堡垒自身的三个命门是什么？和 VPN、零信任什么关系？**

**覆盖**：必会 · 常考

**对应**：知识点 [十一、命门：堡垒自身的单点、网络与性能](知识点.md)

### 场景

架构评审：有人质疑「你们把所有鸡蛋放一个篮子里了」；也有人提议「干脆全员 VPN 替代堡垒」。

### 完整解答

> 🎯 **一句话**：单点、网络盲区、性能瓶颈三个都要预案；VPN 管接入、堡垒管通道，不是替代关系。

- **单点**：堡垒挂 = 全员进不了生产 → 控制面多实例（LB 前置 → [20](../20-HAProxy与Keepalived/)）、会话状态外置 Redis、配置库主从、录屏卷独立共享存储——挂一台会话不丢能重连。
- **网络盲区**：新机房和堡垒网段不通，唯一入口变唯一瘫痪 → 多臂部署/每区域一组，新网络接入清单固定一项「堡垒可达性验证」。
- **性能**：发布日并发会话打满、录屏盘写满、批量下发风暴 → 按「峰值并发 × 会话时长」估容量，录屏 180 天 × 日增量一起算；盘满**先拒新会话再告警**。

**VPN 边界**：VPN 解决网络层接入（把笔记本「搬进」内网），不解决授权与审计——全 VPN 无堡垒 = 内网人人直连，三宗罪原样复发；正确叠法是 VPN 打底 + 堡垒管人工通道。**零信任**把「先接入后鉴权」改成「每会话持续验证」——是堡垒思路的延伸，**演进方向不是取消审计**。

> ⚠️ **别混**：堡垒 HA ≠ 开公网 22 兜底——为保险留一个不认证的入口等于给唯一入口装后门；兜底是 Q11 的破窗预案。

### 再追问

- 堡垒监控看什么？——进程、端口、证书过期、录屏盘水位（→ [22](../22-监控与告警/)）。
- 新 VPC 机器没人能登怎么办？——先验证堡垒到该网段可达性（路由/安全组），不是在生产开公网 22 临时救。

## Q13

**★★★★★｜支付库被 DROP，安全问「谁干的」——60 秒怎么走？**

**覆盖**：核心 · 必会

**对应**：知识点 [十二、作战：对不上人，先查会话](知识点.md)

### 场景

凌晨 3 点支付库一张表被 DROP；堡垒会话列表里该时段查无记录；DB 审计日志显示连接来自应用网段。

### 完整解答

> 🎯 **一句话**：先堡垒会话列表，再本机 last 分流直连或非 SSH 途径；查无 SSH 会话 ≠ 没人操作。

```text
① 0–20s  堡垒会话列表按资产+时间段过滤 → 无
② 20–40s 登 DB 主机 last -a；grep Accepted /var/log/secure → 无人工登录
          连接来自应用网段 → 排除「人从堡垒敲的」，转非 SSH 途径
③ 40–60s 三条门排查：CI/CD 发布记录 · kubectl exec 审计（→ 03-13）· 云控制台操作记录（→ 06-04）
          ——很可能是应用发版带上去的 migration，或被入侵的应用进程（→ 27 隔离取证）
```

决策树两个二分点：堡垒有没有会话 → 有则调录像对工单（授权内/外分流）；没有则本机 last 分流「直连事故」还是「非 SSH 途径」。回复安全要三样：现象、一条证据、下一步动作——不说「应该没人吧」。

> ⚠️ **别混**：堡垒查无会话 ≠ 没人操作——CI、exec、云控制台是另外几条门，各有各的审计；「查不到」只说明「不是人工从堡垒进来」。

### 再追问

- 如果本机 last 有一条家宽 IP 呢？——直连事故：收安全组白名单 + 该时间窗操作按入侵处理（→ [27](../27-Linux安全加固/)）。
- 预防这类「应用侧 DROP」靠什么？——DB 账号最小权限、DDL 走审批流、备份可回放（[31](../31-备份与恢复/)）——那是另一章的阵地。

## Q14

**★★★★★｜白板：人工登录一生 + 审计定责 + break-glass 边界？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图](知识点.md) · [十三、收口](知识点.md)

### 场景

白板：「画堡垒主线，说『装了 JumpServer ≠ 做了堡垒』验收清单。」

### 完整解答

> 🎯 **一句话**：**工单→认证→授权→通道→会话→退场**；审计三件套；破窗不是临时开 22。

```text
三宗罪: 直连/共享密码/无审计
定责: 堡垒会话 → last → CI/exec/云控制台
隧道: -J 正途  -R 红线
验收: MFA+授权+录像+拦截 四模块齐
```

> 📝 **面试**：查无会话≠没人操作（Q13）。

### 再追问

- 堡垒单点？——命门三预案（Q12）。
