## Q1 Connection refused vs timed out

**★★★★★｜「ssh 报 Connection refused 和 Connection timed out，分别说明什么？第一刀查哪？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [二、敲门：到 22 端口之前](知识点.md)

### 场景

割接后有一台机器 ssh 不上。值班敲了一下：`ssh: connect to host 10.0.0.21 port 22: Connection refused`。他松了口气开始查 sshd；旁边实习生问你为什么他连另一台是 timed out，气氛反而更紧张。

### 完整解答

> 🎯 **一句话**：refused = 网络通、22 没人听（修 sshd）；timed out = 包没到或回不来（修网络/防火墙）。

```bash
# refused 的第一刀：sshd 活着吗、端口对吗、监听地址对吗（可走云控制台/带外）
systemctl status sshd
ss -lntp | grep sshd
# LISTEN 0 128 0.0.0.0:22    users:(("sshd",pid=980,fd=3))  ← 22 在听、全网卡
# LISTEN 0 128 127.0.0.1:22  users:(("sshd",pid=980,fd=3))  ← 只听回环：远程永远 refused
```

深挖机制：refused 是**对方内核回了 RST**——TCP 层到了，端口上没人 LISTEN；timed out 是 **SYN 石沉大海**——IP 不对、路由不通、或防火墙 DROP（DROP 不回话才叫超时；REJECT 会表现成 refused）。监听 `127.0.0.1` 是 refused 里最阴的一种：sshd 明明活着，`ss` 一看只绑了回环。改过端口的机器要先用 `ssh -p 2222` 试对端口再谈故障。

> ⚠️ **别混**：把 timeout 当 sshd 故障反复重启服务，是第一刀砍错——timeout 属于网络/防火墙段，按 [02](../02-网络排查命令/) 的刀法 ping → traceroute 逐跳走，云上先看安全组和 iptables（→ [17](../17-iptables与conntrack/)）。

> 📝 **面试**：先答机制（RST vs 无响应）再答排查（systemctl/ss vs ping/traceroute/安全组）；refused 反而是好消息——说明你和服务端之间网络无恙。

### 再追问

- sshd 挂了怎么进的机器？——云控制台/VNC、带外管理卡、或同网段跳板；这也是为什么不把所有鸡蛋放在 ssh 一条路上（→ [28](../28-堡垒机与跳板机/)）。
- 一直拒绝但 sshd 在跑？——查监听地址（127.0.0.1 陷阱）和端口是不是改过；再看 `journalctl -u sshd` 有没有起服务失败的报错（→ [11](../11-Systemd与服务管理/)）。

## Q2 SSH 连接建立全过程

**★★★★★｜「从敲下 ssh 到拿到 Shell，中间发生了什么？为什么说密码不会被链路上抓到？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：一次 SSH 连接的一生](知识点.md) · [三、对暗号：算法协商与密钥交换](知识点.md)

### 场景

面试官递白板：「画出/说出 SSH 连接建立的完整过程。」提示一句：tcpdump 上抓 SSH 全是密文，这是为什么。

### 完整解答

> 🎯 **一句话**：TCP → 版本协商 → 算法协商（KEXINIT）→ DH 密钥交换 → NEWKEYS 起加密 → 用户认证 → 会话通道。

```text
客户端                          sshd（服务端）
   │ ── SSH-2.0-OpenSSH_9.x ──→   版本协商：说同一种协议
   │ ←── SSH-2.0-OpenSSH_9.x ──
   │ ── KEXINIT（算法清单）──→    算法协商：取交集
   │ ←── KEXINIT ────────────
   │ ── KEX（g^x）──────────→     密钥交换：x、y 各自藏着
   │ ←── g^y + 主机私钥签名 ──     两端各自算出 K = g^(xy)
   │ ── NEWKEYS ⇄ NEWKEYS ───     从此刻起全部加密（每包带 MAC）
   │ ── 用户认证（公钥/密码）──→   认证在加密通道**里面**进行
   │ ←── 认证通过 · 开会话通道 ──  → 落 Shell
```

**Diffie-Hellman 凭什么明文传也安全**：双方各自握一个**从不上网**的随机私数（x、y），网上走的只有 g^x 和 g^y，从 g^x 反推 x 是离散对数难题——窃听者攒下全部报文也算不出 g^(xy)。**会话密钥从没在网络上出现过**。

所以抓包全是密文是**正常的**：加密在认证之前就生效了，密码、命令、输出都在加密通道里面走；想看明文不是抓包能解决的（抓包刀法 → [16](../16-网络排障与抓包/)），只能上服务端审计。

> ⚠️ **别混**：和 HTTPS 思想同源（明文信道上协商密钥），但 **TLS 靠 CA 证书体系认服务端，SSH 靠 known_hosts 指纹认服务端**（→ [14](../14-HTTP与TLS/)、Q3）。

> 📝 **面试**：六步顺序背熟；「SSH 为什么安全」答三支柱——加密（DH + 每包 MAC）、服务端认证（指纹）、用户认证（公钥）——按「对线路/对服务器/对人」分组。

### 再追问

- 我一次都没输密码，哪来的会话密钥？——密钥不是「谁输给谁」的，是两边各自算出来的；你输入的密码只用于**之后的**用户认证。
- 服务端怎么证明「它就是它」？——DH 应答里带**主机私钥的签名**，客户端拿 known_hosts 里的指纹验——这就是认门（Q3）。

## Q3 REMOTE HOST IDENTIFICATION HAS CHANGED

**★★★★★｜「ssh 突然报 HOST KEY VERIFICATION FAILED / REMOTE HOST IDENTIFICATION HAS CHANGED，你怎么处理？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [四、认门：known_hosts 与主机指纹](知识点.md)

### 场景

十台批量重装的机器，你 ssh 第一台就刷出一屏 `@@@@ WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED! @@@@`。同组的人已经准备 `rm -rf ~/.ssh/known_hosts` 一把清掉。

### 完整解答

> 🎯 **一句话**：指纹变更只有两种解释——重装换了主机密钥（良性）或中间人（恶性）；先带外核指纹，确认重装才删**单条**，不清账本。

三步处置：

```bash
# ① 带外核对真指纹：云控制台/VNC 上目标机本地执行
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
# 256 SHA256:8nRf0Kq…wKk root@host (ED25519)   ← 和告警里的指纹逐字比对
# ② 确认是重装 → 只删这一条，重连重记
ssh-keygen -R 10.0.0.21
# Host 10.0.0.21 found: line 12        ← 精准删除，账本里其他 199 条不动
ssh ops@10.0.0.21                      # 重新人肉核指纹后 yes
# ③ 对不上/无人承认重装 → 停止连接，按安全事件上报（→ 27）
```

深挖：每台 sshd 装好时生成**主机密钥**，公钥哈希即指纹；known_hosts 是客户端自己攒的指纹账本。重装会重新生成主机密钥 → 指纹变 → 告警；中间人冒充服务端时它拿不出原私钥、签名对不上 → 同样告警。**告警本身正是 SSH 防中间人的机制在工作**，无脑清账本等于把这道防线拆掉。

批量场景的正确姿势：重装是计划内变更时，用配置管理**预置**新的 `/etc/ssh/ssh_known_hosts`，而不是逐台 yes 或全局 no（→ [28](../28-堡垒机与跳板机/)）。

> ⚠️ **别混**：`StrictHostKeyChecking` 三档——yes（没记过就拒，自动化首选）、accept-new（首次自动记、变更仍拒，推荐值）、no（来了就连，等于拆门，只许一次性测试环境）。`rm known_hosts` 和全局 no 是同一个错误的两种写法。

> 📝 **面试**：「SSH 怎么防中间人」——known_hosts 指纹核对；「告警怎么办」——带外核指纹 → 重装才 `ssh-keygen -R` 删单条 → 疑 MITM 上报。这套顺序就是满分答案。

### 再追问

- 首次连接的 yes 提示要不要直接回？——生产上首次也该带外核指纹（或用预置账本）；accept-new 至少保证「变更仍会拦」。
- 指纹存在哪、哪些机器共享一份？——`~/.ssh/known_hosts`（用户级）和 `/etc/ssh/ssh_known_hosts`（全局预置）；同镜像克隆的机器主机密钥相同，指纹也相同——这本身是另一个要治理的问题。

## Q4 密钥认证为什么比密码安全

**★★★★★｜「公钥登录为什么比密码登录安全？私钥会不会被传到服务器上？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、验身：密码认证 vs 密钥认证](知识点.md)

### 场景

主管要求全网切密钥登录、关密码。有人反对：「密码也是走加密通道的，抓包又抓不到，换密钥图什么？」你要当场说服他。

### 完整解答

> 🎯 **一句话**：链路安全不是全部——密码认证服务端存着「能对上的秘密」，公钥认证**私钥永远不出你的电脑**，验的是签名不是口令。

两条认证路的对比，说服口径就三条：

```text
密码认证：你输的密码 → 加密通道里送到服务端 → 和 shadow 里的哈希比对
          风险面：服务端有可偷的秘密；密码可被字典爆破（Failed password 刷屏）

公钥认证：服务端发随机数 → 你用私钥签名传回 → authorized_keys 里的公钥验签
          链路上只有公钥和签名；服务端没有秘密可偷；没有口令可猜
```

所以「抓不到」只是三支柱里「加密」那一根；公钥认证把**服务端泄漏面**和**爆破面**也消掉了——这就是切密钥的全部理由。生成与分发：

```bash
ssh-keygen -t ed25519 -C "ops@laptop"     # ← 现代默认 ed25519
ssh-copy-id ops@10.0.0.21                 # ← 公钥追加进对方 ~/.ssh/authorized_keys
```

严格说：私钥一个字节都没过网，`~/.ssh/id_ed25519` 只在你本机；被拷走的风险只有两个——笔记本失窃（用 passphrase 兜底，Q6）或你手动 scp 了私钥（那就是事故）。

> ⚠️ **别混**：authorized_keys 里放的是**公钥**；「把私钥传到服务器上备份」是把两种钥匙搞反了，等于把家门钥匙复印了塞门缝里。

> 📝 **面试**：「为什么密钥更安全」答三句——私钥不上网、服务端无可偷的秘密、爆破面消失；追问握手细节就答「签名/验签，不是传输口令」。

### 再追问

- 服务器怎么知道用哪把公钥验？——按你声称的身份找 `~/.ssh/authorized_keys`，逐条试；这也是权限坑的入口（Q5）。
- 密码认证完全没用了吗？——密钥丢了/agent 没起时是兜底；生产做法是密钥就绪后 `PasswordAuthentication no` 关掉它（Q7），不是留着弱密码裸奔。

## Q5 公钥放好了就是登不进

**★★★★☆｜「ssh-copy-id 都跑完了，ssh 还是要密码/被拒绝——除了钥匙本身，还有什么会挡住密钥登录？」**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [五、验身：密码认证 vs 密钥认证](知识点.md)

### 场景

新同事的公钥你亲手放进 `~ops/.ssh/authorized_keys` 了，他 ssh 还是进不来，客户端反复提示输密码。他怀疑「公钥传坏了」。

### 完整解答

> 🎯 **一句话**：sshd 的 StrictModes 检查三处权限——家目录、.ssh、authorized_keys——任何一处组/其他人可写，直接拒绝这把钥匙。

```bash
ls -ld ~ops ~ops/.ssh ~ops/.ssh/authorized_keys
# drwxrwxr-x 6 ops ops 4096 /home/ops                ← 家目录组可写：病根
# drwxr-xr-x 2 ops ops 4096 /home/ops/.ssh           ← 应为 700
# -rw-rw-r-- 1 ops ops  381 /home/ops/.ssh/authorized_keys   ← 应为 600

journalctl -u sshd -n 20 | grep -i refused
# Authentication refused: bad ownership or modes for directory /home/ops   ← 病名在这行
```

修法一行（权限位的语言 → [25](../25-用户权限与特殊位/)）：

```bash
chmod 700 ~ops/.ssh && chmod 600 ~ops/.ssh/authorized_keys && chmod g-w ~ops
ssh -i ~/.ssh/id_ed25519 ops@10.0.0.21     # ← 客户端再试，通了
```

深挖：为什么 sshd 这么苛刻——authorized_keys 是「谁能进门」的名单，若目录组可写，任何同组人（或打穿同组账号的人）都能往名单里加自己的钥匙；sshd 宁可拒登也不接受一份可能被篡改的名单。排查时的两端命令：客户端 `ssh -v` 看「Offering key 之后有没有 accepted」，服务端 `journalctl -u sshd` 直接给病名。除了权限，还查三样：authorized_keys 是不是多行拼坏了、AllowUsers 名单有没有他（Q7）、服务器是否禁了公钥（`PubkeyAuthentication no`）。

> ⚠️ **别混**：权限坑拒绝的表现通常是**静默回退到问密码**（或 publickey 方式失败），不会弹「权限不对」——所以它才排在「登不进」排查的第一嫌疑。

> 📝 **面试**：`~/.ssh 700、authorized_keys 600、家目录不可组写`三个数字随口报出，就是这题的考点本体。

### 再追问

- 怎么区分「钥匙没被 offered」和「offered 了没被接受」？——`ssh -v`：`Offering public key` 之前失败是本地钥匙/路径问题；offered 之后 `Authentications that can continue: publickey` 是服务端没认（权限/名单/方式禁用）。
- 管理机批量分发怎么避免逐台踩这坑？——分发工具统一落权限（700/600），预置校验脚本；分发体系 → [28](../28-堡垒机与跳板机/)。

## Q6 passphrase、ssh-agent 与 -A

**★★★☆☆｜「私钥的 passphrase 是干嘛的？ssh-agent 解决什么问题？ssh -A 为什么默认不开？」**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [五、验身：密码认证 vs 密钥认证](知识点.md)

### 场景

同事给私钥设了 passphrase，抱怨「每台机器都要输一次口令，比密码登录还麻烦」；另一边有人习惯性 `ssh -A` 跳板满场跑。两个习惯都要点评。

### 完整解答

> 🎯 **一句话**：passphrase 是**私钥文件的口令**（防笔记本失窃），ssh-agent 把解锁后的私钥放内存里代签，-A 是把这张「代签权」借给远端——所以默认不开。

```bash
eval "$(ssh-agent -s)"       # ← 起一个签名代理人
ssh-add ~/.ssh/id_ed25519    # ← 输一次 passphrase，私钥解锁进内存
ssh ops@10.0.0.21            # ← 之后所有连接由 agent 代签，不再问口令
ssh-add -l                   # ← agent 里现存哪些钥匙
```

三个概念分清：**私钥**是钥匙本体（`~/.ssh/id_ed25519`，600）；**passphrase** 是这把钥匙的口令（只在人脑和 ssh-add 交互里）；**agent** 是内存里的代签人。抱怨「每台机器输一次」的解法就是 agent——一次解锁，会话内全免。

`ssh -A`（agent forwarding）让**跳板机上的** ssh 也能用你本机的 agent：在跳板上直接 ssh 第三台，不用把私钥拷过去。代价：跳板上的 root 能借用你的 agent 连遍全网——所以口径是**默认不开，只在可信跳板临时开**，用完就停。

> ⚠️ **别混**：passphrase 不是服务器密码、也不是登录口令——它保护的是私钥文件本身；「删掉 passphrase 图省事」等于把钥匙裸放在笔记本里。

> 📝 **面试**：三概念各一句 + 「-A 是借出代签权，默认不开」；追问「私钥丢了怎么办」——passphrase 兜底是挡时间，正经动作是从所有 authorized_keys 里摘公钥、换新钥对。

### 再追问

- agent 里的私钥会被远端读到吗？——不会，远端只能**请求签名**，拿不到私钥本体；但签名权本身已经够敏感，所以 -A 才要克制。
- 多把钥匙怎么管理？——`ssh-add` 多次、`ssh-add -l` 列出；指定钥匙用 `ssh -i`，或 ssh_config 里按 Host 配 IdentityFile。

## Q7 加固 sshd 且不把自己锁死

**★★★★★｜「给你一台新机器，sshd 怎么加固？改配置怎么保证不把自己锁在外面？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [六、管家：sshd_config 高频参数](知识点.md)

### 场景

等保整改单下来了：改端口、禁 root、关密码、限白名单。有人改到一半 `systemctl restart sshd`，然后当前会话一断，全组等带外救援。

### 完整解答

> 🎯 **一句话**：加固五参数，改动三步——`sshd -t` 语法检查 → `reload`（不断旧连接）→ 新开终端验证成功，再退旧会话。

五参数（能背的程度）：

```text
Port 2222                          # 改端口：挡扫描噪音，不是安全手段
PermitRootLogin prohibit-password  # root 只许密钥（比 no 温和：留密钥救生通道）
PasswordAuthentication no          # 关密码登录：前提是公钥已经放好
MaxAuthTries 6                     # 收紧认证尝试
AllowUsers ops deploy              # 白名单：不在名单连密码对也拒
```

三步流程（锁死事故的全套预防）：

```bash
sshd -t                             # ← ① 语法检查：写错一个词，新连接全挂
systemctl reload sshd               # ← ② reload 重读配置且不断现有连接
# ③ 新开一个终端验证能登录、能 sudo，再退出旧会话——顺序不能反
```

顺序讲究再钉一遍：**先放钥匙、再关密码**——`PasswordAuthentication no` 之前必须确认公钥能登；`PermitRootLogin no` 的前提是有可 sudo 的普通账号（→ [25](../25-用户权限与特殊位/)）。`AllowUsers` 是最后一道闸，「密码明明对也不让进」先查它。

> ⚠️ **别混**：`sshd_config`（服务端门规，管别人怎么进这台机）vs `ssh_config`（客户端偏好，管你出去怎么连）——/etc/ssh/ 下就差一个字母 d；`reload` vs `restart`——reload 不断连接、restart 全断。

> 📝 **面试**：五条参数 + 三步流程一起答，就是「运维过」和「背题的」的区别；追问改错了怎么办——旧会话还在就改回去，不在了走带外/云控制台。

### 再追问

- 增量配置怎么管？——`/etc/ssh/sshd_config.d/*.conf` drop-in，后读覆盖先读；配置管理统一分发，别都挤主文件。
- 改完怎么验证生效？——`sshd -T | grep -Ei 'permitroot|passwordauth'` 看运行时合并后的配置；再从外部实际连一次。

## Q8 -L 转发查内网管理台

**★★★★☆｜「办公网摸不到内网管理台，你怎么用 ssh 看到？-L 参数每一字段什么意思？」**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、挖隧道：-L、-R、-D 与 scp/rsync](知识点.md)

### 场景

活动出了问题要登内网管理台（`10.0.0.5:80`），它只在游戏内网。有人已经在申请把管理台端口对办公网防火墙全开。

### 完整解答

> 🎯 **一句话**：`ssh -L 8080:10.0.0.5:80 ops@bastion`——把内网端口顺着堡垒的加密隧道搬到本机 8080，不用开任何防火墙。

```bash
ssh -L 8080:10.0.0.5:80 ops@bastion
#    ↑本机端口 ↑目标主机 ↑目标端口  @跳板
```

字段读法固定四段，**目标主机是站在跳板机的视角解析的**——所以这里写的是内网 IP `10.0.0.5`（bastion 能路由到它），你本机根本不用认识这个地址。数据路径：

```text
本机 localhost:8080 → 加密隧道 → bastion → 10.0.0.5:80
```

然后本机浏览器开 `http://localhost:8080`。申请全开防火墙的方案直接否掉：那等于把管理台暴露给整个办公段，还绕过堡垒机的审计。需要**同时**访问内网好几个服务时，用 -D 动态转发一次借道整个内网（SOCKS5，`ssh -D 1080 ops@bastion`，浏览器代理填 `127.0.0.1:1080`）。

> ⚠️ **别混**：-L 默认只绑**回环地址**（localhost）——这是保护，只有你自己能用这条隧道；加 `-g` 把它绑到 0.0.0.0 让别人也能用，是红线动作（Q9）。

> 📝 **面试**：-L 的四段字段逐个能讲 + 「目标主机按跳板视角解析」这一句，就证明真用过。

### 再追问

- 连上 bastion 之后隧道就生效吗？——隧道随这条 ssh 连接存活；要「挂着不占终端」加 `-N`（不执行远程命令）和 `-f`（后台）。
- 8080 被占了怎么办？——换本机端口（`-L 18080:...`）；目标主机和端口不用变。

## Q9 -R 反向转发与安全红线

**★★★★☆｜「开发要看我本机 3000 端口的调试页，他不在我的网段——怎么办？什么情况下禁止用端口转发？」**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、挖隧道：-L、-R、-D 与 scp/rsync](知识点.md)

### 场景

联调到凌晨，开发要在真实数据下看你的本地页面。他说「你把 3000 端口在你们网关上映射出来吧」；另一边你想起白天有人为了「方便办公网查库」，在跳板上挂了一条 `-L 0.0.0.0:13306:mysql:3306`。

### 完整解答

> 🎯 **一句话**：`ssh -R 9090:localhost:3000 ops@dev.jump` 把**你本机**的端口倒挂到远端——方向和 -L 相反；而「把生产端口裸转到办公网」是红线。

```bash
ssh -R 9090:localhost:3000 ops@dev.jump
#    ↑远端端口 ↑从跳板视角看的「你这边」的目标   @你登过去的机器
```

数据路径与 -L 完全反向：

```text
开发访问 dev.jump:9090 → 加密隧道 → 你的 localhost:3000
```

红线的部分：白天那条 `-L 0.0.0.0:13306:mysql:3306` 要立刻拆——`-g`/`GatewayPorts` 把隧道绑到 0.0.0.0，等于**整个办公网都能直连生产库**，绕过堡垒机审计、无失败锁定、无操作留痕；生产库的爆破面一夜回到解放前（防爆破与加固 → [27](../27-Linux安全加固/)）。对照口诀：**-L 把远处搬来、-R 把本地递出去、-D 万能代理；默认只绑回环是保护，绑 0.0.0.0 是事件**。

> ⚠️ **别混**：-L 与 -R 的方向——站在**敲命令的本机**视角：-L 是「拉过来」（本机开端口），-R 是「递出去」（远端开端口）；两边的目标主机都按**隧道对端**的视角解析。

> 📝 **面试**：三种转发各举一个场景 + 红线一句「禁止把生产端口裸转到办公网」，这题就是送分变加分。

### 再追问

- 开发访问 dev.jump:9090 连不上？——sshd 默认远端转发也只绑回环，dev.jump 本机访问 localhost:9090 可以；要让他从别的机器访问就得开 GatewayPorts——先自问该不该。
- 隧道挂断怎么办？——`-o ServerAliveInterval=60` 保活；断了重挂即可，-R 场景考虑 autossh 常驻。

## Q10 scp 还是 rsync

**★★★★☆｜「传一个 8G 的发版包，scp 和 rsync 选哪个？断了怎么办？」**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、挖隧道：-L、-R、-D 与 scp/rsync](知识点.md)

### 场景

发版窗口 20 分钟，包 8G，跨境专线抖。值班用 scp 传，第 6G 断线，从头再来了一遍；第二次第 7G 又断。他在考虑把窗口拖到明天。

### 完整解答

> 🎯 **一句话**：scp 中断 = 从头再来；大文件一律 rsync -P——断点续传 + 增量传输，断了接着传。

```bash
rsync -avP /data/release/game-1.2.5.tar ops@10.0.0.21:/data/release/
# ← -a 保属性权限（含权限位，→ 25）  -v 进度  -P = --partial --progress
# 断线后重新执行同一条命令：从已传的半截继续，不从头来
```

选择口径三条：

```text
单个小文件、临时抓一个日志        → scp patch.tar ops@host:/path/  （简单直接）
大文件 / 长距离 / 专线抖          → rsync -P（--partial 续传；--append-verify 追加式断点）
目录同步 / 只传差异               → rsync（增量算法只传差异块，几十 G 的目录第二次秒级）
```

scp 的定位就是「单文件、一把过」；它没有断点语义，8G 传到 7G 断了就是 0。rsync 之外的两个值班常识：目录同步**末尾斜杠有意义**（`src/` 是「里面的内容」，`src` 是「这个目录本身」）；`-a` 会带上权限位与属主（root 执行时），同步后权限对不上先想 `-a` 加没加。

> ⚠️ **别混**：`-P` 在 scp 里是**端口**（`scp -P 2222`），在 rsync 里是**断点续传**——同一字母两个意思，跨命令手滑是真实事故。

> 📝 **面试**：「scp 和 rsync 选谁」答三句——小文件 scp、大文件/断点 rsync -P、目录增量 rsync；追问 rsync 好在哪——增量算法只传差异块 + --partial 续传。

### 再追问

- 带宽敏感的窗口怎么限速？——rsync `--bwlimit=10m`（MB/s），避免发版把玩家流量挤死。
- 传完怎么验证完整性？——两边 `sha256sum` 对哈希；rsync `-c`（checksum）模式按内容校验而不是按时间/大小。

## Q11 每台机器都要卡 30 秒

**★★★★★｜「ssh 每次都要等 30 秒才出密码框，网络团队说链路没问题——你查什么？」**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [八、生病：连得慢与登不进](知识点.md)

### 场景

全组反映 ssh 内网机器「先卡半分钟再弹密码框」，工单派给网络组查了一天没结论。有人开始怀疑交换机。你登上一台（等了 30 秒）准备动手。

### 完整解答

> 🎯 **一句话**：卡在**密码框之前**是服务端配置病——UseDNS 反解和 GSSAPIAuthentication 干等两刀下去，立竿见影。

两刀的机制：**UseDNS** 让 sshd 把你的 IP **反向解析**成域名记账，内网 DNS 没配反解区时干等到超时；**GSSAPIAuthentication** 先谈一遍 Kerberos/GSSAPI，内网没有 KDC 又是一段干等：

```bash
grep -E '^(UseDNS|GSSAPIAuthentication)' /etc/ssh/sshd_config
# GSSAPIAuthentication yes      ← 病根之一；两行都应显式为 no
# UseDNS no
# 若缺行或为 yes：改/加为 no，然后
systemctl reload sshd           # ← reload 即可，不断现有连接（→ Q7 三步）
ssh ops@10.0.0.21               # ← 秒出密码框，结案
```

深挖「先定位再动刀」：**到密码框之前慢** = 本节两刀 + 客户端连接复用；**认证之后慢**（密码输完又等半天）是另一类病——家目录模板、磁盘满（→ [08](../08-磁盘与IO/)）、motd 脚本。「每台都慢」还有一个通用加速：连接复用，第一条连上后 10 分钟内的 ssh/scp/rsync 全部复用，批量操作机标配：

```bash
ssh -o ControlMaster=auto -o ControlPath=~/.ssh/cm-%r@%h:%p -o ControlPersist=10m ops@bastion
```

> ⚠️ **别混**：慢的位置决定刀的方向——一律怪 DNS、或者更糟一律怪网络（本案的真实走向），都是没先定位；`ssh -v` 的输出会明确停在哪一步。

> 📝 **面试**：「SSH 慢怎么排查」——先分密码框前/后，框前两刀 UseDNS、GSSAPIAuthentication no；再补 ControlMaster 复用，满分。

### 再追问

- 怎么确认就是 DNS 段在等？——`ssh -v` 看卡在哪一行；或临时 `time ssh -o GSSAPIAuthentication=no -o UseDNS=no ...` 对比耗时。
- 改完后单台快了，批量改怎么落地？——配置管理统一分发这两行 + reload；顺手把 ControlMaster 写进跳板机的 ssh_config。

## Q12 接到 ssh 故障的第一分钟

**★★★★☆｜「值班第一分钟，ssh 连不上/登不进，你按什么顺序敲命令？」**

**覆盖**：必会 ｜ **对应**：知识点 [九、作战：60 秒定责](知识点.md)

### 场景

交接班第一晚，工单：「多台机器 ssh 异常」。你只知道这一句，问你第一分钟的动作。

### 完整解答

> 🎯 **一句话**：照**报错原文**分型——refused / timeout / 慢 / 指纹告警 / denied——每型第一刀固定，比凭感觉重试快一个数量级。

```text
① 0–10s   照原文定分型：
   refused → 敲门段    timeout → 网络段    卡 30s → 服务端配置段
   HOST KEY CHANGED → 认门段    Permission denied → 验身段
② 10–30s  refused → systemctl status sshd + ss -lntp（或带外）
           timeout → ping / traceroute（→ 02）、安全组与 iptables（→ 17）
③ 30–45s  denied → ssh -v 看卡在哪一步 + 对端 journalctl -u sshd 找拒绝理由
④ 45–60s  对症下刀，新开连接验证；指纹告警走带外核指纹——绝不 rm known_hosts 收工
```

分型速查（背到肌肉记忆）：

```text
Connection refused        → sshd 没起 / 端口不对 / 只听 127.0.0.1
Connection timed out      → 路不通 / 防火墙 DROP（02、17 段）
卡 30s 才出密码框          → UseDNS、GSSAPI 两刀
HOST IDENTIFICATION CHANGED → 带外核指纹 → 重装才 ssh-keygen -R
Permission denied (publickey) → authorized_keys 权限 / 钥匙没认
密码对也进不去             → AllowUsers / PAM / fail2ban 拉黑（→ 27）
```

「多台机器同时异常」本身就是线索：全量超时先想网络/安全组段，全量指纹告警先想重装或中间人事件，单台 denied 才往验身段查。

> 📝 **面试**：这题考肌肉记忆与优先级感；答出「按报错原文分型、每型第一刀固定、验证后再收工」，并点出多台 vs 单台的定位差异，就和背题的区分开了。

### 再追问

- 改 sshd_config 时怎么保证自己不成为下一个故障？——`sshd -t` → `reload` → 新开终端验证 → 再退旧会话（Q7）。
- 指纹告警最后确认是中间人呢？——停止连接、保留现场、按安全事件流程上报，处置与取证 → [27](../27-Linux安全加固/)。

## Q13

**★★★★☆｜sshd_config 里 Match 块是干什么的？客户端 ssh_config 分层怎么记？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [五、锁门：SSH 加固清单](知识点.md)

### 场景

内网要密码、跳板要密钥、运维网段要双因素——全写进一个 `sshd_config` 乱成一团。

### 完整解答

> 🎯 **一句话**：**Match 按 User/Group/Address 分段生效**；客户端 `~/.ssh/config` 用 Host 别名分层，别和服务器 Match 混。

```sshconfig
# 服务器端示例
Match Address 10.0.0.0/8
    PasswordAuthentication no
Match User breakglass
    PasswordAuthentication yes
```

| 文件 | 作用 |
|------|------|
| `/etc/ssh/sshd_config` | 服务端，Match 在后 |
| `/etc/ssh/ssh_config` | 客户端全局 |
| `~/.ssh/config` | 客户端 per-host |

改完 `sshd -t` → reload → 新会话验证（Q7）。

### 再追问

- AllowUsers 配错会怎样？——密码对也进不去（Q12 分型表）。
