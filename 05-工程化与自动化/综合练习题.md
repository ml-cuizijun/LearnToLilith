## Git（01）

## Q1：生产回退用 revert 还是 reset？

**★★★★★**

**场景**  
活动中 main 上那次热更把登录打挂了。有人准备 `reset --hard` 再 force push，「历史干净一点」。Argo 开着 selfHeal。

**完整解答**

已推送的公共历史 **只用 revert**，再走同一条流水线出制品。reset + force 改写 SHA，CI 缓存、GitOps 跟踪、同事 clone 全部错位。

```
  坏 commit 已在 origin/main
           |
           +-- git revert <bad> && push     ← 新反向 commit，历史完整
           |     流水线 / Argo 能跟上
           |
           +-- reset --hard + force         ← 生产禁止
                 Jenkins / Argo 已基于旧 SHA 会乱
```

GitOps 下集群期望在 Git 里。只 `kubectl rollout undo`、Git 仍是新 tag，selfHeal 会把坏版本再推回来。回滚 = revert 改 image 的那次 commit，再 sync（04-22）。

**再追问：hotfix 怎么带到还活着的 release 分支？**  
cherry-pick **同一颗修复**（squash 合过的，pick 合入后那个 SHA）。不要在 prod 机器 vim 完再补历史。

## Q2：为什么倾向 Trunk-based，而不是 GitFlow？

**★★★★**

**场景**  
「我们一直 GitFlow，develop 养三周再合 release。」活动窗口要热更登录，冲突堆在 merge 当天。

**完整解答**

Trunk-based：短分支、高频合主干，未完成功能用 **flag** 关掉。冲突少、回滚快。GitFlow 把风险堆到 merge 日，游戏热更 / 活动窗口扛不住。

```
  Trunk：  feature（小时级）→ 门禁 → main 随时可发
           未完成靠 flag，不靠长分支隔离

  GitFlow：develop 养三周 → release 日一次性合
           冲突 + 回归一起爆
```

Trunk 不是直推 main。三件同时成立：CI 快（目标 <10min）、回滚快（目标 <5min）、flag 能关功能。客户端整包可以单独留 release 线，**服务端主干不要被它拖死**。

**再追问：没有 feature flag 也能 Trunk 吗？**  
能，但未完成代码会进生产二进制，必须强门禁 / 滞后部署 / code owner。代价是「看起来在主干，实际不能开」。

## Q3：bisect 和 reflog 各救什么？

**★★★★**

**场景**  
热更后登录失败率升，中间几十个 MR。另一边有人本地 `reset --hard` 把还没 push 的修复弄丢了。

**完整解答**

| 工具 | 救什么 | 不救什么 |
|------|--------|----------|
| bisect | 哪颗 commit 引入 bug（log₂(n) 次） | 根因在数据 / 配置 / 下游时会指错 |
| reflog | 本仓库 HEAD 怎么移动的（约 90 天） | 远程备份；新 clone 没有你的 reflog |

```
  已知 v1.2.0 好、HEAD 坏
       git bisect start → good / bad / skip
       脚本测「能否登录」比猜 MR 快

  本地误 reset（未 push）
       git reflog → reset --hard HEAD@{n}
```

中间某次编不过：`git bisect skip`。测试必须可重复，不要依赖「当时那份玩家数据」。

**再追问：reflog 是远程的吗？force 了 main 还能靠它救？**  
reflog 是 **本地的**。已 force 的公共分支看别人是否 fetch 过、托管平台能否恢复，当事故复盘，不要当常规手段。

## CI/CD 与 Jenkins（02）

## Q4：Delivery 和 Deployment 差在哪？游戏生产用哪个？

**★★★★★**

**场景**  
「门禁都绿了，为什么 prod 还要人点？」有人把持续部署理解成「合 main 就上全服」。

**完整解答**

CI：合入后自动测 / 编，失败 **阻断** 合入。  
Delivery：随时有一份可发制品，生产要审批、窗口、观测门禁。  
Deployment：门禁过自动上 prod。

```
  CI 绿 ──► 制品进仓库 ──► 随时可发（Delivery）
                                |
                                +-- 人闸 / 窗口 / 金丝雀 --> prod
                                +-- 全自动（Deployment）游戏生产少见
```

游戏有状态、活动窗口、DB 变更，生产几乎都是 **Delivery**。无状态 + 强门禁 + 自动回滚 + 非冻结窗，才考虑 Deployment。

**再追问：什么可以全自动？**  
无状态接入层、已演练过自动回滚、金丝雀看业务 SLI、且不在开服 / 活动冻结窗。逻辑服和 schema 不要套这套。

## Q5：流水线阶段怎么切？失败了怎么办？哪步最容易被人情跳过？

**★★★★★**

**场景**  
扫描黄了，群里说「活动要开，先 skip 扫，下周补」。金丝雀只看了 `/health`。

**完整解答**

测 / 扫阻断合入与推送；staging 冒烟阻断晋升；金丝雀业务 SLI 失败 **自动回滚**。权限上不可 skip，不是靠「下次注意」。

```
  lint/单测 ──► build ──► 扫描 Critical=0
       |                      |
       阻断合入              阻断推送
                              v
                    staging 冒烟 100%
                              v
                    金丝雀：登录/支付 SLI → 全量
```

**Pipeline green ≠ 玩家能登录。** 健康检查过宽、金丝雀没看登录 / 支付、只发了网关没发逻辑服，流水线照样绿。

**再追问：哪步最容易被人情跳过？**  
扫描和金丝雀。High CVE 用阈值 + 截止日期，不是永久豁免；金丝雀必须对齐 canary Pod 的业务指标，不要只看集群均值。

## Q6：为什么禁止 prod 重新 build？

**★★★★★**

**场景**  
staging 测过 `app:v1.2.3`。发 prod 时 Jenkins 又 `docker build` 一次，「代码一样」。上线后行为对不上。

**完整解答**

构建不是纯函数：基础镜像、包索引、时间戳都会让同一份代码变成不同二进制。staging 的结论不能用于一份 **新 build** 的 prod。

```
  CI 构建一次 → harbor/.../app:<ver>-<sha>   digest sha256:abc
       |
       +-- 复制 staging（digest 不变）
       +-- 审批后复制 prod（digest 不变）
       +-- 集群按 @sha256:abc pull
  禁止每个环境再 docker build
```

配置差异用注入（ConfigMap / 环境变量），**不改镜像**。引用优先 digest；tag 给人读。`docker tag` 换仓再 push 同一 digest 才叫复制。

**再追问：配置怎么跟环境走？**  
注入配置，镜像锁死。密钥不进 Git、不进镜像（04-12）。核对：`crane digest` 必须等于集群里那串 sha256。

## Q7：Jenkins Master、弹性 Agent、凭证怎么配才不会挡生产？

**★★★★**

**场景**  
Master 自己跑 build，UI 卡死。Console 里能搜到 Harbor 密码。K8s Agent 跑完 Pod 留着不删，节点被 Completed 占满。

**完整解答**

1. Master **`numExecutors=0`**，只调度；跑 build 会把 UI 和队列一起拖死。
2. K8s Pod Agent 用完即毁；冷启动用预热镜像 + cache PVC，不要无脑加静态机。
3. 凭证走 `withCredentials`，禁止 `echo` 密码到 Console。进了日志 = 泄漏，先 rotate。

```
  Jenkins Master（调度 / 凭证 / UI）  numExecutors=0
           |
           v
  Agent Pod（jnlp + 构建容器）──跑完销毁
           |
           +-- 队列 Pending：先查 label / 磁盘 / 僵尸 Job，再加容量
           +-- podRetention: never，防 Pod 泄漏
```

**再追问：队列一直 Pending，先加机器吗？**  
先看 Nodes、label 是否匹配、`$JENKINS_HOME` 磁盘、僵尸 executor。加速先砍最慢 stage 和依赖缓存，不要先堆 Agent。

## Q8：回滚前必须问什么？混合版本窗口怎么办？

**★★★★★**

**场景**  
金丝雀业务红了，有人要立刻 `rollout undo`。这次 MR 改了表结构，也改了缓存 key。

**完整解答**

回滚前三问：**schema 能否倒、缓存格式变了没有、旧 digest 还在不在。** 代码回滚容易，schema 不行。禁止一个 MR 里改库又改不兼容代码。

```
  expand / contract
       1. 先加列，旧代码仍能跑
       2. 发新代码
       3. 再删旧列
```

制品至少留够一次回滚的 N 个 digest。GameDay 演练回滚，不要事故当天第一次点 undo。GitOps 回滚还要改 Git（04-22）。

**再追问：滚动期间两版本并存，协议不兼容怎么办？**  
协议必须双向兼容，或走维护窗写进变更单。金丝雀只切了网关、逻辑服还是旧 digest，Pipeline 照样绿——要对 **digest + 区服**。

## 制品（03）

## Q9：生产为什么禁用 latest？

**★★★★★**

**场景**  
Deployment 写 `repo/app:latest` + `imagePullPolicy: Always`。扩容后一半节点行为不对，回滚发现 latest 已经不是上一版。

**完整解答**

tag 默认可被重新 push 覆盖。Always + latest = 每次调度可能换内容，排障无法复现。IfNotPresent + 可变 tag = 节点缓存旧内容，看起来「发了没更新」。

```
  节点 A 昨天拉到 sha256:old
  节点 B 今天拉到 sha256:new     ← 同一 latest，内容不同
  回滚：latest 已经不是上一版了
```

生产用 `v1.2.3-<sha7>` + **digest**。开发环境可以用 latest；**任何会自动重启、会扩容的集群不行。**

**再追问：开了 immutable tag 还要 digest 吗？**  
要。引用层以 digest 为准；tag 给人读、给流水线对账。不可变 tag 打开后，「覆盖 latest 救火」必须停。

## Q10：镜像怎么瘦？Harbor 比「私有 Hub」多什么？

**★★★★**

**场景**  
开服 200 节点拉 2GB 逻辑服镜像超时。镜像里塞了 JDK、策划表、`.git`。仓库只当 Docker Hub 用，跨机房打中心仓。

**完整解答**

瘦：多阶段（builder 编、runtime 只拷二进制）+ 层顺序（依赖在前、源码 COPY 在后）+ `.dockerignore` 丢掉 `.git` / `node_modules`。热更包走 CDN，不要塞进业务镜像。

Harbor 要能说到：

| 能力 | 现场用处 |
|------|----------|
| 项目 RBAC | CI 只能 push 指定 project |
| Replication | 多机房同一 digest，就近拉 |
| Proxy Cache | 基础镜像走内网，防 Hub 限流 |
| 扫描 / GC | Critical 阻断；GC 前对照集群引用 |

复制是同一 digest，不是对面再 build。

**再追问：开服拉镜像超时先加带宽吗？**  
本机房复制 + 预拉 + 瘦身。开服清单含「本机房 Harbor 已有该 digest」。复制延迟大就不要切流量。分层细节在 07。

## Q11：节点 pull 失败，你怎么查？GC 会不会删正在跑的层？

**★★★★**

**场景**  
部分节点 ImagePullBackOff。有人刚在 Harbor 跑了 GC，「磁盘满了先清」。

**完整解答**

到节点用 **同一 digest** `crictl pull`，别只看 Deployment 事件。

```
  ImagePullBackOff
       |
       +-- 401 / 403     → imagePullSecret、项目权限
       +-- x509          → Harbor 证书 / 节点不信任
       +-- timeout / DNS → 还在打中心仓、跨机房、解析不到
       +-- 磁盘满        → overlay / imagefs（07）
```

GC 清无 tag blob。删之前对集群 `spec.containers[].image`。合服后旧 digest 先留过回档窗口。代理缓存别把生产正在用的基础层清掉。

**再追问：GC 会不会把正在跑的容器层删掉？**  
现代 Harbor 在线 GC 按引用走；风险是「仅 digest 引用、tag 已删」的正在跑的 Pod。先对照集群引用，再 GC。

## Ansible（04）

## Q12：幂等怎么保证？第二次跑为什么还有一堆 changed？

**★★★★**

**场景**  
playbook 每次 deploy 都 `state=restarted`，有状态逻辑服跟着抖。CI 里第二次跑 changed 仍然几十。

**完整解答**

模块用 `state=`（present / started），表达「处于某状态」，不是「再执行一遍」。`command` / `shell` 加 `creates`。第二次应 `changed=0`。每次 restart 会抖有状态服。

```
  yum/file/service state=  → 第二次 ok，changed=0
  command 无 creates       → 每次都跑
  template 含时间戳/随机   → 每次 changed
  handler: reloaded        → changed 才触发，一个 play 一次
```

Handler 用 **reload** 不断连接，不要每次 `restarted`。

**再追问：`--check` 绿，真跑却挂，能省金丝雀吗？**  
不能。部分模块 check 不准，custom module 可能空跑。check 绿不是生产通行证。

## Q13：批量变更怎么控风险？和 Terraform 怎么分工？

**★★★★★**

**场景**  
一条 playbook 打一千台登录服，配错了还在继续。另一边 TF 管安全组，Ansible 又改同一套 iptables。

**完整解答**

```
  --check --diff → --list-hosts
       v
  --limit 1～2 台   看登录成功率
       v
  serial 10%   max_fail_percentage: 0
       |
       +-- 失败 → 停；回滚只打已改主机
```

`--limit` 写空可能变成全量。高峰期减 forks，避开玩家连接抢 fd。

分工：

```
  Terraform Day 0：VPC / VM / 安全组 / 集群
  Ansible Day 1+：装软件 / 改配置 / reload
  K8s 应用 → Helm / Argo（04-22）
```

**不要两个工具写同一资源的同一属性**，否则 drift，两边都「正确」线上是乱的。

**再追问：`serial 10%` 仍全挂？**  
配置本身是错的，百分比救不了。先 limit 1 台看业务 SLI。

## Q14：Handler 为什么倾向 reload？密码进了 Git 怎么办？

**★★★★**

**场景**  
nginx.conf 变了，handler 写 `restarted`，战斗长连接全断。group_vars 里明文写了 prod 密码。

**完整解答**

Handler 仅 task **changed** 才 notify，一个 play 里同一 handler 只跑一次。`reloaded` 不断连接；有状态服配置变更更要 reload / 优雅重启，写进 role README，别让接手的人改成 `restarted`。

密码进 Git：**当泄漏 rotate**，历史用 filter / BFG 清，光删文件不够。Vault 加密，vault 密码不进 Git，CI 注入 `--vault-password-file`。prod 密码不要写进 role defaults。

**再追问：明文已经 push 了，删文件再 commit 够吗？**  
不够。历史里还在。先 rotate 线上密钥，再清历史，收紧仓库权限。

## Terraform（05）

## Q15：plan 必审看什么？apply 能不能直接跑？

**★★★★★**

**场景**  
CI 绿了，有人 `terraform apply -auto-approve`。plan 里有一行 RDS `- destroy`。

**完整解答**

盯 **destroy 和 replace**。apply **只用已审的 plan 文件**，禁止不带 plan 的 apply，禁止生产 `-auto-approve`。

```
  HCL vs state vs 云 API  →  terraform plan -out=plan.out
                                    |
                         人审：- destroy / -/+ replace
                                    |
                         terraform apply plan.out
```

plan 和 apply 之间又改 HCL，跑的就不是你审过的那份。`prevent_destroy` 加在数据库，不要加在可重建的 ASG 上挡合法缩容。

**再追问：plan 里 unexpected destroy？**  
**停，不要 apply。** 查 count / 资源地址 / provider 大升级。moved 或 pin 回版本，staging 先验证。

## Q16：state 丢了会怎样？锁卡住能不能直接 unlock？

**★★★★★**

**场景**  
本地 tfstate 弄丢了，下一轮 plan 要新建一整套 RDS。另一边 CI 被 kill，报 `Error acquiring state lock`。

**完整解答**

state 是地址 ↔ 云资源 ID。丢了：TF 以为资源不存在 → 再 create → 同名冲突或两套账单。生产必须 **远程 backend + 锁 + versioning**。prod / staging **分 key**，禁止共用一份 state。

```
  锁卡住
       |
       +-- 先确认没有别人 / CI 在 apply
       +-- 再 force-unlock
       +-- 乱 unlock = 双 apply 把资源改烂
```

能读 state ≈ 能看资源 ID 和部分明文，backend 权限当机密。

**再追问：prod 和 staging 共用一份 state 省事吗？**  
禁止。切错等于拿 staging tfvars 打 prod 资源。workspace 小项目可用；生产推荐目录分离。

## Q17：for_each 和 count 差在哪？和 Helm 边界？

**★★★★★**

**场景**  
合服用 `count` 删了「第 3 服」，后面所有 RDS 被 replace。另一边 TF kubernetes provider 和 helm upgrade 抢同一 Deployment。

**完整解答**

`for_each` 按 key 稳；`count` 删中间元素，后面索引全 rebuild——RDS 级事故。区服用 `server_id` 当 key，不要按「第几个服」。

```
  count  [0]=服1 [1]=服2 [2]=服3 [3]=服4
  删服2 → 后面移位 → TF 以为要 replace 一串库

  for_each key=s1..s4
  删 s2 → 只 destroy 那一个
```

TF 管集群外（VPC / 节点组 / RDS）；Helm / Argo 管集群内工作负载。同一 Deployment 不要两边管，plan 每次都脏。

**再追问：已经用了 count，怎么迁？**  
`moved` block 迁到 for_each，staging 先演。重构地址不要靠 destroy + create。

## Q18：drift 怎么治？`state rm` 会删云资源吗？

**★★★★**

**场景**  
有人在控制台把机型改成 large。定时 plan 全红。有人准备 `terraform state rm`「先摘掉再 destroy」。

**完整解答**

禁控制台改 TF 管的资源。定时 `plan -detailed-exitcode`（2=有变更）告警。处理：要么 apply 拉回声明，要么改 HCL 承认变更。紧急控制台改了，事后必须 import / 改 HCL。

| 命令 | 改云吗 |
|------|--------|
| `refresh` | 否，只更新 state 记忆 |
| `state rm` | **否**，只是不再管 |
| `destroy` | **是**，真删 |

**再追问：`state rm` 之后那台 RDS 还在吗？**  
在。只是 TF 不管了；下次别人用同名再 create 会冲突。真要下线才 `destroy`，且 plan 里只能看到那一个。

本模块 06 是运维平台，07 Docker，08 GHA。下面四题属于开发能力模块。

## Q19：`set -euo pipefail` 缺一个会怎样？

**★★★★★**

**场景**  
脚本没加 `-u`，空变量拼进 `rm -rf "$PREFIX/$DIR"`。另一条 `grep 5xx | wc -l`，文件不存在仍 exit 0，CI 当成功。

**完整解答**

| 缺谁 | 现场 |
|------|------|
| `-e` | 命令失败继续跑，后面当成功 |
| `-u` | 未定义变量当空；`rm -rf /` 一类拼接事故 |
| `pipefail` | 只看管道最后一条；`false \| true` 仍成功 |

变量加双引号。`pipefail` 是 `-e` 的另一半。允许失败用 `if cmd` 或写清的 `|| true`，后者会吞失败。

**再追问：后台 `wait` 有什么坑？**  
不收 pid 退出码会把失败当成功。并发必须汇总失败，有一个非 0 则脚本非 0（06-开发能力/01）。

## Q20：现场 one-liner 能当变更吗？

**★★★★**

**场景**  
跳板机上一条 awk 改了 200 台 nginx 配置。「改完了，明天补脚本。」列号和 `log_format` 对不上，改错了字段。

**完整解答**

one-liner **只能排障**。变更进 Git，可复现、可 review、可回滚。列号先对 `log_format`，再切字段。复杂 JSON 换 Python / `jq`，不要在 shell 里硬拆。

```
  排障：one-liner 看现场
  变更：Git → 门禁 → Ansible / 流水线
  默认 dry-run，先打印将改谁
```

**再追问：复杂 JSON 还用 awk 吗？**  
换 Python。Shell 负责编排和失败码；结构化解析用对的工具（06-开发能力/02、05）。

## Q21：Python 运维脚本底线是什么？和 Ansible 怎么选？

**★★★★**

**场景**  
Cron 调了一个巡检脚本，异常被 `except: pass` 吞掉，exit 0。HTTP 没 timeout，下游挂了脚本卡死。POST 失败自动重试，订单建了两次。

**完整解答**

底线：`--dry-run`、logging、HTTP **timeout**、失败 `sys.exit(1)`、并发汇总失败。POST / 创建类不要盲目重试（至少幂等键或只重试 GET）。禁止裸 `except pass`。Cron 只看退出码。

```
  OS 配置 / 包 / 服务状态  → Ansible（幂等模块）
  平台 API / JSON / 跨系统编排 → Python
```

**再追问：和 Ansible 重叠时怎么选？**  
装软件、改文件、reload 用 Ansible。调云 API、聚合多源、写门禁用 Python。不要 Python ssh 循环代替 Ansible，也不要 Ansible 里堆一大段不可测的 shell。

## Q22：简历没写 Go，被问 exporter / 泄漏怎么答？

**★★★★**

**场景**  
自研 exporter RSS 只增不减。有人把 `user_id` 当 Prometheus label。让你讲 goroutine 语法。

**完整解答**

简历没写 Go：**不展开语法**。会读四类指标和高基数；泄漏用 pprof 看 goroutine 是否只增不减。

```
  Counter / Gauge / Histogram / Summary
       |
       +-- label 带 user_id → 基数爆炸，监控先挂
       +-- RSS 涨且 goroutine 单调升 → pprof goroutine
```

方向：加 timeout / 限制 worker / 改 label。补丁交给开发。pprof 不要公网裸奔。

**再追问：`user_id` 当 label 为什么是事故？**  
每个用户一条时间线，基数随 CCU 爆炸，Prometheus 先挂，告警和自愈全部失明。聚合用低基数维度（区服 / 接口 / 错误码）。

## Q23：GitOps 回滚怎么做？和 `rollout undo` / Helm rollback 的关系？

**★★★★★**

**场景**  
发坏了。有人在集群里 `kubectl rollout undo`，Argo selfHeal 开着。另一边 Jenkins 还在 `helm upgrade`。

**完整解答**

正规回滚：**git revert + sync**。undo 只是临时止血。开着 selfHeal 只改集群，Git 仍是新 tag，会被再推回来。

```
  CI 出镜像、改 Git tag     ← CI 到此为止
  Argo 拉 Git、apply        ← CD，凭证不出集群

  回滚：git revert → Argo sync
  紧急：UI Rollback 止血 + 立刻改 Git（必要时先关 selfHeal）
```

CI 不要和 Argo **同时** apply。Jenkins helm 和 Argo 双管 = 所有权冲突。Argo 管 Helm 时集群里往往没有 Helm Secret，`helm rollback` 对不上（04-21）。

**再追问：Helm rollback 和 Argo 同时做会怎样？**  
两套历史、两套期望。以 Git 为准的那条才是真相；另一条必须停。CD 只留一条路径。

## Q24：prod 的 prune / selfHeal 怎么开？误删 git 目录呢？

**★★★★★**

**场景**  
有人把 staging 的 `automated.prune: true` 原样拷到 prod。配置仓误删了 `game-gateway/overlays/prod`。

**完整解答**

staging 可 auto-sync + prune + selfHeal。prod **慎 auto prune**（误删目录 = 删生产）；selfHeal 可开，但 HPA 副本要 `ignoreDifferences`。关键资源 `sync-options: Delete=false` 是安全带。

```
  Git 删了 path
       |
       +-- prune=true  → 集群对象被删
       +-- Delete=false → 留着，争取时间 revert
```

生产常手动 Sync 或 sync window，避开活动高峰。

**再追问：误删 git 目录第一反应是什么？**  
立刻 revert Git；不要先在集群里手建「补回去」又和 Argo 打架。Delete=false 只是缓冲，不是长期双真相。

## Q25：Helm 生产常用哪几个 flag？改了 ConfigMap 为什么 Pod 不滚？

**★★★★**

**场景**  
CI 写了 `helm upgrade`，Chart 不存在时失败。upgrade 超时留下半残。改了 `values` 里的配置，Pod 还用旧文件。

**完整解答**

生产四件套：`helm upgrade --install --atomic --wait`（加合理 `--timeout`）。没有就装、有就升；timeout 内没 Ready 自动回上一 revision，不留半残。

```
  upgrade --install --atomic --wait
       |
       +-- 失败 / 超时 → 回到上一成功 revision
       +-- Hook 跑向后兼容的 migration（expand/contract）
```

ConfigMap 变了，Deployment spec 没变，kubelet 不滚 Pod。给 Deployment 加 **checksum 注解**（对 CM 内容做 hash），引用变了才会滚动。Kustomize 用 generator 改名达到同类效果（04-21）。

**再追问：Hook 里的 migration 能直接 DROP 列吗？**  
不能。滚动期间新旧代码并存，migration 必须向后兼容。`--atomic` + hook 失败 = 不要把半成品留线上。

## Q26：OutOfSync 但没人改 git，怎么查？Synced 了玩家却进不去？

**★★★★**

**场景**  
Argo 一直 OutOfSync。Git 最近没有 commit。另一边 Synced + Healthy，登录成功率却掉了。

**完整解答**

`argocd app diff`（或 UI Diff），常见不是有人改 Git：

1. HPA 改了 `replicas` → ignore `/spec/replicas`
2. Admission / sidecar 注入字段 → ignore 或把期望写进 Git
3. Helm `randAlpha` 每次渲染不同 → 禁止

```
  OutOfSync
       |
       +-- 真漂移（手改集群）→ selfHeal 或补 Git
       +-- 合理漂移（HPA）  → ignoreDifferences
       +-- 随机函数         → 改 Chart
```

**再追问：Synced 但玩家进不去，GitOps 坏了吗？**  
GitOps 只保证集群趋近 Git，**不替代业务监控**。对照 digest、探针、登录 / 支付 SLI。Pipeline / Argo 绿 ≠ 玩家能登录（回到 Q5）。

## Q27：故障进来先干什么？P0 怎么定？值班当周能不能做项目？

**★★★★★**

**场景**  
开服日告警风暴。有人先开 5-Why。P0 口径靠感觉。主值班想顺手把需求做了。

**完整解答**

**先止血再根因。** 认领 → 定级 → 广播范围（哪些区服、支付是否受影响）→ 回滚 / 摘流量 / 关 flag → 指标回 baseline 再挖。有状态服禁止当无状态乱重启。

```
  告警 → 认领（P0：15min）→ 无人则升级 backup
       → 止血（回滚 / 降级 / 扩容）
       → 观察 → 无责复盘
```

P0 按 **登录 / 战斗 / 支付不可用，或 CCU 腰斩** 定，用 SLO / 用户数，不靠感觉。oncall 当周目标是 **MTTR**，不做项目。

**再追问：oncall 当周做项目可以吗？**  
不做。被叫醒但不是故障 = 告警质量问题，调阈值和抑制，不要再加通道硬叫。

## Q28：变更三问是什么？审批越多越安全吗？

**★★★★★**

**场景**  
变更单只写了「发 1.2.3」。周五晚上活动日还能点发布。普通改配置要过五级审批，有人改走 SSH。

**完整解答**

三问：**改什么、影响什么、怎么回滚**——缺一不能上。标准变更（已门禁的日常发布、弹性扩容）必须自动；普通配置负责人批；紧急双人执行、事后补单。窗口硬拦截，开服 / 活动冻结写进系统，不靠群里吼。

```
  标准 → 自动
  普通 → 负责人
  紧急 → 双人 + 事后补单（先止血）
```

**再追问：审批越多越安全？**  
否。审批过长会逼人走旁路，旁路无审计。安全靠标准变更自动化 + 窗口硬拦截 + 回滚演练，不是加签。

## Q29：复盘怎么写才算数？CMDB 错了比没有更危险吗？

**★★★★**

**场景**  
复盘纪要写成「值班同学没看好」。CMDB Owner 还是离职账号，告警打进黑洞。表很大，IP 是错的。

**完整解答**

复盘 **blameless**：问系统为什么允许这次错误（门禁为什么没拦住、为什么没有自动回滚），不是谁的锅。改进项可验收、有 owner、有日期；没有截止日期 = 没写。「nginx 挂了」不是根因。

CMDB 要拓扑 + Owner，质量大于数量。自动化按错误 IP 操作会放大事故。数据以集群 / 云 API 为准，人填 Owner 为辅。Owner 离职必须轮转，否则告警路由失败。

```
  应用 → 服务 → 实例 → 依赖 → Owner / oncall
  错数据 → 扩容打错集群、告警找不到人
```

**再追问：Owner 离职了会怎样？**  
告警路由失败，开服日打到空账号。轮转是流程，不是「有空再改表」。

## Q30：自动化 / 自愈的边界在哪？

**★★★★★**

**场景**  
L3 自愈把有状态逻辑服重启了，对局全踢。合服脚本接到告警自动跑。支付回调失败被自动重试出双单。

**完整解答**

可逆、高频、blast radius 可控的才自愈：重启无状态、扩容、清磁盘、切只读。 **合服 / 删库 / 支付 / schema / 有状态逻辑服必须人确认。** 要超时、可取消、幂等、审计、一次只动一台 / 一个 ns。自愈失败要告警，不能静默。自愈和人工同时重启会脑裂，要互斥锁。

```
  L0 文档 → L1 人点脚本 → L2 平台按钮 → L3 告警自愈
  白名单：无状态
  黑名单：合服、删数据、改支付、生产 schema、逻辑服
```

没有 Owner 的自愈是随机伤害。平台先打通 Owner + 告警路由 + 变更审计，再做花哨自愈。

**再追问：自愈能不能重启有状态服？**  
不能当默认。越权。白名单无状态；逻辑服停匹配 / 等空再动，那是人闸变更，不是 L3。
