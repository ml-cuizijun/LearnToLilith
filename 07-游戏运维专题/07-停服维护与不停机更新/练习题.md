## Q1

**★★★★★｜把维护变更的一生按阶段讲一遍。**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [一、一张图：维护变更的一生](知识点.md)

### 场景

有人把「热更配置」「合服」「回档」都叫「维护一下」，窗口和门禁混用。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：计划→摘流→执行(停服/不停机/经济)→验证→恢复；类型写进变更单。

计划阶段定窗口、公告、回滚双签；摘流做目录维护 + 踢线 + 写 QPS=0；执行分三条路：全服维护（玩家不可进）、不停机（无状态滚动 + 配置 reload）、经济变更（停产出 + 可能回档）；验证靠冒烟 + SLI；恢复时最后一步开目录。

> 📝 **面试**：维护是壳，里面是热更/合服/回档不同手术。类型不同，门禁和恢复标准不同。

### 再追问

经济配错算哪种？——经济变更，先停产出，未必全服维护。发版回滚和数据回档是两条路。

## Q2

动刀前的麻醉——摘流三步。

**★★★★★｜动库前三步是什么？跨服为何要冻？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、摘流：踢线与写 QPS=0](知识点.md)

### 场景

「维护了」但写 QPS 还有 30。有人已开始 mysqldump。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：目录维护→踢线→写 QPS=0 持续 2min+；跨服回写未冻会脏合服/回档。

五步顺序：目录标维护 → 广播踢线 → 确认 Gate CCU=0 → 确认 MySQL 写 QPS=0 持续 2min+ → 冻跨服入口。门禁没过禁止备份、禁止迁库、禁止回档。写 QPS 还有 30 → 查漏网长连接、GM 工具写路径、定时任务 cron。

> 🔍 **现场**：

```bash
curl -s 'http://prom:9090/api/v1/query?query=sum(rate(mysql_writes{server_id="s1001"}[1m]))' | jq '.data.result[0].value[1]'
```

```text
0
# ← 写 QPS = 0 才能动库
```

> ⚠️ **别混**：跨服回写不冻 → 合服/回档都会脏。冻的是跨服写回本服的路径，不是本服写自己的路径。

### 再追问

P0 回档能 skip 门禁吗？——不能，恐慌中 skip = 二次事故。写 QPS>0 时回档，备份和窗口期写入混在一起，恢复后数据不一致。

## Q3

这是主图执行类型的分流。

**★★★★★｜停服维护和不停机更新各适用什么？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [四、停服维护：全服不可进](知识点.md)

### 场景

改活动图要全服维护；Schema 加 nullable 列也想全服踢人。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：停服用 Schema 不可逆/合服/整服回档；不停机=无状态滚+配置 reload。

停服适用：DB Schema 不可逆变更（改列类型/删列）、战斗二进制换 digest 无法摘流、合服（06）、整服回档（09）。停服不适用：配置 reload（05 配置类）、无状态滚动、经济配错但产出已停。

改活动图是配置/资源（05），不是停服。加 nullable 列可在线，顺序是先 deploy 新代码 → DDL → 写逻辑 → backfill → NOT NULL。

> ⚠️ **别混**：停服维护（计划全服不可进）≠ 摘服止血（P0 应急，只关入口停产出，可能很快恢复）。

### 再追问

配置 reload 要维护窗吗？——通常不必全服，但要回执 `loaded_version` 齐，不齐不能开活动。

## Q4

就是「战斗能不能滚动」——Q3 的有状态版。

**★★★★☆｜战斗服能不停机 RollingUpdate 吗？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [五、不停机更新：滚动与摘流](知识点.md)

### 场景

战斗和登录同一 RollingUpdate 策略。公会战 CCU 掉一截。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：战斗必须摘流四步，禁 RollingUpdate；登录可滚。

不停机只适用于无状态或可重建层。登录/目录可 RollingUpdate 或蓝绿；大厅可滚（Session 重建到 Redis）；Gate 谨慎滚（长连接会断，要重连快通道）；战斗必须摘流等空换 digest，禁 RollingUpdate。进行中的局钉旧进程，不能切流。

> ⚠️ **别混**：「不停机」不是「零感知」——Gate 滚会断长连接，要靠客户端重连走快通道，不进登录百万队（02）。

> 📝 **面试**：不停机不是战斗 RollingUpdate。Gate 滚完要看重连 SLI 和 `reconnect_success_rate`，不只看 Deployment Ready。

### 再追问

大厅呢？——可滚，Session 可重建 Redis。但探针要测业务不是 `/health` 200。

## Q5

开头那个掉落 ×100 现场。

**★★★★★｜掉落配错顺序？能热更 ×0.01 吗？**

**覆盖**：必会 · 常用 · 常考 ｜ **对应**：知识点 [六、经济变更：停产出与回档](知识点.md)

### 场景

掉落 ×100 十分钟。有人热更 ×0.01，有人要立刻全服维护。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：回配置停产出→评估回档；禁止 ×0.01；产出停不必全服维护除非整服回档。

第一刀永远是**停产出**——回配置 version 或关活动开关，不是再发一个 ×0.01 热更（时间窗更乱，回档圈人更难）。产出还在刷 → 摘服或关活动入口止血，不必等维护窗口。评估影响面后选路径：可圈人 → 定向补偿/扣回；不可圈 → 整服回档（09）；轻微 → 公告+补偿。

> 💡 **类比**：经济配错像印钞机多印了一个零——先关机器（停产出），再数假钞（评估回档），不是再印一批「负钞」假装抵消。

> ⚠️ **别混**：发版回滚（换配置 version，分钟级）≠ 数据回档（改玩家背包，走 09 流程，可能要停服）。两者混说「回滚」处置路径完全不同。

> 📝 **面试**：经济错了先停产出，再评估回档。不能热更 ×0.01。发版回滚和数据回档分开。

### 再追问

何时全服维护？——需要整服回档时（不可圈人），不是每个经济错都全服。监控应有产出数量级告警。

## Q6

手术后怎么苏醒——开目录与验证。

**★★★★☆｜维护结束开放前要验什么？目录何时开？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [七、恢复：开服与验证](知识点.md)

### 场景

Pod 全绿，运营要开目录。创角步骤其实还失败。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：冒烟+SLI+回执齐，最后开目录；观察 30～120min。

恢复顺序：后端 Ready + 冒烟脚本通过 → 配置 `loaded_version` 齐 → 关键 SLI 5min 窗口正常（登录、进战斗、支付）→ 目录取消维护（最后一步）→ 观察 30～120min。

> 🔍 **现场**：

```bash
curl -s 'http://prom:9090/api/v1/query?query=sum(rate(login_success_total[5m]))/sum(rate(login_attempt_total[5m]))'
```

```text
0.998
# ← 登录 SLI 恢复，再开目录
```

> 📝 **面试**：Pod 绿 ≠ 维护完成。分服维护时只看该服 SLI，全服 SLI 可能仍绿是假象。

### 再追问

含 CDN/强更的维护？——还要查下载成功率（08）。紧急维护恢复也要走最小冒烟。

## Q7

不是全服时怎么摘——分服维护。

**★★★☆☆｜分服维护和全服维护区别？**

**覆盖**：常用 ｜ **对应**：知识点 [八、分服维护与部分摘流](知识点.md)

### 场景

只改 S1003 Schema，却把全服目录标维护。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：只摘目标 server_id 目录+该服写 QPS=0；全服 SLI 可能仍绿。

部分摘流五步：目录只下架 `server_id=S1003` → 踢该服在线 → 确认该服写 QPS=0（其他服仍可写）→ 变更后单独冒烟 → 只恢复 S1003 目录。误将全服目录标维护 → 不该停的服也进不去。跨服玩法要冻该服进出（01）。

> ⚠️ **别混**：分服维护看**分服 SLI**，全服 SLI 可能仍绿——不能只看大盘。

### 再追问

恢复？——只开 S1003 目录，单独冒烟，不要误开全服。

## Q8

和计划节呼应——计划内 vs P0。

**★★★☆☆｜计划内维护和 P0 有何不同？**

**覆盖**：常考 ｜ **对应**：知识点 [二、计划：窗口、公告与变更单](知识点.md)

### 场景

合服维护中 SLI 破了，有人说「计划内的不用升 P0」。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：公告/预算账不同；SLI 破了仍按 P0 指挥；恢复标准相同。

计划内停服维护消耗**另本账**（13），不占故障错误预算。但维护失败若 SLI 破，仍按 P0 响应——「计划内」只是说明这次变更有变更单，不代表失败后可以降级响应。对外公告口径有窗口有 ETA，P0 先发「正在处理」ETA 写「进一步通知」。

> ⚠️ **别混**：计划内停服（有公告、有窗口、另本预算）≠ 故障 P0（未计划、SLI 破）。但恢复标准一样：冒烟 + SLI。

### 再追问

对外补偿？——对照 SLA，运营填，工程师不拍券。对内说 SLO，对外说 SLA，不混一句 99.9%。

## Q9

这是 Q8 的叠窗版——活动别硬叠。

**★★★★☆｜活动整点能顺便热更战斗吗？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [九、与版本发布、合服的边界](知识点.md)

### 场景

活动 20:00 开启，19:50 要热更战斗系数。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：活动整点禁无关变更；战斗热更+活动=叠窗事故。

活动整点（03）变更纪律：**可**做扩登录、开排队、扳降级开关；**禁**做无关战斗热更、合服、强更抬 min、CDN 首切。变更单里要写互斥项。战斗热更叠维护窗 = 事故套餐——两件事同时出错，定责和回滚都混乱。

### 再追问

只 reload 配置？——仍要回执齐，非必要仍拒。版本日任何时刻只一人下指令。

## Q10

不停机线的 Gate 版。

**★★★☆☆｜Gate 滚动要注意什么？**

**覆盖**：常用 ｜ **对应**：知识点 [五、不停机更新：滚动与摘流](知识点.md)

### 场景

Gate RollingUpdate 后重连进登录队 80 万。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：长连接会断；看重连 SLI；重连走快通道不进队。

Gate 滚动注意：`maxUnavailable` 对长连接 = 强制断线；滚动前通知客户端「即将维护」或静默重连；观察 `reconnect_success_rate` 5min 窗口；重连必须走**快通道**不进登录百万队（02）。

> ⚠️ **别混**：Gate 可滚但谨慎滚——不是不能滚，是滚完必须看重连 SLI，不能只看 Deployment Ready。

### 再追问

维护态能滚 Gate 吗？——可以但要看重连和 SLI，低峰更好。Gate 滚和战斗摘流是两回事，不要混在一起做。

## Q11

紧急维护怎么压缩检查表。

**★★★☆☆｜紧急维护最小流程？**

**覆盖**：常用 ｜ **对应**：知识点 [十、维护公告与玩家沟通](知识点.md)

### 场景

P0 安全漏洞，要立刻动库，指挥混乱四人同时改。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：唯一指挥→评估范围→摘流/维护→止血一项→SLI→开放→补公告复盘。

紧急维护（P0）最小流程五步：唯一指挥官 + 影响评估（全服 / 分服）→ 目录维护或摘服（能不全服不全服）→ 止血一项（回配置 / 指针打回 / pause rollout）→ 验证 SLI 恢复 → 开放 + 补公告 + 复盘动作项。

公告先发「正在处理」，ETA 不确定写「进一步通知」——不要承诺给运营没对齐的时间。P0 回档仍要写 QPS=0——恐慌中 skip 门禁是二次事故。

> 📝 **面试**：紧急维护能不全服不全服。止血只做一项，不要四线同时动。

### 再追问

公告 ETA 不确定？——写「进一步通知」，不瞎承诺。事后补正式公告和复盘。

## Q12

Schema 在线变更的边界。

**★★★☆☆｜在线加 nullable 列顺序？**

**覆盖**：常考 ｜ **对应**：知识点 [四、停服维护：全服不可进](知识点.md)

### 场景

先 DDL 加列，旧代码还不认识新列，全服 panic。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：先 deploy 能读新列代码→DDL→写逻辑→backfill→NOT NULL。

在线加列顺序：先 deploy 能读新列的新代码（nullable）→ 再 DDL 加列 → 再 deploy 写新列逻辑 → 再 backfill 回填历史数据 → 最后改 NOT NULL。反序会导致旧代码读新 Schema 崩溃。改列类型/删列通常要停服。

复制延迟大时 DDL 会拖长锁——维护窗或 pt-osc 类工具，不是高峰期直接 `ALTER`。

> ⚠️ **别混**：加 nullable 列可在线，但加 NOT NULL 列要停写或默认值 + 回填。改列类型/删列 = 停服维护。

### 再追问

高峰期直接 ALTER？——避免，或 pt-osc + 维护窗。索引可在线但要盯锁和复制延迟。

## Q14

把前面维护分流收成定责剧本。

**★★★★☆｜接到「维护后创角失败」怎么定责？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [十二、作战：维护变更定责](知识点.md)

### 场景

维护刚结束，创角 500。有人要再全服维护，有人要 roll 登录。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：先问计划内阶段：冒烟过了吗？静态表/import 了吗？回执齐吗？

定责三条入口问题：计划内还是 P0？→ 定响应级别；经济配错？→ 停产出第一刀；写 QPS=0？→ 定能否动库。三条并行判断不串行等。

60 秒剧本：0–10s 问计划/P0 和变更单阶段 → 10–30s 经济则停产出、动库则查 CCU+写QPS → 30–45s 选停服/滚动/reload → 45–60s 恢复前冒烟+SLI，最后开目录。

> 📝 **面试**：维护恢复 checklist 最后开目录。Pod 绿但创角失败 → 跑冒烟，不要开目录。维护超时 → 按变更单回滚，不现场加时。

### 再追问

能 skip 冒烟「玩家等着」？——人为事故，拒。超时未验证通过 → 回滚改期，不现场加时。
