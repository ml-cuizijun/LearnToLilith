版本日，玩家卡在「更新中」，源站带宽打满。群里有人要全网 purge，另有人把包挂到逻辑服 Nginx「顶一下」。登录监控全绿，下载成功率掉到 60%——**下载和登录是两条路，先传、再预热、最后切指针。**

**本章主线（发布就按这三步想）：**

1. **分离**：下载走 CDN，登录/API 走高防；逻辑服不当下载源。
2. **版本**：指针短 TTL，文件 URL 带 content hash 长 TTL；四元组（指针、文件、hash、min）同一时刻自洽。
3. **止血**：回源打爆 → 回上一份已预热指针；不要全网 purge；CDN 炸不叠抬 min。

**读完你能：** 画指针短文件长、源站不露脸；预热验收 HIT+hash；切备 CDN 两边都预热。

## 1. 基本概念

客户端启动先拉**小指针**（`version.json`），对比本地 hash 只拉差集。差集第一次全球出现 = 版本切换危险窗口。

**值班里什么时候碰到：**

| 玩家说的 | 技术含义 | 你的第一刀 |
|----------|----------|------------|
| 「卡在更新中」 | CDN miss / 回源 | 查 HIT 和源站带宽 |
| 「登录能进、更新进不去」 | **CDN 事故** | 不要扩逻辑服 |
| 「部分地区闪退」 | 同名覆盖/边缘分裂 | 查 hash 和缓存键 |
| 「更新完进不去服」 | min/协议（03） | 不要叠抬 min 修 CDN |

| 角色 | 干什么 |
|------|--------|
| **指针** | 告诉客户端「现在该哪一版」；必须快失效 |
| **文件** | 带 content hash 的不可变对象；边缘长持有 |
| **源站** | 只给 CDN 回源；玩家永远不直连 |

> **记住：** 下载和登录是两条路。人卡在更新页，加逻辑服没用。登录绿、下载红 = **CDN 事故**。

**面试怎么说**：「人卡在更新页我先查 CDN HIT 和回源，不扩逻辑服。指针短 TTL、文件带 hash 长 TTL，先传再预热最后切指针。」

## 3. 原理

### 3.1 指针短、文件长

**一句话：** 指针快失效让边缘吐新清单；文件带 hash 长 TTL 几乎不用 purge。

**打个比方**：指针像餐厅今日菜单（天天换）；文件像 sealed 罐头——**换内容就换 SKU（新 hash URL），不用把旧罐头从货架上一个个抠下来**。

**现场走一遍**（指针 max-age=3600，切了边缘还吐旧清单）：

1. 后台 10:00 切指针到 version=2.5。
2. 10:05 抽检：`curl -sI version.json | grep Age` → `Age: 2847`。
3. 部分边缘仍吐 2.4 manifest → 客户端差集混乱、闪退。
4. 正确：指针 `max-age=30`；文件 `max-age=31536000, immutable`。
5. 灰度指针用**独立文件名**，勿和全量共用长 TTL URL。

| 对象 | TTL | 为什么 |
|------|-----|--------|
| 指针 | 短（如 30s） | 切了边缘须快吐新清单 |
| 文件 `foo.<hash>.bundle` | 长+`immutable` | 内容变=新 URL |
| 灰度指针 | **独立文件名** | 勿和全量共用长 TTL URL |

**面试怎么说**：「文件和指针不能一样长 TTL。同名覆盖再 purge 是错的，用 content hash。」

### 3.2 回源放大

**一句话：** 四条件同时满足就炸；客户端失败猛重试是第二放大器。

**打个比方**：回源像同时打开全市水龙头——**水库（源站）扛不住，不是多装几个水表（扩逻辑服）能解决的**。

**现场走一遍**（先切指针再传包，源站打满）：

1. T0 指针切到 2.5，全球边缘同时 miss 新 manifest。
2. 大包上传进度 40%，源站带宽 10Gbps 打满。
3. 下载成功率 99% → 60%；登录仍绿。
4. 四条件：① 对象大/多 ② 边缘无缓存 ③ 同时启动多 ④ 源站扛不住——**四者齐=炸**。
5. 止血：指针打回上一份已预热 → 源站限并发/扩 → 预热完再切 → **最后**才定向刷新。

加重回源的错误操作：全网 purge；文件 `no-cache`；先切指针后传文件；同名覆盖不带 hash。

**面试怎么说**：「回源打爆先回指针，不全网 purge。CDN 炸不要叠抬 min——客诉不可分。」

### 3.3 缓存键

**一句话：** 路径带 hash 最好；预热 URL 必须和客户端完全一致。

**打个比方**：缓存键像快递单号——**差一个字母就当成另一件货，预热了 A 客户端拉 B = 白预热**。

**现场走一遍**（预热工单绿，现场仍 miss）：

1. 预热 URL：`https://res.example.com/foo.bundle?v=2.5`
2. 客户端真实 URL：`https://res.example.com/foo.abc123.bundle`（路径带 hash，无 query）
3. 工单显示 100% 完成，玩家仍 miss。
4. 部分 CDN 忽略 query → `?v=2` 和裸路径是不同键。
5. 验收：多地 HIT + hash 对 + **切指针前**源站回源带宽已下降。

| 做法 | 结果 |
|------|------|
| 路径带 hash | 新内容新 URL，几乎不用 purge |
| 同名覆盖 | 部分地区新、部分地区旧 |
| query `?v=2` | 部分 CDN 忽略 query |

**面试怎么说**：「预热工单绿不等于可切指针。要对客户端真实 URL 抽检 HIT+hash。」

### 3.4 差分与整包

**一句话：** 差分失败率高就按整包峰值备容量；关整包入口 = 差分失败的人永远进不了服。

**打个比方**：差分像只寄补丁——**补丁失败得能 fallback 全本，否则读者永远缺页**。

**现场走一遍**（差分失败 30%，关整包省带宽）：

1. 差分 manifest 指向 patch；30% 客户端 patch 校验失败。
2. 运营关整包入口「省带宽」。
3. 失败玩家永远卡在更新页——**不是客户端 bug，是 fallback 被关了**。
4. 容量：差分失败 30% 按整包峰值准备。
5. 约定指数退避；404 停重试。

**面试怎么说**：「差分失败关整包入口是错的。失败回滚先回指针，不删源站新文件。」

## 4. 落地

| 项 | 选 | 不选 |
|----|----|------|
| 下载入口 | 独立域名+CDN | 逻辑服公网 IP |
| 对象命名 | 路径带 content hash | 同名覆盖 |
| 预热 | 大版本提前数小时 | 开服前 10 分钟才点 |
| 多 CDN | 主备同一批 hash 都预热 | 只改 CNAME |
| 海外 | 每 region 独立指针预热（10） | 国内预热完全球切 |

验收：多地 HIT + hash 对 + **切指针前**源站回源带宽已下降。

## 5. 核心配置

```
文件：Cache-Control: public, max-age=31536000, immutable
指针：Cache-Control: public, max-age=30

错：文件 no-cache          → 每次回源
错：指针 max-age=3600      → 你以为切了边缘还吐旧清单
错：URL 带随机 query       → 缓存键分裂
```

| 参数 | 改错会怎样 |
|------|------------|
| 源站鉴权过严 | miss 时 403，客户端当损坏重下 |
| Range 无限制 | 分片把回源连接翻倍 |

## 6. 命令与操作

```bash
URL="https://res.example.com/foo.abc123.bundle"
curl -sI "$URL" | grep -iE 'HTTP/|X-Cache|Age|Cache-Control'
curl -s "$URL" | sha256sum
curl -sI "https://res.example.com/version.json" | grep -iE 'X-Cache|Cache-Control'
```

典型输出（已 HIT）：

```text
HTTP/2 200
X-Cache: HIT
Age: 842
Cache-Control: public, max-age=31536000, immutable
```

**输出解读**：

| 字段 | 正常 | 异常 |
|------|------|------|
| `X-Cache: HIT` | 边缘有缓存 | `MISS` → 会回源 |
| `Age: 842` | 已在边缘 842s | 切指针后 Age 仍很大 → 指针 TTL 太长 |
| `immutable` + 长 max-age | 文件层正确 | `no-cache` → 每次回源 |
| `sha256sum` vs manifest | 一致 | 不一致 → 源未同步或同名覆盖 |

### 发布六步

1. 文件全部上传，hash 与 manifest 一致
2. 预热并抽检 HIT+hash
3. 服务端已兼容该资源协议（03）
4. 原子切换指针
5. 观察下载成功率、回源、版本分布
6. 失败：指针打回，**不删**源站新文件

### 回源打爆止血

回上一份已预热指针 → 或暂停强制更新 → 源站扩/限并发 → 预热完再切 → **最后**才定向刷新脏 URL。

### 切备 CDN

同一批 hash URL 在备上预热，多地 HIT；证书覆盖下载域名；防盗链在备上回源也要通。

## 7. 生产排障

| 现象 | 先做 | 别做 |
|------|------|------|
| 源站 5xx、登录绿 | 回已预热指针 | 全网 purge；扩逻辑服 |
| 工单绿、现场 miss | 对客户端真实 URL | 先怪厂商 |
| manifest 404 死循环 | 回指针补文件 | 当客户端 bug |
| 部分地区闪退 | 同名覆盖/源未同步 | 无脑全网刷新 |
| TLS 失败、回源不高 | 证书到期 | 当回源打爆扩源站 |
| 国内好、出海卡 | 海外源/预热（10） | 改国内预热 |
| CDN 炸 | — | 叠抬 min、加投放 |

## 8. 必会 · 常考

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 卡在更新页先扩逻辑服 | 错 | 下载和登录两条路 |
| 回源打爆先全网 purge | 错 | 先回指针 |
| 预热工单绿=可切指针 | 错 | 多地 HIT+hash+切前回源降 |
| 文件和指针一样长 TTL | 错 | 指针短、文件长+hash |
| 同名覆盖再 purge 就行 | 错 | 用 content hash |
| 差分失败关整包省带宽 | 错 | 失败的人永远进不了 |
| CDN 炸时抬 min | 错 | 客诉不可分 |
| 失败回滚先删源站新文件 | 错 | 回指针即可 |
| 切备只改 CNAME | 错 | 先在备上预热 |
| 国内预热完切全球指针 | 错 | 海外独立源 |

数字：指针 TTL 常见 **30s**；文件 max-age **31536000**；差分失败 30% 按整包容量；预热提前**数小时**。
