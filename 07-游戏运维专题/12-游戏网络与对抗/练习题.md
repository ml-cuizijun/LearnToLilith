## Q1

**★★★★★｜开服带宽 20%、新玩家进不去，加网卡对吗？容量报哪两个数？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [二、握手：长连接与 CPS](知识点.md)

### 场景

监控带宽充裕，Gate `ListenOverflows` 涨，fd 48000/65535。有人要加网卡。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**fd/CPS 满**，不是带宽满——报 **稳态连接 + CPS** 两个数；扩 Gate/粘滞/排队，不加网卡。

```bash
ls /proc/<gate_pid>/fd | wc -l
nstat -az | grep -iE 'ListenOverflows|ListenDrops'
```

```text
48102                          # ← fd 接近上限
ListenOverflows: 12847         # ← 全连接队列溢出
```

> 📝 **面试**：3 万 CCU 可被 2000 CPS 打穿——开服报两个数。

### 再追问

**ulimit 1024 默认值？**——必改，否则假容量。C++/Go 单进程 3～6 万，Java 2～4 万，默认 1024 不改就只有假容量。

## Q2

fd 满 vs Tick 满——别混。

**★★★★★｜fd 满和 Tick 满现象差在哪？各怎么止血？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [二、握手：长连接与 CPS](知识点.md)

### 场景

老玩家「卡着不动」；新玩家「连不上」。有人都要「扩 Gate」。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**fd 满** = 新 SYN 失败（ListenOverflows）；**Tick 满** = 已连接无回包——后者查 CPU/逻辑，不是加 fd。

| 现象 | 先做 |
|------|------|
| 新玩家进不去 | fd/CPS/粘滞/排队 |
| 老玩家无回包 | Tick/下游/单进程 CPU |

> ⚠️ **别混**：fd 满止血扩 Gate/粘滞/排队；Tick 满止血查战斗逻辑/CPU——不是加 fd 也不是加网卡。

### 再追问

**和 [13-TCP与UDP](../../01-基础底座/13-TCP与UDP/) 的 retrans 关系？**——单连接弱网看 13；本章看入口容量。卡点顺序是 fd → 内存 → Tick → somaxconn → PPS → 下游。

## Q3

粘滞跟 uid 不跟 IP。

**★★★★★｜开服三台 Gate，只有 gate-02 有 4.8 万连接，要封加速 IP 吗？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [三、粘滞：跟 uid，不跟源 IP](知识点.md)

### 场景

LB `sessionAffinity: ClientIP`。加速器出口 IP 段集中。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**粘滞改 uid/token hash**——封加速 IP 误杀真玩家；和厂商要出口段单独阈值。

```bash
ss -nt state established '( sport = :9000 )' | awk '{print $4}' | \
  cut -d: -f1 | sort | uniq -c | sort -rn
```

```text
  48102 10.20.30.40          # ← 加速器出口汇聚
   2001 10.20.30.41
```

修复：

```nginx
hash $cookie_session_uid consistent;
```

> 📝 **面试**：「粘滞按源 IP 最稳？」——「错。加速器万人一出口，按 uid hash。」

### 再追问

**封加速 IP 前先做什么？**——先查粘滞/LB 配置是否 ClientIP；和加速厂商要出口段做高防单独阈值，不按 IP 封死。

## Q4

心跳、LB、NAT 对齐。

**★★★★★｜14:00 集体掉线、14:05 登录队爆，无攻击，第一刀？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [四、维持：心跳、NAT 与 LB 超时](知识点.md)

### 场景

LB idle timeout 从 900s 改 60s；心跳 120s。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**LB idle < 心跳** → LB 摘连接 → 重连风暴；修复 **LB ≥ 2× 心跳**。

| 参数 | 典型 |
|------|------|
| 心跳 | 30～60s |
| LB idle | ≥2×心跳 |
| keepalive 7200 | 不能当游戏心跳 |

> ⚠️ **别混**：keepalive 7200s（TCP 层）vs 游戏心跳 30～60s（应用层）vs NAT ~5min（运营商）——三档不同。

### 再追问

**心跳 1s 更稳吗？**——错，打爆 CPU。重连风暴期间开快通道（见 Q5），不是关验证码。

## Q5

弱网重连快通道。

**★★★★★｜CCU 稳、登录 QPS 3 倍，弱网晚高峰，原因？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [五、弱网：重连快通道](知识点.md)

### 场景

重连全走登录 HTTP 排队 5min。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**session_token 有效应走 Gate 快通道**——不进登录队；快通道也要 CPS 限流防伪造 token。

```bash
grep 'reconnect' /var/log/gate.log | grep -c 'login_http'
grep 'reconnect' /var/log/gate.log | grep -c 'fast_path'
```

```text
15234                          # ← 大量走了登录 HTTP
   87                          # ← 快通道几乎没用
```

> ⚠️ **别混**：CCU 稳、登录 QPS 爆 = 重连路由错了，不是开服洪峰——开服洪峰 CCU 也在涨。

### 再追问

**和 [02](../02-登录排队与选服/) 的关系？**——02 管 HTTP 队、ticket/选服；12 管长连接 fd/CPS、快通道。弱网重连风暴走快通道，02 登录队仅收 token 过期。

## Q6

TCP 通 UDP 不通。

**★★★★★｜登录 HTTPS 正常，战斗 UDP 9001 全超时，先杀战斗进程吗？**

**覆盖**：核心 · 必会 · 🔧 ｜ **对应**：知识点 [六、UDP/KCP：TCP 通 ≠ UDP 通](知识点.md)

### 场景

内网 `nc -u` 通，公网超时。刚换高防 VIP。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**先查高防/SG UDP 放行 + 边界抓包**——有状态战斗进程杀了 = 随机判负。

```bash
nc -u battle.internal 9001 -c 1     # 内网通
nc -u battle.public 9001 -c 1        # 公网超时
```

```text
1 byte received          # ← 内网通
timeout                  # ← 公网超时
```

新高防 VIP 检查清单：

```text
□ HTTPS 443 探活
□ TCP Gate 长连接端口
□ UDP 战斗/KCP 端口
□ 清洗后登录成功率
```

> ⚠️ **别混**：TCP 通了 UDP 就通？——错，高防常默丢 UDP。KCP 用户态可靠但链路上仍是 UDP 报文。

### 再追问

**怎么证明是边界问题？**——边界抓包（链 [16-网络排障与抓包](../../01-基础底座/16-网络排障与抓包/)）：SYN 出了，UDP 9001 无回包 → 查高防/SG 策略。

## Q8

防外挂 vs 反作弊。

**★★★★★｜防外挂和反作弊各做什么？开发让运维 Gate drop 某协议号制裁外挂，行吗？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [七、防外挂：限流、隔离与熔断](知识点.md) · [八、反作弊：日志、审计与不可 drop](知识点.md)

### 场景

开发让运维「drop 某协议号」制裁外挂。有人要封加速器出口 IP。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**防外挂**做网络层限流/验证码/隔离熔断；**反作弊**做证据层日志/审计/封号——Gate drop 无法审计，不可。

**防外挂可做**：按行为特征限 CPS、可疑 uid 进验证码、隔离服熔断、缩公网面（GM/DB 零公网）。

**反作弊不可做**：Gate 随意 drop（无法审计错杀）、改战斗数值「制裁」（破坏数据一致性）、无审计封 IP 段（加速器出口后面是真玩家）。

> ⚠️ **别混**：防外挂是网络层措施（限流/隔离/验证码）；反作弊是证据层措施（日志/审计/封号流程）。同一路流量，不同处理阶段。

### 再追问

**封加速 IP 前先做什么？**——先查粘滞配错（Q3）；和厂商要出口段做高防单独阈值，不按 IP 封死。日志交安全（链 [11](../11-游戏日志与埋点链路/)）。

## Q9

开头那个 DDoS vs CC 现场。

**★★★★★｜高防绿勾、创角≈0、无投放，DDoS 还是 CC？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [九、DDoS vs CC：止血不同](知识点.md)

### 场景

带宽正常，登录 QPS 正常，验证码 503。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**CC 创角/登录**——排队+验证码+按账号限流；**不是**再切高防 alone。

```bash
sar -n DEV 1 3 | grep eth0
grep -c 'create_role' /var/log/gate.log
```

```text
11:30:01  eth0  125.43  890.21  0.00  0.00   # ← 带宽正常
    0                                         # ← 创角为 0
```

| 类型 | 打什么 | 动作 |
|------|--------|------|
| DDoS | 带宽/SYN | 高防清洗 |
| CC | 创角/登录 | 业务限流（02） |

> 📝 **面试**：看**清洗后登录成功率**，不看厂商绿勾 alone。DDoS 打带宽/SYN 切高防；CC 打业务走排队/验证码/按账号限流。

### 再追问

**DDoS 和 CC 都切高防？**——错。CC 走业务限流；运维不在 Gate drop 外挂——无法审计错杀。CC 下载打 CDN 源站 → 回源指针（链 [08](../08-CDN与资源更新/)）。

## Q10

conntrack 满怎么认。

**★★★★★｜高防无告警、带宽正常、新连接失败，查什么？**

**覆盖**：必会 · 🔥 ｜ **对应**：知识点 [九、DDoS vs CC：止血不同](知识点.md)

### 场景

`nf_conntrack_count` 接近 `nf_conntrack_max`。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**conntrack 表满**——现象像 DDoS 但无攻击；提 max/减超时/扩表，不是只加清洗带宽。

```bash
cat /proc/sys/net/netfilter/nf_conntrack_count
cat /proc/sys/net/netfilter/nf_conntrack_max
dmesg | grep -i conntrack
```

```text
262136                          # ← count
262144                          # ← max，接近满
nf_conntrack: table full, dropping packet
```

| 现象 | conntrack 满 | 真 DDoS |
|------|--------------|---------|
| 带宽 | 可能正常 | 常打满 |
| 高防 | 无告警 | 有攻击 |
| 老连接 | 可能正常 | 全受影响 |

> ⚠️ **别混**：高防无告警 + 新连接失败 → 先查 conntrack 和 fd，不是只加清洗带宽。

### 再追问

**和 fd 满同时发生？**——可能，分别查；卡点顺序见知识点二节（fd → somaxconn → PPS → conntrack → 下游）。

## Q11

开服洪峰 vs 攻击怎么分。

**★★★★｜开服洪峰和 CC 攻击怎么分？**

**覆盖**：常用 ｜ **对应**：知识点 [九、DDoS vs CC：止血不同](知识点.md)

### 场景

开服 5 分钟 fd 满，创角成功率正常。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：开服 **CPS/fd** 高但**创角成功** → 容量问题；**创角≈0** 无投放 → CC。

| 特征 | 开服洪峰 | CC / DDoS |
|------|----------|-----------|
| 时间 | 开服/活动 | 随机/持续 |
| 创角 | 高但成功 | 创角≈0 |
| 带宽 | 可能不高 | SYN/UDP flood 高 |
| 动作 | 预扩 Gate + 排队 | 限流/清洗/验证码 |

开服：预扩 Gate + [02](../02-登录排队与选服/) 排队 + 粘滞 uid。

### 再追问

**只扩登录不扩 Gate？**——新连接仍 fd 满。开服 CPS 峰值 often 20× 稳态登录 QPS——预扩在压测里算。

## Q12

新高防 VIP 探活。

**★★★★★｜新高防 VIP 上线必做哪三条探活？**

**覆盖**：必会 · 🔧 ｜ **对应**：知识点 [六、UDP/KCP：TCP 通 ≠ UDP 通](知识点.md)

HTTPS 探活全绿，玩家进房间 UDP 超时。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

> 🎯 **一句话**：**HTTPS 443 + TCP Gate 长连接 + UDP 战斗/KCP** 分别探；变更后盯 15min 登录成功率与 UDP 抽检。

**切高防是变更吗？**——是；要有回滚条件。切高防后重连走快通道避免登录队爆炸（见 Q5）。

## Q14

somaxconn 与 Listen 队列。

**★★★★☆｜fd 还有余量但 `ListenOverflows` 仍涨，和 somaxconn 什么关系？**

**覆盖**：常用 · 🔧 ｜ **对应**：知识点 [二、握手：长连接与 CPS](知识点.md) · [九、踩坑清单](知识点.md)

### 场景

`ls /proc/<pid>/fd | wc -l` 只有 2 万，但 `nstat` 里 `ListenOverflows` 每秒涨。有人继续加 `ulimit -n`，无效。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：**fd 满** 与 **Listen 全连接队列满** 是两层——后者看 **`somaxconn` / `net.core.somaxconn`、应用 `listen(backlog)`**，不是只加 fd。

```bash
cat /proc/sys/net/core/somaxconn          # ← 内核全连接队列上限
ss -lnt | grep :4103                      # ← Send-Q 常顶在 backlog
nstat -az | grep -iE 'ListenOverflows|ListenDrops'
```

SYN 进半连接队列 → 完成握手进 **全连接队列** → 应用 `accept`。全连接队列小：fd 未满但新握手被 `ListenOverflows` 拒绝——现象像 fd 满（新玩家进不去），但根因是 **backlog/somaxconn**。修法：调 `somaxconn`（与内核、应用 backlog 取 min）、扩 Gate 实例分散 CPS，不是只加网卡或 ulimit。

> ⚠️ **别混**：排查顺序 **fd → somaxconn/backlog → CPS/粘滞 → conntrack**（Q10）。Tick 满（老玩家无回包）不是加 backlog。

> 📝 **面试**：开服报 **稳态连接 + CPS** 两数；ListenOverflows 涨要同时看 fd 和 backlog。
