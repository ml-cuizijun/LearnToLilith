## Q1

**★★★★★｜资源更新的一生分哪几段？**

**覆盖**：核心 · 必会 ｜ **对应**：知识点 [一、一张图：资源包的一生](知识点.md)

### 场景

把 CDN 更新和战斗热更、强更 min 混在同一张变更单，出问题时四人同时动。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：打包 hash→上传→预热→切指针→客户端差分→回滚；与登录是两条路。

玩家永不直连源站。监控分阶段：上传看源站同步，预热看 HIT/回源带宽，切指针后看下载成功率与版本分布，回滚先看指针是否打回。

> 📝 **面试**：人卡更新页查 CDN，不扩 logic。下载绿、登录红才查登录链路。

### 再追问

资源更新和强更关系？——CDN 就绪是强更前置（[05](../05-热更新与版本发布/)）；CDN 炸不叠 min。

## Q2

打包后的 TTL 分工——指针短、文件长。

**★★★★★｜指针和文件 TTL 为何不同？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、切指针：原子切换](知识点.md)

### 场景

指针 max-age=3600，切了边缘仍吐旧 manifest，版本双峰闪退。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：指针短(~30s)快失效；文件 hash URL 长(31536000)+immutable。

灰度用独立指针文件名（`version-canary.json`）。manifest version ≠ 文件 hash。指针被边缘长 TTL 缓存 → 你以为切了部分边缘仍旧清单 → 版本分布双峰。

> ⚠️ **别混**：**指针 TTL 长**（以为切了边缘还旧清单）≠ **文件 TTL 长**（hash URL 正确做法）——两者必须相反策略。

### 再追问

query `?v=2` 代替 hash？——部分 CDN 忽略 query，缓存键分裂；路径 hash 更安全。

## Q3

发布六步把一生串起来。

**★★★★★｜发布六步顺序？失败删源站文件吗？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [五、切指针：原子切换](知识点.md)

### 场景

先切 version.json，包还在传。部分客户端死循环更新。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：上传→预热→服务端兼容→切指针→观察→失败打回指针不删新文件。

观察下载成功率、回源、崩溃、版本分布。失败打回指针到上一份**已预热** manifest，源站新文件保留——下次预热完可直接再切。

> 📝 **面试**：先传再预热最后切指针。失败不删文件，回指针即可。

### 再追问

服务端兼容指什么？——能解析新 manifest/资源协议（[05](../05-热更新与版本发布/)）。

## Q4

就是开头那个回源打爆现场。

**★★★★★｜回源打爆四条件？止血顺序？**

**覆盖**：核心 · 必会 · 常考 ｜ **对应**：知识点 [七、回滚：指针打回](知识点.md)

### 场景

版本日源站 5xx，登录绿，有人全网 purge。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：大/无缓存/同时启动/源站扛不住四条件齐才炸；先回指针，最后定向刷新。

止血五步：① 指针打回已预热 manifest → ② 暂停强更（旧资源兼容时）→ ③ 源站扩/限并发 → ④ 预热完再切 → ⑤ 最后定向刷新确认脏的少量 URL。客户端重试是第二放大器。

> ⚠️ **别混**：purge 制造全球 miss，更糟。**回源打爆**（带宽/5xx 先响）≠ **TLS 失败**（证书到期，回源带宽不高）。

### 再追问

排队很少能加投放吗？——不能，人还没登录，排队人数假性偏低。

## Q5

和 Q4 配套——预热怎么验收 HIT。

**★★★★★｜预热怎样才算成功？**

**覆盖**：核心 · 必会 · 常用 ｜ **对应**：知识点 [四、预热：HIT 验收](知识点.md)

### 场景

厂商工单 100% 绿，切指针回源仍高。说 CDN 骗人。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：多地 HIT+hash 一致+切指针前回源已降；URL 与客户端完全一致。

大版本提前数小时。海外 region 独立预热（[15](../15-出海与多区域/)）。预热 URL 和客户端真实 URL 差一个 query = 白预热——部分 CDN 忽略 query 导致缓存键分裂。

> 🔍 **现场**：

```bash
URL="https://res.example.com/bundles/hero.abc123.bundle"
curl -sI "$URL" | grep -iE 'X-Cache|HTTP/'
curl -s "$URL" | sha256sum
```

```text
HTTP/2 200
X-Cache: HIT
# ← 多地都要 HIT

e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855  -
# ← 与 manifest sha256 一致
```

### 再追问

CDN 命中靠什么？——五件套：hash 不可变 + 指针短 TTL + immutable + 预热验证 + Vary 不乱设。记忆分组：文件层管不变，指针层管可变，操作层管可靠。

## Q6

hash 内容寻址 vs 覆盖同名。

**★★★★☆｜为何 URL 带 content hash？同名覆盖后果？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [二、打包：manifest 与 content hash](知识点.md)

### 场景

始终 `hero.bundle` 覆盖上传。部分闪退部分正常。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：新内容新 URL；覆盖导致边缘分裂，刷新不治本。

immutable 语义：换内容换 URL。ETag 边缘与源要一致。同名覆盖时部分边缘缓存旧版、部分新版，客户端随机命中 → 闪退。

> 📝 **面试**：同名覆盖是部分新部分旧的根源。对 hash URL 做 purge 是错的——换 hash 即可。

### 再追问

全网刷新？——制造 miss，只对确认脏的少量 URL 定向刷。

## Q7

客户端差分失败怎么 fallback。

**★★★★☆｜差分失败为何要整包兜底？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [六、客户端：差分与 fallback](知识点.md)

### 场景

差分失败 25%，关整包入口省带宽。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：失败必须 fallback 整包；容量按最坏整包×峰值；关整包=永远进不了。

盯 `patch_fallback_ratio`。404 on manifest 停重试（防死循环），超时指数退避 1s/2s/4s/8s 上限 60s。源站单 URL QPS 上限防重试放大。

> ⚠️ **别混**：控失败率，不是拆兜底。关整包入口省带宽是假省钱。

### 再追问

灰度差分？——盯兜底比例，不只报平均下载体积。

## Q8

下载线 vs 登录线——别混绿。

**★★★★☆｜下载域名为何不能挂逻辑服？**

**覆盖**：必会 · 常考 ｜ **对应**：知识点 [三、上传：源站与 OSS](知识点.md)

### 场景

版本日 Nginx 顶大包，次日 IP 被打，高防账单爆炸。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：下载走 CDN 源站不露脸；逻辑入口不提供大包体。

`res.example.com` → CDN → OSS。API 走高防 Gate。源站鉴权：预热和玩家拉包用相同方式抽检——鉴权过严 → miss 时 403 → 客户端当损坏重下。

> 📝 **面试**：下载和登录两条路。更新页事故第一刀永远是 HIT/回源，不是扩 logic。

### 再追问

运维内网直连调试？——可以，走内网或带鉴权管理入口，不进客户端配置。

## Q9

CDN 炸时 min_client 怎么协同。

**★★★★☆｜CDN 炸时能抬 min 吗？**

**覆盖**：必会 · 常用 · 常考 ｜ **对应**：知识点 [九、与强更、灰度的协同](知识点.md)

### 场景

更新卡住，运营抬 min「逼人更新」；排队短想加投放。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：CDN 炸不抬 min、不加投放、不扩 logic；旧资源兼容可暂停强更。

`min` 抬起后大量老端被挡在登录——若 CDN 同时 miss，新端也下不完包，客诉不可分。投放在下载成功率恢复前不加——排队人数假性偏低。协议不兼容只能修 CDN/回指针，不能叠 min。

> 📝 **面试**：下载线和登录线并排指挥。CDN 就绪是强更两段抬闸的前置。

### 再追问

协议不兼容旧资源进服会炸？——不能放旧资源进，只能修 CDN。

## Q10

失败码分流定责。

**★★★★☆｜404/hash/超时/TLS 怎么分流？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [十一、作战：资源更新定责](知识点.md)

### 场景

「更新不了」一刀切要 purge。带宽还行成功率差。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：404 回指针补文件；hash 查覆盖；超时查 miss；TLS 查证书别当回源打爆。

源站单 URL QPS 上限防重试放大。403/401 在 miss 时触发，客户端表现为「损坏重下」——预热和抽检必须带与客户端相同的 Referer / 签名 query / Cookie。

> ⚠️ **别混**：TLS 失败回源带宽往往不高。证书到期有独立告警，与回源打爆看板分开。

### 再追问

证书监控？——单独到期告警，不混进 CDN 命中率看板。

## Q11

出海 miss 的预热版。

**★★★☆☆｜出海全卡国内正常怎么查？**

**覆盖**：常用 · 常考 ｜ **对应**：知识点 [八、多 CDN、防盗链与 Range](知识点.md)

### 场景

国内 HIT 99%，东南亚超时。改国内预热参数。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：分 region HIT+海外源/预热；国内完≠全球可切。

跨洋回源超时或海外文件 404 死循环。每 region 独立指针预热（[15](../15-出海与多区域/)）。回源盾（Origin Shield）全球 miss 收成少数节点回源——盾 miss 时源站仍吃一波，不能替代预热。

> 📝 **面试**：国内预热完不等于全球可切。海外要独立预热、独立验收。

### 再追问

全球单源省钱？——小包或许行，版本日远距=事故。

## Q12

回滚不够时切备 CDN。

**★★★☆☆｜切备 CDN 只改 CNAME 够吗？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [八、多 CDN、防盗链与 Range](知识点.md)

### 场景

主 CDN 抖，改 CNAME。证书错，备上全 miss。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：备上预热同一批 hash URL+证书+防盗链；主备都 miss 先回指针。

多 CDN 切换清单：① 备 CDN 预热同一批 hash URL → ② 证书覆盖下载域名 → ③ 防盗链/时间戳鉴权在备上回源一致 → ④ 切完盯下载成功率+HIT → ⑤ 主备都 miss 先回指针。

> 🔍 **现场**：

```bash
curl -sI "https://res-backup.example.com/bundles/hero.abc123.bundle" \
  | grep -iE 'HTTP/|X-Cache'
```

```text
HTTP/2 200
X-Cache: HIT
# ← 备 CDN 也要 HIT 再切流
```

### 再追问

回源盾能替代预热吗？——不能，盾 miss 源站仍吃一波。

## Q13

下载线独立看板。

**★★★☆☆｜版本日 CDN 看板看什么？**

**覆盖**：常用 ｜ **对应**：知识点 [十、监控与看板：下载线独立](知识点.md)

### 场景

只看登录 SLI 绿，下载成功率 61% 没人报。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：下载成功率、回源带宽、HIT、版本分布、patch_fallback 独立告警。

版本日指挥台必须下载线和登录线并排。版本分布双峰查指针 TTL 过长、灰度 URL 与全量混用、海外未预热——不是先怪客户端。

> 🔍 **现场**：

```bash
curl -s 'http://prom:9090/api/v1/query?query=sum(rate(download_success_total[5m]))/sum(rate(download_attempt_total[5m]))'
```

```text
0.612
# ← 下载成功率 61% → CDN 线 P0，与登录无关
```

### 再追问

CC 打 manifest？——限 QPS+WAF，不是无限带宽（[12](../12-游戏网络与对抗/)）。带宽计费 vs 请求数计费两个预算都要版本日前检查。

## Q14

把前面收成 60 秒定责。

**★★★★☆｜60 秒资源更新定责剧本？**

**覆盖**：必会 · 常用 ｜ **对应**：知识点 [十一、作战：资源更新定责](知识点.md)

### 场景

版本日多地区报障，指挥混乱 purge+抬 min+扩 logic。

先自己试试：不看下面，先口述一遍你的答案，再往下对。

### 完整解答

> 🎯 **一句话**：10s 登录绿→CDN线；30s HIT/hash/5xx；45s 四条件→回指针；60s 禁 purge/min/logic。

定责决策树：卡更新页 → HIT/回源/源站 5xx → 海外则 region 预热；闪退 → hash/双峰/同名覆盖；都不是 → min/协议（[05](../05-热更新与版本发布/)）。失败码分流：404 回指针补文件，hash 查覆盖，超时查 miss，TLS 查证书。

> 📝 **面试**：更新页=CDN，不是登录。一人指挥下载线。

### 再追问

同时 battle roll？——另线处理，别混进 CDN 止血。
