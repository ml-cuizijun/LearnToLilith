## 每份模板统一结构

```text
① 项目卡片   30 秒电梯版（规模 + 你的角色 + 1 个数字）
② STAR 口述  2 分钟：背景/任务/动作与取舍/结果
③ 五层追问   L1 做了什么 → L2 为什么 → L3 怎么做 → L4 失败 → L5 重来
④ 数字占位   答题前换成真实口径（窗口、分母、MTTR 定义）
```

---

## 五层追问（所有项目共用）

| 层 | 考官在验 | 备到什么程度 |
|----|---------|--------------|
| L1 | 真实性 | 规模、你的职责、1 个结果数字 |
| L2 | 权衡 | 至少 1 个 rejected 方案和原因 |
| L3 | 是否亲手 | 架构、配置、命令、流水线阶段 |
| L4 | 是否操过生产 | 一次失败或故障的止血和根因 |
| L5 | 是否高级 | 重来怎么改；规模 ×10 怎么拆 |

---

## 通用打法

| 原则 | 说明 |
|------|------|
| **主语是「我」** | 「我负责/我推动/我定位」，协作如实说，不把全组平台揽完 |
| **每个项目 ≥2 个数字** | 没数字不可信；说不清算法就用量级 + 口径 |
| **讲权衡** | 为什么这么做、代价是什么 |
| **能扛五层** | 答完一层停；不会的技能不要写进简历 |
| **数字不虚构** | 占位符换成真实值；假精确一问就穿 |

## 开场 2 分钟（串起项目，让考官来选）

```text
我有 <N> 年游戏运维/SRE，做过 <业务> 从 0 到 1，峰值 CCU <X>、区服 <Y>、云 <阿里云/AWS>。

最有代表性的几件事：
① <开服或故障复盘> —— 一句话结果 + 1 个数字
② <K8s / 发布 / 中间件> —— 一句话结果 + 1 个数字
③ <工程化提效> —— 一句话结果 + 1 个数字

擅长把稳定性和发布做成可复制的门禁，这也是我想在贵司继续做的。
```

开场点到的 3 个必须都能深挖到 L5，考官会挑一个往下问。
