## Q1

**★★★★★｜设计游戏开服系统，支持每天开 N 服，失败可回滚。**

**覆盖**：核心 · 必会 · 常考

### 场景

「画一个每天能开 5 个新区的系统。」有人直接画 Jenkins 连 K8s，没有对玩家开关，失败继续跑完。

### 完整解答

先问：每天几服、单服 CCU、可见开关、失败 RTO、镜像是否钉死。假设写在角上。

```mermaid
flowchart TB
    a[1 预检<br/>镜像钉死 / 配额 / server_id 未占用 / 中心服健康] --> b[2 数据面<br/>建库、静态表、Redis 默认关活动]
    b --> c[3 服务面<br/>Gate / 大厅 / 逻辑，尚未进目录]
    c --> d[4 验收<br/>登录冒烟、支付沙箱、核心 RPC]
    d --> e[5 唯一开关<br/>写服列表 · 建议人工确认]
    d -->|失败| f[拆除 job<br/>禁止半成品挂出去]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef ok fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    classDef bad fill:#DC2626,stroke:#7F1D1D,stroke-width:2px,color:#fff
    class a,b,c,d a
    class e ok
    class f bad
```

合服不要混进这题：合服失败恢复备份，禁止反向再迁。给分点是可停、可拆、玩家不可见直到目录写入。

### 再追问

流水线某步失败但继续跑完了怎么办？——这是事故。门禁必须失败即停；目录写入做成独立审批。补预检项和告警，当天用干净环境重开，不修脏环境凑合开。

## Q2

**★★★★★｜设计游戏服监控告警：SLO 怎么定，什么情况该半夜叫醒？**

**覆盖**：核心 · 必会 · 常考

### 场景

「给我们游戏做一套监控。」有人只画 Prometheus + Grafana，SLO 写 HTTP 99.9%，半夜 CPU 90% 也打电话。

### 完整解答

先问长连接还是 HTTP、谁 on-call。SLO 拆登录成功率、核心协议 / 进战斗、掉线、支付、CCU 异常。

```mermaid
flowchart TB
    a[exporter / 埋点] --> b[Prometheus 分片]
    b --> c[VM / Thanos · 按团队选]
    b --> d[Alertmanager 分组抑制]
    d --> e[电话 / IM]
    b --> f[Grafana 燃烧率 + 开服 / 活动大盘]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    classDef c fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class a,b a
    class c,d,f b
    class e c
```

叫醒：登录跌破、支付失败、CCU 10 分钟腰斩、开服验收失败。单机 CPU 不叫醒。P0 绑燃烧率和业务 SLI。Rejected：单实例扛所有 series；无分级全量告警。错误预算烧完停非关键发布。

### 再追问

CCU 掉了一半，但 CPU 都正常？——按业务故障处理：登录、网关连接、目录、发版、热更。CPU 正常不能排除逻辑挂死或玩家进不去。这正是必须有业务 SLI 的原因。

## Q3

**★★★★★｜百万注册、峰值 CCU，你怎么做容量？**

**覆盖**：核心 · 必会 · 常考

### 场景

运营给了「注册破百万」。有人按注册数给逻辑服做 HPA。

### 完整解答

先定口径：注册、DAU、CCU、登录 QPS 不能混。按层建模。压测登录脉冲和平稳在线分开。

```mermaid
flowchart TB
    a[目标 CCU × 单玩家资源] --> b[网关连接 / 逻辑人数上限 / DB / Redis]
    b --> c[水位告警在先满的一层]
    c --> d[能扩的扩]
    c --> e[不能扩的排队 / 分服 / 降级]

    classDef ok fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    classDef bad fill:#DC2626,stroke:#7F1D1D,stroke-width:2px,color:#fff
    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    class a,b,c a
    class d ok
    class e bad
```

压测到 1.2× 找第一瓶颈；活动前 freeze 非必要发布。有状态逻辑服加机器不自动接人。成本翻倍则分层 SLO，非核心降级。公式写在白板上：目标 CCU × 单玩家连接 / 单网关连接上限 = 网关台数。逻辑服按人数上限算，不按 CPU。

### 再追问

现场 CCU 超模型，逻辑服能立刻扩吗？——多数不能立刻接人。现场扩网关 / 大厅、收紧排队放行、降级非核心玩法。逻辑服扩容是活动前的事。

## Q4

**★★★★★｜设计发布系统：灰度、强更、热更、一键回滚。**

**覆盖**：核心 · 必会 · 常考

### 场景

「我们要一键回滚。」有人说 Git revert。战斗服用 Web 的 liveness。配表热更发错准备改库。

### 完整解答

先问日发布次数、热更是否改协议、强更是否踢在线、回滚 RTO、DB 是否同发。

```mermaid
flowchart LR
    a[Git] --> b[CI 构建 / 测试 / 扫描]
    b --> c[不可变制品]
    c --> d[预发]
    d --> e[灰度 · 区服或玩家比例]
    e --> f[全量]
    e -->|门禁失败| g[回滚上一制品<br/>分钟级，演练过]
    f -->|预算耗尽| h[冻结 promote]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef bad fill:#DC2626,stroke:#7F1D1D,stroke-width:2px,color:#fff
    class a,b,c,d,e,f a
    class g,h bad
```

门禁：错误率 / 掉线 / 登录（金丝雀，不要集群均值）。热更能停、配表版本化；强更兼容旧客户端；战斗服谨慎配 liveness；DB expand-contract，禁止破坏性 DDL 和代码同发。

### 再追问

热更发错配表怎么回？——配表当制品；一键回上一份；必要时关活动开关。不要现场改库。

## Q5

**★★★★★｜设计生产 K8s 集群，升级时战斗服不能集体掉线。**

**覆盖**：核心 · 必会 · 常考

### 场景

「集群要滚动升级。」有人 drain 全节点，PDB 被删掉赶时间。

### 完整解答

先问战斗服是否在集群内、能否停服、多 AZ 与否。

```mermaid
flowchart TB
    cp[控制面 + etcd 3/5 跨 AZ] --> wl[工作负载 PDB + topologySpread]
    wl --> up[升级：先无状态后有状态<br/>战斗单独窗口]
    up --> live[liveness 不能按 Web 套到战斗进程]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    class cp a
    class wl,up,live b
```

控制面挂：已有 Pod 仍跑、无法变更。etcd 挂：失忆，靠备份。调度器挂：新 Pod Pending。禁止一个大集群塞所有大区。发布走 GitOps。etcd 备份并演练恢复。偶数不要。

### 再追问

PDB 把 drain 卡住了？——先看 maxUnavailable / minAvailable 是否与副本数冲突；战斗服升级窗口单独排；禁止为了赶升级删 PDB。

## Q6

**★★★★★｜游戏要多活，你怎么设计？**

**覆盖**：核心 · 必会 · 常考

### 场景

「我们要多活。」有人画两个 AZ 前面一个 LB，战斗服双写 Redis。

### 完整解答

先问同城双活、异地灾备还是分区多活，以及 RPO / RTO、跨区玩法。画两个 AZ 负载均衡不等于多活。

```mermaid
flowchart TB
    a[同城双 AZ：机器 + 无状态接入 + etcd<br/>Session 粘滞或可重建]
    b[分区多活：按大区拆集群和数据<br/>最常见可落地]
    c[异地灾备：RTO 小时级<br/>切流前停写；多数厂做不到热双活]
    d[题眼：MySQL 延迟、Redis 能否丢、切流开关、脑裂以谁为准]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    classDef c fill:#0891B2,stroke:#155E75,stroke-width:2px,color:#fff
    classDef d fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class a a
    class b b
    class c c
    class d d
```

不要一上来双写所有游戏库。全球同一套战斗服热双活成本极高。排行榜 / 交易 / 公会跨区要单独设计。

### 再追问

Redis 跨城同步行不行？——延迟和脑裂不可接受就不要当多活数据面。Session 可重建的才可丢；交易和背包以 MySQL 准，切流前停写。

## Q7

**★★★★☆｜系统设计开头你问哪些约束？不问直接画图会怎样？**

**覆盖**：核心 · 必会 · 常考

### 场景

45 分钟题，前 10 分钟已经画满微服务。对方改口「我们单服只有 2000 CCU」，图全废。

### 完整解答

规模与口径、SLO / 失败定义、是否有状态、回滚 RTO、自建还是云 / 团队规模。不问就画，假设错了整题作废，按中级评。

开口：「先确认约束再画。」假设写在角上，允许改数字。45 分钟：0–5 问清，5–15 数据流，15–30 失败路径，30–40 SLO / 发布，最后权衡。时间不够保主干 + 回滚 + 谁被叫醒。白板口诀：先问再画，先流后盒，先失败后功能，先 SLO 后组件。

### 再追问

对方说规模你定。——自己给一档合理假设并声明可调：例如单服 CCU 8000、日开 5 服、开服失败玩家不可见。

## Q8

**★★★★☆｜设计中途卡住或不会某个组件怎么办？**

**覆盖**：必会 · 常用

### 场景

对方问 Spinnaker 策略。你没用过。沉默了两分钟。

### 完整解答

回到数据流：谁产生、谁存储、谁消费、失败谁停。不会的产品说原则和同类替代，不编细节。把题往 SLO / 回滚 / 容量上收。

沉默超过一分钟就降级：先画主干再填名字。换题用同一骨架重启。编造没用过的 Cilium / Spinnaker 细节，追问即崩。

### 再追问

重来这套监控你怎么改？——更早上业务 SLI 和依赖抑制；长期存储按团队能力选简单的；和发布事件打通便于归因。

## Q9

**★★★★☆｜对方让你设计 LLM 推理平台，你怎么处理？**

**覆盖**：必会 · 常用

### 场景

业务 SRE 岗。白板写成 Prompt 链路和 Agent。游戏稳定性一句没有。

### 完整解答

业务 / 游戏 SRE 岗不当主菜。先确认是不是 AI Infra 岗；用限流、队列、GPU 水位、降级、超时点到为止，拉回你的游戏稳定性经验。

不要展开 MCP / Prompt / Agent。若对方坚持，骨架仍是约束→容量（token/s、队列）→失败降级→SLO。然后明确：生产主战场是开服和游戏 SLO。投纯 AI Infra 再按第九章展开。

### 再追问

那日志系统 / 秒杀要不要画？——SRE 岗频率低于六主菜。被问到讲缓冲、成本、限流、降级，尽快回到可观测和容量。

## Q10

**★★★★☆｜开服和多活两道题时间不够，怎么取舍？**

**覆盖**：必会 · 常用 · 常考

### 场景

开服图画完，多活只剩 8 分钟。有人硬画全球双活。

### 完整解答

时间不够先保：**主干数据流 + 一种失败怎么停 + 谁被叫醒**。多活 8 分钟：声明假设（分区多活、RPO 分钟级、不做战斗服热双活），画大区独立 + 切流开关 + 数据以谁为准，点名 rejected（全球双写）。不要半成品全球架构。

### 再追问

考官换题怎么办？——同一骨架重启，不解释上一题为什么没答完。
