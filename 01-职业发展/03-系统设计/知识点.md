## 1. 基本概念

系统设计轮看的是 **你能不能把生产约束问清，再把失败路径画成可停的系统**。不是会不会背组件名。六主菜：开服、监控告警与 SLO、容量、发布回滚、K8s 集群、多活。LLM 平台不当主设计题。

开口 2–3 分钟只问、不画。把假设写在白板角上：「按单服峰值 CCU 8000、日开 5 服、开服失败玩家不可见来设计，不对你纠正。」对方改数字，你改图，不要争。不问清楚就画，假设错了整题作废。对方说「规模你定」，自己给一档合理假设并声明可调。

| 必问 | 例子 | 不问会怎样 |
|------|------|-----------|
| 规模与口径 | 每天开几服？峰值 CCU 还是登录 QPS？区服数？ | 容量和机器数全错 |
| SLO / 失败定义 | 登录成功率、掉线、支付、开服 RTO | 告警和多活方案无法选 |
| 状态 | 大厅无状态还是战斗服有 Session？ | 乱画弹性扩容 |
| 回滚 | 失败是拆环境、回版本还是回档？RTO？ | 开服和发布题直接挂 |
| 约束 | 自建还是云、团队人数、能否停服、合规 | 堆一堆养不起的组件 |

45 分钟节奏：0–5 问约束和容量假设 → 5–15 画数据流 → 15–30 深挖 1–2 个失败路径 → 30–40 SLO / 告警 / 发布 → 40–45 权衡和演进。时间不够先保 **主干 + 失败回滚 + 谁被叫醒**。

开场可以原话：

```
这题我按生产系统来设计。先确认几件事：
规模（CCU / 日开服数 / 节点）、SLO（什么叫坏了）、
是否有状态、失败回滚的 RTO、自建还是云。
确认后我写容量假设，再画数据流。
```

白板口诀：**先问再画，先流后盒，先失败后功能，先 SLO 后组件。**

每层选型一句话：「选 A 因为…；B 淘汰因为成本 / 运维 / 有状态。」不会的组件说「生产没用过 X，我会用 Y 的原则做」，禁止编没见过的产品细节。

> **记住**：不问约束直接画图，按中级评。时间不够保主干 + 回滚 + 谁被叫醒。

## 3. 原理

原理只保留白板会用到的：为什么先流后盒、为什么失败路径比功能分高、有状态为什么不能套 Web 弹性。

数据流先于盒子：谁产生（运营点开服、玩家登录、CI 打制品）、谁存储（server_id 目录、MySQL、镜像仓库）、谁消费（Gate、大厅、战斗服、Alertmanager）、失败谁停（拆除 job、回滚上一制品、切流开关）。先画盒子再补箭头，一定漏失败。

游戏生产三条硬约束，六主菜都会撞上：

| 约束 | 含义 | 设计后果 |
|------|------|----------|
| **有状态** | 战斗 / 逻辑服绑 Session、人数上限 | 不能按 CPU 做 HPA；现场加副本不接人 |
| **对玩家开关** | 目录 / 服列表写入 = 可见 | 开服最后一步才写；半成品禁止挂出去 |
| **数据不能丢** | 交易、背包、回档以 MySQL 为准 | 多活看 RPO / 停写 / 脑裂以谁为准，不是两个 AZ 框 |

容量公式写在白板上（允许对方改数字）：目标 CCU × 单玩家连接 / 单网关连接上限 = 网关台数。逻辑服按人数上限算，不按 CPU 利用率。压测两条曲线分开打：登录脉冲 vs 平稳 CCU，打到 **1.2×** 找第一瓶颈。

错误预算：烧完停 **非关键变更 / 功能发布**，不停 hotfix 和回滚。金丝雀门禁用金丝雀自己的错误率相对发布前 5 分钟 baseline，不用集群均值（均值会把金丝雀淹掉）。

> **重点**：有状态逻辑服不能按 HPA 乱扩；目录写入是开服最后一步；多活看数据层，不是两个 AZ 框。

## 4. 落地方法

六主菜。每题先问约束，再套第 2 节骨架。

### 4.1 开服系统：每天开 N 服，失败可回滚

约束问完，对方说：「按日开 5 服、单服 CCU 8000 画。」再问：是否要排队、镜像是否钉死、对玩家可见的开关是哪个、失败是否允许残留。

系统里发生的是一条可停的流水线，不是「点一下就出服」。每段失败必须 **阻断**；开放目录是最后一步；回滚是拆脏环境，不是对玩家「再试一次」。

```mermaid
%%{init: {"flowchart": {"padding": 16, "nodeSpacing": 28, "rankSpacing": 48}, "theme": "base"}}%%
flowchart TB
    gm[运营 / GM 点击开服<br/>server_id · 规格 · 窗口]
    gm --> p1

    subgraph pipe ["流水线 · 失败即停"]
        p1["1 预检<br/>镜像 tag 钉死 禁 latest<br/>配额 / 节点池 / Redis 规格<br/>server_id 未占用<br/>中心服 / 目录 / 支付沙箱健康"]
        p2["2 数据面<br/>按 server_id 建库 + 静态表<br/>Redis 默认关活动开关<br/>备份策略挂上"]
        p3["3 服务面 · 尚未挂公网目录<br/>Gate / 大厅 / 逻辑服<br/>只对内网探活"]
```

卡住先看哪：

1. **预检失败仍继续跑** → 流水线没有「失败即停」。目录里会出现半成品服。先看这一段有没有阻断，不要先画 K8s YAML。
2. **服务面起来了，玩家已经能搜到服** → 目录写入太早。开放开关必须是第 5 步，建议人工确认。
3. **验收登录超时，有人说「改改配置再开」** → 禁止修脏环境。走拆除 job，当天用干净环境重开。
4. **对方把合服和开服画在同一条流水线** → 纠正：合服失败是 **恢复备份**，禁止反向再迁。细节见 08。本题考你能不能把流水线画成可停的系统。

流水线某步失败但继续跑完了 = 事故。目录写入做成独立审批。给分点是可停、可拆、玩家不可见直到目录写入。不是会不会调云 API。

### 4.2 监控告警与 SLO

开服图画完，对方追：「这套系统怎么知道坏了？谁被叫醒？」再问：长连接还是 HTTP、保留多久、谁 on-call、半夜叫醒标准。

游戏 SLI 不要只套「HTTP 99.9%」：登录成功率、进战斗 / 核心协议成功率、掉线率、支付成功率、CCU 异常（10 分钟腰斩）。错误预算：预算烧完停非关键变更。

叫醒：登录跌破 SLO、支付失败、CCU 腰斩、开服验收失败。不叫醒：单机 CPU、已抑制的上游连锁。依赖链：下游库挂抑制上游全员告警，核心路径不误抑制。P0 绑燃烧率和业务 SLI。Rejected：单实例 Prometheus 扛所有 series；无分级的全量告警。

卡住：CCU 掉了一半但 CPU 都正常，你还在讲机器告警。按业务故障处理（登录、网关连接、目录、发版、热更）。先看大盘上有没有 **登录成功率和 CCU**，没有就不要说「监控很全」。谁被叫醒看业务 SLI，不看 CPU。

重来这套监控怎么改：更早上业务 SLI 和依赖抑制；长期存储按团队能力选简单的；和发布事件打通便于归因。

### 4.3 容量：百万注册、峰值 CCU

对方改角上的数字：「注册百万，峰值 CCU 提到 2 万，活动当天超模型怎么办？」再问：口径是注册、DAU 还是 CCU；瓶颈在登录洪峰还是平稳在线；有状态服能否加机器生效。运营给了「注册破百万」就按注册数给逻辑服做 HPA = 中级。


压测：登录脉冲与平稳 CCU 分开打，打到 1.2× 找第一瓶颈。活动前：freeze 非必要发布；预热 CDN；扩无状态。成本翻倍时分层 SLO，非核心降级。

卡住：有状态服扩容不接人——要讲踢人、迁移 Session、还是只扩无状态接入。现场 CCU 超模型：扩网关 / 大厅、收紧排队放行、降级非核心玩法。逻辑服扩容是活动前的事。能扩的提前扩；不能扩的排队、分服、降级。逻辑服现场加副本不当容量方案。

### 4.4 发布回滚：灰度、强更、热更、一键回滚

对方：「开出来的服怎么发版本？热更发错配表怎么办？」再问：日发布次数、热更是否改协议、强更是否允许踢在线、回滚 RTO、DB schema 是否同发。有人说 Git revert 就算一键回滚；战斗服用 Web 的 liveness；配表热更发错准备改库——都挂。


游戏约束：

1. 热更失败能停；配表当制品版本化。发错配表：回上一份制品；必要时关活动开关。不要现场改库「修数据」。
2. 强更兼容旧客户端。
3. 战斗服滚动：liveness 不能按 Web 套，PDB + 分区。对方问战斗服能不能跟大厅一起滚——明确说不，liveness 过激会集体重启踢人。
4. DB：expand-contract，禁止破坏性 DDL 和代码同发。

Git revert 或 rollout undo 要演练过才敢称一键回滚。发布题给分在门禁和一键回滚是否演练过。

### 4.5 K8s 集群：升级时战斗服不能集体掉线

对方把题扩成：「这些服用 K8s 跑，控制面怎么放、升级怎么不踢人？」再问：节点规模、战斗服是否在集群内、是否多 AZ、etcd 谁运维、升级窗口能否停服。有人 drain 全节点、PDB 被删掉赶时间——拒绝。

### 4.6 多活

对方最后一问：「机房挂一个 AZ 怎么办？」再问：目标是同城双活、异地灾备还是分区多活；RPO / RTO；排行榜 / 交易 / 公会能否跨区；玩家是否接受切区。游戏数据有状态，**画两个 AZ 负载均衡不等于多活**。数据层才是题眼。不要一上来上全球同一套战斗服双活、双写所有游戏库。


| 模式 | 适用 | 代价 |
|------|------|------|
| 同城双 AZ | 机器 / 无状态接入 / etcd | 逻辑服 Session 仍要粘滞或可重建 |

卡住：对方等你画两个框加一条 LB。补上数据 RPO、停写、以谁为准，这题才像高级。多活 8 分钟：声明假设（分区多活、RPO 分钟级、不做战斗服热双活），画大区独立 + 切流开关 + 数据以谁为准，点名 rejected（全球双写）。不要半成品全球架构。

## 5. 常见坑与红线

| 扣分 | 加分 |
|------|------|
| 不问约束直接画图 | 假设写在角上，允许改数字 |
| 组件堆砌、无数据流 | 先箭头后盒子 |
| 无失败路径、无回滚 | 每题讲一种失败怎么停 |
| 把有状态服当 Web 无状态 | 明确能扩 / 不能扩 |
| 多活只画双 AZ | 讲数据 RPO 和切流开关 |
| 编造没用过的组件 | 「没用过 X，原则是 Y」 |

红线：

1. 开服预检失败仍跑完、半成品挂目录。
2. 逻辑服现场 HPA 当容量方案。
3. 金丝雀用集群均值；一键回滚没演练过。
4. 为赶升级删 PDB；战斗服套 Web liveness。
5. 业务 / 游戏 SRE 岗把题做成 Prompt / Agent 主线。

业务 SRE / 游戏 SRE 岗，主动把题往开服、SLO、容量、发布上引。若对方坚持出推理平台：用同一套骨架点到为止——网关限流、队列、GPU 水位、失败降级模型、计费与超时——然后拉回「我生产主战场是游戏稳定性，GPU 我按容量和故障域这样保」。不要把 MCP、Prompt、Agent 当主线。投纯 AI Infra 岗再展开第九章。若对方坚持，骨架仍是约束→容量（token/s、队列）→失败降级→SLO。

日志系统、短链、秒杀：SRE 岗频率低于六主菜。被问到就讲缓冲、成本、限流、降级，快速收束到可观测和容量。

沉默超过一分钟就降级：先画主干再填名字。编造没用过的 Cilium / Spinnaker 细节，追问即崩。换题用同一骨架重启，不解释上一题为什么没答完。

## 7. 必会 · 常考

白板和追问高频，能一口回：

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 开口先画接入-逻辑-DB | 错 | 先问约束，假设写在角上 |
| 开服失败改改配置再开 | 错 | 拆除 job，当天干净环境重开 |
| 目录写入可以和服务面一起做 | 错 | 第 5 步唯一开关，建议人工确认 |
| 合服和开服同一条流水线 | 错 | 合服失败恢复备份，禁止反向再迁 |
| SLO 写 HTTP 99.9% 即可 | 错 | 登录 / 进战斗 / 掉线 / 支付 / CCU 腰斩 |
| 半夜 CPU 90% 该叫醒 | 错 | 叫醒看业务 SLI |
| 注册百万就给逻辑服 HPA | 错 | 先定 CCU 口径；有状态不能乱扩 |
| 现场 CCU 超模型立刻扩逻辑服 | 错 | 扩网关 / 大厅、排队、降级 |
| Git revert 就算一键回滚 | 错 | 回上一制品且演练过 |
| 金丝雀看集群均值 | 错 | 看金丝雀相对 baseline |
| 战斗服跟大厅一起滚 | 错 | liveness 过激会踢人；单独窗口 |
| 为赶升级可以删 PDB | 错 | 先看 maxUnavailable；战斗单独排 |
| 两个 AZ + LB = 多活 | 错 | 看数据 RPO / 切流 / 脑裂 |
| Redis 跨城同步当多活数据面 | 错 | Session 可丢才跨；交易以 MySQL 为准 |
| LLM 平台当游戏 SRE 主设计题 | 错 | 点到为止，拉回开服 / SLO |
| etcd 挂了玩家立刻掉线 | 错 | 已有 Pod 还在，不能变更 |

数字：单服 CCU 假设常见 **8000**；日开 **5** 服；压测 **1.2×**；CCU **10 分钟腰斩** 叫醒；回滚 **分钟级 RTO**；etcd **3 或 5**；多活 8 分钟先保分区多活 + 切流开关。

易混：开服拆除 vs 合服恢复备份；能扩 vs 不能扩；金丝雀 vs 集群均值；控制面挂 vs 玩家掉线；同城双 AZ vs 分区多活 vs 异地灾备；功能盒子 vs 失败路径。
