## Q1

**★★★★★｜用 2 分钟介绍你最能定级的游戏运维项目。**

**覆盖**：核心 · 必会 · 常考

### 场景

开场：「做个自我介绍，重点讲一个项目。」有人从入职第一年讲到现在，超时还没数字。

### 完整解答

选开服 / 故障治理 / 发布之一。STAR 按编号，超时砍背景。

1. **S**：N 个区服，日均开 M 服，手工复制，失败残留脏 server_id。
2. **T**：我作为流水线 Owner，目标单服耗时降下来且失败不对外开放。
3. **A**：预检阻断（镜像钉死、ID 未占用）；数据面和服务面分段，未写目录前玩家不可见；验收失败走拆除。淘汰「复制模板机再改配置」，因为漂移清不干净。
4. **R**：耗时 X→Y，脏环境从每月 A 到 0。

```mermaid
flowchart LR
    A[规模 + 痛点] --> B[你的目标]
    B --> C[2-4 个动作<br/>含 rejected]
    C --> D[两个数字]

    classDef a fill:#0891B2,stroke:#155E75,stroke-width:2px,color:#fff
    classDef b fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef c fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class A,B a
    class C b
    class D c
```

### 再追问

Argo / Jenkins 你为什么选当时那套？——按团队约束答：已有 Jenkins + 游戏服有状态，先把门禁做成可停；GitOps 后置。不要吹没用过的工具。

## Q2

**★★★★★｜简历写了「主导 K8s / 监控 / 开服」，五层追问你怎么扛？**

**覆盖**：核心 · 必会 · 常考

### 场景

对方顺着简历一条 bullet 往下挖。L1 数字很漂亮，L3 说不出流水线阶段名。

### 完整解答

1. **L1** 规模 + 角色 + 1 个数字（30 秒电梯版）。
2. **L2** 为什么，必须有 rejected。
3. **L3** 配置 / 命令 / 环境名 / 告警名 / 流水线阶段。
4. **L4** 一次真实失败：开服预检验收没过、探针误杀、告警漏报。
5. **L5** 禁止「没什么要改」；讲当时没做金丝雀 / 目录开关的原因和现在的演进。

每个代表项目一页稿，2–3 个备到 L5。L3 说不出命令，L1 的数字会被当成包装。开服 L3 当场要能报出：预检 / 数据面 / 服务面 / 验收 / 目录写入；镜像禁 `latest`；失败走拆除 job。

### 再追问

现场写一条你当时的命令 / 配置？——准备真的：`kubectl describe` 事件、Argo sync policy、开服 job 失败退出码、PromQL 燃烧率。编的命令会在下一问穿。

## Q3

**★★★★★｜简历上「变更故障 40%→12%」这种数字怎么来的？对方不信怎么办？**

**覆盖**：核心 · 必会 · 常考

### 场景

「40% 是怎么算的？」说不出分母，开始改口。

### 完整解答

说清统计窗口、分母、标签口径。同一口径前后对比。说不清算法就改成「四十分钟级到十分钟内」并补定义，不要硬编精确百分比。

示例：「按 P0 / P1 复盘标签，变更类包括配置错误、未灰度、requests 设错。改造前 12 个月 25 起 P1+ 里 10 起变更相关 ≈40%；上线后 6 个月 17 起里 2 起 ≈12%。」主动承认还有审批、演练等并行因素，GitOps / 流水线是主因之一。继续降：金丝雀、自动回滚、错误预算门禁。

### 再追问

MTTR 从发现算还是从告警算？——先定义你用的：发现到恢复，还是告警到恢复，是否含等开发。口径变了就不要和简历混用。

## Q4

**★★★★★｜不会的技能写上了，被问倒怎么办？正确做法是什么？**

**覆盖**：核心 · 必会 · 常考

### 场景

简历「精通 Thanos」，生产是 VictoriaMetrics。对方开始问 compact 和 downsample。

### 完整解答

当场承认边界，给推理和下一步，不编生产经历。正确做法是投前删掉或降级：熟练 / 用过 / 不写。

Thanos 只做过 PoC 就不要写精通。K8s 网络只会 apply，删「精通 CNI」。AWS 只会开 EC2，不写「熟悉 VPC / IAM」。Go 改过工具写「脚本级」。ATS 对齐 JD 只能用真实经历里的词。现场：先说「这块生产我没 Owner，我按故障域会这样设计」，再拉回开服或告警。编 Cilium Hubble 下一层命令就死。

### 再追问

那你简历为什么还写？——若确实误写：承认包装过度，说明已改、真实边界在哪。比继续圆更好。

## Q5

**★★★★☆｜游戏运维经历怎么写成 SRE 语言，又不假？**

**覆盖**：必会 · 常用 · 常考

### 场景

JD 要 SLO、GitOps。真实工作是手工开服和 Jenkins。有人写成「落地了错误预算驱动发布」，实际从未冻结过发布。

### 完整解答

用稳定性 / 变更 / 容量 / 回滚重组真实工作，不发明项目。

```mermaid
flowchart TB
    a[手工开服] --> a1[分段门禁 + 失败拆除]
    b[Jenkins 发版] --> b1[制品不可变 + 灰度 + 回滚]
    c[加机器过活动] --> c1[能扩的层 vs 排队]
    d[改库救数据] --> d1[禁止直接改库，走回档审批]

    classDef a fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef b fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class a,b,c,d a
    class a1,b1,c1,d1 b
```

关键词给 JD 可以，每个词后面要有你做过的动作。没有 SLO 就说自建登录成功率和掉线率，不要写从未做过的错误预算冻结。

### 再追问

合服你能讲到哪一层？——能讲停写、双备份、映射冲突、失败恢复备份而不是反向再迁——再写进简历。只会「跟过一次合服当晚值班」就不要写主导合服。

## Q6

**★★★★☆｜「主导」和「参与」怎么界定？对方怀疑夸大怎么办？**

**覆盖**：必会 · 常用 · 常考

### 场景

团队 8 个人简历都写了主导同一平台。

### 完整解答

主导 = 方案主要你定、落地你推、结果你复盘。参与 = 模块或执行。质疑时展开 L3 / L4，并如实说同事做了哪块。

GitOps：架构和 Argo 你调、培训你组织、指标你盯，Helm 同事写，可以说协作但不把 Owner 让掉。团队人数、你写过哪段流水线 / 代码，如实答。经理背调口径要和自述一致。把全组平台写成个人从 0 到 1，L3 一问就穿。拆模块：你负责开服门禁和回滚，别人负责监控采集。

### 再追问

团队 8 个人都写了主导怎么办？——拆模块，不要争「整个项目都是我」。

## Q7

**★★★★☆｜技能哪项最强、哪项可能被问倒？**

**覆盖**：必会 · 常用

### 场景

「你技能栈最熟的是哪块？」有人列 15 个名词。

### 完整解答

最强选你日常 Owner、能到命令和失败案例的。弱项诚实 + 学习计划，简历里不要标熟练。

例如最强：游戏开服流水线 + 生产排障 + 告警治理。弱：大规模多集群联邦、没做过生产 GPU。投岗若强依赖弱项，说入职补什么，不现场装熟。准备 1 条真 PromQL 或一条真开服失败日志，比罗列名词强。

### 再追问

现场写 burn rate？——能写就写；不能写就不要在简历写 SLO 驱动发布。

## Q8

**★★★★☆｜7 年经历很碎、没有「大项目」，怎么写？**

**覆盖**：必会 · 常用

### 场景

换过几条业务线，每段都是救火和脚本，没有从 0 到 1 的平台。

### 完整解答

按主题聚合：稳定性（几次故障闭环）、工程化（脚本 / 流水线总人天）、规模（区服 / 机器加总）。仍要动词 + 数字，答题只深挖 1 个你最有发言权的点。

不要按时间流水报 10 个小需求。没有 SLO 就讲自建指标和告警治理。换工作频繁用发展叙述，不抱怨。禁止把别人的平台和没做过的开服合成一个假项目。

### 再追问

你还做过什么没写在简历上？——准备 1 个小而完整、和岗位相关的（ChatOps、巡检自动化）。不主动展开 GPU / LLM，除非对方岗需要。

## Q9

**★★★★☆｜一句话自我介绍超时了，怎么砍？**

**覆盖**：必会 · 常考

### 场景

讲了 4 分钟还在讲第一份工作的机房搬迁。

### 完整解答

固定 4 句：年限与游戏角色；规模（CCU / 区服 / 云）一个数字；最强项目一个结果数字；为什么投这个岗。项目细节留给追问。早期无关经历直接不说。

### 再追问

对方说「再展开一下 K8s」？——切到那个项目的 L1+L2，不要从 kubelet 原理讲起。原理放技术轮。

## Q10

**★★★★☆｜ATS 为了对齐 JD，把没做过的 Cilium 写上了，投前还来得及改吗？**

**覆盖**：必会 · 常用 · 常考

### 场景

投出去的版本已经写了。对方约了项目深挖。

### 完整解答

来得及改下一封；已经投出的，深挖时不要硬扛。开场可以主动收口：「简历上网络部分我生产是 Calico，Cilium 只做过阅读，不应当作 Owner。」比被问 Hubble 再编强。下一版删掉。

### 再追问

会不会因为删了关键词筛不过？——筛过但深挖穿，更亏。用真实做过的 CNI / Service / 排障词对齐 JD，比假词安全。
