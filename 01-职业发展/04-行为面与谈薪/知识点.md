## 1. 基本概念

定级对话听 **Owner**：主语「我」、有数字、先止血再追责、有留下的机制。谈薪听 **区间**：4 年 Total Comp，不是月薪。总监面前不算薪，HR 面前不讲内核。

目标带是一线城市高级 SRE 的 **中位锚点**，不是保底。实际随城市、厂梯队、股票和当年行情浮动。前提：定级按高级；四维证据不足会被按中级预算谈，见 01。下午把 P0 时间线讲糊了，晚上再报 70–75，HR 手里已经是中级预算。两段必须分开备，但定级材料决定谈薪天花板。

准备 5 个 STAR 即可：① P0 指挥 ② 与研发冲突 ③ 主动推进 ④ 最大失误 ⑤ 高压活动 / on-call。每个 ≥2 个数字，主语是「我」。出现「他们不配合所以没做成」，评语直接降。

| 题型 | 对方要确认 | 你必须带到 |
|------|-----------|-----------|
| 事故复盘 | 会不会指挥、会不会改进系统 | 时间线、影响面、止血决策、根因、action 落地 |
| 冲突 | 会不会把发布和人搞砸 | 数据、试点、妥协边界、结果 |
| 推进 | 是不是只接单 | 非 KPI 也推动、跨团队、量化 |
| 失败 | 诚实不装英雄 | 真实错误、担责、已改、0 次同类 |
| 离职 / 规划 | 会不会来了就跑、岗是否匹配 | 向前看；规划对齐 JD |
| on-call | 是否认岗位、会不会裸扛 | 接受 + 告警治理 / runbook，不是「没问题」 |

高分：主语「我」、有数字、先止血再追责、有留下的机制。低分：甩锅、骂前司、无数字、「我们团队」。

> **记住**：下午交 Owner 证据，晚上交区间。两段不要混。

## 3. 原理

原理只保留下午和晚上会用到的：为什么先恢复后根因、为什么冲突用数据、为什么先问级再给区间。

复盘是 RCA 的口述版：技术根因不够，必须接到流程根因和还在线上的机制。下次同样告警还要你在场吗——答治理是否还在，不要答「我会盯得更紧」。

冲突考的是 **线上结果优先**，不是情商演讲。以赢人结尾会情商负分；以线上结果和机制结尾才像高级。推进必须是 **没人派给你仍去做** 的，证明不是只接单。

谈薪三档（一线、高级 band，投前按当年 offer 校准）：

| 档 | 年包 | 用法 |
|----|------|------|
| 保底 | 约 65 万 | 低于此且职级不对齐，谨慎接 |
| 期望 | 70–75 万 | 谈判锚点 |
| 惊喜 | 80 万+ | 多 offer 或职级上探时 |

谈的是 4 年 TC，不是月薪。纸面「80 万」和 4 年均值不是一回事：股票打折、refresh、forfeiture、签字费只算第一年、游戏厂项目奖波动。职级明确中级且差距大：礼貌拒，不贬对方 band。当前司 counter：除非解决你离职的根本原因（规模 / 体系 / 职级），否则向前看，避免被年包单独留下。

> **重点**：先问级，给 70–75 区间，保底看 65，拆 4 年 TC。不报最低月薪。

## 4. 落地方法

### 4.1 事故复盘怎么讲

总监说：「讲一次登录故障。」结构固定，临场不要抒情。用你真处理过的一次，准备到命令和群消息时间线。游戏场景高频：开服前组件挂、热更协议不兼容、活动配表错误、回档误伤。有人从根因 Redis 讲起，没有影响面，也没有自己的决策点——不像能指挥。

```mermaid
flowchart LR
    A[发现] --> B[影响面]
    B --> C[止血]
    C --> D[对外]
    D --> E[根因]
    E --> F[改进]
    F --> G[结果]

    classDef a fill:#0891B2,stroke:#155E75,stroke-width:2px,color:#fff
    classDef b fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef c fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class A,B a
    class C,D,E b
    class F,G c
```

1. **发现**：哪条告警、几点几分、你是 primary 还是被拉进去的。
2. **影响面**：哪几个区服、峰值 CCU 掉了多少、支付过不过。不要只说「有点卡」。
3. **止血**：回滚 / 切流 / 降级 / 扩容，选了哪个、谁有权。现场抠代码、不回滚，会被问「当时为什么不回」。
4. **对外**：应急群时间线、和运营对齐的玩家公告口径。指挥过 3 人以上才像 7–10 年。
5. **根因**：技术 + 流程。可以说「变更未灰度」，不要说「某某开发太菜」。5 Why 到机制。
6. **改进**：监控 / 门禁 / 演练，每项有人和截止日期。action 还在线上才算落地。
7. **结果**：MTTR、是否复发、机制是否还在。

原则：① 先恢复后根因。② 无指责。③ 你的角色——指挥、止血、同步、推动复盘，至少占一块；全是「协助重启」像中级。④ 承认可更快的点，例如「先看了 CPU，10 分钟后才看 Redis，下次 runbook 改顺序」。

用一次真实 P0 把时间线念出来（数字换成你的）：

```
21:03  登录成功率告警，我是 primary，拉 war room
21:05  影响：3 个区服，CCU 从 N 掉到 0.6N，支付还通
21:08  最近一次变更是热更配表；我拍板回滚上一制品
21:12  和运营对齐公告：「部分区登录排队，预计 10 分钟」
21:20  登录恢复。根因：配表未灰度 + 没有错误预算门禁
次日   门禁上线，90 天 0 复发
```

口述骨架：「大促 / 开服前登录错误率 X%，影响 Y CCU，持续 Z 分钟。我是 on-call primary：5 分钟拉 war room，先问有没有变更，有则回滚；没有则看支付 / Redis / 网关。止血后和运营对齐公告口径。次日复盘主因是新 key 无 TTL / 配表未灰度，我推动规范、水位告警、演练。同类 0 复发。可更快的点：当时先看了 CPU，10 分钟后才看 Redis，runbook 已改顺序。」

现场有人和你吵回滚：对事，用错误率和 SLO，先止血。争论放到恢复后。不讲「我赢了那个开发」。

### 4.2 冲突与推进

对方：「研发要跳过预发赶活动，你怎么办？」你若说「我强制落地」或「那就算了」，都偏。

系统里该走的五步：

1. 立场不同（赶窗口 vs 变更故障率）。
2. 你用什么数据（「跳过预发的回滚率」比「我觉得危险」有用）。拿出近半年变更类 P0 占比。
3. 试点或折中（热修复通道、压缩验证窗口、金丝雀）。非核心试点两周：回滚耗时下降、频率未降。紧急通道保留，24h 补 Git。活动：压缩预发 + 金丝雀，不是跳过。
4. 升级路径（拉双方 TL，用 SLO / 变更故障率）。对方始终拒绝：先核心链路、SLO 挂钩、书面记录风险请老板拍板。
5. 结果数字。活动准时上了，变更故障 A%→B%。

不要演「我强制落地」或「我放弃规范」。承认一次没留热修通道导致反弹，后来加例外和补交时限，规范才落地。被问「你有没有过于强硬」：用上面那次反弹承认，重点是后来机制能落地，不是性格辩论。

推进必须是 **没人派给你仍去做** 的：告警治理、开服自动化、变更进 Git。要有：发现问题的数据、你争取到的时间、落地阻力、结果。「除了值班你还做了什么？」答「领导让我做的脚本」= 接单。

推进口述：「日告警 N、有效率低，无人牵头。我做两周采样，出 top 噪声；提 P0–P3 和抑制规则；找 TL 要 20% 时间；先一个业务试点再铺。结果告警量、周叫醒次数下降，且没有漏掉 P0。」功劳用时间线和文档，不靠「大家觉得我拼」。业务不改阈值：自助改阈值、用他们团队占用的无效告警占比说话、纳入发布评审。先核心链路。

优先级：P0 永远第一；发版 / 活动窗口提前锁；其余和经理周对齐。不会默默全接。例子：大促周暂停非紧急审计，事后补——体现 7–10 年会做取舍。

### 4.3 反问：定级对话结尾

总监说：「你有什么想问的？」反问是你在验团队，也在给「我是来做稳定性的」信号。准备 3 个，临场选，不要全念。问加班和多久晋升 = 像来过日子。

**问：**

1. 团队目前最大的稳定性挑战是容量、变更还是可观测？
2. 这个岗位半年最重要的目标怎么衡量？
3. on-call 轮值、P0 谁指挥、复盘 action 谁盯？
4. SRE 和研发在发布 / 回滚上的边界是什么？
5. （游戏岗）开服和版本窗口谁有最终否决权？

**不问：** 加班多吗、多久晋升、能不能少 on-call、工资什么时候调。职级和 band 留给 HR。

听完对方回答，用 1 句接上你的经验（「你们卡在活动峰值，我这边是排队 + 提前扩无状态」），证明你在听，不是背题。听完还感兴趣吗：结合对方刚说的挑战接 1 点，说你做过的对应手段，不要空夸。对方答完你说「好的没了」= 浪费信号。

### 4.4 年包 65–75 万：按编号走的谈判路径

晚上 HR：「期望薪资？」有人报「最低 60 万，月薪也可以」——锁死在 band 下沿。

| 构成 | 你要问清 | 风险 |
|------|---------|------|
| Base | 几薪、公积金基数 | 只看月薪会低估 / 高估 |
| 年终 | 保底几个月、绩效分布 | 游戏厂项目奖波动大 |
| 股票 / 期权 | 归属、是否打折、刷新、离职 forfeiture | 纸面总包虚高 |
| 签字费 | 一次还是分期、是否要赔 | 补跳槽空窗；不是 4 年 TC 的稳定部分 |

**编号路径（按这个走，不要跳步先报底价）：**

1. **技术 / 定级结束前不主动报数。** 被问：「希望先确认级别和职责，年包按市场和我能扛的范围谈。」
2. **被逼问给区间，不报「最低 60」。** 期望 70–75 万，可随 base / 股票结构调整。
3. **HR 问当前薪资：** 如实年包或区间，不虚构（背调风险）。问「最低多少」：不报保底绝对值，改说「级别和 package 匹配的话，65–70 万年包我会认真看，更希望按高级 band 定」。
4. **拿到口头包后拆 4 年 TC：** Base × 薪数 + 年终期望 + 股票摊 4 年 + 签字费。游戏厂问清：项目奖是否进 offer 口径、亏损年有没有保底。互联网厂问清股票 refresh。
5. **对标竞品：** 用更高的作锚，表达对本团队更感兴趣，请对方匹配到期望档。话术：感兴趣 + 具体数字（「能否争取年包到 72 万，base 可灵活」）+ 你的回复 deadline。筹码是你能立刻上手的开服 / 告警 / K8s（事实，不贬前司）。
6. **对方报 62 万：** 感谢并表达兴趣；指出和高级 band 及你能扛范围的差距；用竞品流程作锚，争取 70–72，股票可灵活。职级明确是中级且差距大：礼貌拒，不贬对方 band。
7. **当前司 counter：** 除非解决你离职的根本原因（规模 / 体系 / 职级），否则向前看，避免被年包单独留下。
8. **威胁式「不给到 XX 我就拒」不要用。** 把合作空间关死。差距过大就礼貌结束。

对话骨架（数字按你的三档替换）：

```
HR：期望薪资？
你：想先确认职级和职责。按 7-10 年游戏/SRE 和现在市场，
    年包期望 70-75 万，base 和股票可以调结构。

HR：我们只能到 62 万。
你：对团队方向感兴趣。62 万和高级 band 以及我能扛的
    开服/稳定性范围有差距。手头有一条流程在 70 万左右，
    能否争取到 70-72 万？股票比例我可以灵活。
```

口头包到手，当场拆 4 年 TC。例：base 3 万 × 16 薪 = 48 万，年终 4 个月期望 12 万，股票 4 年 40 万摊每年 10 万，签字费 5 万只算第一年——纸面「80 万」和 4 年均值不是一回事。

多 offer：一条 78 万总包股票虚、一条 70 万但职级和开服匹配。用更高的作锚，但表达对本团队更感兴趣，请匹配到期望档（70–75 的上沿或 72）。拆 4 年 TC：虚高股票按折现和 forfeiture 算完可能不如 70 的现金 + refresh。不要「不给到 78 我就拒」。签字费要进比较，但问清分期和赔付，只能补空窗。

依据：7–10 年、能独立扛开服 / 稳定性、有量化结果、市场高级 band。HR 开始拆 base / 股票，说明区间接住了。HR 追问「最低多少」，不要报 60。已经说漏「保底 60」——立刻拉回到职级和 70–75 结构，不要再补一个更低的数。

### 4.5 离职、规划、on-call 口径

这三问常跟在复盘后面，或 HR 再问一次。口径向前看，数字对齐 JD。

**离职**：业务进入维护期 / 想去更大容量和更完整的 SRE 体系 / 城市家庭。不说领导差、加班多、钱少。短呆：业务线调整 + 你学到什么 + 下一份要对齐什么。选对方：规模或窗口纪律、JD 匹配你的开服 / K8s / 稳定性，不要「因为是大厂」。其他 offer 可说类别，强调对本岗兴趣最高。「上家待一年是不是不稳定」：给具体业务变化，承诺交接周期，用 3 年规划对齐本岗，不争辩性格。

**3 年规划**：第 1 年熟悉基础设施和 on-call，在告警或变更上交出数字；第 2–3 年成为 1–2 条核心链路的稳定性 Owner（SLO / 容量 / 重大复盘）。管理还是 IC：先 IC 深度，带项目自然带人，不空喊转管理或转 AI。规划必须能对上对方 JD。3 年没晋升：看成长和环境，不把公司当跳板演讲。投 IC 岗却大谈带 20 人 = 岗不匹配。「如果来了还是写脚本值班」：接受 on-call 是职责；但会推动门禁和告警治理，让值班可持续。用你过去把人从救火里捞出来的数字说话。

**on-call**：接受，这是职责。紧接着讲可持续：告警有效、P0 有 runbook、复盘驱动、轮换公平。用你做过的告警量 / MTTR 数字证明你不是来裸扛的。好的 on-call 是系统质量问题不是觉悟问题。反问团队现状（一周几次、有无 secondary）。表演「随叫随到没问题」像没干过。对方追「能接受凌晨电话吗」：先答接受，立刻补「我这边把日告警从 N 收到 M、叫醒从每周 A 次到 B 次，P0 有 runbook」。on-call 太多：先治理无效告警和自动修复，再谈加人。只要求加人会被认为不会治理。半夜：电话升级、secondary。

## 5. 常见坑与红线

| 坑 | 后果 | 改法 |
|----|------|------|
| 复盘无时间线、无你的决策 | 不像能指挥 | 按 4.1 结构背一版 |
| 冲突故事以赢人结尾 | 情商负分 | 以线上结果和机制结尾 |
| 先报 60 万 | 锁死在 band 下沿 | 先问级，给 70–75 区间 |
| 只谈 base | 4 年 TC 差一截 | 拆股票年终签字费 |
| 骂前司 | HR 标不稳定 | 向前看 |
| 反问加班晋升 | 像来过日子 | 问挑战、目标、复盘文化 |
| 最大失误编英雄 | 追问穿 | 真实小事故 + 已改 |
| 「没有犯过」 | 下一问穿 | DDL / 脚本 / 配表 / 开服漏预检都可以 |

红线：

1. 复盘点名羞辱开发。
2. 编造没发生的 P0。
3. 虚构当前年包（背调风险）。
4. 威胁式拒 offer。
5. 最大失误想过瞒——瞒会使回档和公告出错；透明才能改流程。

**最大坑**：定级对话当闲聊。年包很大程度看你 **事故里像不像 Owner、钱上像不像知道自己 band**。

## 7. 必会 · 常考

白板和追问高频，能一口回：

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 复盘从根因 Redis 讲起 | 错 | 先发现、影响面、止血，再根因 |
| 第一个发现火 = 能指挥 | 错 | 要拍板、同步、action 落地 |
| 冲突以赢人结尾 | 错 | 以线上结果和机制结尾 |
| 推进讲领导让做的脚本 | 错 | 必须非 KPI 仍去做 |
| 最大失误「其实是我救了场」 | 错 | 真实错误 + 已改 + 同类 0 |
| 反问加班 / 晋升 | 错 | 问稳定性挑战和半年目标 |
| on-call「随叫随到没问题」 | 错 | 接受 + 治理数字 |
| 离职讲领导差 / 钱少 | 错 | 向前看 |
| IC 岗大谈带 20 人或转 AI | 错 | 规划对齐 JD；先 IC 深度 |
| 期望薪资先报最低 60 / 月薪 | 错 | 先问级，区间 70–75 |
| 只看月薪或纸面总包 | 错 | 拆 4 年 TC |
| 职级中级硬谈到 75 | 错 | 礼貌拒或先重定级 |
| 「不给到 78 我就拒」 | 错 | 用更高的作锚，表达更感兴趣 |
| 当前司 counter 只看加钱 | 错 | 除非解决离职原因，否则向前看 |
| 签字费当成 4 年稳定 TC | 错 | 问清分期赔付，只补空窗 |

数字：五个 STAR 各 **≥2** 个数字；P0 指挥 **3 人以上**；拉 war room **5 分钟**；保底约 **65**、期望 **70–75**、惊喜 **80+**；争取口令常见 **70–72**；热修复 **24h** 补 Git；找 TL **20%** 时间做治理。

易混：定级对话 vs HR 谈薪；止血 vs 根因；主导冲突 vs 强制落地；接受 on-call vs 裸扛；纸面总包 vs 4 年 TC；保底档 vs 先报最低。
