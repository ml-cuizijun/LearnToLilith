**本章主线（定级就按这三步想）：**

1. **对照四维**：稳定性 / 容量 / 工程化 / 故障指挥——每维 1 个 Owner 故事 + 2 个硬数字，缺一维 band 往下打。
2. **听 High / Low**：主语「我」、有口径、有 rejected、有游戏约束（有状态 / 开服 / 热更）= High；「我们团队一起」、无数字 = Low。

## 1. 基本概念

定级（leveling）看 **决策的影响面和证据**，不看工龄。7–10 年游戏运维是门票；桌上对照本厂高级 band 最低证据。目标锚点：阿里 P6+ / P7、字节 2-1 / 2-2、腾讯 T9 / T10、游戏厂高级 / 专家；年包 **65–75 万**（一线城市高级中位，随城市和股票浮动）。

**值班里怎么认角色**（总监问「你负责什么」，先对表再开口）：

四个角色不要混：

| 角色 | 干什么 | 不是什么 |
|------|--------|----------|
| **稳定性 Owner** | 定义「坏了」：SLI / SLO / 错误预算进发布门禁 | 「有监控」 |
| **容量 Owner** | 活动前按层扩；现场知道什么不能扩 | 「大促加机器」 |
| **工程化 Owner** | 别人在用你的流水线 / 告警规则 / IaC | 「写了很多脚本」 |
| **故障指挥** | war room 拍板止血、对外同步、action 落地 | 第一个发现火、靠重启恢复 |

**打个比方**：定级像评球队——工龄是「踢了几年球」，四维证据是「你有没有当队长带队赢过、有没有定战术别人照着打」。只会射门（命令）当不了队长。

L5 / L6 用影响面区分：

| 档 | 约等于 | 最低证据 | 再往上还要 |
|----|--------|----------|------------|
| **L5 · 高级** | 阿里 P6 扎实、字节 2-1、腾讯 T9、游戏厂高级 | **一条业务** 的稳定性和容量你能独立扛；P0 能指挥到止血和复盘落地 | — |
| **L6 · 门槛** | 阿里 P7、字节 2-2、腾讯 T10、游戏厂资深 / 专家 | 你定的规范别人在用；跨 2 条以上业务复用同一套机制 | 带演练、改组织纪律、跨团队 impact |

「独立扛」现场三句：你是 on-call primary；活动窗口扩什么、冻什么你拍板；发布冻结 / 回滚你有否决权。你不在场时门禁仍按你的规则跑，才像 L6。

**7 年 vs 10 年**：差在标准复用和带演练，不是多会几个命令。10 年仍讲「我重启好了」，不如 6 年能讲 SLO、容量水位、war room 决策。7 年合格线 = **一条业务独立扛**。

同一套 K8s：互联网厂证明管集群；游戏厂必须再证明 **开服失败怎么回滚、活动时有状态服扩什么不能扩什么**。缺游戏证据 → 定中级。

> **记住**：工龄是门票，四维证据才是定级材料。缺一维，band 往下打。技术题答满不自动 Senior。

**面试怎么说**：「我定级看四维 Owner 证据：稳定性有 SLO 和停发版记录，容量有模型和水位，工程化有别人在用的流水线，故障有 war room 指挥和 action 落地——缺一维我会自己先承认缺口。」

**读图三句话：**

1. **没有箭头从「工龄」直接指向高级 band**——10 年只扛自己几台，出口在 stuck。
2. **四维都要有你 Owner 的数字**；一维只能答「我们团队一起」，这一维记 0。
3. **出口是 band，不是故事。** High 信号够 → 高级预算；Low 信号多 → 中级预算。

四家对照（同一套 K8s，游戏厂还要有状态证据）：

| 厂 | L5 最低证据 | L6 门槛 |
|----|------------|---------|
| **阿里** | 变更可审计、冻结发布、容量模型、窗口纪律 | 定规范，别人按你的标准做 |
| **字节** | 数字驱动：告警有效率 / 水位 / MTTR、多集群 | 把人从重复劳动捞出来，跨业务 impact |
| **腾讯** | 海量 CVM 或游戏 BG：发布、故障闭环完整 | 版本 / 活动保障可复制，影响其他业务纪律 |
| **游戏厂** | 开合服、热更、活动高峰；有状态服门禁和回滚 | 监控 / 发布 / 开服流水线被后续项目复用 |

投阿里：变更管控、容量、大促对等窗口。投字节：容量、多集群、告警治理数字。投腾讯 / 游戏厂：**开服、热更、活动、回档** 必须能讲 5 分钟。AI / GPU 是加分，不是定级主科。

## 3. 原理

### 3.1 稳定性：SLO 才是门禁

**一句话：** 没有一次「因预算烧完而停发版」的记录，就别把 SLO 写进简历。

**打个比方**：SLO 像银行信用额度——额度（1−SLO）用完了，本月不能再刷大额消费（功能发布），但紧急还款（hotfix / 回滚）还能走。

**现场走一遍**（总监抽查：「这条业务什么叫坏了，谁被叫醒？」）：

1. 你开口先定口径，不要背组件清单：「登录成功率、进战斗成功率、掉线率、支付成功率分开量；CCU 10 分钟腰斩单独告警。」
2. 对方追问：「SLO 多少？」——你答目标 + 统计窗口：「登录 SLO 99.5%，按 30 天滑动窗口；错误预算 0.5%。」
3. 对方追问：「预算烧完怎么办？」——这是分水岭：「Q3 有一次预算烧到 80%，我拍板冻结非关键功能发布 2 周，hotfix 和回滚通道保留。」
4. 屏幕若让你指证据：SLO 文档、发布冻结记录、告警规则里「CCU 腰斩」那条。
5. 若只能答「可用性 99.9%」一句话、说不出谁被叫醒 → 稳定性维记中级。

**输出解读**（中级 vs 高级信号对照）：

| | 中级信号 | 高级信号 |
|--|---------|---------|
| SLO | 「可用性 99.9%」一句话 | 登录成功率、进战斗 / 核心 API、掉线、支付分开 |
| 变更 | 有审批流 | 发布窗口、灰度门禁、错误预算耗尽停功能发布 |
| 演练 | 「做过故障演练」 | 杀过 AZ / 切过主从 / 演练过回档，有失败记录和改进 |

三个词不要混：

| 词 | 是什么 | 定级怎么用 |
|----|--------|------------|
| **SLI** | 你量的那根针：登录成功率、掉线率、支付成功率 | 游戏不要套纯 Web 的 HTTP 占比 |
| **SLO** | 和业务约定的目标 | 写进简历就必须能约束发布 |
| **SLA** | 对外合同 / 处罚 | 面试少讲 SLA，多讲 SLO 怎么进门禁 |
| **错误预算** | `1 − SLO` 允许烧掉的那截 | **烧完停功能发布**，不停 hotfix / 回滚 |

没有历史 SLO：先连续测 **2 周** 核心 SLI，目标略松于现状 P99，再收紧；同时先上叫醒规则。只有机器 CPU 告警，稳定性评不上高级。

**面试怎么说**：「稳定性 Owner 不是有监控，是我定义 SLI/SLO、错误预算烧完能停发版，CCU 腰斩和登录队列有预案——没有停发版记录我不会把 SLO 写进简历。」

> **记住**：SLO 写进简历 = 必须能约束发布。CCU 10 分钟腰斩必须能讲到告警和预案。

### 3.2 容量：先满的那一层

**一句话：** 说「大促前加机器」没有模型，容量维记 0。

**打个比方**：容量像水库——注册百万是「流域面积」，峰值 CCU 才是「洪峰流量」；网关是能泄洪的闸，逻辑服是固定容积的池子，池满了加闸也接不住人。

**现场走一遍**（活动前容量评审，总监问「CCU 超 30% 你怎么办？」）：

1. 先拆口径，不要混：「注册 800 万、DAU 120 万、峰值 CCU 4.5 万、战斗并发 1.2 万——我按 CCU 算容量，不按注册。」
2. 报模型：「网关按连接数，单台 8000 连接上限，峰值要 6 台留 20% 水位；逻辑服按人数上限 500/服，不按 CPU HPA。」
3. 对方改题：「现场 CCU 突然超模型 30%？」——高级答法：「扩网关和大厅；逻辑服**现场加副本不接人**，走排队 + 降级非核心玩法。」
4. 指证据：容量模型表、压测报告、活动前扩了几台网关的记录。
5. 若答「再加两台逻辑服」→ 有状态边界没讲清，容量维往下打。

**输出解读**：

| | 中级信号 | 高级信号 |
|--|---------|---------|
| 口径 | 注册 / DAU / CCU 混用 | 注册、DAU、CCU、战斗并发、登录 QPS 分开 |
| 模型 | 感觉再加两台 | 哪一层先满、水位、扩容边界 |
| 有状态 | 逻辑服按 HPA 扩 | 能扩网关 / 大厅；不能扩走排队、分服、降级 |

你眼睛里该有的数字：峰值 CCU、单玩家资源、哪一层水位先红、活动前扩了几台网关、逻辑服人数上限。

**面试怎么说**：「容量 Owner 是我知道哪一层先满、活动前扩什么、现场 CCU 爆了逻辑服不能 HPA——只能排队分服降级，网关和大厅提前扩。」

> **别混**：注册百万 ≠ 峰值 CCU；逻辑服按人数上限算，不按 CPU 利用率。

### 3.3 工程化：别人在用才算

**一句话：** 「参与建设监控平台」没有个人模块和数字，工程化记 0。

**打个比方**：工程化像修路——你自己挖了 30 条土路没人走，不如修一条别人天天开的主干道，还统计「通行时间从 40 分钟降到 10 分钟」。

**现场走一遍**（「你做过什么平台化？」）：

1. 不要罗列脚本数量：「我主导开服流水线，第 2 个项目接入同一套，失败能重放、能回滚。」
2. 报数字：「接入 2 个项目；变更类 P1+ 从 12 个月 10 起降到 6 个月 2 起；告警日量从 800 收到 200。」
3. 对方追问阶段名：「预检 → 数据面 → 服务面 → 验收 → 目录写入；失败走拆除 job，镜像禁 latest。」
4. 指证据：流水线 stage 名、接入项目清单、告警前后对比。
5. 若只能说「写了很多脚本」→ 工程化记 0。

**输出解读**：

| | 中级信号 | 高级信号 |
|--|---------|---------|
| 产出 | 写了很多脚本 | 别人在用、故障率 / 人效下降、失败能重放 |
| 流水线 | 能跑 | 有门禁、失败能停、能回滚到确定版本 |
| 告警 | 有 Prometheus | 有效率、on-call 叫醒次数有前后对比 |

DevOps / SRE / 平台工程：

| 词 | 一句话 |
|----|--------|
| **DevOps** | 协作和交付节奏（「关系好」不是 DevOps） |
| **SRE** | 用 SLO / 错误预算量化可靠性 |
| **平台工程** | 把能力做成自助产品（开发自助开服 / 回滚） |

同一套 GitOps：互联网厂追变更可审计、回滚 RTO；游戏厂还要：有状态能不能套 HPA、liveness 会不会集体踢人、开服目录写入是不是流水线最后一步。

**面试怎么说**：「工程化 Owner 是别人在用我的流水线 / 告警规则，有接入项目数和前后对比数字——不是脚本数量。」

### 3.4 故障指挥：不是救火英雄

**一句话：** 只讲「我定位到 Redis 然后重启」是执行层；高级要补为什么先止血、谁有权回滚、action 是否还在。

**打个比方**：故障指挥像急诊室主刀——第一个发现火的是护士（执行层），主刀要决定先止血还是先查病因、和谁对齐对外口径、术后 action 谁跟进。

**现场走一遍**（「讲一次你指挥的 P0」）：

1. **发现**（按分钟）：「21:03 登录成功率告警，我是 primary，5 分钟内拉 war room。」
2. **影响面**：「3 个区服，CCU 从 4.5 万掉到 2.7 万，支付还通。」
3. **止血决策**（主语「我」）：「我拍板回滚最近热更配表，不先重启战斗服；Redis 热点切只读。」
4. **对外**：「和运营对齐公告口径；指挥过 3 人以上。」
5. **根因 + 治理**：「配表未灰度 + 无错误预算门禁；次日门禁上线，90 天 0 复发。」

**输出解读**：

| | 中级信号 | 高级信号 |
|--|---------|---------|
| 角色 | 第一个发现、熟练重启 | war room 拍板止血、对外同步、action 落地 |
| 时间线 | 模糊 | 发现 → 影响面 → 止血 → 根因 → 防复发，按分钟 |
| 规模 | 单人操作 | 指挥过 **3 人以上**、和运营对过玩家公告 |

根因是同事引入的：如实讲协作——你负责止血、时间线和推动复盘；不点名羞辱。

**面试怎么说**：「故障指挥不是第一个发现火，是我在 war room 拍板止血、对齐公告、推动 action 落地——时间线按分钟，指挥过 3 人以上。」

> **记住**：只讲重启 = 执行层。高级 = 决策 + 同步 + 机制还在。

### 3.5 各轮在判什么

**一句话：** 上一段过了不自动带下一段；技术轮过了 ≠ 定级过了。

**打个比方**：四轮像四级跳——跳远过了（技术轮）不保证撑杆过了（定级）；每关判的东西不同，不能拿上一关的卷子答下一关。

**现场走一遍**（同一天四轮，各交什么）：

1. **上午技术轮**：Linux / K8s 排障到命令；带 1 个小故障闭环（六段走到治理）。
2. **下午项目深挖 / 系统设计**：游戏项目五层 + 白板先问约束（见 [02](../02-简历与项目/)、[03](../03-系统设计/)）。
3. **傍晚定级 / 总监**：只打四维 + 复盘 + 推动；不问 kubelet 原理。
4. **晚上 HR**：年包 **70–75 万** 区间，拆 4 年 TC（见 [04](../04-行为面与谈薪/)）。

```mermaid
flowchart LR
    A[技术轮<br/>会不会干活] --> B[项目深挖 / 系统设计<br/>是不是真操过生产]
    B --> C[定级 / 总监对话<br/>能不能定到高级]
    C --> D[HR 谈薪<br/>稳不稳、价是否在 band]

    classDef a fill:#0891B2,stroke:#155E75,stroke-width:2px,color:#fff
    classDef b fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef c fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    classDef d fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class A a
    class B b
    class C c
    class D d
```

**输出解读**（High / Low 听自己）：

| High | Low |
|------|-----|
| 开口先确认规模和 SLO | 直接背组件清单 |
| 每个结论跟数字和口径 | 「大幅提升」「稳定性很好」 |
| 主语「我」，决策点清楚 | 「我们团队一起」 |
| 有 rejected 方案和代价 | 只有唯一正确架构 |
| 游戏约束（有状态、开服开关）主动讲 | 把战斗服讲成可随意滚动的 Web |

65–75 万是一线城市高级 band 中位锚点，**前提是定级按高级**。四维不足 → 中级预算；职级明确中级，很难谈到 75。

**面试怎么说**：「技术轮证明会干活，定级看四维 Owner 证据——两关材料不同，我不会用 kubectl 命令答总监的 war room 题。」

## 4. 落地方法

### 4.1 每维怎么备证据

**一句话：** 每维只备 **1 个 Owner 故事 + 2 个硬数字**，不要四维都讲成「我们有 Prometheus」。

备料不是写论文，是对照下表各填一格——填不出的一维，定级前先承认缺口：

| 维 | 故事从哪抽 | 数字从哪来 | 现场要能指 |
|----|-----------|-----------|-----------|
| 稳定性 | 一次因预算烧完停发版；一次灰度拦住 | SLO 文档、发布冻结记录 | 哪条 SLI、谁被叫醒 |
| 容量 | 一次活动前扩容 + 现场超模型 | 容量模型表、压测报告 | 哪一层先满、逻辑服上限 |
| 工程化 | 一条流水线被第 2 个项目接入 | 接入项目数、告警量前后 | 阶段名、失败退出码 |
| 故障指挥 | 一次你拍板回滚的 P0 | MTTR、是否复发、action owner | 分钟级时间线 |

自评口诀：对照四维说现有证据和缺口。不要说「我肯定 P7」。

人设一句话（按真实数字替换，禁止虚构）：

> N 年游戏运维 / SRE，做过 XX 从 0 到 1：开合服自动化、K8s、监控。峰值 CCU / 区服数 / 云。目标高级 SRE，稳定性和发布做成可复制体系。

### 4.2 技术题六段

**一句话：** 停在「命令」会被判中级；必须走到止血和治理。

技术轮最容易死在第三段——只会报命令，不会说「接下来怎么止血、怎么防复发」。六段是强制补全路径：

```mermaid
flowchart LR
    A[原理] --> B[现象带规模]
    B --> C[看哪个指标 / 日志]
    C --> D[止血]
    D --> E[根因]
    E --> F[治理]

    classDef a fill:#0891B2,stroke:#155E75,stroke-width:2px,color:#fff
    classDef b fill:#2563EB,stroke:#1E3A8A,stroke-width:2px,color:#fff
    classDef c fill:#7C3AED,stroke:#4C1D95,stroke-width:2px,color:#fff
    class A,B a
    class C,D b
    class E,F c
```

用登录成功率从 99.5% 掉到 92%、持续 8 分钟串六段：

1. **原理**：登录链过网关 → 大厅 → Redis session → 目录。
2. **现象带规模**：峰值 CCU N，哪几个区服，错误率 A%→B%，持续 Z 分钟。
3. **看哪个**：登录失败码、网关连接数、Redis 延迟 / 热点，不是先看 CPU。
4. **止血**：最近变更能回就回；Redis 热点切只读 / 扩从；**不先重启战斗服**。
5. **根因**：技术（热点 key）+ 流程（没有水位告警、变更未灰度）。
6. **治理**：水位告警上线、变更冻结窗口，90 天能否 0 复发。

系统设计开口第一句：**先问约束再画图**（规模、SLO、有状态、RTO、预算）。画法见 [03](../03-系统设计/)。

### 4.3 本模块怎么用：不要平均复习

复习像备料——四块肉（技术 / 简历 / 白板 / 定级谈薪）不能每块切一样厚：

1. 技术底座扛住，同时改简历（第 1 周就改）。
2. 每个代表项目填一页深挖稿，按五层追问练口述（见 [02](../02-简历与项目/) + [项目深挖模板总索引](../项目深挖模板总索引.md)）。
3. 系统设计只练六主菜：开服、监控告警与 SLO、容量、发布回滚、K8s 集群、多活。
4. 定级前把四维证据和谈薪三档背熟。

投游戏厂主故事必须是开服 / 热更 / 活动。AI 经历加分一笔，主线不跑偏。

## 5. 常见坑与红线

定级现场最常见的坑，不是答错技术题，是 **证据链断了**——下面这张表是考官视角：

| 坑 | 考官怎么判 | 改法 |
|----|-----------|------|
| 用工龄换职级 | 「7 年」但故事全是接单 | 每维补 1 个 Owner 证据 |
| 四维只讲稳定性 | 容量 / 工程化 / 指挥全空 | 容量模型和一次 war room 必须备 |
| 游戏履历讲成 Web | 有状态、开服、热更没出现 | 主故事必须是游戏约束 |
| 把 AI / LLM 当主线 | 岗是业务 SRE，主线跑偏 | 加分一笔带过 |
| 技术轮炫架构、定级不会讲人 | 定级材料没备 | 定级只打四维 + 复盘 + 推动 |

7 年被打成中级典型信号：答题停在命令；主语「我们」；没有数字和 rejected；游戏履历讲成 Web；定级骂前司。

红线（当场把 band 往下打）：

1. 把不会的 SLO / GitOps 写成 Owner。
2. 战斗服按 Web 滚动、逻辑服现场 HPA。
3. 先报底价、只谈月薪（定级材料不足时晚上再争也晚了）。
4. 虚构 P7 / 2-2。自评对证据，不对称号。

> **记住**：技术题答满不自动 Senior。大厂按 **你有没有独立扛过稳定性和容量** 定级。

## 6. 卡住时怎么改

**一句话：** 主语是谁？有没有口径？有没有游戏约束？

定级对话里对方一皱眉，通常是这三样缺了一样——按图改口，不要硬撑：

```mermaid
flowchart TB
    A[对方皱眉或追问] --> B{刚才 3 分钟里有什么}
    B -->|主语「我们」| C[改口补「我」和决策点]
    B -->|结论没口径| D[补分子分母或改成量级]
    B -->|没有 CCU / 开服 / 有状态| E[拉回游戏主故事]
    B -->|停在命令| F[补止血 + 治理]
    B -->|直接画盒子| G[停笔，先问约束]
    B -->|四维被抽空| H[只打备过的那一维，承认缺口]

    classDef ok fill:#16A34A,stroke:#14532D,stroke-width:2px,color:#fff
    class C,D,F,G ok
    class E,H bad
```

现场顺序：停 2 秒 → 改口「我这边的口径是……我拍板的是……」→ 接一个数字 → 点名最弱一轮 + 已做的补法。

## 7. 必会 · 常考

下面这张对错表是定级口试的高频雷区——背口径，不要背「对/错」两个字：

| 说法 | 对错 | 口径 |
|------|:----:|------|
| 工龄 8 年就该定 P7 / 2-2 | 错 | 按证据，不按工龄 |
| 技术题答满自动 Senior | 错 | 技术是门票；四维定 band |
| 四维缺容量仍可定高级 | 错 | 缺一维，band 往下打 |
| 「可用性 99.9%」算稳定性 Owner | 错 | 要分 SLI，且错误预算能停发布 |
| 大促加机器 = 容量 Owner | 错 | 要口径、模型、水位、有状态边界 |
| 写了 30 个脚本 = 工程化 | 错 | 别人在用、失败能重放 |
| 第一个发现火 = 故障领导力 | 错 | 要拍板、同步、action 落地 |
| 逻辑服可以按 CPU 做 HPA | 错 | 有状态；现场排队 / 分服 / 降级 |
| 同一套 K8s，游戏厂按互联网口径定级 | 错 | 还要开服回滚和有状态边界 |
| 职级中级也能谈到 75 万 | 错 | 很难；先重定级或礼貌拒 |
| AI / GPU 可以当定级主线 | 错 | 加分；主线仍是稳定性 |

数字：年包锚点 **65–75 万**；每维 **1 个 Owner + 2 个硬数字**；P0 指挥 **3 人以上**；没有 SLO 先测 **2 周**；错误预算烧完停 **功能发布**；CCU **10 分钟腰斩** 必须能讲预案；7 年合格线 = **一条业务独立扛**。

易混：L5 一条业务 Owner vs L6 定规范别人用；救火英雄 vs 故障指挥；DevOps vs SRE vs 平台工程；SLI vs SLO vs SLA；技术轮过了 vs 定级过了。
