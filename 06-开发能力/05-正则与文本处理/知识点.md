# 05｜正则与文本处理 · SRE 开发能力

> 把 grep / sed / awk / jq / Python re 当**管道工具链**：先 `head -1` 对格式，先过滤再聚合，sed 改文件先预览；不是「一条万能正则打天下」。

## 面试怎么考

| 标记 | 考点 |
|------|------|
| **核心** | 先过滤再聚合；列号以 `log_format` 为准；BRE vs ERE；贪婪 vs 字符类 |
| **必会** | Top IP / 每小时 QPS / jq 非 Running Pod；sed 预览 + `-i.bak`；Python 命名组 + search |
| **常用** | access / error log 字段提取；10GB 日志 grep 缩小；YAML `image:` 不能靠 grep |
| **常考** | RE2 vs PCRE；grep 默认 BRE；回溯爆炸 `(.+)+`；Top IP 不能直接封禁 |

**30 秒怎么说**：正则排障三步——先 `head -1` 对列号，Nginx 以你们 `log_format` 为准；大文件 grep 缩小再 awk 计数，禁止几十 GB 直接 sort；sed 改配置先 `diff` 预览再 `-i.bak`。JSON 用 jq，YAML 用 yq / safe_load，别 awk 硬拆。Python re 用 search 和命名组，用 `[^"]*` 代替贪婪 `.*`，禁止嵌套量词。Top IP 只解释现象，封禁走变更单。

## 能力边界

| 维度 | grep / sed / awk / jq | Python re | Shell 脚本 |
|------|----------------------|-----------|------------|
| **适合** | 跳板机 one-liner、GB 级过滤计数、kubectl JSON 抽取 | 命名组、跨行、坏行跳过、接 API 输出 | 管道编排、调已有命令 |
| **不适合** | 嵌套 JSON 硬拆、多行 YAML 审计、复杂回溯正则 | 纯过滤几 GB（C 更快） | 十层管道无人 review |
| **生命周期** | 5 分钟排障、一次性统计 | 可入库脚本、结构化输出 | Git 脚本 + Runbook |
| **vs 彼此** | awk 分列计数；jq 专 JSON | 百万行逐行 + Counter | 把上面串起来 |

三个角色不要混：

| 角色 | 干什么 | 面试口径 |
|------|--------|----------|
| **grep** | 缩小范围（5xx、ERROR、去注释） | 默认 BRE，生产写 `-E` |
| **awk** | 分列、计数、substr 时间窗 | 列号以 log_format 为准 |
| **sed** | 流式替换；预览后再 `-i` | 不是配置管理系统 |
| **jq** | kubectl JSON、日志 JSON 行 | 不要用 awk 拆 `{` |
| **Python re** | 命名组、畸形行容错 | search 不是 match |

> **记住**：10 行管道 → grep/awk/jq；要命名组 / 接 API → Python；改 100 台配置 → Ansible，不是裸 `ssh sed -i`。

## 语法必会

按 SRE 场景组织：每点 **用法 + 示例 + 易错**。

### 1. grep -E

**用法**：生产默认 `grep -E`（ERE）；缩小日志、抽 IP、去注释行。

```bash
# 5xx 行
grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log

# 抽 IP（-o 只输出匹配部分）
grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' access.log | head

# 去注释和空行
grep -vE '^\s*(#|$)' nginx.conf

grep -E 'ERROR|WARN|FATAL' app.log
```

**易错**：

| 写法 | 结果 |
|------|------|
| `grep 'error+'` | BRE 下 `+` 是字面量，匹配不到 `errorr` |
| `grep -E 'error+'` | 正确：一个或多个 r |
| `cat file \| grep pat` | 多进程；大文件用 `grep pat file` |
| `\d+.\d+.` 当 IP | `.` 匹配任意字符，误匹配 |

### 2. sed 先预览

**用法**：改配置**永远**先不加 `-i`，管道到 `diff` 看差异；确认后 `-i.bak`。

```bash
# 预览 my.cnf
sed 's/max_connections=100/max_connections=500/' my.cnf | diff -u my.cnf -

# 确认后加备份
sed -i.bak 's/max_connections=100/max_connections=500/' my.cnf

# 路径含 / 换分隔符
sed 's|/old/path|/new/path|g' config.conf

# 多机模板渲染
sed -e 's/{{DB_HOST}}/192.168.1.100/g' \
    -e 's/{{DB_PORT}}/3306/g' template.conf > production.conf
```

```text
--- my.cnf
+++ -
@@ -1,3 +1,3 @@
 [mysqld]
-max_connections=100
+max_connections=500
 port=3306
```

**易错**：

| 坑 | 修法 |
|----|------|
| `s/100/500/g` 误改端口里的 100 | 匹配完整键 `max_connections=100` |
| macOS `sed -i` 把后缀当文件名 | `sed -i ''` 或 `sed -i.bak` |
| `.` 未转义 | `s/10.0.0.1/` 会误伤 `10x0x0x1` |
| 多机裸 `ssh sed -i` | 走 Ansible / Git，见 04 |

### 3. awk 字段

**用法**：默认空白分列；`-F` 指定分隔符；`$1..$NF` 字段，`NR` 行号，`OFS` 输出分隔符。

```bash
# 先对列
head -1 access.log
awk '{print $1, $7, $9}' access.log | head

# 状态码分布
awk '{count[$9]++} END {for (c in count) print c, count[c]}' access.log | sort -k2 -rn

# 5xx Top IP
awk '$9 ~ /^5/ {count[$1]++} END {for (ip in count) print count[ip], ip}' access.log \
  | sort -rn | head -10

# 每小时 QPS（combined $4 形如 [28/Aug/2026:10:00:00）
awk '{h=substr($4,14,2); count[h]++} END {for (h in count) print h, count[h]}' access.log | sort
```

```text
192.168.1.10 /login 502
192.168.1.20 /api 200
10 15234
11 18902
```

**易错**：

| 坑 | 修法 |
|----|------|
| 抄网上 `$9` 当 status | 以你们 `log_format` 为准 |
| `$NF` 当 RT | combined 里 `$NF` 常常是 `-` 或 `"Mozilla..."` |
| 只取小时做 key | 跨天文件两天的 10 点会加在一起 |
| awk 硬拆 JSON | 用 jq |

### 4. jq + kubectl JSON

**用法**：几 MB 的 `kubectl -o json` 用 jq 流式抽取；比 Python 先 loads 全量更顺手。

```bash
# 基础
echo '{"a":{"b":2}}' | jq '.a.b'

# Pod 名 + 状态
kubectl get pods -A -o json | jq '.items[] | {name: .metadata.name, ns: .metadata.namespace, status: .status.phase}'

# 所有镜像
kubectl get pods -A -o json | jq -r '.items[].spec.containers[].image'

# 非 Running
kubectl get pods -A -o json | jq -r '.items[] | select(.status.phase != "Running") | "\(.metadata.namespace)/\(.metadata.name)"'

# restartCount > 0（先判 null）
kubectl get pods -A -o json | jq -r '.items[] | select(.status.containerStatuses != null) | select(.status.containerStatuses[].restartCount > 0) | .metadata.name'
```

```text
default/nginx-7d8f9c-abc12
kube-system/coredns-xyz
registry.example.com/app:v1.2.3
monitoring/prometheus:2.45.0
```

**易错**：Pending Pod 可能没有 `containerStatuses`；宽表 `kubectl get pods` 会截断镜像名，必须 `-o json`。

### 5. Python re 命名组

**用法**：`re.compile` + `(?P<name>...)` + `search` 逐行；输出 `groupdict()`。

```python
import re

error_pat = re.compile(
    r'\[(?P<ts>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})\]'
    r'\s+\[(?P<level>\w+)\]'
    r'\s+(?P<msg>.*)'
)

results = []
with open("app.log") as f:
    for line in f:
        m = error_pat.search(line)   # search 任意位置；match 只从开头
        if m:
            results.append(m.groupdict())
```

**易错**：

| 坑 | 修法 |
|----|------|
| `re.match` 对 syslog 前缀行 | 改用 `search` |
| `.*` 抽引号内 URL | 用 `[^"]*` |
| `\d+.\d+.` 当 IP | `.` 要 `\.` |
| 全文件 `read()` 进内存 | 逐行 + 超长行截断 |

## 原理讲透

### 3.1 BRE / ERE / PCRE / RE2

**一句话**：grep 默认 BRE（`+ () {}` 要转义）；生产写 `-E`；Python 用 PCRE 系；Go/Rust 常用 RE2（无回溯灾难）。

**打个比方**：像不同方言的「加号」——BRE 里 `+` 是字面字符，ERE 里才是「一个或多个」。

**现场走一遍**（grep 搜 error 行数为零）：

1. `grep 'error+' app.log` → 无匹配（BRE 下 `+` 是字面量）。
2. `grep -E 'error+' app.log` → 匹配 `error`、`errorr`。
3. **输出解读**：笔试问默认模式 → **BRE**；生产 one-liner 一律 `-E`。

**面试怎么说**：「grep 默认 BRE，生产写 -E；Python re 是 PCRE，Go regexp 是 RE2 无灾难回溯。」

| 引擎 | 标志 / 环境 | 特点 | SRE 场景 |
|------|-------------|------|----------|
| **BRE** | 裸 `grep` | `+ () {}` 需 `\` 转义 | 笔试陷阱 |
| **ERE** | `grep -E` | `+ () {}` 直接用 | **生产默认** |
| **PCRE** | `grep -P`、Python `re` | 前瞻后顾、命名组 | 复杂提取 |
| **RE2** | Go `regexp`、ripgrep | 线性时间、无灾难回溯 | 新工具选型 |

> **记住**：笔试问「grep 默认什么模式」→ **BRE**。生产 one-liner 一律 `-E`。

### 3.2 贪婪与回溯

**一句话**：`.*` 贪婪吃到最后一个分隔符；嵌套量词 `(.+)+` 让引擎指数级吐回字符，畸形行 CPU 100%。

**打个比方**：像贪吃蛇一口吞到地图尽头——`.*` 会吃到最后一个 `"`，中间 URL 全糊在一起。

**现场走一遍**（Python 正则抽 JSON 行字段，CPU 100%）：

1. `re.compile(r'(.*:)+$')` 跑 10GB 畸形日志。
2. `top` 里 Python 单核 100%，脚本像 hang 住。
3. 改 `r'^[^:]+(:[^:]+)*$'` + 跳过超长行 → 线性扫描恢复。

**面试怎么说**：「抽引号内字段用 `[^"]*` 不用 `.*`；禁止 `(.+)+` 嵌套量词。」

```mermaid
flowchart LR
    A["(.+)+ 或 (.*:)+$"] --> B[畸形行 / 超长行]
    B --> C[尝试次数指数涨]
    C --> D[CPU 100% · 排障卡住]

    classDef bad fill:#DC2626,stroke:#7F1D1D,stroke-width:2px,color:#fff
    class A,D bad
```

### 3.3 awk 分列

**一句话**：awk 按分隔符切 `$1..$NF`；Nginx combined 常见 `$1` IP、`$4` 时间、`$7` path、`$9` status——**偏移随 log_format 变**。

**打个比方**：像 Excel 按列统计——列号抄错，求和全错；必须先 `head -1` 对表头。

**现场走一遍**（5xx 统计为零）：

1. 网上抄 `$9` 当 status，实际 log_format 把 status 放在 `$10`。
2. `head -1 access.log` + 对 nginx.conf 里 `log_format`。
3. `awk '{print $9, $10}' access.log | head` 确认后再统计。

**面试怎么说**：「列号以 log_format 为准，combined 小时用 substr($4,14,2)；跨天 QPS key 要带日期。」

### 3.4 jq vs awk 拆 JSON

**一句话**：JSON 是结构化数据，jq 懂层级；awk 按空格切会把 `{` 和键名拆散。

**现场走一遍**（kubectl 找非 Running Pod）：

```bash
kubectl get pods -A -o json | jq -r '.items[] | select(.status.phase != "Running") | "\(.metadata.namespace)/\(.metadata.name)"'
```

**输出解读**：Pending Pod 可能没有 `containerStatuses`；宽表 `kubectl get` 会截断镜像名，必须 `-o json`。

**面试怎么说**：「JSON 用 jq，YAML 用 yq/safe_load，别 awk 硬拆。」

### 3.5 性能：先过滤再聚合

**一句话**：几十 GB 禁止直接 `sort` 打满内存；顺序是 `head -1` → grep 缩小 → awk 计数 → 必要时 sort Top N。

**打个比方**：像大海捞针——先用磁铁（grep 5xx）缩小范围，再数针（awk），别先把整片海水舀干（全文件 sort）。

**现场走一遍**（10GB access.log Top IP）：

1. `grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log | awk ... | sort -rn | head -10`
2. 禁止：`sort access.log` 一次进内存 → 跳板机 OOM。

**面试怎么说**：「大文件先 grep 再 awk；Top IP 只解释现象，封禁走变更单。」

```mermaid
flowchart LR
    log[日志/JSON] --> h[head -1] --> g[grep 缩小] --> a[awk/jq 计数]
    a --> out[sort | head Top N]
```

## 生产模板

**502 现场标准三步**：状态码分布 → 5xx Top IP → Top URL → 分扫号还是上游挂。

### 模板 1：access / error log 字段提取

**现场走一遍**：先 `head -1 access.log` 对列，再 awk 或 Python 命名组抽字段。

```bash
head -1 access.log
awk '{print $1, $4, $7, $9, $NF}' access.log | head -5
```

```text
192.168.1.10 [28/Aug/2026:10:00:01 /login 502 "-"
192.168.1.20 [28/Aug/2026:10:00:02 /api 200 "Mozilla/5.0..."
```

**error log**（Python 命名组 + `search`）：

```python
import re
pat = re.compile(
    r'\[(?P<ts>\d{4}-\d{2}-\d{2} \d{2}:\d{2}:\d{2})\]\s+\[(?P<level>\w+)\]\s+(?P<msg>.*)'
)
with open("app.log") as f:
    for line in f:
        m = pat.search(line)
        if m and m.group("level") in ("ERROR", "FATAL"):
            print(m.group("ts"), m.group("msg")[:120])
```

### 模板 2：5xx Top IP（现场走一遍）

1. `head -1 access.log` 对列号。
2. grep 缩小 5xx，再 awk 计数（10GB 禁止直接 sort 全文件）。
3. Top IP 集中 URL 杂 → 扫号；`/login` 集中 → 上游挂。**不要直接 iptables 封 Top IP。**

```bash
# 大文件先缩小
grep -E 'HTTP/[0-9.]+" 5[0-9][0-9]' access.log \
  | awk '{count[$1]++} END {for (ip in count) print count[ip], ip}' \
  | sort -rn | head -10
```

```text
842 203.0.113.50
156 198.51.100.22
89 192.168.1.100
12 10.0.0.5
```

口径：Top 里有探活 / NAT 出口——统计只解释现象，封禁走变更单（见模板 5 踩坑）。

### 模板 3：每小时 QPS

```bash
awk '{k=substr($4,14,2); count[k]++} END {for (h in count) print h, count[h]}' access.log | sort -n
```

```text
09 12450
10 28901
11 31200
12 19880
```

跨天：key 用 `substr($4,2,11) substr($4,14,2)`（日期+小时），不要只取 2 位小时。

### 模板 4：jq 非 Running Pod

```bash
kubectl get pods -A -o json | jq -r '
  .items[]
  | select(.status.phase != "Running")
  | "\(.metadata.namespace)\t\(.metadata.name)\t\(.status.phase)"
'
```

```text
default     nginx-deploy-abc12    CrashLoopBackOff
game        login-svc-xyz99       Pending
monitoring  alertmanager-0        ImagePullBackOff
```

### 模板 5：sed 改 my.cnf + diff 预览

活动前 100 台改 `max_connections`：

```bash
# 1. 预览
sed 's/max_connections=100/max_connections=500/' my.cnf | diff -u my.cnf -

# 2. 确认后备份写入
sed -i.bak 's/max_connections=100/max_connections=500/' my.cnf

# 3. 批量（仍建议 Ansible）
find /etc/mysql -name 'my.cnf' -exec sed -i.bak 's/max_connections=100/max_connections=500/' {} +
```

```text
--- my.cnf
+++ -
@@ -2,4 +2,4 @@
 [mysqld]
-max_connections=100
+max_connections=500
 port=3306
```

502 现场：先状态码分布 → 5xx Top IP → Top URL → 分扫号（path 随机）还是上游挂（`/login` 集中 5xx）。

## 踩坑清单

| 现象 | 原因 | 修法 |
|------|------|------|
| 5xx 统计为零 | 列号抄错（`$10` vs `$9`） | `head -1` + 对 `log_format` |
| `grep 'error+'` 无匹配 | 默认 BRE，`+` 字面量 | `grep -E 'error+'` |
| sed 端口里的 100 也被改 | `s/100/500/g` 太宽 | 匹配完整键名 |
| 正则 CPU 100% | `(.+)+` / `(.*:)+$` | 改 `[^:]*` 字符类 |
| `.*` 两个 URL 糊一段 | 贪婪吃到最后 `"` | `[^"]*` |
| awk 拆 JSON 字段乱 | JSON 不是空白分列 | jq |
| grep `image:` 漏镜像 | 多行 YAML / 缩进 | yq / `safe_load` |
| Top IP 封禁后登录全挂 | 探活 / NAT 出口被封 | 白名单 + 变更单 |
| 几十 GB sort OOM | 未先 grep 缩小 | 先过滤再聚合 |
| `re.match` 全 None | 行首有 syslog 前缀 | 改 `search` |
| macOS `sed -i` 异常 | BSD sed 规则 | `-i ''` 或 `-i.bak` |
| 只取小时 QPS key | 跨天加总 | 日期+小时做 key |

## 必会 · 常考

| 说法 | 对错 | 口径 |
|------|:----:|------|
| grep 默认 ERE | 错 | 默认 **BRE**；生产写 `-E` |
| RE2 和 PCRE 一样 | 错 | RE2 线性无灾难回溯；功能子集 |
| `.*` 抽引号字段最省事 | 错 | 贪婪；用 `[^"]*` |
| `(.+)+` 只是「一个或多个」 | 错 | 嵌套量词 → 回溯爆炸 |
| `re.match` 和 `search` 一样 | 错 | match 只从行首 |
| 网上 `$9` 一定是 status | 错 | 以 `log_format` 为准 |
| `sed -i` 不用 bak | 错 | 不可逆；先 diff |
| JSON 用 awk 拆 | 错 | jq |
| grep `image:` 能审计全部镜像 | 错 | 多行 YAML |
| Top IP 可以直接 iptables | 错 | 可能是探活；走变更 |
| `cat \| grep` 和 grep 文件一样 | 错 | 多进程；大文件更差 |

**数字**：Top N 常用 `head -10`；combined 小时 `substr($4, 14, 2)`；分钟 5 字符 `substr($4, 14, 5)`。

**易混**：BRE vs ERE vs PCRE vs RE2；贪婪 vs 字符类；search vs match；sed vs awk；jq vs awk；统计 vs 变更（封禁）。
